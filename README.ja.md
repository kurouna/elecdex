# elecdex

SF 風のデスクトップ用ターミナルエミュレーター兼システムモニターです。
[eDEX-UI](https://github.com/GitSquared/edex-ui)（2021 年にアーカイブ済み）を、現在の安全な技術スタックで
一から書き直したもので、Windows・macOS・Linux に対応しています。

  <img src="./docs/screenshots/elecdex-tron.jpg" alt="Tron テーマの elecdex：左にシステムモニター、中央にランチャーとファイルブラウザーを備えた 3 つのシェルタブ、右にワールドビュー、マーケット、天気、カレンダー">
</p>

> *unreleased* と記したものは `main` にあり、次のリリースで入ります。
>

> 見つけたものはぜひ[報告](https://github.com/kurouna/elecdex/issues)してください。

> 設計メモと、すべての判断とその理由：[docs/architecture.md](docs/architecture.md)。

## 機能

ペインは作業ごとに並べ替えられます。6 つの **レイアウトプリセット** が、その作業に合うペインをキー一つ
（**Ctrl+Shift+F1**〜**F6**）で画面に並べます。どのプリセットも左端にシステムの列を持つので、切り替えても
計器はそのままで、舞台だけが替わります。以下では機能を、それを見せるプリセットごとに
まとめました。どの画像も、そのプリセットを別々のテーマで写したものです。

### standard — このマシン、シェル、そして外の世界

elecdex を最初に開いたときの配置で、ページ冒頭の画像がこれです（Tron）。

- **ターミナル** — 本物のシェル（PowerShell、bash、zsh、fish）を、タブと分割で好きなだけ開けます。
  シェル統合により作業ディレクトリと終了コードが Windows でも伝わり、ペインを移動したりリロードしたりしても
  セッションのスクロールバックは残ります。起動時はシェルにフォーカスがあり、テキストを選択するとコピー、
  右クリックで貼り付けです。Ctrl+Shift+F でスクロールバック内を検索でき、シェルが出力した URL は
  ブラウザーで開けます。
- **システムモニター** — タイムゾーン付きの時計、バッテリーゲージ付きのシステムストリップ、コアごとの CPU
  （グラフまたはバー）、メモリとスワップの推移、読み書きの動きが見えるディスク、上位プロセス、
  ネットワークの状態と通信量。既定のレイアウトのアイドル時の負荷は 1 コアの約 13% です。
- **ファイルとアプリ** — シェルに追従するファイルブラウザー（クリックで `cd`、またはパスを挿入）と、
  スタートメニュー（ストアアプリなどのパッケージアプリも含む）、`/Applications` または
  `.desktop` エントリーに自分で追加したものを加え、よく使う順に並べるランチャー。
- **天気・マーケット・カレンダー** — 世界中どこでも見られる天気予報（日本は気象庁、
  米国は National Weather Service、それ以外は MET Norway）、Yahoo Finance のマーケットボード、
  日本の祝日も表示できる月表示のカレンダー。

### network — このマシンの通信相手

<p align="center">
  <img src="./docs/screenshots/elecdex-network.jpg" alt="Amber テーマの network プリセット：左にシステムの列、接続先への弧を描くアンバーのワールドビューの地球儀、その横にプログラムごとのソケット（firefox、code、elecdex、thunderbird、curl、ssh、syncthing）を一覧する connections ペイン、下に横長のシェル">
  <br><sub>network · Amber</sub>
</p>

- **ワールドビューと接続** — このマシンの接続先を示す地球儀と、すべての TCP ソケットを保持しているプログラム
  ごとに一覧するペイン。どちらも同梱の GeoIP データベースで位置を求めるので、
  オンラインで問い合わせることはありません。地球儀の下のシェルは ping や traceroute のためのものです。
- **Wi-Fi** — ソケット一覧の上で、無線のどの区間で問題が起きているかを示します（*ペイン* を参照）。

### earth — 頭上と足もと

<p align="center">
  <img src="./docs/screenshots/elecdex-earth.jpg" alt="Tron テーマの earth プリセット：世界地図、時刻が切り替わる線、9 都市の時計、ISS とその地上軌跡、天宮、淡い点で描いた Starlink 衛星とその 1 基のカードを表示する ORBIT ペイン。横にワールドビュー、日本の最近の地震を一覧する地震ペイン、天気。地図の下にシェル">
  <br><sub>earth · Tron</sub>
</p>

- **Orbit** — 管制室の正面スクリーンです。夜の側、時刻が切り替わる線と各地域の時刻を描いた世界地図に、
  ISS と天宮の現在位置と地上軌跡、選んだ都市の上空を次に通過する時刻、
  管制室の GMT 通算日時計を囲む世界の時計を表示します。求めに応じて Starlink 衛星群も表示します。
- **地震と津波** — 日本（気象庁）または世界（USGS と NOAA）を対象に、選んだ震度やマグニチュードでの
  警報（既定ではオフ）、発表中は常に見える津波警報、最近の地震を一覧する地震ペイン、
  地球儀上の震央表示を提供します。

### dev — 作業中のエージェントと、それが変えているリポジトリ

<p align="center">
  <img src="./docs/screenshots/elecdex-dev.jpg" alt="Phosphor テーマの dev プリセット：2 つの Claude Code セッション（1 つはサブエージェントが作業中でテストがバックグラウンドで実行中）と変更したファイルを表示する AI AGENT ペイン、その下に 2 つのシェルタブ、右に同じチェックアウトを表示する GIT ペイン（passes.ts の差分と、ポインターを置いたコミットのカード付きのコミットグラフ）">
  <br><sub>dev · Phosphor</sub>
</p>

- **AI Agent** *(実験的)* — このコンピューターで作業中の Claude Code セッションを表示します。
  それぞれが今何をしているか、どれだけの量を抱えているか、そのサブエージェントとバックグラウンドタスク、
  変更した各ファイルの差分を、このマシン上の Claude Code 自身の記録から読み取ります。
- **Git** — 選んだリポジトリを読み取り専用で表示します。変更されたファイル、構文を色分けした
  各ファイルの差分、ブランチとタグを含むコミットグラフを、変更に合わせて最新に保ちます。隣のペインで
  AI エージェントの作業を見守れます。ペインは 1 リポジトリにつき 1 つです。

### media — 観て、眺めて、音を見る

<p align="center">
  <img src="./docs/screenshots/elecdex-media.jpg" alt="White テーマの media プリセット：撮影用に用意した代わりのページ（テレビの動画ホーム画面風とタイムライン風。チャンネルもアカウントも架空）を表示する YouTube (TV) ペインと X ペイン、X の後ろに RSS のタブ。テレビの下に蛍光管シアンの 16 バンドのスペクトラムと、マスター・Music Player・Web Browser のストリップを持つミキサー">
  <br><sub>media · White — Web ペインには撮影用に用意した代わりのページを表示しています</sub>
</p>

- **Web ペイン** — ブラウザー、YouTube、X を、必要なときに追加するペインで表示します。
  テーマの色で（設定によってはサイト本来の色で）描かれ、サイトごとのサインインは 1 つを共有します。
- **スペクトラムとミキサー** — コンピューターが再生している音のスペクトラムアナライザーを、
  1990 年代のカーステレオの表示のように（蛍光管のシアンかアンバー、LED、またはテーマの色で）描きます。
  システム音量と、音を出している各アプリの音量を調整するミキサーもあります。
- **RSS** — 登録した RSS・Atom フィードの見出しを新しい順に表示します。

<p align="center">
  <img src="./docs/screenshots/elecdex-desk.jpg" alt="Business (Light) テーマの desk プリセット：リリースのチェックリストを書いたメモペイン、その下にタイマーと電卓、今日・明日・それ以降に分けて期限をメーターで描くタスクペイン、3 か月分のカレンダー">

### モデルと話す

<p align="center">
  <img src="./docs/screenshots/elecdex-aichat.jpg" alt="Business (Dark) テーマで、ターミナルの下に AI チャットペイン：Node.js でフォルダーを監視する方法への、コードブロックとトークン数付きの回答と、届きつつある 2 つ目の回答（見出しに RX と経過秒数・文字数）">
  <br><sub>AI チャット · Business (Dark)</sub>
</p>

- **AI チャット** — 自分で動かす言語モデル（Ollama、LM Studio、llama.cpp など、
  OpenAI のチャット API を話すもの）や、API キーを持っているサービス（Anthropic、OpenAI、
  Gemini、OpenRouter）と会話できます。回答はストリーミングで届き、推論部分は折りたたまれます。キーは
  OS によって暗号化されてページには渡らず、会話はこのコンピューターの中にとどまります。

<p align="center">
  <img src="./docs/screenshots/elecdex-elec.jpg" alt="Tron テーマで、中央の列いっぱいに ELEC system ペイン：六角形のコアを囲む三角形に同じ大きさの 3 枚のプレート。LOGOS と PATHOS は APPROVE で緑に点灯し、REJECT で少数となった ETHOS は暗い赤で後ろに下がり、議決の帯は APPROVED 2-1-0-0、その下に 3 つの意見">
  <br><sub>ELEC system · Tron</sub>
</p>

- **ELEC system** — 『新世紀エヴァンゲリオン』の MAGI にならい、はい／いいえで答える議題を
  3 つのモデルの評議会にかけます。LOGOS（論理）、ETHOS（倫理）、PATHOS（感情）がそれぞれの立場から
  判断して APPROVE、REJECT、ABSTAIN のいずれかに投票し、ペインが多数決または全会一致で
  議決します。各席は AI チャットのプロバイダーを使います。3 席すべてが同じモデルでも構いません。

### レイアウト、見た目、そのほか

<p align="center">
  <img src="./docs/screenshots/elecdex-layouts.jpg" alt="Tron テーマの standard レイアウトの上に開いたレイアウトダイアログ：1〜6 の番号が付いた保存レイアウトとしての 6 つのプリセット（それぞれに配置の縮図）、その下にプリセットの棚（縮図、一覧での位置、キー Ctrl+Shift+F1〜F6）">
  <br><sub>レイアウト（Ctrl+Shift+G） · Tron</sub>
</p>

- **レイアウト** — どのペインもタイトルをドラッグして移動でき、閉じる、分割する、タブにする、サイズを変える、
  元に戻すことができます。レイアウトは保存され、リセットもできます。配置に名前を付けて保存し、
  あとで戻ることも（Ctrl+Shift+G、またはステータスバーの *layouts*）、6 つのプリセットから始めることも
  できます。
- **見た目と操作感** — その場で切り替わる 6 つのテーマ。HUD 向けの Tron、Amber、Phosphor、White と、
  普段の仕事向けに Windows 11 の配色、システムフォント、フルカラーのアイコンを使う Business (Dark) と
  Business (Light) があり、どれも上のいずれかの画像に写っています。このマシンの実際の情報を並べる
  Linux 風のブートログのあと、
  CRT の電源が入るような起動シーケンスが続きます（あとから追加したペインも同じように点灯し、閉じたペインは消灯して
  隣のペインがその場所へ広がります。保存したレイアウトに切り替えると画面全体が消灯し、次のレイアウトが
  ペインごとに点灯します。ダイアログや通知も消灯します）。走査線とグロー、
  合成したインターフェース音、テーマに合わせたタイトルバー、画面下端からスライドして現れるステータスバーもあります。
  月ごとの日付の波、せり上がる天気予報、3 秒間ハイライトしながらスライドインする新しい見出しや
  地震といった短い登場エフェクトはモーション設定に従います。モーションを減らす設定
  （またはシステムの「視差効果を減らす」設定）にすると、何も動きません。
- **設定** — テーマ、モーション、サウンド、ターミナルの開始フォルダー、保存したレイアウト、
  ランチャー、変更可能なキーボードショートカット、アップデートの確認を設定するダイアログ。すべて
  手で編集できる `settings.json` に保存されます。

<p align="center">
  <img src="./docs/screenshots/elecdex-settings.jpg" alt="Tron テーマの設定ダイアログ、キーボードの項目">
  <br><sub>Settings → Keyboard · Tron</sub>
</p>

- **プラグイン** — TypeScript ファイル 1 つで自分だけのペインを作れます。サンドボックス化された
  ワーカーの中で、許可した権限だけで動きます（[プラグイン](#プラグイン)）。
- **バックグラウンド実行** — 通知領域・メニューバー・トレイのアイコン、システム全体で使える
  表示／非表示のショートカット、サインイン時の起動。提供される機能はそのマシンで実際にできることに
  合わせるため、環境によって異なります。Windows では通知領域への最小化と、閉じたときの格納が加わります。
  macOS ではそれらを Dock に任せ（ウィンドウを閉じても elecdex は動き続けます）、ログイン項目から
  非表示で起動することはできません。Linux ではトレイとショートカットはデスクトップ環境次第で、
  どちらもないセッションでは、何もしないスイッチを出す代わりにそう表示します。どれも
  *Settings → Window* でオンにするまではオフです。

## インストール

お使いのプラットフォーム向けのインストーラーを
[Releases](https://github.com/kurouna/elecdex/releases) からダウンロードしてください。

| プラットフォーム | ファイル |
| --- | --- |
| Windows x64 / arm64 | `elecdex-win-x64-<version>.exe` / `elecdex-win-arm64-<version>.exe` |
| macOS Apple silicon / Intel | `elecdex-mac-arm64-<version>.dmg` / `elecdex-mac-x64-<version>.dmg` |
| Linux x64 | `elecdex-linux-x86_64-<version>.AppImage` または `elecdex-linux-amd64-<version>.deb` |
| Linux arm64 | `elecdex-linux-arm64-<version>.AppImage` または `elecdex-linux-arm64-<version>.deb` |

作者が普段使っているのは Windows 版です。macOS 版と Linux 版も同じリリースワークフローで作られ、
GitHub のランナー上でエンドツーエンドテストに合格していますが、実機で触って確かめたことはありません。
十分に検証されていないものとしてお使いください。

### 警告が表示されたら

インストーラーにはコード署名をしていません。証明書の費用は個人のプロジェクトで負担できる額を超えるためです。
そのため、Windows と macOS は初回の起動前に警告を表示します。これは発行元が OS にとって未知であることを
示すもので、ファイルに何かが見つかったという意味ではありません。ダウンロードしたファイルを先に確かめたい場合は、
リリースページにすべてのファイルの SHA-256 チェックサムが載っています。各インストーラーは、タグの付いたソースから
GitHub のランナー上で [リリースワークフロー](.github/workflows/release.yml) によってビルドされています。
以下の手順が必要なのは、インストールごとに一度だけです。

**Windows**

1. ブラウザーがダウンロードを保留することがあります（「一般的にダウンロードされていません」）。Edge では、
   ダウンロードの *⋯* メニュー → *保存* → *詳細表示* → *保持する* を選びます。Chrome では *保存* を選びます。
2. `.exe` を実行します。SmartScreen が **「Windows によって PC が保護されました」** と表示したら、**詳細情報** を
   クリックし、続けて **実行** をクリックします。
3. インストーラーは現在のユーザーだけにインストールするため、管理者権限は求めません。

ファイルがブロックされたと表示され、*実行* が出てこない場合は、`.exe` を右クリック →
*プロパティ* → **許可する** にチェック → *OK* とし、もう一度実行してください。

**macOS**（15 Sequoia 以降。それより前のバージョンは最後の手順を参照）

1. `.dmg` を開き、**elecdex** を *アプリケーション* にドラッグします。
2. *アプリケーション* から elecdex を開きます。macOS が **「“elecdex”にマルウェアが含まれていないことを
   検証できませんでした」** と表示したら、**完了** をクリックします（*ゴミ箱に入れる* ではありません）。
3. **システム設定 → プライバシーとセキュリティ** を開き、*セキュリティ* までスクロールして、elecdex についての
   行の横にある **このまま開く** をクリックします。パスワードか Touch ID で確認し、もう一度 **このまま開く** を
   クリックします。
4. macOS 14 以前では、アプリを右クリック → **開く** → **開く** で同じことができます。

代わりに **「“elecdex”は壊れているため開けません」** と表示された場合も、ファイルは壊れていません。
起動を止めているのは、ダウンロード時に付いた検疫（quarantine）属性です。この属性を取り除いてから、
もう一度アプリを開いてください。

```bash
xattr -dr com.apple.quarantine /Applications/elecdex.app
```

**Linux**（警告は出ませんが、知っておいてほしいことが二つあります）

- **deb**（Debian、Ubuntu）: `sudo apt install ./elecdex-linux-amd64-<version>.deb`。Ubuntu 24.04 以降で
  Electron のサンドボックスを起動するために必要な AppArmor プロファイルも、あわせてインストールされます。
- **AppImage**: `chmod +x elecdex-linux-*.AppImage` を実行してから起動します。FUSE 2（`libfuse2`、Ubuntu 24.04
  では `libfuse2t64`）が必要です。Ubuntu 24.04 以降では AppArmor がサンドボックスをブロックするため、
  *SUID sandbox helper* についてのメッセージを出して止まることがあります。その場合は deb を使ってください。
  `--no-sandbox` を付けて起動しないでください。レンダラーをあなたのファイルから遠ざけているのは、このサンドボックスです。

elecdex はフルスクリーンで起動します。**F11** でフルスクリーンを抜け、**Ctrl+Shift+Q** で終了します。
`--windowed` を付けるとウィンドウで起動し、`--no-intro` を付けると起動シーケンスを省略します。

| Ctrl+Shift+W | フォーカス中のペインを閉じる（ホバーで表示される × ボタンでも可） |
| Ctrl+Shift+Z | フォーカス中のペインをワークスペースの手前に出し、また元に戻す（Escape でも可） |
| Ctrl+Shift+[ / ] | ペイン間でフォーカスを移動 |
| Ctrl+Shift+← / → | フォーカス中のタブグループ（シェルのタブなど）で前 / 次のタブへ |
| Ctrl+Alt+Shift+← / → | シェルから: 前 / 次のシェルペイン（またはシェルのタブグループ）へ |
| Ctrl+Shift+A | ペインを追加: 任意のウィジェットを、フォーカス中のペインの右・下、またはその隣のタブとして |
| Ctrl+Shift+Backspace | 既定のレイアウトに戻す |
| Ctrl+Shift+G | 保存したレイアウト: 今の配置に名前を付けて残す、または保存した配置に戻る |
| Ctrl+Shift+1 … 9 | 保存したレイアウトのうち、ダイアログに並ぶ順で最初の九つを適用 |
| Ctrl+Shift+F1 … F6 | プリセットへ切り替え: standard、network、earth、dev、media、desk |
| Ctrl+Shift+L | ランチャーを検索（ランチャーペインがなければ追加） |
| Ctrl+Shift+S | 選択中のタブのシェルにフォーカス（シェルペインがなければ追加） |
| Ctrl+Shift+F | シェルのスクロールバックを検索（Enter / Shift+Enter で次と前、Escape で閉じる） |
| Ctrl+Shift+. | 設定 |
| F11 | フルスクリーンの切り替え |
| Ctrl+Shift+M | ウィンドウを最小化（Windows、Linux） |
| Ctrl+Shift+Q | 終了（閉じても elecdex を通知領域に隠すだけの設定のときも終了します） |
| Ctrl+Alt+Shift+E | どのアプリからでも elecdex を表示 / 非表示（Wayland セッションでは不可。*Settings → Window* でオンにするまでオフ） |
| 区切り線の上で矢印キー | サイズ変更（Shift で大きく動かす） |

elecdex の起動時には、シェルにフォーカスがあります。シェルでは、PuTTY や Windows Terminal と同じように、
テキストを選択するとコピーされ、右クリックで貼り付けられます。Ctrl+C はシェルの割り込みのままです。
検索バーが移動した一致箇所はコピーされず、コピーされるのは自分で選択したものだけです。タブグループの外では
Ctrl+Shift+← / → はそのままシェルに届き、PSReadLine では単語単位の選択になります。

システム全体の表示 / 非表示ショートカットは、*Settings → Window* のスイッチの横で設定します。使えるのは
英字、数字、ファンクションキーだけで、ほかのアプリがすでにそのキーを使っている場合は、その旨を添えてオフに
戻ります。*reset all shortcuts* では変更されず、ショートカットの記録中はキーを手放すので、このショートカット
自体も記録できます。これがオンの間、同じキーを使うアプリ内ショートカットは *Settings → Keyboard* で警告
されます。OS がそのキーを先に elecdex のウィンドウ用ショートカットに渡すためです。elecdex が前面にあるときは
elecdex をしまい、それ以外のときは elecdex を前面に出します。

*Settings → Window* には、ウィンドウの外に置くアイコン（通知領域、メニューバー、トレイ）の設定もあります。
アイコンをクリックすると elecdex が開き、右クリックメニューからは設定を開くか終了できます。また
*launch elecdex when you sign in* もあり、システム側でオフにされた場合は、設定でもオフに戻って表示されます。
ほかに何があるかはマシンによって異なり、elecdex は実際にできることだけを提示します。

| | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 最小化 / 閉じるでアイコンにしまう | 可 | 不可 — ウィンドウを閉じても elecdex は動き続け、Dock から戻せます | デスクトップにアイコンを置く場所がある場合 |
| システム全体の表示 / 非表示ショートカット | 可 | 可 | X11 では可。Wayland セッションはそのキーを自分で握っているため、オプションにその旨が表示されます |
| サインイン時に起動 | Run キーのエントリ（アンインストーラーが削除） | アプリのログイン項目（macOS が許可を求めることがあります） | `~/.config/autostart/elecdex.desktop` |
| *start in the background* | 可 | 不可 — ログイン項目は引数を取れません | 可 |

どの場合でも、elecdex をもう一度起動すれば動いているほうが戻ってくるので、ウィンドウに手が届かなくなる
ことはありません。

区切り線のキー以外のショートカットは、すべて *Settings → Keyboard* で割り当て直せます。項目をクリックして
新しいキーを押してください。ショートカットには Ctrl（macOS では Cmd）、Alt、またはファンクションキーが必要で、
それ以外のキーはすべてシェルに届きます。すでに使われている組み合わせには警告が出ます。ステータスバー
（ポインターを画面の下端に移動すると出ます）には、左端に保存したレイアウトごとの番号付きボタン（番号は
そのレイアウトを適用するキーです）があり、ほかにペインの追加、保存したレイアウト、レイアウトのリセット、設定、
テーマ、サウンド、終了のボタンがあります。Windows と Linux のフルスクリーンでは、ポインターを右上の隅に
移動すると、最小化、フルスクリーン解除、閉じるのボタンが降りてきます。閉じるボタンは、通知領域で動き
続ける設定なら elecdex を通知領域にしまい、そうでなければ確認のうえ終了します。

ペインを動かすには、タイトル（時計のようにタイトルのないペインは上端の線）をドラッグして、別のペインの上で
離します。ポインターに最も近い側に、そのペインと並べて置かれます。離すときに Ctrl（macOS では Cmd）を
押していると、代わりにそのペインのタブとして、タブの並びのうちポインターが指す位置に加わります。すでに
タブが入っているグループの上では、同じ Ctrl でタブの並べ替えになります。シェルのタブは単独でドラッグして
取り出せ、タブグループのヘッダーをドラッグするとグループ全体が動きます。Escape で取り消せます。動かした
シェルはセッションを保ちます。

もっとよく見たいペインは手前に出せます。**Ctrl+Shift+Z** か、右上の × の隣にある ⤢ ボタン（タブグループにも
同じ隅があり、その × はグループ内のすべてのタブを閉じます。タブ自身の × はそのタブだけを閉じます）を使うと、
ペインがほかのペインの上にウィンドウの大部分を覆って表示され、ほかのペインは暗幕の後ろで元の位置に
留まります。広くしても得るもののないペインは対象外です。システムの帯とネットワーク状態には ⤢ がなく、
電卓、タイマー、ミキサー、ディスク、プロセス一覧は、ウィンドウ全体ではなく中央にパネルとして出てきます。
手前に出ている間は、シェルの切り欠きのある枠を一回り大きくした枠（隅にブラケット付き）がペインのすぐ外側を
囲みます。外側に描くので、ペインは与えられた広さをすべて使えます。
Escape、もう一度のショートカット、ボタン、または暗幕のクリックで元に戻ります。タブはグループごと手前に
出るので、ほかのタブにもそのまま切り替えられます。配置は何も変わらず、何も保存されません。シェルは
セッションを、Web ペインはページを保ち、アプリは次回もすべてのペインが元の位置にある状態で起動します。

残しておきたい配置は、名前を付けて保存しておき、あとで戻れます（**Ctrl+Shift+G**、またはステータスバーの
*layouts*）。最初の九つは Ctrl+Shift+1 から 9 と、ステータスバー左端の番号付きボタンに割り当てられます。
レイアウトは作業に追従します。今使っているレイアウトには印が付き、ワークスペースに加えた変更はすべてその
レイアウトに保たれるので、戻ってきたときには離れたときのままです。レイアウトをリセットすると、どのレイアウト
からも離れ、そのあとに作った配置は、保存するかいずれかを適用するまでどのレイアウトにも属しません。
ダイアログではレイアウトの名前を変えたり、上下に移動したりできます。リスト内の位置が *そのまま* 番号キーに
なります。保存できるのは十二個までです。

レイアウトを適用するとワークスペースが置き換わり、置き換えられるペインのシェルは、それらのペインを閉じた
ときとまったく同じように終了します。シェルが開いている間は先に確認があり、その確認には、以後確認しない
ようにする方法（*Settings → General → Layouts*）も示されます。古い配置はブラウン管のように電源が落ち、
新しい配置は起動時と同じようにペインごとに立ち上がります。動きを減らす設定では、この演出はありません。

一覧の下には 6 つの **プリセット** が、それぞれペインの並びを小さな図にして並んでいます。
**standard**（既定のレイアウト）、**network**（地球儀とシェル、その横に Wi-Fi と connections）、**earth**（ORBIT、地球儀、
地震、天気）、**dev**（AI AGENT、シェル、GIT）、**media**（YouTube (TV) とその下の spectrum と mixer、
タブに重ねた X と RSS）、**desk**（notes、timer、calculator、tasks、calendar）です。どれも左端にシステムの列を
持つので、切り替えても計器はそのままで、舞台だけが替わります。プリセットを選ぶと、そこから作ったレイアウトが
追加されてそこへ切り替わり、以後は作業に追従する自分のレイアウトになります。もう一度選ぶと、別のものを
追加せずにそのレイアウトへ戻ります。↺ でプリセットの状態に戻せます。プリセットにはそれぞれ専用のキー
（Ctrl+Shift+F1 から F6）があり、どこからでも同じことができます。新しくインストールしたときは 6 つが
Ctrl+Shift+1 から 6 に並んだ状態で始まり、すでにある一覧に足されることはありません。

レイアウトは、このマシン固有のものを何も含まない一つのファイルに保存されます。**`layouts.json` を別の
コンピューターにコピーすれば、配置も一緒に持っていけます。** ダイアログの *layouts.json* ボタンで、
ファイルマネージャーに表示できます（詳しくは [テーマと設定](#テーマと設定) を参照）。

タブグループにはシェルだけでなく、どのペインでも入れられます。そのため、ときどき使うペインは、専用の場所を
取らせずにシェルと同じ場所に置けます。たとえば RSS や天気をシェルのタブの後ろに置く、といった使い方です。
ペインをグループに入れるには、上のようにグループの上へ Ctrl を押しながらドラッグするか、グループ内のペインに
フォーカスしてピッカー（Ctrl+Shift+A、またはステータスバーの追加ボタン）を開き、ウィジェットより先に
**⧉ new tab** を選びます。以後はタブをクリックして切り替えられます。背後のタブにあるシェルは動き続け、
切り替えて戻ればセッションも画面もそのままです。グループは入れ子にできません。一つのタブには一つのペインが入ります。
## Panes

既定のレイアウトは、ペインの役割ごとに並んでいます。**左はこのマシン**: 時計、システム、CPU、メモリ、
ディスク、上位プロセス、ネットワークの状態と通信量。**中央は作業**: 3 つのシェルタブと、その下に
ランチャーとファイルブラウザー。**右は外の世界**: ワールドビュー、マーケット、天気、カレンダー。

- **Terminal** — ペインの見出しは TERMINAL で、選んでいるシェルのフルパスが並びます。各タブには
  そのフォルダーの名前が付き（ホームもそのフォルダー名で表示されます）、2 つのタブが同じ名前になる
  ときだけ親フォルダーが添えられます。タブにポインターを重ねると、シェルとフルパスが表示されます。
  終了したシェルは、終了コードとともにタブにそう表示されます。新しいシェルはホームフォルダー、または
  *Settings → General → Terminal* で設定したフォルダーで開きます（"~" はホーム。もう存在しない
  フォルダーならホームに戻ります）。**Ctrl+Shift+F** でペインの上に検索バーが開きます。一致箇所は
  テーマの色で示されて件数が数えられ、Enter と Shift+Enter で順にたどれます。シェルが出力した URL は
  リンクになり、ブラウザーで開きます。
- **System** — 日付と曜日、稼働時間、OS の種類、バッテリーゲージ付きの電源状態（緑、20% 未満で赤）。
  OS の完全なバージョンとアーキテクチャ（`uname` や `winver` が表示する形で）、マシンのメーカー、
  モデル、筐体。アプリの実行中に変わりえない情報は一度だけ読み、ポーリングしません。
- **CPU** — コアの平均負荷を示す 2 つのグラフ、または論理コアごとのバー（ペイン内で切り替えます）。
- **Memory** — 直近 1 分間の使用率とスワップを CPU のグラフと歩調を合わせてスクロール表示し、
  現在の量はバーで示します。
- **Disk** — 各ボリュームを、容量に対する使用量のバーで表示します（90% から琥珀色、97% から赤）。
  空き容量、ファイルシステム、リムーバブルかネットワーク上かも示します。その上には読み書きの速度と
  ディスクの稼働率が並びます（macOS では手軽に読み取る手段がないため表示しません）。
- **Launcher** — プラットフォームのアプリケーションと自分で追加した項目を、よく使うものから順に
  並べます。入力して絞り込み、Enter で起動します。アイコンはテーマのアクセント色で描かれ、ポインターを
  重ねると本来の色になります（Business テーマでは常に本来の色です）。Windows ではアイコンを Windows
  シェルが描き、アプリ名はスタートメニューの表示どおりで、ショートカットを持たないパッケージアプリ
  （Teams、Outlook、Terminal）も含まれます。項目は `settings.json` の `launcher.items` に追加します
  （ペインの EDIT LIST ボタンで開けます）。

  ```json
  "launcher": {
    "showSystem": true,
    "items": [
      { "name": "Project notes", "target": "C:\\Users\\me\\notes.md" },
      { "name": "Docs", "target": "https://github.com/kurouna/elecdex" },
      { "name": "Node REPL", "target": "C:\\Program Files\\nodejs\\node.exe", "args": ["-i"] }
    ]
  }
  ```

- **Filesystem** — 追従しているシェルのディレクトリをグリッドで表示します。フォルダーをクリックすると
  そこへ `cd` し、ファイルをクリックすると引用符付きのパスがプロンプトに入力されます。
- **World view** — 回転する地球儀の上に、国ごとの接続を表示します。「現在地」はシステムのタイム
  ゾーンの国（ゾーンが国を示さないときはロケールの国）で、OS の位置情報サービスには一切問い合わせません。
- **Connections** — このマシンが持っているすべての TCP ソケットを、それを持っているプログラムごとに
  まとめて表示します。ローカルポート、接続先、そのポートの一般的な用途、接続先の国が並びます。
  スイッチで待ち受け中のソケット、つまりこのマシンが開けている扉に切り替えられます。2 回の読み取りの
  間に開いて閉じた接続も取り消し線付きで一度は表示するので、短命な接続も見逃しません。一覧はカーネルから
  取得し（Windows では `GetExtendedTcpTable`、Linux では `/proc/net/tcp*`、macOS では `netstat`。
  macOS では所有プロセスを特定できず、ペインにもそう表示されます）、国はワールドビューと同じ同梱の
  GeoIP データベースで割り出します。オンラインで調べることは一切ありません。**MASK** はすべての
  アドレスの後半を隠すので、スクリーンショットや画面共有に使えます。待ち受けているプログラムは、
  コマンドラインから何を提供しているかを示します（`node` は `vite · my-app` になります）。
  ポートに何かを問い合わせることはありません。
- **Wi-Fi** — 無線接続のどこで問題が起きているかを示します。途切れる通話や、何度も切れる新幹線の
  Wi-Fi の原因を探すためのものです。このマシンからインターネットまでの経路を区間ごとに測り（電波の
  信号と再送、ゲートウェイとインターネットへの毎秒の ping、このマシン自身の送信量）、原因の区間を根拠の
  数値とともに示します：RADIO、LOCAL LINK、UPSTREAM、UPSTREAM LOST（アクセスポイントは応答するのに
  その先が応答しない）、OWN UPLOAD、SIGN-IN NEEDED。通話品質の推定値（MOS）も出します。その下に
  電波（信号のゲージ、チャネルと DFS 帯を示す帯域図、規格と PHY レート）、1〜60 分のタイムライン
  （クロスヘア付き）、システムが記録した過去 1 日の切断とその理由（Windows）、アクセスポイントの
  切り替わり、フレームカウンタを表示します。**MASK** はネットワーク名とアドレスを隠し、**COPY** は
  直近数分のレポートをクリップボードに入れます。
  どの項目もポインタを置くと、それが何か、判定に使うしきい値、今の値を説明します。判定の下の凡例で
  残りの読み方も分かります。広い画面で前面に出すと 2 列になり、局の間の線にその区間の直近 1 分を描き、
  ログの上に過去 24 時間の接続を帯で出します。無線アダプタが複数あるときは、ヘッダーの下のチップで
  表示するアダプタを選べます。ゲートウェイへの ping と履歴はアダプタごとです。位置情報が必要なものは読まないので、BSSID や
  周囲のネットワークのスキャンはありません。ping はペインが画面に出ている間だけ行います。
- **AI Agent** *(実験的)* — 実行中の Claude Code セッションごとに 1 枚のカードを表示します。名前と
  フォルダー、処理中かどうか、最後に行ったこと（ツールと、その対象）、モデル、コンテキスト内のトークン数と
  出力したトークン数、そして回答です。その下には、セッションが起動したサブエージェントとバックグラウンドで
  実行中のコマンドが、実行中・完了・失敗・停止の状態とともに並び、実行中のサブエージェントはその最後の
  ステップも示します。終わったものは 10 分間残ります。カードを開くと、使ったツールと変更したファイルが
  表示されます。ファイルを開くと、セッションが最初にそのファイルに触れる前に Claude Code が保存していた
  コピーとの差分が表示されます（サブエージェントが変更したものには SUB の印が付き、そのようなコピーは
  ありません）。Claude Code 自身のフォルダー（`~/.claude`、または `CLAUDE_CONFIG_DIR`）を読むのは
  ペインが開いている間だけで、記録のうち前回読んだ後に書かれた部分だけを読みます。長い記録は末尾から
  読み、その件数には *recent* と表示されます。どこにも何も送信しません。これらの記録は Claude Code の
  もので文書化されていないため、Claude Code の新しいバージョンで表示できる内容が変わるかもしれません。
  これが *実験的* である理由です。どの記録を読むかは `settings.json` の `agents.sources` で指定します
  （今のところ `claude-code`）。
- **Orbit** — 位置は、アプリが CelesTrak からダウンロードした軌道要素をもとに、お使いのコンピューター上で
  計算します（SGP4）。軌道要素は、宇宙ステーションは 1 日 2 回、約 10,000 基の Starlink 衛星は 1 日 1 回、
  それもペインが表示している間（**STARLINK**）だけダウンロードします。注目しているステーションの軌跡は
  1 周回前から 2 周回先まで描かれ、日照中は明るく、地球の影の中では暗く、10 分ごとに印が付きます。その
  周りの輪は、そのステーションが見える地上の範囲です。地図の下には、現在位置、高度と速度、次に地球の影に
  入る・出る時刻、観測地の上空を次に通過する時刻（肉眼で見えるかどうか）が表示されます。観測地は
  ペインごとに、同梱の都市リストから選びます（既定はお使いのタイムゾーンで最大の都市）。位置情報は
  求めません。地図を横切る細い線は今日の時刻の境目で、上端の目盛りは 15 度ごとのゾーンにその時刻を示し、
  真夜中と正午を明るく表示します。
- **Git** — **SELECT REPOSITORY** でフォルダーを選ぶと、ペインはそれ以降そのリポジトリを監視し、
  変更のたびに読み直します（多くても 1 秒に 1 回で、何も変わらない間は読みません）。ステージ済み、
  未ステージ、未追跡、競合中のファイルを、それぞれ追加・削除された行数とともに表示します。選んだ
  ファイルの差分は、統合形式または左右並べて表示し、変更された単語を強調します。コミットグラフには
  ブランチの線と各コミットに付いた名前（チェックアウト中のブランチ、他のブランチ、リモート、タグ）が
  描かれ、このブランチとその上流、または **ALL** で全ブランチを、**MORE** で 100 コミットずつ表示します。
  コミットをクリックするとそのファイルと差分が開き、ポインターを置くとメッセージ、作成者、日付、変更
  内容の全体が表示されます。このペインは読むだけです。ステージやコミットはターミナルで行ってください。
  ダブルクリックでファイルを開きます。`settings.json` の `git.openCommand` にコマンドがあればそれで
  （`{file}` と `{line}` が埋められます。例: `code -g "{file}:{line}"`）、空ならシステムの既定の
  アプリケーションで開きます。git が PATH にある必要があります。
- **Markets** — 指数、通貨、そのほか Yahoo Finance が提示するあらゆる銘柄を、約 1 分ごとに、スパーク
  ライン、ローソク足、または変化率のバーで表示します（リストの順、または変化率順）。行はペインを分け合い、
  幅が広いときは 2 列、高さが低いときは 1 行ずつになり、ローソク足は名前の下に行の幅いっぱいに並びます。
  銘柄をクリックすると、そのチャートがペイン全体に広がります。価格軸、下端の時刻、期間の高値・安値・基準値、
  ポインターの下にあるバーの値の表示が付き、矢印でリストに戻るまでそのままです。ボードの上の帯で期間を
  選びます。1D（5 分足）、5D（30 分足）、1M（1 時間足）、6M（日足）、1Y（週足）、5Y（月足）です。設定
  ボタンでリストを編集でき、各銘柄の後ろにはラベルを添えられます:
  `^N225 日経平均, JPY=X ドル円, 7203.T トヨタ`。1D は前日の終値から、それより長い期間は期間の開始前の
  終値からの変化を測ります。組み込みの名前はアプリの言語に従います（`--lang=en-US` で英語に固定されます）。
  Yahoo にはリアルタイムの TOPIX 指数がないため、既定のボードには CME の円建て TOPIX 先物（`TPY=F`）を
  表示します。
- **Weather** — 設定ボタン → PLACE で、同梱の大都市・首都と気象庁の予報区の一覧から選ぶピッカーが
  開きます。`lat, lon` を入力することもできます。日本は気象庁、米国は National Weather Service（選べば
  MET Norway）、それ以外の地域は MET Norway を使います。°C か °F か、週間予報を表示するかどうかは
  ペインごとに選べます。既定はニューヨーク市です。予報をクリックすると、その地点についての提供元自身の
  ページ（気象庁の予報ページ、NWS の地点予報、または yr.no）がブラウザーで開きます。
- **AI chat** — 既定のレイアウトにはありません。ピッカー（Ctrl+Shift+A）から追加でき、いくつでも
  置けます。まず *Settings -> AI* でプロバイダーを登録します。プリセット（Ollama、LM Studio、llama.cpp、
  Anthropic、OpenAI、Gemini、OpenRouter、またはカスタムのアドレス）を選び、アドレスを調整し、ホスト型の
  サービスなら API キーを貼り付けます（他の設定と同じく、フィールドを離れたときに保存されます。それまでは
  **show** で入力内容を確認でき、保存済みのキーは黒丸で表示され、二度と表示されません）。**test** で
  プロバイダーにモデルを問い合わせると、その結果がモデル欄の候補になります。ペインでプロバイダーとモデルを
  選び、入力して Enter を押します（Shift+Enter で改行。Esc か **stop** で回答を終わらせ、それまでに
  書かれた分は残ります）。回答は Markdown として描かれ、コードブロックごとにコピーボタンが付きます。
  プロバイダーがモデルの推論を返す場合（Claude の要約された thinking、`reasoning_content`、または
  インラインの `<think>`）は、**reasoning** の下に折りたたまれます。回答を書いている間は見出しに経過秒数と
  文字数が表示され、書き終わると、プロバイダーが報告する場合は入力・出力のトークン数と毎秒のトークン数が
  表示されます。メッセージにポインターを重ねると、**copy** でコピー、**edit** で以前の質問を編集（その質問と
  それ以降が置き換わります）、**again** で質問し直せます。普通に終わらなかった回答は、どう終わったかを
  示します。`STOPPED`、`TRUNCATED`、`DECLINED`、`LINK ERROR`、またはそのアドレスで誰も応答しなかった
  ときの `NO CARRIER` で、その横にプロバイダー自身の言葉が添えられます。**+ new** で新しい会話を始め、
  **log** で既存の会話を新しい順に一覧します。会話にポインターを合わせると Markdown で書き出したり削除
  したりできます。開き直した会話は、それに回答したプロバイダーとモデルで続きます（プロバイダーを削除して
  追加し直した場合は名前で探します）。何も送れないときは、ペインがその理由を示します。空のペインは接続先
  （`LINK STANDBY`、プロバイダーとモデル、アドレス）を表示し、モデル欄はプロバイダーの一覧を読んでいる間は
  `QUERYING`、読めないときは理由とともに `NO LIST` を表示します。
  **長い会話はモデルのコンテキストウィンドウに収めます**。ローカルサーバーは起動時に指定された数千
  トークンで応答し、それより長いものは先頭から（システムプロンプトから）黙って切り捨てます。そのため、
  どのプロバイダーにも設定に *context window* があります（このコンピューターやネットワーク上のアドレスは、
  別の値を入力するまで 8192 トークン、ホスト型のサービスは無制限。Ollama では設定しているコンテキスト長を
  入力してください）。送るのはその 4 分の 3 までで、それを超えると古いメッセージから送らなくなります。
  1 ターンごとに少しずつではなく一度に大きく区切るので、サーバーのプロンプトキャッシュが生き残ります。
  ログの `NOT SENT · n ABOVE` の行が、モデルに見えている範囲の始まりを示します。会話そのものと、その
  書き出しは欠けずに残ります。*summarise what no longer fits* をオンにすると（Settings -> AI、既定はオフ）、
  まずモデルに、送らなくなる部分の要約を頼みます。会話が区切られるたびに同じプロバイダーとモデルへの
  リクエストが 1 回増え、`TX · COMPACTING` と表示されます。要約はそれ以降、システムプロンプトの後に
  送られます。このとき行は `SUMMARISED · n ABOVE` となり、開くとモデルに何を伝えたかが見られます。
  要約に失敗しても失うのは要約だけで、質問はそのまま送られます。会話はペインではなくアプリのものです。
  ペインを動かしたりタブの裏に回したりしても回答は途切れず、ペインを閉じるとリクエストは止まります。
  メッセージを送るまで（または **test** を押すか、モデル一覧を開くまで）どこにも何も送りません。
  設定で任意のシステムプロンプトを指定すると、すべての会話の先頭に付きます。ツールはありません。
  モデルがファイルを読んだり、コマンドを実行したり、ウェブを閲覧したりすることはできません。
- **ELEC system** — 既定のレイアウトにはありません。ピッカーから追加します。*Settings -> AI* の
  プロバイダーに問い合わせるので、先にそこで登録してください。**seats** で各ユニット（LOGOS、ETHOS、
  PATHOS）のプロバイダーとモデルを選び、**all** で 1 つの席の選択を 3 つすべてに適用します。各ユニットには
  それぞれの立場が伝えられるので、全席が同じモデルでも構いません（立場は *Settings -> AI -> elec system ·
  standpoints* で編集します）。賛否で答えられる議題を入力して Enter を押します。各ユニットは議題と同じ
  言語で短い所見を書き、最後に `VERDICT` の行（APPROVE、REJECT、ABSTAIN）と `CONFIDENCE` を添えます。
  投票が進むにつれてプレートが光ります（`TX`、`RX`、そして評決）。ユニットは議題が来るまで電源が落ちて
  おり、1 基ずつ電源が入ります。審議の間は、問い合わせ中のプレートの周りと動くグリッドの床の上を光が走り、
  回答の断片は届くたびにそれぞれのスポークを流れ下ります。そのため速いモデルは光が流れ続け、じっくり
  考えているモデルのスポークは暗いままです（動きを減らす設定ではどれも表示されません）。隅のコンソールが
  各ステップを記録します。最後の投票で明かりが消え、少しして **resolution**（議決）が点灯します。それを
  支持しなかったユニットは後ろに下がります。議決はバーで選んだ規則に従います。
  **majority**（2 席で決まり、決まらなければ `DEADLOCK`）または **unanimous**（3 席すべてが承認で可決、
  1 席でも否決なら否決、それ以外は `NO CONSENSUS`）です。数えられない票、つまり接続に失敗したもの
  （`LINK ERROR`、`NO CARRIER`）や評決のない回答（`NO VERDICT`）は、棄権ではなく無効票です。有効票が
  2 票未満なら `QUORUM NOT MET` になります。確信度は表示するだけで、集計には使いません。**2 rounds** に
  すると、各ユニットは他のユニットの最初の所見を読んで（小さいコンテキストウィンドウに収まるよう切り詰めて）
  もう一度投票します。リクエストは 2 倍になり、変わった票は `REJECT › APPROVE` のように表示されます。
  このコンピューターやネットワーク上の同じサーバーにあるユニットには 1 基ずつ順に、ホスト型のサービスには
  同時に問い合わせます。Esc か **stop** で審議を終わらせ、それまでに書かれた分は残ります。**again** で同じ
  議題を今の席の構成の評議会にかけ直し、**log** で過去の審議を議決とともに一覧して、開き直したり、Markdown
  で書き出したり、削除したりできます。席、規則、ラウンド数は設定で、審議はかけられたときの席の構成を
  保持します。議題を提出するまで（またはモデル一覧を開くまで）何も送りません。
- **RSS** — 既定のレイアウトにはありません。ピッカー（Ctrl+Shift+A）から追加します。最初は空で、設定
  ボタンでフィードの URL を 1 行に 1 つずつ登録するまで何も取得しません（RSS 2.0、RSS 1.0、Atom。
  ペインあたり 10 件まで）。すべてのフィードを通じて最新の見出し 20 件を、フィード名と時刻（今日）または
  日付（それ以前）とともに表示し、ペインが低いときはリストがスクロールします。クリックすると記事が
  ブラウザーで開きます。各フィードは、ペインが登録している間 **15 分ごと** に確認します。それより間隔を
  空けるのはフィード自身が求めるとき（Cache-Control、Expires、`<ttl>`）だけで、それでも 1 時間より長くは
  しません。条件付きリクエストを使うので、変わっていないフィードは再ダウンロードしません。取得に失敗した
  フィードは最後の見出しを残し、ペインに STALE と表示します。同じフィードを登録した複数のペインは 1 つの
  リクエストを共有し、最後のペインを閉じると取得は止まります。ペインが開いている間に届いた見出しは、
  その位置に滑り込んで 3 秒間強調されます。リストを下へスクロールしているときは、読んでいる箇所は動かず、
  「↑ n new」のピルで上へ戻れます。
- **Quakes** — 既定のレイアウトにはありません。ピッカーから追加します。最近の地震を新しい順に、
  *Settings → Alerts* で選んだ情報源から表示します。**Japan**（気象庁: 最大震度を示し、3 から琥珀色、
  5- から赤。気象庁が発表する遠地地震も含みます）または **the world**（USGS: マグニチュード 4.5 以上、
  5 から琥珀色、6 から赤）です。各行には場所、時刻、マグニチュード、深さがあり、クリックすると情報源の
  ページが開きます。発表中の津波警報・注意報などは、リストの上に帯で表示します。ペインにはアラートの
  設定状態が表示され、設定ボタンでその設定が開きます。新しい地震はその色で強調されて滑り込み、リストを
  下へスクロールしているときは RSS ペインと同じ「↑ n new」のピルが出ます。ペインが開いているか、
  アラートがオンの間は、情報源を **1 分ごと** に確認します（条件付きなので、一覧が変わっていなければ
  ダウンロードは発生しません）。どちらでもなければ何も取得しません。このときワールドビューには、その日の
  地震が震央の位置に、マグニチュードに応じた大きさとリストと同じ色で示され、直近 1 時間の地震は脈打ちます。
  **緊急地震速報ではありません。** 情報は揺れの 1 分以上後に届きます。ペインとアラートにもそう表示します。
- **Earthquake and tsunami alerts** — *Settings → Alerts* で設定します。既定はオフです。情報源は自動
  （システムのタイムゾーンが東京か、ロケールが ja-JP なら日本、それ以外は世界）または手動で選びます。
  オンにすると、選んだ最大震度（日本、既定は 5-、5弱）またはマグニチュード（世界、既定は 6.0）以上の
  地震で、画面上部に場所、震度またはマグニチュード、深さを示すバナーが表示され、続報が届くと更新されます。
  強い地震のバナーは閉じるまで残り、それより弱いものは 1 分で消えます。**津波** の警報・注意報など（日本は
  気象庁の大津波警報・津波警報・津波注意報、世界は NOAA の Pacific and National Tsunami Warning Centers。
  オフにもできます）は、その段階、到達予想時刻と高さを添えた地域、発表元の見出しをカードで表示します。
  閉じると、発表中は小さなタブに折りたたまれ、解除されるとカードがそれを知らせます。段階が引き上げられると
  改めて知らせます。アラート音が鳴り（インターフェースの音がオンのとき）、elecdex が前面にないときは
  システム通知が出ます。どちらもオフにできます。各地震は一度だけ、それも新しいうち（日本は 30 分、世界は
  1 時間）だけ知らせるので、後からアプリを起動しても古いニュースは知らせません。
- **Calculator** — 既定のレイアウトにはありません。ピッカーから追加します。入力する行のすぐ下に答えが
  表示され、これまでの答えはすべてテープに残り、そこから数値を取り出して使えます。全角数字、`×` `÷`、
  数字の後の桁（`3百万`、`5千`）も入力どおりに読むので、日本語キーボードのまま式を書けます。バイト、時間、
  パーセント、万・億・兆の定数、`sqrt` から `gcd` までの関数、32 ビットのビット演算があり、`ans` で
  直前の答えを使えます。`rate = 8 * percent` のように書くと、名前がレジスタ行に残り後の行で使えます。
  `0x` を付けると答えの下に 32 列のビットマップが表示されます。`C` で行を消し、行が空ならテープを消します。
  空の行で `?` を押すと電卓が知っているものがすべて表示され、↑ で入力履歴をさかのぼれます。**tally**
  モードでは、貼り付けた数値の列を集計し（件数、合計、平均、中央値、標準偏差、四分位数）、ヒストグラムと
  箱ひげ図を描きます。日付の各部分を別々の数値と取り違えることはありません。コードとして評価されるものは
  一切ありません。式のパーサーは elecxzy のもので、そのテストとともに同梱しています。
- **Notes** — 既定のレイアウトにはありません。ピッカーから追加します。マークアップもレンダリングもない
  プレーンテキストで、入力をやめて 0.5 秒後に保存されます。保存待ちの間はフッターのバーが満ちていき、
  保存されると光るので、黙って自動保存されたかどうか気をもむ必要はありません。メモはレイアウトではなく、
  アプリの userData の `notes.json` に保存されるので、ペインを閉じても残り、2 つのペインで同じメモを
  表示できます（2 つ目のペインは入力中の内容を上書きせず、*edited elsewhere* と表示します）。1 行目が
  メモの名前になり、タイトルバーにすべてのメモが並び、それぞれの × で削除できます（元に戻せます）。
  **Ctrl+=** はキャレットのある式を計算して答えをその後ろに書き込み、地の文には手を付けません。
  *Save as .md…* と *delete*（元に戻せます）は設定ボタンの中にあります。
- **Tasks** — 既定のレイアウトにはありません。ピッカーから追加します。各締め切りを、タスクの期間の
  どれだけが過ぎたかを示すメーターで描くリストです。残りが少なくなると琥珀色、過ぎると赤になり、見出しでは
  最も近い締め切りがカウントダウンされます。`歯医者 明日 9:00`、`review fri 18:30`、`毎週 掃除` と入力すると、
  行から日付と繰り返しを読み取り、タスクを追加する前に読み取った内容を示すので、読み違いはその場で気づけます。
  理解できない行は入力どおりに残ります。タスクは読んでいるその場で直せます。タイトルをクリックすると名前を
  変更でき、時刻をクリックすると同じ書き方で締め切りを設定できます（空の行で締め切りを外します）。
  キーボードでは Delete でタスクを削除し、F2 で名前を変更します。完了したタスクは DONE の下に並び、
  必要なら折りたためます。タスクは `tasks.json` に保存され、次の締め切りのリマインダーはアプリ自身が
  予約します。ペインが閉じていても、別のタブにあっても、一度も開いていなくても届き、隅に *done*、
  *snooze*、*open* の付いたカードが出て、elecdex が前面にないときはシステム通知も出ます。すべての
  締め切りのうち次の 1 つを 1 つのタイマーが待つだけで、ポーリングはしません。リマインダーはペイン自身の
  設定ボタンで設定します。既定はオンで、スヌーズの長さと何分前に知らせるかを選べます。
- **Timer** — 既定のレイアウトにはありません。ピッカーから追加します。1 つのペインに 3 つの計器が
  あります。ストップウォッチのラップはバーとして並び、計測中は伸びていき、記録すると光って固定されます。
  最速と最遅には印が付き、最も高いバーには保持されたピークの線が引かれます。そして **countdowns** は
  最大 6 本で、それぞれに時間を設定でき、区切られたはしごを 1 段ずつ消しながら減っていき、最後の 10 秒は
  脈打ち、終わるとカードで知らせます。ストップウォッチとカウントダウンは、スマートフォンと同じく別々の
  装置です。片方を開始してももう片方は始まらず、片方をリセットしてももう片方はそのままで、画面の
  モードがストップウォッチでもカウントダウンは動き続け（時間が来れば鳴り）、それぞれのモードは見出しで
  そのことを示します。手で入力した時間は電卓を通るので、`90/2` は 45 分になります。すべてをティックの数では
  なく実時間の時刻として保持するので、ペインを動かしても、タブを切り替えても、再読み込みや再起動をしても、
  動いているタイマーはまったく同じところにあります。表示は 10 分の 1 秒までで、これは共有の 10 fps 描画
  ループで正直に示せる精度です。ラップはミリ秒単位で記録します。カウントダウンは `+1 +3 +5 +10 +25` を
  タップして設定済みの時間に足していき、その横の欄では分数をちょうどの値で設定できます。
  3 つ目は **alarms** です。時刻とラベルを、選んだ曜日に鳴らします。毎回作り直すのではなく、一覧から
  オン・オフを切り替えて使います（起床、昼休みの始まりなど）。アラームは `alarms.json` に保存され、
  アプリが予約するので、ペインが閉じていても一度も開いていなくても鳴り、応答するまで待つカードと、
  （elecdex が前面にないときは）システム通知が出ます。1 回限りのアラームは鳴った後に自動でオフになります。
  `07:30`、`7`、`19.5`、`１９：３０` はどれも時刻として読みます。
- **Calendar** — 今日の印が付いた月を表示します。‹ › かマウスホイールで月を変えると、日付が動いた方向に
  流れます。余裕があれば（幅の広いペイン、または Ctrl+Shift+Z で前面に出したペイン）、前月と翌月が両側に
  薄く加わり、矢印で 3 か月とも動きます。設定ボタンで祝日カレンダーを選べ（今のところ日本のみ、ローカルで
  計算します）、月の下に次の祝日の名前が表示されます。
- **Spectrum** — 既定のレイアウトにはありません。ピッカーから追加します。システムの音声出力を 7、10、16、
  31 のいずれかの帯域に分け、ピークを保持するセグメントの列で表示します。設定ボタンで、スタイル（既定の
  VFD シアン、VFD 琥珀、LED、テーマ）、帯域の数、バー・鏡像のパターン・ピークのみ、ピークホールドを
  選べます。音を拾うのはペインが画面に出ている間だけで（バックグラウンドのタブでは拾いません）、描くのは
  音がある間だけ、1 秒に 20 フレームです（i5-1335U で、音が鳴っている間はコアの約 3 分の 1、無音の間は
  10 分の 1）。キャプチャは専用の隠しウィンドウで行い、ペインに届くのはレベルだけです。録音はしません。
  Windows で検証済みです。macOS も同じ画面キャプチャの経路で（画面収録の許可があれば）動くはずですが、
  検証していません。Electron にループバックキャプチャがない Linux では、代わりに `parec`（pulseaudio-utils。
  PulseAudio と PipeWire のどちらでも）が既定の出力のモニターを録ります。システム設定でモニターの音量を
  下げていても補正するので、バーは鳴っているとおりの音を示します。ミュートされているときはそう知らせ、
  ミュートを解除するボタンを出します。
- **Browser, YouTube and X** — 既定のレイアウトにはありません。ピッカーから追加します。*Browser* には
  アドレスバーがあり、任意の http(s) のページを開けます。*YouTube (TV)* と *X* はそれぞれのサイトを開いて
  そこにとどまり、他のサイトへのリンクは既定のブラウザーに送ります。*YouTube (TV)* は YouTube の
  リビングルーム向けインターフェースで、矢印キーで操作します。これを YouTube のペインとして提供しているのは、
  サインインできるのがこちらだからです（表示されるコードをスマートフォンで yt.be/activate に入力します）。
  Google は埋め込みブラウザーからのサインインを拒否します（「このブラウザまたはアプリは安全でない可能性が
  あります」）。各ペインには戻る、進む、再読み込み（サイトのペインではホーム）、「ブラウザーで開く」の
  ボタンがあり、再起動をまたいでページを覚えています。ページはペインの上に重ねた、サンドボックス化された
  別のブラウザービューが描きます。このビューは elecdex にアクセスできず、カメラ、マイク、位置情報、通知を
  使えず、ファイルをダウンロードできません。すべてのウェブペインはサイトごとに 1 つのサインインを共有し
  （YouTube へのサインインは一度で済みます）、アプリの他の部分とは分けて保持されます。
  *Settings → General → sign out of all sites* で削除できます。ページは既定では本来の色で表示します。
  アドレスの右にある ◐ ボタンで、そのペインのページを見ている間テーマの色で描けます。
  *Settings → General → tint pages in the theme's colour* は、自分のボタンを使っていないペインの既定で、
  Business テーマでは色付けしません。ダイアログ、通知、ドラッグ中のペインが上に重なっている間は、ページの
  代わりに静止画を表示します。ページがキーボードを受け取っている間もアプリのショートカットは効き、それ以外の
  キーはすべてページに届きます。ポインターがページの上にある間は、ステータスバーと全画面時のウィンドウ
  コントロールは現れません（ショートカットを使うか、ポインターを別のペインに移してください）。
- **Mixer** — 既定のレイアウトにはありません。ピッカーから追加します。出力デバイスの音量とミュート、
  そして Windows と Linux では音を出している各アプリを、フェーダー、ミュートボタン、（Windows では）
  ピークメーターで表示します。macOS はマスター音量のみです。読み取るのはペインが画面に出ている間だけで、
  Windows では常駐する 1 つの PowerShell、macOS では AppleScript、Linux では pactl（PulseAudio または
  PipeWire。PulseAudio 16 以降の pactl）を使い、pactl がない環境ではマスター音量に WirePlumber の wpctl を
  使います。
## プラグイン

プラグインはペインを 1 つ追加するもので、アプリの userData にある `plugins` フォルダーに置いた
TypeScript または JavaScript のファイル、あるいは `index.ts` を持つフォルダーです。保存するたびに
読み込み直され、隣にある `elecdex-plugin.d.ts` がエディターに API の型を教えます。
*Settings → Plugins → **install from a folder…*** を使えば、コピーはアプリが行います。プラグインの
フォルダーを選ぶと、elecdex はそこからプラグインだけを取り出します。取り出すのはエントリーと、
そこから import されるものだけです。コードの隣にある README、`package.json`、`.git`、`node_modules`
やテストはそのまま残ります（ただし `tests/` の下にあっても、プラグインが import しているファイルは
一緒にコピーされます。基準はプラグインから辿れるかどうかで、フォルダーの名前ではありません）。
コピー先の名前はフォルダー自身の名前で、同じ名前のプラグインがすでにある場合は先に確認します。
実行せずに分かることはコピーの前に確かめます。コードがコンパイルできること、そしてすべての import
が一緒にコピーされるファイルを指していることです。そのため、プラグインではないフォルダーや npm を
必要とするフォルダーは、後になって動かないのではなく、理由を示してその場で断られます。プラグインを
*入れてある*フォルダーと、それ自体がプラグインであるフォルダーも区別されます。手で置くための
*Open plugins folder* も引き続き使えます。新しく作られる plugins
フォルダーには **ポモドーロタイマー**（このリポジトリの `examples/plugins/pomodoro`）が入っています。
集中セッション、短い休憩、数ラウンドごとの長い休憩を VFD 風のメーターで表示し、フェーズが終わると
チャイムと通知で知らせます。再起動しても続きから動きます。

プラグインは *Settings → Plugins* で有効にするまで動きません。この画面には各プラグインに許される
ことが一覧され（メトリクスのソースを読む、指定されたホストにアクセスする（リクエストはすべてアプリが
行い、その一覧と照合します）、サイト用に自分専用のサインインセッションを使う、ペインを開いていない
ときも動き続ける、通知する）、初回の実行前と、後でプラグインがより多くの権限を求めたときに確認を
求めます。プラグインはそれぞれ専用の Web Worker で動き、ページ、ファイル、ネットワークには
アクセスできません。描画はアプリがテーマに合わせて表示するブロック（テキスト、数値、メーター、
チャート、表、リスト、ボタン）を通してのみ行います。応答しなくなったプラグインは、アプリを
止めることなく停止されます。API とルールは [docs/plugins.md](docs/plugins.md) にあります。

## テーマと設定

設定ダイアログでの変更はすべて、その場でアプリの userData フォルダーにある `settings.json` に
保存されます。このファイルはアプリの実行中に手で編集することもできます。読み取れないファイルは
そのまま残され（直るまでは既定値が使われます）、アプリからの変更で置き換える前に
`settings.json.bak` へコピーされます。

```json
{
  "theme": "amber",
  "sound": { "enabled": true, "volume": 0.5 },
  "motion": "system",
  "terminal": { "startDirectory": "~/work" },
  "keybindings": { "app.quit": null },
  "window": { "minimizeToTray": false, "closeToTray": true, "globalShortcut": true, "startInBackground": false },
  "updates": { "check": true },
  "layout": { "confirmSwitch": true },
  "web": { "tint": false },
  "quakes": { "source": "auto", "notify": true, "minIntensity": "5-", "minMagnitude": 6, "tsunami": true, "system": true, "sound": true },
  "reminders": { "notify": true, "system": true, "sound": true, "snoozeMinutes": 10, "leadMinutes": 0 }
}
```

テーマを追加するには、その隣にある `themes` フォルダー（*Settings → General →
themes folder*）に JSON ファイルを置きます。すぐに反映され、組み込みテーマと同じ `id` を持つものは
そのテーマを置き換えます。読み込めないファイルは、黙って一覧から消えるのではなく、テーマ選択の下に
理由とともに表示されます。

```json
{
  "id": "ice",
  "name": "Ice",
  "accent": { "h": 200, "s": 60, "l": 70 },
  "surfaces": { "s0": "#000000", "s1": "#010203", "s2": "#040506", "line": "#101820" },
  "terminal": { "ansiPull": 0.5, "ansi": { "red": "#ff5f56" } },
  "effects": { "scanlines": false, "glow": 0.2 }
}
```

色は `#rrggbb` で指定します。`status`（danger / warn / ok / info の色相）、`fonts`、`text`
（文字色の `primary` と `muted`。指定しなければ文字はアクセント色になります）、`mode`（明るい地には
`"light"`。ステータス色が濃くなり、ターミナルは薄い色を 4.5:1 まで引き上げます）、
`effects.iconTint`（`false` にするとランチャーのアイコンを元の色で表示します）は省略できます。
レイアウトは同じ場所の `layout.json` にあります。現在使っている唯一の配置で、手で編集した場合は
読み込み時に検証され、読み込めないときは破棄されずに `layout.json.bak` へ退避されます。

保存したレイアウトは `layouts.json` にあり、名前ごとの各レイアウトと、作業中のレイアウトの id を
持っています。このマシンに固有のものは含みません（ターミナルのセッション id は保存時に取り除かれます）。
そのため **このファイルはそのまま別のコンピューターにコピーできます**。新しいシェルがこのファイルを
書き換えることもありません。読み込めないエントリーはそれだけが取り除かれ、残りは保たれます。
ファイル全体が読み込めない場合は `layouts.json.bak` へ退避されます。

```json
{
  "version": 1,
  "active": "k3f9d1ab",
  "items": [
    { "id": "k3f9d1ab", "name": "work", "tree": { "version": 1, "root": { "kind": "pane", "id": "p1", "widget": "terminal" } } }
  ]
}
```

## なぜ作り直したのか

eDEX-UI はアーカイブされました。作者自身の言葉を借りれば、そのコードベースは "in dire need of a fresh
refactoring"（新たなリファクタリングがどうしても必要）な状態でした。elecdex はそのアイデアを受け継ぎ、
実装は捨てています。

| eDEX-UI | elecdex |
| --- | --- |
| PTY を localhost の WebSocket（ポート 3000 以降）経由でトンネリング | `MessageChannelMain` でセッションごとに 1 チャネル。待ち受けるソケットはありません |
| `nodeIntegration: true`、`contextIsolation: false`、`@electron/remote` | `sandbox: true`、`contextIsolation: true`、型付きの preload ブリッジが 1 つだけ。レンダラーはネットワークにもファイルシステムにもアクセスできません |
| コアごとに `cluster` を fork し、各ウィジェットが独自のタイマーで `systeminformation` をポーリング | `utilityProcess` 1 つと、購読で動き誰も見ていなければ止まるスケジューラー。Windows では読み取りごとに PowerShell を起動せず、常駐するサンプラー 1 つで取得します（監視のコストは実測で 1 コアの 144% → 14%） |
| カレントディレクトリを `/proc`、`lsof`、`ps` のポーリングで追跡（Windows 非対応） | シェル統合（`OSC 7` / `OSC 133`）により Windows でも動作 |
| 画面の 5 領域が固定、ターミナルのタブは 5 つ | 永続化されるレイアウトツリー。ペイン、分割、タブに上限はありません |
| バンドラーなし。minify は後処理 | electron-vite（Vite + Rollup） |

## 開発

スタック: Electron 44 · TypeScript 7 (native) · electron-vite 5 / Vite 7 · Svelte 5 (runes) ·
`@xterm/xterm` 6 · node-pty 1.1 · systeminformation · three · zod 4 · Biome 2 · Vitest 5 ·
Playwright · electron-builder 26

```bash
npm ci
npm run dev -- -- --windowed --no-intro   # the second -- hands flags to Electron; npm start is the same
```

```bash
npm run verify       # lint + typecheck + unit/component tests
npm run build        # bundle main / preload / renderer into out/
npm run test:e2e     # Playwright against the built app (run build first)
npm run package      # installers into release/
```

**Windows と macOS** ではネイティブのツールチェーンは不要です。node-pty にはビルド済みの N-API
バイナリが同梱されており、Electron がそのまま読み込みます。**Linux** ではインストール時に node-pty が
一度だけコンパイルされます（`python3`、`make`、C++ コンパイラーが必要）。npm 11 は先に承認を求める
ので、`npm install-scripts approve node-pty && npm rebuild
node-pty` を実行してください。

Electron のバイナリは、このプロジェクトの `postinstall` スクリプトがダウンロードします（Electron 44
には独自のインストールスクリプトがなく、初回使用時のダウンロードも electron-vite からは起動されない
ためです）。このスクリプトは node-pty の macOS 用 `spawn-helper` に実行権限も付けます。
`--ignore-scripts` を使った後は、一度 `npx install-electron` を実行してください。

エンドツーエンドテストは実際のサービスに接続せず、実行しているマシンにも手を触れません。天気、
マーケット、更新確認は閉じたポートかローカルのスタブに向けられ（予報とともに気象庁の地震・津波の
一覧、USGS と NOAA のフィードも同様です）、RSS フィード、AI プロバイダー、プラグインのホスト、
Web ペインのサイトはローカルサーバーが応答します。サウンド、通知領域のアイコン、サインイン時の
登録、ソケットの一覧、API キーの暗号化は代用品に置き換えられます。スイート全体には数分かかります。
リリース前には全体を実行し、個々の変更ではその変更が影響しうるスペックを実行します。

```
src/shared/     contracts shared by all processes (API types, IPC channel names, schemas, pure logic)
src/main/       app lifecycle, window, IPC handlers, pty, weather, markets, feeds, quakes, launcher,
                audio, plugins, web panes, reminders, running in the background, updates
src/preload/    the one and only contextBridge surface
src/renderer/   Svelte 5 UI: layout tree, widgets, the plugin host, dialogs, design tokens
src/services/   utilityProcess: the metrics collector
examples/       the sample plugin (pomodoro)
tests/          unit (vitest) · component (vitest + jsdom) · e2e (playwright _electron)
scripts/        asset generators (icon, banner, globe data, city list, README screenshots)
docs/           architecture.md (the design and the decision log, in Japanese), plugins.md,
                weather-providers.md
```

変更が守るべきルール（セキュリティ境界、ネットワークをどこで扱うか、テストが触れてよいもの）は
[CLAUDE.md](CLAUDE.md) にあります。

### リリース手順

1. `package.json` の `version` を設定し、コミットして push します。
2. そのコミットに `v<version>` のタグを付けて push します: `git tag v0.1.0 && git push origin v0.1.0`。
3. Release ワークフローがタグと `package.json` の一致を確認し、lint、型チェック、ユニットテストを
   実行したうえで、自動生成したノート付きの GitHub プレリリースを作成し、Windows（x64、arm64）、
   macOS（arm64、x64）、Linux（AppImage と deb、x64 と arm64）のインストーラーを添付します。
4. プレリリースを確認し、準備ができたら "Set as a pre-release" のチェックを外します。更新確認は
   プレリリースを無視するので、動いているアプリが新しいリリースを知らせるのはこの後です。
