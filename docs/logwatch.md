# LOG WATCH ペイン 設計

利用者が選んだログファイルを 1 ペインに 1 つ見張り、**追記された分だけ**を読んで、解析して見せる。
`tail -f` の代わりに、レベルの色分け、繰り返しの畳み込み、初めて見るパターンの印、エラーの急増の
ランプ、パターンごとの件数、AI による解説（EXPLAIN）を持つ。ファイルには何も書かない。設計段階
（2026-10-12）。要約は architecture.md §5.21。

見た目のたたき台はモック [logwatch-mock/index.html](logwatch-mock/index.html)（ブラウザで開くだけで動く。
ログはすべて作り物）。モックは DOM に行を足していくだけで、仮想スクロールも main もない（§6、§4）。

## 1. 目的と非目的

**目的**

- 開発中のアプリ、ローカルのサーバ、ツールのログを、シェルを 1 枚潰さずに横で流し見る
- 大量の行から「いつもと違うもの」が目に入る。初めて見るパターン、エラーの急増、レベル
- 目に入った 1 行を、その場で AI に説明させる（押したときだけ）

**非目的**

- 書き込み、保存、エクスポート、ログの削除や切り詰め
- Windows イベントログ、journald、macOS の `log stream`（Windows イベントログは別のペインの候補で、利用者の指示があるまで扱わない）
- 複数ファイルのマージ、ログの集約、全文検索インデックス、ネットワーク越しのログ
- 隠れている間の見張りと通知
- 権限の昇格（読めないファイルは読めないと言う）

## 2. 画面構成

上から次の順に並べる（モックのとおり）。

- **見出し**（hud-label）: `LOG WATCH`。右に、ファイル名、ホームを `~` にしたフォルダ、判定した形式、文字コード
- **状態の行**: ランプ（LIVE / PAUSED · n HELD / ERROR BURST / WAITING FOR FILE / CANNOT READ）、RATE（行/秒）、
  ERR と WARN の 5 分の件数、PATTERNS の数。右に PAUSE、MASK、WRAP、EXPLAIN（§7）、設定のアイコン（ほかのペインと同じスライダーの絵、
  `widgets/common/SettingsButton.svelte`）
- **レーン**: 直近 5 分を 5 秒ごと 60 本の積み上げ棒で、レベル別に描く（ERR は `--danger`、WARN は `--warn`、
  ほかはアクセントの濃淡）。下に `−5 min` と `now`
- **タブ**: STREAM と PATTERNS
- **絞り込みの行**: レベルのトグル（DBG・INF・WRN・ERR、件数付き）、文字列か `/正規表現/` の絞り込み、
  ミュート中のパターンの数
- **本体**: STREAM なら行の一覧と右端のミニマップ、PATTERNS ならパターンの表（§6.4）
- **足元**: 「n lines kept of N · read n KB」と「read only while shown · nothing written」

### 2.1 幅による組み替え

- **wide**: 時刻・レベル・発生元・本文・印（×n、NEW、+n lines）
- **narrow**（目安 30 rem 未満）: 発生元の列を落とし、カードに回す。PATTERNS は推移と最終時刻の列を落とす
- 高さが足りないときは、レーンを先に落とす（行の一覧が主役）

### 2.2 ペインごとに切れるもの

レーン（CHART）と右端のミニマップ（ERROR BAR）は、設定のパネルでペインごとに ON / OFF できる（既定はどちらも ON）。
OFF にしたものは描かず、その分の計算もしない（レーンの件数は 5 分の ERR / WARN の数字のためにだけ数える）。
文字コード（§4.1）、時刻の見せ方、WRAP、繰り返しの畳み込みも同じくペインごと（§8）。

## 3. ソース

### 3.1 指定と登録

- GIT ペインと同じ方式にする。ペインの SELECT LOG を押すと main がファイル選択を開き、`realpath` で確かめて
  `log-files.json` に登録し、16 桁の id だけを返す
- ペイン状態とレイアウトに入るのは id だけ。パスを受け取るチャンネルは作らない。別の機械では「知らない id」
  として選び直しを求める
- 見出しに出すフォルダは表示用の文字列で、チャンネルには戻さない
- **フォルダ＋パターン**: 選択でフォルダを選び、ファイル名のパターン（`*` と `?` だけ、再帰なし）を添えて
  登録できる。一致するもののうち、更新時刻が一番新しいファイルを読む
  - より新しいファイルが現れたら乗り換え、区切り線（「switched to <名前>」）を入れる
  - 日付ごとにファイルを替えるログや、`npm` の debug ログのように実行ごとにファイルを作るものに使う
- 選んだ時点で先頭 8 KB を読み、NUL を含むファイルはバイナリとして断る

### 3.2 読めないとき

- 権限がない（Linux の `/var/log/messages` など）: CANNOT READ とその理由を出す。昇格はしない
- ファイルがない（まだ作られていない、ローテーションの途中）: WAITING FOR FILE。フォルダの変化で見つける
- 何度か失敗したら、30 秒ごとにやり直す（GIT ペインと同じ）

## 4. 読み取り（main、`src/main/logwatch/`）

- **見えている間だけ**（`seen`）購読し、購読している間だけ見張る。最後の購読者が去ったら監視を閉じる。
  `keepWhileHidden` には何も載せない。隠れている間とウィンドウが非表示の間は何もしない
- **見張り方**: ファイル（フォルダ＋パターンならフォルダ）を `fs.watch` で見て、変化から 200 ms 待って読む
  - Windows では、別のプロセスが開いたまま追記しているファイルの通知とサイズの更新が遅れることがある。
    ネットワークドライブや `\\wsl$` では通知そのものが来ないことがある
  - そこで、購読している間だけ、1 秒ごとの `BoundaryTimer` でも `stat` する。ポーリングはこれだけ
- **読み方**: 前回の位置の続きだけを、1 回あたり最大 1 MB ずつ非同期に読む。ファイルは読むたびに開いて閉じ、
  開きっぱなしにしない（書き手のリネームや削除を邪魔しない）
- **ローテーション**: サイズが前回の位置より小さい、または同一性（`ino` と `birthtime`）が変わったら、先頭から
  読み直し、区切り線（「rotated · reading from its start」）を入れる
- **最初の表示**: 開いたとき、ファイルを選んだときは、末尾から「開いたときに読む行数」（§8）ぶんだけを読む
  （末尾から 64 KB ずつ遡って改行を数え、多くても 4 MB まで）
- **見えるようになったとき**: 保存していた位置からの差分を読む
  - 差分が 4 MB 以下なら全部を読み、「While hidden」の帯（期間、行数、ERR、WARN、新しいパターンの数）を
    行の前に入れる
  - 超えるときは末尾だけを読み、帯に「partial」と出す。数えられるのは読んだ範囲だけ
- **行の区切り**: LF と CRLF。改行で終わっていない最後の行は、次の読み取りまで持っておく。1 行が 64 KB を
  超えたら、そこで切って「cut」の印を付ける
- **文字コード**: §4.1
- **ページへの送り方**: 0.25 秒の格子（`BoundaryTimer`）でまとめて送る。新しい行がなければ送らない
- **保持**: main は 1 ソースにつき 1 つのリングバッファを持ち、共有するペインのうち一番大きい保持行数に
  合わせる。1 回の読み取りで上限を超えた分は、古いほうから捨てて「DROPPED n」と出す
- **共有**: 同じ id を見るペインが複数あれば、監視とファイルの読み取りは 1 つ（参照カウント、`whenPageGoes` で
  落とす）。文字コードはペインごとなので、読んだバイトを文字コードごとに解読し、解析とバッファは
  「id と文字コード」の組ごとに持つ（ふつうは 1 組）
- **書かないもの**: ログの中身はディスクに書かない。`log-files.json` に持つのは id、パス、パターン、形式の
  指定だけ。読んだ位置は main のメモリにだけ持つ（再起動したら末尾から読み直す）

### 4.1 文字コード

- **ペインごと**の選択で、既定は auto。選べるのは auto、UTF-8、UTF-16LE、UTF-16BE、Shift_JIS、EUC-JP、
  Windows-1252（`TextDecoder` で、Electron の ICU が持つもの）
- **auto の判別**（純粋、`detectEncoding`）: 最初に読むバイト（末尾の塊）で決め、決めたものを見出しに
  「AUTO · UTF-8」のように出す
  1. BOM があれば、それに従う
  2. 偶数番目か奇数番目のバイトに NUL が並べば UTF-16（LE / BE）
  3. UTF-8 として正しく読めれば UTF-8（ASCII だけのログもここ）
  4. 読めなければ、Shift_JIS と EUC-JP で解読し、置換文字（U+FFFD）と制御文字の少ないほう。どちらも多ければ
     Windows-1252
- **文字化けの知らせ**: 解読した行に置換文字が一定の割合（たとえば 1%）を超えて現れたら、状態の行に
  「TEXT LOOKS GARBLED · ENCODING ▸」を出す。押すと設定のパネルの文字コードの欄が開く。auto は途中で勝手に切り替えない
  （同じログの行が途中から別の読み方になると、かえって分からなくなる）
- **指定を変えたとき**: main は保持している行を、その文字コードで読み直す（ファイルの末尾から「開いたときに
  読む行数」ぶんを読み直し、バッファを置き換える）。パターンと NEW の学習もやり直す
- auto が決めた文字コードはペイン状態に書かない（ファイルが変われば判別し直せるように）。書くのは利用者の指定だけ

## 5. 解析（純粋、`src/shared/logwatch/`）

DOM、Node、時計を触らない純粋関数にし、単体テストで固める。

- **形式の判定**（`detectFormat`）: 先頭の 50 行ほどのサンプルから判定する
  - JSON Lines（pino、bunyan、winston、Serilog compact などのよくあるキー名）、logfmt、syslog（RFC 3164 / 5424）、
    Apache / nginx の combined、IIS W3C（`#Fields:` を読む）、汎用の「時刻 [レベル] 本文」
  - 判定できなければ plain（1 行 1 エントリ、レベルは本文のキーワードから推す）。設定のパネルで手で直せる
- **正規化**（`parseLine`）: 時刻、レベル（TRC / DBG / INF / WRN / ERR / FTL にそろえる）、発生元、本文、
  フィールドに分ける
  - 時刻がない行は、届いた時刻を使い、印を付ける
  - 年のない syslog の時刻は今年とし、未来になるなら前年にする
  - タイムゾーンのない時刻は機械のローカル時刻とみなし、カードにその旨を出す
- **複数行のまとめ**（`joinContinuation`）: 字下げされた行、`at `、`Caused by`、`Traceback`、`File "…", line` で
  始まる行は、直前のエントリの続きにする。行の一覧では畳み、「▸ +n lines」で開く
- **パターン**（`signature`）: UUID、16 進数の id、IP、引用符で囲まれた文字列、数値をプレースホルダ
  （`{id}` `{ip}` `{s}` `{n}`）に置き換え、レベルと発生元を前に付けたものを署名にする
- **繰り返しの畳み込み**: 直前に見えている行と同じ署名なら、新しい行は足さずに ×n を増やし、時刻を最新にする
  （ブラウザのコンソールと同じ）。設定のパネルで切れる
- **初めて見るパターン**（NEW）: 開いたときに読んだ末尾の行では署名を覚えるだけにし（学習期間）、NEW の印は
  そのあと届いた行で、まだ知らない署名にだけ付ける。署名は 1 ソース 2000 件までで、長く使われていないものから捨てる
- **件数**: レーンと 5 分の件数は、届いた時刻でなく**ログ自身の時刻**の 5 秒ごとに積む。隠れていた間の差分を
  読めば、グラフの空白も埋まる
- **急増**（`burstLevel`）: 直近 15 秒の ERR の件数を、それ以前の 5 分の平均と比べる。閾値を超えた状態が
  一定の時間続いたときだけ ERROR BURST にする（CLUSTER の警告灯と同じく、ちらつかせない）
- **トークン**（`tokens`）: 本文の数値と単位、IP、パス、`key=`、引用文字列、id を色分けの種類に分ける。
  `lib/highlight.ts` と同じく、テキストとして描き、HTML にはしない
- **伏せ字**（`maskLine`）: IPv4 / IPv6、メールアドレス、32 文字以上の 16 進数や base64、`Bearer …`、
  `password=` / `token=` / `secret=` / `key=` の値を伏せる

**どこで解析するか**: 案は main（読んだ直後に解析し、解析済みのエントリを送る）。1000 行/秒で 1 バッチあたり
8 ms に収まるかを測り、超えるなら collector（utilityProcess）へ移す。数字は decisions.md に書く（§12）。

## 6. 表示（`src/renderer/widgets/logwatch/`）

### 6.1 行の一覧

- 仮想スクロール（見えている行と前後の少しだけを DOM に置く）。保持行数が 50k でも DOM は数百行
- 行: 時刻・レベルの札・発生元・本文・印。ERR と FTL は札を塗り、左端に `--danger` の線、WRN は枠と線を
  `--warn` にする。DBG と TRC は本文を薄くする
- 時刻の見せ方: 絶対（`12:04:01.231`）/ 何秒前 / 前の行との差（ペイン状態）
- WRAP: 本文を折り返す（ペイン状態）
- 届いた行は一度だけ光る。アクセント色の重ねを不透明度で消すだけで、キーフレームで色は動かさない
- 行をクリックすると選択になる（EXPLAIN とコピーの対象。§7、§9）

### 6.2 追従

- 一番下にいる間は、新しい行に合わせてスクロールする
- 上へ戻すと追従を止め、下に「▼ n NEW」（ERR があれば「n ERR」も）を出す。押すか一番下まで戻ると再開する
- **マウスが一覧の上にある間は自動スクロールしない**。読んでいる行が流れていかないようにするためで、
  その間の行も「▼ n NEW」に数える
- PAUSE: 読み取りは続け、画面への反映だけを止める（ランプに「n HELD」）。再開すると、溜まった分をまとめて流す

### 6.3 絞り込みとミニマップ

- レベルのトグル、文字列か `/正規表現/`（不正なら枠を `--danger` にして、前の絞り込みのまま）。
  一致した部分を塗る
- ミュートしたパターンは一覧に出さない
- 右端のミニマップに、保持している範囲での ERR と WARN の位置を目印で出し、今見ている範囲を枠で示す。
  クリックでそこへ移る

### 6.4 PATTERNS タブ

- 署名ごとの件数、レベル、パターン（プレースホルダを色分け）、直近 1 分の推移（12 本の棒）、最後に見た時刻、
  MUTE / UNMUTE
- 並びは ERR を先に、そのあと件数の多い順
- 見えている間、1 秒ごと（`onBoundary`）に描き直す

### 6.5 動きと負荷の決まり

- ランプは `pulse`、カードと設定のパネルは CRT の電源の入り切り（`crt-on`、`crtPower`）
- レーンは 2D canvas。値が変わったときだけ、1 秒ごと（`onBoundary`）に描き直す。テーマが変わったら
  `appearance.revision` で色を読み直す
- 0.25 秒ごとの行の追加と、1 秒ごとの描き直しのほかに、自分のタイマーは持たない

## 7. EXPLAIN

- **出す条件**: AI の設定にプロバイダが 1 つ以上あるときだけ、ボタンを出す。なければボタンごと出さない
- **選び方**: AI チャットと同じく、ペイン状態にプロバイダの id とモデル名を持ち、ないときはそのプロバイダの
  既定のモデルを使う。設定のパネルに選択欄を置く
- **流れ**: 行を選んで EXPLAIN を押すと、ペインの下半分に送る本文を見せ（選んだ行、その前の数行、スタック
  トレース、判定した形式とファイル名）、SEND を押したときだけ送る
  - 前の行数は 10 行（固定。2026-10-12、利用者の決定）
  - MASK が ON なら伏せた状態で送る。OFF のときは、送る前の画面に「MASK is off」と出す
- **main で**（`main/logwatch/explain.ts`）: ページから受け取るのは、選んだエントリの id と前の行数だけ
  - 本文は main が自分のバッファから組み立てる。ページが書いた文章は送らない
  - プロバイダへは AI チャットの方言（OpenAI 互換 / Anthropic）で送り、キーはページに渡らない
  - 同時に 1 件まで、180 秒で打ち切る。会話は続けない（1 回で終わり。続けたいときは AI チャットへ）
- **答え**: `lib/markdown.ts` の木として描き、HTML にはしない。答えはペインのメモリにだけ持ち、閉じれば消える。
  AI チャットの会話の一覧には入らない
- **システムプロンプト**: 「ログの 1 行を説明する。原因の候補、確かめ方、関係する設定。分からないことは
  分からないと言う」を固定で持つ。利用者が編集する欄は v1 では持たない
- 失敗は AI チャットと同じ語彙（`FAILED` と、プロバイダの言葉を並べて出す）

## 8. 設定

| 項目 | 範囲 | 既定 | 置き場所 |
|------|------|------|----------|
| 保持する行数 | 1k / 5k / 20k / 50k | 5k | `settings.logWatch.keepLines`（全ペイン共通） |
| 開いたときに読む行数 | 100 / 500 / 2k | 500 | `settings.logWatch.initialLines`（全ペイン共通） |
| 時刻の見せ方、WRAP、繰り返しを畳むか | — | 絶対・OFF・ON | ペイン状態 |
| 文字コード | auto / UTF-8 / UTF-16LE / UTF-16BE / Shift_JIS / EUC-JP / Windows-1252 | auto | ペイン状態（§4.1） |
| CHART（レーン） | ON / OFF | ON | ペイン状態 |
| ERROR BAR（右端のミニマップ） | ON / OFF | ON | ペイン状態 |
| 形式 | 自動か指定 | 自動 | `log-files.json`（ファイルごと） |
| EXPLAIN のプロバイダとモデル | AI の設定にあるもの | 最初のプロバイダ | ペイン状態 |
| ミュートしたパターン | — | なし | ペイン状態（署名の配列、200 件まで） |

## 9. 詳細カード

HoverCard（`cardPlacement`、`anchorOf`、`HoverRest`）で開く。行にないことだけを、テキストとして描く。

| 対象 | カードに出すもの |
|------|------------------|
| 行 | 日付付きの完全な時刻（タイムゾーンが分からなければその旨）、全フィールド、パターンと件数と初出時刻、×n の内訳、生の行（MASK が ON なら伏せる）、cut の印 |
| ランプ | 今の状態の理由（急増の閾値、読めない理由、HELD の件数） |
| レーンの棒 | その 5 秒のレベル別の件数 |
| パターンの行 | 初出と最後の時刻、例の 1 行 |

行の COPY は選んだ行の生の文字列を、ページのクリップボード書き込みでコピーする（許可されている clipboard 権限）。

## 10. チャンネルと境界

`registerTable` の表 1 つ（`main/logwatch/`）。ページから main へ渡るのは id と小さな値だけで、パスは渡らない。

| チャンネル | 引数 | 返り値 |
|------------|------|--------|
| `logwatch.pick` | なし（main がファイルかフォルダの選択を開く）、パターン | 登録した id |
| `logwatch.describe` | id | 表示名、表示用のフォルダ、形式、文字コード、状態 |
| `logwatch.subscribe` / `unsubscribe` | id、保持行数、文字コード | 最初の行、続けて 0.25 秒ごとの差分（auto が決めた文字コードと、文字化けの知らせを含む） |
| `logwatch.setFormat` | id、形式 | なし |
| `logwatch.explain` | id、エントリの id、前の行数、プロバイダ、モデル、伏せるか | 答えの流れ（AI チャットと同じ snapshot と delta） |
| `logwatch.cancelExplain` | id | なし |

- 購読は preload と main で参照カウントし、`whenPageGoes` で落とす。`watching()` は監視中の id を並べた配列を返す
- メトリクスのソースにはせず、プラグイン API も出さない
- ポップアップは不可（ファイルを選ぶペインなので、ファイルブラウザと同じ扱い）。ズームは `full`

## 12. 負荷と測定

実装の段階で測り、decisions.md に書く。

- 何も追記されないとき: CPU 0%（`fs.watch` と 1 秒ごとの `stat` だけ）。アイドルの予算（metrics.spec.ts）を守る
- 100 行/秒と 1000 行/秒で、main の 1 バッチの処理時間、ページの描画時間、CPU
- 50k 行を持ったときのメモリ、絞り込みを変えたときの時間
- 1 GB のファイルを開いたときの、最初の表示までの時間（末尾だけを読むので、大きさによらないはず）

## 13. テスト

- **単体**: 形式ごとの判定と正規化（作り物の各形式のサンプル）、続きの行、署名、NEW の学習期間、畳み込み、
  急増、伏せ字、トークン、ローテーションの判定、UTF-16 と Shift_JIS、途中で切れた行、長すぎる行、バイナリ
- **main**（実ファイル、一時フォルダ）: 追記分だけを読む、リネームと切り詰めのローテーション、フォルダ＋
  パターンの乗り換え、購読がなくなったら見張らない、複数のペインで共有する
- **e2e**（`logwatch.spec.ts`）: 一時フォルダのファイルに追記していき、行が届く、追従と ▼ n NEW、PAUSE、
  ペインを隠すと読まず、見えるようになったら While hidden の帯、EXPLAIN（ローカルのスタブのプロバイダ）、
  AI の設定がないと EXPLAIN が出ない
  - ファイル選択はテスト用の環境変数で決まった一時ファイルを返す（GIT ペインのテストと同じやり方）
- **手で試すとき**（Windows）:
  - `scripts/log-feed.mjs`: JSONL、logfmt、syslog、Apache、スタックトレース付きのテキスト、UTF-16LE、Shift_JIS、
    リネームと切り詰めのローテーション、1000 行/秒、改行の途中で切れる書き込み
  - `%LOCALAPPDATA%\npm-cache\_logs\*-debug-0.log`: フォルダ＋パターンの乗り換え（`npm` を実行するたびに増える）
  - `%APPDATA%\Code\logs\<日時>\…\*.log`: 汎用の形式。VS Code を使っている間ずっと増える
  - `~\.claude\projects\<フォルダ>\<セッション>.jsonl`: JSON Lines と長い行
- e2e は既定で、この PC のログを決して読まない
