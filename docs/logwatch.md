# LOG WATCH ペイン 設計

利用者が選んだログファイルを 1 ペインに 1 つ見張り、**追記された分だけ**を読んで、解析して見せる。
`tail -f` の代わりに、レベルの色分け、繰り返しの畳み込み、初めて見るパターンの印、エラーの急増の
ランプ、パターンごとの件数、AI による解説（EXPLAIN）を持つ。ファイルには何も書かない。実装済み
（2026-10-12）。要約は architecture.md §5.21。

見た目のたたき台はモック [logwatch-mock/index.html](logwatch-mock/index.html)（ブラウザで開くだけで動く。
ログはすべて作り物）。モックは DOM に行を足していくだけで、仮想スクロールも main もない（§6、§4）。

## 1. 目的と非目的

**目的**

- 開発中のアプリ、ローカルのサーバ、ツールのログを、シェルを 1 枚潰さずに横で流し見る
- 大量の行から「いつもと違うもの」が目に入る。初めて見るパターン、エラーの急増、レベル
- 目に入った行を選び、その場で AI に説明させる（押したときだけ、選んだ行だけ）

**非目的**

- 書き込み、保存、エクスポート、ログの削除や切り詰め
- Windows イベントログ、journald、macOS の `log stream`（Windows イベントログは別のペインの候補で、利用者の指示があるまで扱わない）
- 複数ファイルのマージ、ログの集約、全文検索インデックス、ネットワーク越しのログ
- 隠れている間の見張りと通知
- 権限の昇格（読めないファイルは読めないと言う）

## 2. 画面構成

上から次の順に並べる（モックのとおり。実装で移したものはそう書く）。

- **見出し**: `LOG WATCH` と、副題にファイル名（パターンならパターン）。右上に設定のアイコン（ほかのペインと
  同じスライダーの絵、`widgets/common/SettingsButton.svelte`）
- **状態の行**: ランプ（OPENING / LIVE / PAUSED · n HELD / ERROR BURST / WAITING FOR FILE / CANNOT READ / ERROR）、
  RATE（行/秒。いまの 5 秒の前の 10 秒で数える: 始まったばかりの 5 秒を入れると、一定の流れでも 5 秒ごとに半分に見えた）、ERR と WARN の 5 分の件数。右に、いま読んでいるファイル名、判定した形式、文字コード。
  ファイル名はボタンで、ポインターを置くとフルパスのカード（§9）、クリックでファイル選択を開き、別のファイルに
  替える（パターンで追っているペインは、選んだファイルからまたパターンを作る）。閉じれば何も変わらない。
  断られたらその理由をこの下に出す（2026-10-12、利用者の提案: 設定の ANOTHER FILE だけでは見つけにくかった）
  読めない理由はその下の 1 行、文字化けの知らせ（§4.1）もその下
- **レーン**: 直近 5 分を 5 秒ごと 60 本の積み上げ棒で、レベル別に描く（ERR は `--danger`、WARN は `--warn`、
  ほかはアクセントの濃淡）。下に `−5 min` と `now`
- **タブ**: STREAM と PATTERNS
- **絞り込みの行**（タブと同じ行）: レベルのトグル（DBG・INF・WRN・ERR、件数付き。既定で DBG は OFF）、文字列か
  `/正規表現/` の絞り込み、PAUSE、MASK、WRAP、ミュート中のパターンの数（押すと PATTERNS へ）
- **本体**: STREAM なら行の一覧と右端のミニマップ、PATTERNS ならパターンの表（§6.4）
- **EXPLAIN**: 開いている間、一覧の下に（§7）
- **足元**: 行を選んでいないときは「click lines to copy them or have AI explain them」と「n lines kept of N ·
  read n KB」。選んでいる間は「n lines chosen · Ctrl+click adds · Shift+click a run」（macOS は ⌘）と
  CLEAR、COPY、EXPLAIN（§7、§9）。
  AI の設定にプロバイダがなければ、EXPLAIN の代わりに「EXPLAIN · SET UP AI」を出し、設定の ai を開く。設定のパネルの
  explain の欄も同じ（2026-10-12、利用者が EXPLAIN の使い方を見つけられなかった: ボタンごと出していなかったため）
- **何も出ていないとき**: 絞り込みやレベルで全部が隠れていれば「no line held matches the levels and the filter
  shown」、まだ 1 行もなければ「no lines yet: they appear here as they are written」を一覧の中ほどに出す
- **レベルのボタンの数**: 保持している行のうち、そのボタンが出し入れする行の数（5 分の件数はレーンと状態の行）
- **設定のパネル**: 「this file, in every pane」の欄に、フルパスと ANOTHER FILE を並べる（利用者の提案）

### 2.1 幅による組み替え

- **wide**: 時刻・レベル・発生元・本文・印（×n、NEW、+n lines）
- **narrow**（一覧の幅が 80 桁未満）: 発生元の列を落とし、カードに回す。PATTERNS は幅 34 rem 未満で推移と
  最終時刻の列を落とす
- 高さが足りないときは、設定でレーンを消せる（§2.2）

### 2.2 ペインごとに切れるもの

レーン（CHART）と右端のミニマップ（ERROR BAR）は、設定のパネルでペインごとに ON / OFF できる（既定はどちらも ON）。
OFF にしたものは描かず、その分の計算もしない（レーンの件数は 5 分の ERR / WARN の数字のためにだけ数える）。
文字コード（§4.1）、時刻の見せ方、WRAP、繰り返しの畳み込みも同じくペインごと（§8）。

## 3. ソース

### 3.1 指定と登録

- GIT ペインと同じ方式にする。ペインの SELECT LOG FILE を押すと main がファイル選択を開き、`realpath` で確かめて
  `log-files.json` に登録し、16 桁の id だけを返す。これまでに選んだファイルは RECENT に並ぶ（最大 40）
- ペイン状態とレイアウトに入るのは id だけ。パスを受け取るチャンネルは作らない。別の機械では「知らない id」
  として選び直しを求める
- 見出しに出すフォルダは表示用の文字列で、チャンネルには戻さない
- **フォルダ＋パターン**: FOLLOW THE NEWEST LIKE IT で選んだファイルの名前から、数字の並び（日付、時刻、番号）を
  `*` にしたパターンを作り（`patternFor`。`2026-10-12T09_08_16_117Z-debug-0.log` は `*-debug-*.log`）、
  そのフォルダとパターンで登録する。一致するもの（再帰なし、大文字小文字を区別しない）のうち、更新時刻が一番
  新しいファイルを読む（同じ時刻なら名前の後のもの。2000 を超えるときは名前の順で後ろの 2000）。数字のない名前は、
  追う相手がないので断る
  - より新しいファイルが現れたら乗り換え、区切り線（「switched to <名前>」）を入れる
  - フォルダを並べ直すのは、パターンに合う別の名前の変化を聞いたときと、10 秒ごと（時計で。呼ばれた回数で数えていたので、追記の多いファイルでは 2 秒ごとに並べ直していた）。読んでいるファイルへの
    追記ではしない（レビューで指摘: 追記のたびにフォルダ全体を読んでいた）
  - 日付ごとにファイルを替えるログや、`npm` の debug ログのように実行ごとにファイルを作るものに使う
- 選んだ時点で先頭 8 KB を読み、NUL を含むファイルはバイナリとして断る

### 3.2 読めないとき

- 権限がない（Linux の `/var/log/messages` など）: CANNOT READ とその理由を出す。昇格はしない
- ファイルがない（まだ作られていない、ローテーションの途中）: WAITING FOR FILE。見えている間の 1 秒ごとの
  見回りで見つけ、見つけたらそこから開く

## 4. 読み取り（main、`src/main/logwatch/`）

- **見えている間だけ**（`seen`）購読し、購読している間だけ見張る。最後の購読者が去ったら監視を閉じる。
  `keepWhileHidden` には何も載せない。隠れている間とウィンドウが非表示の間は何もしない
- **見張り方**: ファイルのフォルダを `fs.watch` で見て（ローテーションでファイルが替わっても見失わない）、
  そのファイルの名前の変化から 200 ms 待って読む
  - Windows では、別のプロセスが開いたまま追記しているファイルの通知とサイズの更新が遅れることがある。
    ネットワークドライブや `\\wsl$` では通知そのものが来ないことがある
  - そこで、購読している間だけ、1 秒ごとの `BoundaryTimer` でも `stat` する。ポーリングはこれだけ
- **読み方**: 前回の位置の続きだけを、1 回あたり最大 1 MB ずつ非同期に読む。ファイルは読むたびに開いて閉じ、
  開きっぱなしにしない（書き手のリネームや削除を邪魔しない）
- **ローテーション**: サイズが前回の位置より小さい、または同一性（`ino` と `birthtime`）が変わったら、先頭から
  読み直し、区切り線（「rotated · reading from its start」）を入れる
- **最初の表示**: 開いたとき、ファイルを選んだときは、末尾から「開いたときに読む行数」（§8）ぶんだけを読む
  （末尾から 64 KB ずつ遡って改行を数え、多くても 4 MB まで）
- **見えるようになったとき**: 保存していた位置からの差分を読み、ほかの行と同じく届ける。絞り込みのとおりに
  最新まで出し、帯や区切りは入れない（2026-10-12、利用者の決定: 「While hidden」の帯はやめた）
  - 差分が 4 MB を超えるときは末尾の 4 MB だけを、その最初の行の頭から読む。保持行数よりずっと多いので、
    見える行は全部を読んだときと変わらない
  - 持つ行は main とページが同じ規則（`trimHeld`: 行数と文字数の上限、古いものから）で持つ
- **行の区切り**: LF と CRLF。改行で終わっていない最後の行は、次の読み取りまで持っておく。1 行が 64 KB を
  超えたら、そこで切って「cut」の印を付ける。持つのは本文 8,000 字、続きの行は 1 行 4,000 字まで（行数だけで
  なく大きさでも抑える）。持つ分より長かった行も「cut」とし、COPY と EXPLAIN は「... (cut: longer than what is kept)」と添える（2026-10-13、レビューで: 4,000 字を超えた行が黙って短く送られていた）。読んだ位置はチャンク（1 MB）ごとに進め、途中で読み取りに失敗しても送った分を読み直さない
- **ファイルの中から読み始めるとき**（開くとき、長い差分の末尾）: 最初の改行の後から。UTF-16 では改行は
  ファイルの偶数番目の位置の 2 バイト（`0A 00` / `00 0A`）だけで、ほかの 0A は別の文字の半分
  （上 は `0A 4E`）なので数えない（レビューで指摘: 1 バイトずれて、以後ずっと化けた）
- **文字コード**: §4.1
- **ページへの送り方**: 0.25 秒の格子（`BoundaryTimer`）でまとめて送る。新しい行がなければ送らない
- **保持**: main は「id と文字コード」の組ごとに、設定の保持行数（全ペイン共通）と 2,400 万字
  （`HELD_CHARS`、本文・発生元・生の行・続きの行・フィールドの合計）の両方の内側を持つ。超えた分は古いほうから捨てる。
  行数だけでは、1 行が大きいときのメモリの上限にならないため。どこまで送ったかは「最後に送った番号」
  （`sentSeq`）で持ち、それより後がまだ送っていない分になる。どのペインにも見えなくなったソースは、読んだ位置と持ち分を 8 つまで保ち（新しいものから）、
  見えたらその続きを読む。ページの側も、ファイルと文字コードの組ごとの持ち分を 8 つまで保ち、それより古いものは行を手放すがフィードとしては残す（隠れたペインがまだ持っているフィードと同じ組の 2 つめを作らないため。2026-10-13、レビューで）
- **共有**: 同じ id を見るペインが複数あれば、監視とファイルの読み取りは 1 つ（参照カウント、`whenPageGoes` で
  落とす）。文字コードはペインごとなので、読んだバイトを文字コードごとに解読し、解析とバッファは
  「id と文字コード」の組ごとに持つ（ふつうは 1 組）
- **書かないもの**: ログの中身はディスクに書かない。`log-files.json` に持つのは id、パス、パターン、形式の
  指定だけ。読んだ位置は main のメモリにだけ持つ（再起動したら末尾から読み直す）

### 4.1 文字コード

- **ペインごと**の選択で、既定は auto。選べるのは auto、UTF-8、UTF-16LE、UTF-16BE、Shift_JIS、EUC-JP、
  Windows-1252（`TextDecoder` で、Electron の ICU が持つもの）
- **auto の判別**（純粋、`detectEncoding`）: 最初に読むバイト（末尾の塊）で決め、決めたものを見出しに
  「AUTO · UTF-8」のように出す。開いたときにファイルが空（または改行がひとつもない）なら、その時点では決めず、
  20 行か 16 KB 来るまで、または 1 行あって静かになるまで待って、文字コードと形式を一緒に決める
  （レビューで指摘: 空のファイルは plain / UTF-8 のままになっていた）
  1. BOM があれば、それに従う
  2. 偶数番目か奇数番目のバイトに NUL が並べば UTF-16（LE / BE）
  3. UTF-8 として正しく読めれば UTF-8（ASCII だけのログもここ）
  4. 読めなければ、Shift_JIS と EUC-JP で解読し、置換文字（U+FFFD）と C1 制御文字の少ないほう。EUC-JP を
     Shift_JIS で読むと置換文字が出ず半角カナが並ぶので、Shift_JIS の側には半角カナの割合の半分を足して比べる。
     どちらも 1% を超えて悪ければ Windows-1252
- **文字化けの知らせ**: 解読した文字（200 字以上）のうち、置換文字と C1 制御文字が 1% を超えたら、状態の行に
  「TEXT LOOKS GARBLED · CHOOSE THE ENCODING ▸」を出す。押すと設定のパネルが開き、文字コードの欄に移る。auto は途中で勝手に切り替えない
  （同じログの行が途中から別の読み方になると、かえって分からなくなる）
- **指定を変えたとき**: main は保持している行を、その文字コードで読み直す（ファイルの末尾から「開いたときに
  読む行数」ぶんを読み直し、バッファを置き換える）。パターンと NEW の学習もやり直す
- auto が決めた文字コードはペイン状態に書かない（ファイルが変われば判別し直せるように）。書くのは利用者の指定だけ

## 5. 解析（純粋、`src/shared/logwatch/`）

DOM、Node、時計を触らない純粋関数にし、単体テストで固める。

- **形式の判定**（`detectFormat`）: 開くときに読んだ行の最後の 200 行から判定する。各形式で見出しとして読めた
  行の割合（時刻で始まる形式はスタックトレースの行を除いた割合）が 6 割以上のうち、一番高いもの
  - JSON Lines（pino、bunyan、winston、Serilog compact などのよくあるキー名）、logfmt、syslog（RFC 3164 / 5424）、
    Apache / nginx の combined、IIS W3C（`#Fields:` を読む）、汎用の「時刻 [レベル] 本文」
  - 判定できなければ plain（1 行 1 エントリ、レベルは本文のキーワードから推す）。設定のパネルで手で直せる
- **正規化**（`parseHead`）: 時刻、レベル（TRC / DBG / INF / WRN / ERR / FTL にそろえ、名乗らない行は LOG）、
  発生元、本文、フィールドに分ける。その形式で読めない行は、続きの行でなければ plain として読む
  - 時刻がない行は、届いた時刻を使い、印を付ける
  - 年のない syslog の時刻は今年とし、未来になるなら前年にする
  - タイムゾーンのない時刻は機械のローカル時刻とみなし、カードにその旨を出す
- **複数行のまとめ**（`LogReader`、`isStackLine`）: 字下げされた行、`at `、`Caused by`、`Traceback` で始まる行と、
  トレースの中の `…Error` / `…Exception` の行は、直前のエントリの続きにする。時刻で始まる形式（syslog、汎用）
  では、時刻のない行も続きにする。続きは 200 行まで持ち、残りは数だけ。行の一覧では畳み、「▸ +n」で開く。
  続きを待っているエントリは、0.25 秒の間に何も来なければ完了とする
- **パターン**（`signature`）: UUID、16 進数の id、16 進数でない長いトークン（`sk_live_…` や base64 の鍵: 20 字以上で数字 2 つと英字を含む。スラッシュは含めないのでパスの形は残る。2026-10-13、デモを撮っていて、鍵ごとに別のパターンになっていたのを見つけた）、8 桁以上の数字だけの並び（文字を引かなかった 16 進数の id。同日、デモで見つけた）、IP、引用符で囲まれた文字列、数値をプレースホルダ
  （`{id}` `{ip}` `{s}` `{n}`）に置き換え、レベルと発生元を前に付けたものを署名にする
- **繰り返しの畳み込み**: 直前に見えている行と同じ署名なら、新しい行は足さずに ×n を増やし、時刻を最新にする
  （ブラウザのコンソールと同じ）。設定のパネルで切れる
- **初めて見るパターン**（NEW）: 開いたときに読んだ末尾の行では署名を覚えるだけにし（学習期間）、NEW の印は
  そのあと届いた行で、まだ知らない署名にだけ付ける。空のファイルを開いたときは、形式を決める最初のまとまり（20 行か 16 KB）が学習期間になる（それまでは最初の行すべてに NEW が付いていた）。署名は 1 ソース 2000 件までで、長く使われていないものから捨てる
- **件数**: レーンと 5 分の件数は、届いた時刻でなく**ログ自身の時刻**の 5 秒ごとに積む。隠れていた間の差分を
  読めば、グラフの空白も埋まる
- **急増**（`bursting`、`burstLit`）: 直近 15 秒の ERR が 5 件以上で、それ以前の 15 秒あたりの平均の 4 倍＋1 以上。
  その状態が 2 秒続いたときだけ ERROR BURST にする（CLUSTER の警告灯と同じく、ちらつかせない）
- **トークン**（`tokens`）: 本文の数値と単位、IP、パス、`key=`、引用文字列、id を色分けの種類に分ける。
  `lib/highlight.ts` と同じく、テキストとして描き、HTML にはしない
- **伏せ字**（`maskText`）: IPv4 / IPv6、メールアドレス、数字を含む 32 文字以上の英数字（鍵らしいもの。ハイフンの
  入る UUID は id なので残す）、`Bearer …`、名前に password / secret / token / key / auth / session / cookie などを含む値を
  伏せる（`password=x`、`token: x`、JSON の `"password":"x"`。名前は前後 120 字まで）。詳細カードでは、名前が
  そう言うフィールドの値を、見た目によらず伏せる。名前の語は本文とカードで 1 つの一覧（`SECRET_WORDS`。2026-10-12、レビューで、カードが伏せる cookie を EXPLAIN がそのまま送っていたのを見つけた）。時刻（`12:04:01`）は IPv6 と取り違えない。どの正規表現も、
  長い 1 行で行の長さの 2 乗にならないよう、始まる位置を連なりの頭に限り、繰り返しに上限を付ける

**どこで解析するか**: main（読んだ直後に解析し、解析済みのエントリを送る）。1000 行/秒で 1 バッチ（0.25 秒分）
が約 1 ms と、目安の 8 ms に十分収まったので、collector へは移さない（§12、decisions.md）。

## 6. 表示（`src/renderer/widgets/logwatch/`）

### 6.1 行の一覧

- 仮想スクロール（見えている行と前後の少しだけを DOM に置く）。保持行数が 50k でも DOM は数百行
- 行: 時刻・レベルの札・発生元・本文・印。ERR と FTL は札を塗り、左端に `--danger` の線、WRN は枠と線を
  `--warn` にする。DBG と TRC は本文を薄くする
- 時刻の見せ方: 絶対（`12:04:01.231`）/ 何秒前 / 前の行との差（ペイン状態）
- WRAP: 本文を折り返す（ペイン状態）
- 届いた行は一度だけ光る。アクセント色の重ねを不透明度で消すだけで、キーフレームで色は動かさない
- 行をクリックすると選択になる（EXPLAIN とコピーの対象。§7、§9）。Ctrl+クリック（macOS は ⌘）で足し引き、
  Shift+クリックで直前に触れた行からの連なり（行だけ。区切りは入らない）。選んだ行のうち、レベルや絞り込みで
  いま見えていないものはコピーも送信もしない（`chosenLines`）。足元の CLEAR か、ひとつだけ選んだ行の
  もう一度のクリックで放す

### 6.2 追従

- 一番下にいる間は、新しい行に合わせてスクロールする
- 上へ戻すと追従を止め、下に「▼ n NEW」（ERR があれば「n ERR」も）を出す。押すか一番下まで戻ると再開する
- **マウスが一覧の上にある間は自動スクロールしない**。読んでいる行が流れていかないようにするためで、
  その間の行も「▼ n NEW」に数える
- PAUSE: 読み取りは続け、画面への反映だけを止める（ランプに「n HELD」）。再開すると、溜まった分をまとめて流す

### 6.3 絞り込みとミニマップ

- レベルのトグル、文字列か `/正規表現/`（不正なら枠を `--danger` にして、前の絞り込みのまま）。
  本文と発生元、そしてスタックトレースの行を探す（例外の名前はトレースにしかないことが多い）。一致した部分を塗る。
  Escape で消す
- ミュートしたパターンは一覧に出さない
- 右端のミニマップ（ERROR BAR）に、絞り込んだ行の中での ERR と WARN の位置を目印で出し、今見ている範囲を枠で
  示す。クリックでそこへ移る。一覧がペインより短いときは、目印を行の横に置く（バー全体に引き伸ばさない）

### 6.4 PATTERNS タブ

- 署名ごとの件数、レベル、パターン（プレースホルダを色分け）、直近 1 分の推移（12 本の棒）、最後に見た時刻、
  MUTE / UNMUTE。数えるのは保持している行の中（保持行数を超えて流れた行は数えない）
- 並びは ERR を先に、そのあと件数の多い順
- 見えている間、1 秒ごと（`onBoundary`）に描き直す

### 6.5 動きと負荷の決まり

- ランプは `pulse`、カードは CRT の電源の入り切り（HoverCard）。設定のパネルは、git や docker のパネルと同じく、ペインの中に開くだけ
- レーンは 2D canvas。値が変わったときだけ、1 秒ごと（`onBoundary`）に描き直す。テーマが変わったら
  `appearance.revision` で色を読み直す
- 0.25 秒ごとの行の追加と、1 秒ごとの描き直しのほかに、自分のタイマーは持たない

## 7. EXPLAIN

- **出す条件**: AI の設定にプロバイダが 1 つ以上あるときだけ EXPLAIN を出す。なければ「EXPLAIN · SET UP AI」
  を出し、設定の ai を開く
- **選び方**: AI チャットと同じく、ペイン状態にプロバイダの id とモデル名を持ち、ないときはそのプロバイダの
  既定のモデルを使う。設定のパネルに選択欄を置く。モデル名は、そのとき見えているプロバイダ（既定なら最初のもの）と一緒に持ち、main はペイン自身のプロバイダにだけそのモデルを使う。パネルと EXPLAIN の宛先の表示も同じ規則で出す
- **送るもの**: 選んだ行だけ（2026-10-12、利用者の決定: 意図しない情報を LLM に送らない）。各行は生の行と
  その続きの行（スタックトレース）。前後の行、ファイル名やパス、判定した形式は送らない。複数選べば、書かれた
  順にまとめて送る（「Explain these n log lines」）
- **流れ**: 行を選んで足元の EXPLAIN を押すと、一覧の下（ペインの高さの 45% まで）に送る本文を見せ、SEND を
  押したときだけ送る。開いている間に選び直して EXPLAIN を押すと、その選択に替わる（書かれている途中の答えは
  止める）。畳んだ行（×n）は、その最初の 1 行を選ぶ
  - MASK が ON なら伏せた状態で送る。OFF のときは、送る前の画面に「MASK is off」と出す
  - 本文は 12,000 字まで、選べるのは 200 行まで。超えるときは一部を落として送ることはせず、「too long to
    send」と断る（選んだものと違うものを送らないため）。送る前の画面で SEND の代わりにそう言う（main が `preview` で収まるかも答える）。1 行が長すぎるときは、MASK で縮んで全体が収まっても断る（`explainFits`。レビューで見つけた: 切ってから伏せていたので、行の末尾が黙って落ちていた）。選んだ行がもう持たれていなければ断る
- **main で**（`main/logwatch/explain.ts`）: ページから受け取るのは、ファイルの id、文字コード、選んだ行の
  `seq` の並び、プロバイダ、モデル、伏せるかだけ。行は main が自分のバッファから `seq` で引き
  （`LogWatchService.lines`）、ひとつでもなければ何も送らない
  - 本文は main が自分のバッファから組み立て（`explainText`、純粋）、見せるもの（`preview`）と送るものは同じ
    関数の同じ答え。ページが書いた文章は送らない
  - プロバイダへは AI チャットの方言（OpenAI 互換 / Anthropic）で送り、キーはページに渡らない
  - ページごとに同時に 1 件まで、180 秒で打ち切る。STOP で止められ、パネルを閉じれば止まる。会話は続けない
    （1 回で終わり。続けたいときは AI チャットへ）
- **答え**: `lib/markdown.ts` の木として描き、HTML にはしない。答えはペインのメモリにだけ持ち、閉じれば消える。
  AI チャットの会話の一覧には入らない
- **システムプロンプト**: 「ログの行を説明する。意味、原因の候補、確かめ方、変えるところ。分からないことは
  分からないと言う」を固定で持ち（`EXPLAIN_SYSTEM`）、その後ろに AI の設定の利用者自身のシステムプロンプトを
  付ける（答えの言語や使っている技術は、そこで言える）。EXPLAIN だけの編集欄は持たない
- 失敗は AI チャットと同じ語彙（`FAILED` と、`STOP_CODES` の短い言葉、プロバイダの言葉を並べて出す）

## 9. 詳細カード

HoverCard（`cardPlacement`、`anchorOf`、`HoverRest`）で開く。行にないことだけを、テキストとして描く。

| 対象 | カードに出すもの |
|------|------------------|
| ファイル名 | フルパス（パターンならフォルダとパターン、いま読んでいる一番新しいファイル）、形式（判定か手で決めたか）、文字コード、読んだ量、読めない理由。「クリックで別のファイルを選ぶ」 |
| 行 | 日付付きの完全な時刻（ゾーンが書かれていなければこの機械の時刻とみなしたこと、時刻がなければ読んだ時刻であること）、発生元、全フィールド、パターンと ×n、cut の印、生の行。MASK が ON ならどの行も伏せる（発生元とパターンも。2026-10-13、レビューで: パターンにアドレスが残っていた） |

ランプの理由（読めない理由など）はカードではなく、ランプの下の 1 行で言う。レーンの棒とパターンの行には
カードを付けない（v1）。

行を選ぶと、足元に CLEAR、COPY と EXPLAIN（プロバイダがなければ SET UP AI）が出る。COPY は選んだ行の
うち見えているものの生の行と続きの行（省いた行数の注記も。EXPLAIN と同じ `lineText`）を、書かれた順に、ほかのペインと同じく main を通して（`utility.copy`）
クリップボードに置く。MASK が ON なら伏せてから置く。

- メトリクスのソースにはせず、プラグイン API も出さない
- ポップアップにできる（`popup: true`。レイアウトのストアに触れない）。ズームは `full`

## 12. 負荷と測定

2026-10-12、この PC（Windows 11）で測った。数字は decisions.md にも書いた。

- **解析**（main、`LogReader`）: 250 行（1000 行/秒の 0.25 秒分）が JSON Lines で 1.04 ms、汎用の形式で 0.96 ms。
  1 コアの約 0.4%。形式の判定は 200 行で 0.7〜2.9 ms（開くときに 1 回）
- **アプリ全体**（`app.getAppMetrics` の CPU、5 秒、畳み込みを OFF にした最悪の場合）:

  | 流れ | 保持行数 | main | ページ | GPU |
  |------|----------|------|--------|-----|
  | 止まっている | 5k | 0.1% | 0% | 0.2% |
  | 100 行/秒 | 5k | 0.2% | 0.9% | 0.3% |
  | 1000 行/秒 | 5k | 0.2% | 2.4% | 0.5% |
  | 1000 行/秒 | 50k（満杯） | 0.7% | 5.7% | 0.5% |

  畳み込みが ON（既定）で同じパターンが続けば、1000 行/秒でもページは 0.3%
- 開くときは末尾から「開いたときに読む行数」ぶんしか読まない（多くても 4 MB）ので、ファイルの大きさによらない
