ELEC-16 — 新しいスキン 5 案（第 5 版）

モック（elecdex のコードは使っていない単独の HTML）。本体・名前板・液晶・キーの並びと寸法は今のペインのまま。第 5 版: 「かわいい」の MOCHI と、透明なガラスの筐体の GLASS を足して 5 案。光の当たり方で本体を立体に描く relief（面取りの光とパーティングライン、沈んだ液晶と鍵盤の板、キーの側面と影と押した姿、ホームポジションの突起、LED のレンズ、液晶の反射と周辺減光）、本体の素材（ヘアライン、梨地: SVG のノイズを本体の色に焼いたタイル、画像なし）、ブザーの穴、点いていないドットの薄い網、スキンごとのキートップの書体（カナも）、線で描いた矢印。キーはクリックで押せます。比べるために今の CLASSIC を最初に置きます。どれも実在の機種の写しではない架空の機械です。

キートップの書体

アプリの CSP は font-src 'self' なので、書体は同梱する。候補はすべて OFL（SIL Open Font License）で、Fontsource の npm パッケージがある（今の Saira Condensed と同じ入れ方）。各スキンの節の見本で候補を同じキーに並べた。

  • ALLOY → Barlow Condensed 500（名前板は 700、字間 0.12em）: 硬く幅の狭い工業的なグロテスク。80 年代の機器の刻印の「事務的な強さ」。濃いキーの白文字は光のにじみで太く見えるので 1 段細い 500。対抗の Sofia Sans Condensed は DIN に近くさらに冷たいが、小さいと字面が細く頼りない
  • GRAPHITE → IBM Plex Sans Condensed 600、機能キーと BRK は 500: 技術文書や計測器の文字の端正さ。0 と O、1 と I の区別がはっきりしていて、明るいキーの濃い文字でも潰れない。濃い機能キーの白文字は同じ理由で 1 段細く
  • NEO → Inter Tight 500（名前板は 600、字間 0.20em）: 今の UI の標準的なグロテスク Inter の、字幅を詰めた版。Inter そのものは本体の幅 560px で MODE がキーからはみ出す。font-feature-settings: "case" で ( ) [ ] などを大文字の高さに揃える。対抗の Instrument Sans は柔らかく雑誌寄り
  • SHIFT 面の刻印、液晶の表示記号、名前板も、そのスキンのキーと同じ書体にする（実機の印刷は 1 つの書体で揃っている）。今の 8 スキンは今のまま（刻印は JetBrains Mono、表示記号は Saira）
  • 矢印は書体で打たず、SVG の線で描く（軸と開いた矢じり、太さ 1.35、currentColor）。Fontsource の latin の部分集合は ↑ ↓ を持つが ← → を持たず、同梱の JetBrains Mono も同じ。今のスキンでも ← → だけが OS の書体に落ちて形が揃っていない。読み上げは今どおり aria-label
  • カナは、各スキンの和文書体を「カ」と「ナ」の 2 字だけ同梱する（Fontsource の JP パッケージは字の塊に分かれているので、その 2 字を含む塊だけを import するか、unicode-range で絞る）: ALLOY は BIZ UDPGothic Bold、GRAPHITE は IBM Plex Sans JP（同じ一族）、NEO は Noto Sans JP 500。どれも OFL。OS の Yu Gothic UI に落ちて形と太さが浮くのを防ぐ
  • MOCHI → M PLUS Rounded 1c 700（名前板は 800）: 丸ゴシック。欧文とカナが同じ一族なので「カナ」も揃う。対抗の Nunito は欧文だけ、Zen Maru Gothic は小さいと線が細い
  • GLASS → Albert Sans 500: 端正な幾何学的グロテスク。NEO の Inter Tight と分けた。実在の会社が自社の UI とブランドのために作った書体（Geist など）は、その会社の顔になるので使わない。透明なキーの上では細い線が背景に負けるので 400 にはしない。カナは Noto Sans JP 500 の 2 字
  • 狭い本体の刻印: 幅 560〜580px（キーの文字が --step--2）では、Saira 以外のどの書体も MODE がキーの内側を 1〜3px はみ出す。新しいスキンでは、狭いときに機能キーの字間を詰め、それでも収まらない文字だけを横に縮める（文字の大きさは変えない、最大 20%）。実測では縮むのは MODE だけで、0.82〜0.92 倍。丸い字の MOCHI は字間を先に詰め、縮めるのは 12% まで（楕円に崩れるため）。アプリでは DOM を測らない: 各ラベルの幅を、スキンの書体が読み込まれてから（document.fonts.load）canvas の measureText で em 単位に一度だけ測ってとっておき、layout.ts のキー幅から倍率を純粋に計算する
  • 足す書体は Barlow Condensed、IBM Plex Sans Condensed、Inter Tight、M PLUS Rounded 1c、Albert Sans と、和文 3 書体（BIZ UDPGothic、IBM Plex Sans JP、Noto Sans JP）の 2 字分（M PLUS Rounded は和文込み）。第三者の告知（ビルドが同梱したものから作られる）と README の表に載る

スキンに足すデータ

今の Skin（skins.ts）に足す項目。テーマと同じく、今の 8 つのスキンにも全項目を明示する（relief: false、texture: 'none'、stripes: []、deck: null、padKey = key、keyFont = font など）ので、今のスキンは一画素も変わらない。どれも layout.ts の寸法（CASE、GLASS_EXTRA、deviceFit）を動かさない。

変えないもの

  • キーの並び、名前板の文言（ELEC-16 / 16-BIT POCKET COMPUTER / POWER）、本体の比率と deviceFit。モックで合意した形のまま
  • 液晶の解像度と描き方（ドットのすき間と影）。動くのはドットだけで、反射と消えたドットは止まった層
  • 文字の大きさの規則（刻印と印刷は --step--2 以上）。押したキーの点滅（ELEC、TRON）と、今の立体キーの押し方（明るくなる）は今のスキンのまま。relief のキーは押すと沈んで暗くなる（実物のキーは光らない）
  • 地面への影の濃さは地の明るさで変わる（このモックでは暗い地 0.5、明るい地 0.22）。アプリではテーマの mode から読む
  • 2 倍の拡大図は、液晶を 2 倍の解像度で描き直している（ドットのすき間と影は実物の比率のまま）。本体の幅と液晶の倍率は実物と同じ
  • 実在の製品名、ロゴ、配色の組み合わせ、特徴的な形（傾いた本体、開閉式の蓋など）は使わない
