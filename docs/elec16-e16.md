# ELEC-16 機械語（E16）取扱説明書

ELEC-16（elecdex の `ELEC-16` ペインのポケコン）の機械語 **E16** で、プログラムを書く人のための手引きです。CPU のプログラミングマニュアルと、内蔵モニタの説明書を兼ねます。

次のような使い方を考えています。

- BASIC の `MON` でモニタに入り、`E` で機械語を打ち込んで `G` で動かす
- PC で `.asm` ファイルを書き、記憶カードに IMPORT して、BASIC から `LOAD "名前.BIN":CALL 28672` で動かす
- CODE 画面（TypeScript から機械語を作る e16c）が出したアセンブリを読む

設計の経緯と理由は [elec16.md](elec16.md) にあります。この手引きは、そこに書かれたことと実装（`src/shared/elec16/`、`resources/elec16/rom/`）から、プログラムを書くのに要ることだけを集めたものです。食い違うときは実装が正しい扱いです。

**表記**: 16 進数は、アセンブリの中では `0x7000`、モニタの入出力では `7000` のように書きます。`rd` は書き込むレジスタ、`rs1` と `rs2` は読むレジスタ、`imm` は即値です。

## 1. 機械の概要

### 1.1 ひと目で

| 項目 | 内容 |
|---|---|
| CPU | E16。16 ビットの RISC（RISC-V に倣った独自の命令セット）。104 命令 |
| データ | 16 ビット。演算はすべて 16 ビットで折り返す。バイトの並びはリトルエンディアン |
| レジスタ | 汎用 16 本（x0〜x15、x0 は常に 0）と pc |
| 番地 | 16 ビット、64 KB。番地の計算も 64 KB で一周する |
| 命令の長さ | 32 ビットの基本形と 16 ビットの圧縮形。どちらも 2 バイト境界に置く |
| 条件フラグ | なし。比較と分岐が 1 命令になっている |
| 拡張 | M（乗除算と固定小数点の積 MULQ）、B（ビット操作）、C（圧縮命令）、ブロック転送（MCPY、MSET） |
| 特権 | 1 つだけ（RISC-V の M モード相当）。CSR と例外・割り込みを持つ |
| クロック | 既定 4 MHz。ユニットごとに 1 / 2 / 4 / 8 / 16 / 32 MHz と MAX（TUNE で選ぶ） |
| RAM | 32 KB（0000–7FFF）。電池で保たれる扱いで、電源を切っても残る |

### 1.2 レジスタ

| 番号 | ABI 名 | 役割 | 呼ばれた側が守るか |
|---|---|---|---|
| x0 | zero | 常に 0。書いても捨てられる | （変わらない） |
| x1 | ra | 戻り番地。JAL と JALR が書く | 呼ぶ側が守る |
| x2 | sp | スタックポインタ。下へ伸びる | 守る |
| x3 | gp | グローバル域。ROM は使わず、リセットの 0 のまま（0000 の作業域を指す） | 守る |
| x4–x7 | a0–a3 | 引数と戻り値（戻り値は a0） | 守らない |
| x8–x11 | t0–t3 | 一時 | 守らない |
| x12–x15 | s0–s3 | 保存（`fp` は s0 の別名） | 守る |
| pc | | 次に実行する命令の番地（偶数） | |

アセンブラでは `x0`〜`x15` と ABI 名のどちらでも書けます。大文字と小文字は区別しません。圧縮命令のレジスタ欄も 4 ビットあるので、16 本すべてを圧縮命令で使えます（RISC-V の圧縮命令は 8 本だけです）。

### 1.3 メモリマップ（プログラムから見た）

| 番地 | 中身 | プログラムからの扱い |
|---|---|---|
| 0000–00FF | ROM の作業域（カーソル、キーの状態、ECALL の戻り先、モニタの変数など） | 触らない |
| 0100–07FF | BASIC の作業域 | 触らない |
| 0800–6FFF | BASIC のプログラムと変数（下から積む） | BASIC が使っている。空いていれば `LOAD "X.BIN", 番地` で置ける |
| **7000–7BFF** | **機械語の領域（3 KB）**。境は動かない（`CLEAR` は変数を消すだけ） | 自分のコードとデータを置く所 |
| 7C00–7FFF | スタック。sp は 8000 から下へ伸びる | ROM と BASIC とあなたのプログラムが共有する |
| 8000–BFFF | ROM（固定 16 KB）。8000 がリセット、8010 が ROM サービスの表 | 読めるが、書くと例外 |
| C000–DFFF | ROM のバンクの窓（8 KB）。BANK レジスタで選ぶ | 読めるが、書くと例外 |
| E000–F7FF | 液晶の VRAM の窓（6 KB）。使うのはモデルの画面の分だけ | 読み書きできる（§4.2） |
| F800–FEFF | 予約 | 読むと 0、書いても無視 |
| FF00–FFFF | I/O レジスタ | §4 |

- 割り当てのない番地は読むと 0、書いても無視されます（ROM の中で何も書かれていない所は 0xFF と読めます）。**例外になる書き込みは ROM（8000–DFFF）だけ**です
- CODE 画面の e16c は、機械語の領域をさらに分けて使います: コードと文字列が 7000–77FF、大域変数と配列が 7800–7BEF です
- ROM の固定部と BASIC の後半（バンク 0〜4）は、ROM の中身です。番地はビルドごとに変わりうるので、決まっているのは 8000（リセット）と 8010（サービスの表）だけと考えてください

### 1.4 クロックとサイクル

- 命令ごとのサイクル数は §2.12 の表のとおりです。4 MHz なら 1 秒に 4,000,000 サイクル、1 フレーム（60 分の 1 秒）は 66,667 サイクルです
- タイマー（1,024 Hz）と時計は**ホストの時刻**で進みます。クロックを変えても、タイマーで測った時間はずれません。時間を測るときはタイマーを使い、サイクル数は使いません
- `WFI` で眠っている間は、サイクルは進まず、ペインもほとんど CPU を使いません

## 2. 命令セット

### 2.1 約束

- レジスタは 16 ビットです。足し算などは 16 ビットで折り返します（0xFFFF + 1 は 0）
- 「符号付き」と書いた比較・シフト・乗除算は、レジスタをビット 15 を符号とする 2 の補数（-32768〜32767）として読みます。それ以外は符号なし（0〜65535）です
- x0 に書く命令は、結果を捨てるだけです（例外は起きません）
- 1 つの命令は、アセンブラで常に 1 つの機械語になります。16 ビットの値が 1 命令（`li`）に入るので、2 命令に分ける疑似命令はありません
- 即値の範囲はアセンブラが確かめ、外れると誤りにします。I 形の即値は符号付き 14 ビット（-8192〜8191）です

各表の「サイクル」は 32 ビット形でも圧縮形でも同じです。「圧縮」は、アセンブラが自動で 16 ビットにできる形です（§2.10）。

### 2.2 整数演算（レジスタ）10 命令

| 命令 | 動作 | サイクル | 圧縮 |
|---|---|---|---|
| `add rd, rs1, rs2` | rd = rs1 + rs2 | 1 | `c.add`（rd = rs1）、`c.mv`（rs1 = zero） |
| `sub rd, rs1, rs2` | rd = rs1 − rs2 | 1 | `c.sub`（rd = rs1） |
| `and rd, rs1, rs2` | rd = rs1 & rs2 | 1 | `c.and`（rd = rs1） |
| `or rd, rs1, rs2` | rd = rs1 \| rs2 | 1 | `c.or`（rd = rs1） |
| `xor rd, rs1, rs2` | rd = rs1 ^ rs2 | 1 | `c.xor`（rd = rs1） |
| `sll rd, rs1, rs2` | rd = rs1 << (rs2 & 15) | 1 | |
| `srl rd, rs1, rs2` | rd = rs1 >> (rs2 & 15)（論理） | 1 | |
| `sra rd, rs1, rs2` | rd = rs1 >> (rs2 & 15)（算術、符号付き） | 1 | |
| `slt rd, rs1, rs2` | rd = rs1 < rs2 なら 1、でなければ 0（符号付き） | 1 | |
| `sltu rd, rs1, rs2` | 同じく符号なし | 1 | |

シフト量はレジスタの下位 4 ビットだけを見ます（16 ビット以上のシフトはありません）。

### 2.3 整数演算（即値）11 命令

| 命令 | 動作 | 即値 | サイクル | 圧縮 |
|---|---|---|---|---|
| `addi rd, rs1, imm` | rd = rs1 + imm | -8192〜8191 | 1 | `c.addi`、`c.li`、`c.addi2spn`、`c.nop` |
| `andi rd, rs1, imm` | rd = rs1 & imm | -8192〜8191（16 ビットに符号拡張） | 1 | `c.andi`（rd = rs1） |
| `ori rd, rs1, imm` | rd = rs1 \| imm | 同上 | 1 | |
| `xori rd, rs1, imm` | rd = rs1 ^ imm | 同上 | 1 | |
| `slli rd, rs1, n` | rd = rs1 << n | 0〜15 | 1 | `c.slli`（rd = rs1、n ≠ 0） |
| `srli rd, rs1, n` | rd = rs1 >> n（論理） | 0〜15 | 1 | `c.srli`（同上） |
| `srai rd, rs1, n` | rd = rs1 >> n（算術） | 0〜15 | 1 | `c.srai`（同上） |
| `slti rd, rs1, imm` | rd = rs1 < imm なら 1（符号付き） | -8192〜8191 | 1 | |
| `sltiu rd, rs1, imm` | rd = rs1 < imm なら 1（符号なし。imm は 16 ビットに符号拡張してから比べるので、-1 は 0xFFFF） | -8192〜8191 | 1 | |
| `li rd, imm` | rd = imm（16 ビットのどんな値でも） | -32768〜65535 | 1 | `c.li`（-32〜31、rd ≠ zero） |
| `auipc rd, imm` | rd = この命令の番地 + imm | -32768〜65535 | 1 | |

- `li` は 1 命令で 16 ビットの値を入れます。32 ビット機の LUI＋ADDI の組はいりません。番地を入れる `la` は `li` と同じ命令です
- `auipc` の即値は「距離」です。位置によらないコードでは `auipc a0, msg - $` のように書きます（`$` はその行の番地）

### 2.4 ロード・ストア 5 命令

| 命令 | 動作 | サイクル | 圧縮 |
|---|---|---|---|
| `lb rd, imm(rs1)` | rd = 番地 rs1 + imm のバイト（符号拡張） | 2 | |
| `lbu rd, imm(rs1)` | 同じくゼロ拡張 | 2 | |
| `lw rd, imm(rs1)` | rd = 番地のワード（下位バイトが先） | 2 | `c.lw`、`c.lwsp` |
| `sb rs2, imm(rs1)` | 番地へ rs2 の下位バイトを書く | 2 | |
| `sw rs2, imm(rs1)` | 番地へ rs2 のワードを書く | 2 | `c.sw`、`c.swsp` |

- オフセットは -8192〜8191 です。`(a0)` だけならオフセット 0 です
- **ワード（LW、SW）の番地は偶数**でなければなりません。奇数だと例外（読みは原因 4、書きは原因 6、mtval にその番地）です
- ROM（8000–DFFF）へ書くと例外（原因 7、mtval にその番地）です。読むのは自由です
- 番地は `zero` からの負のオフセットでも書けます。`lw t0, -0xe0(zero)` は FF20 を読みます（0x10000 − 0xE0 = 0xFF20）。I/O レジスタはこの書き方で 1 命令で届きます（§4）

### 2.5 分岐とジャンプ 8 命令

| 命令 | 動作 | 届く範囲 | サイクル | 圧縮 |
|---|---|---|---|---|
| `beq rs1, rs2, 先` | rs1 = rs2 なら飛ぶ | ±16 KB | 成立 2 / 不成立 1 | `c.beqz`（rs2 = zero、±128 B） |
| `bne rs1, rs2, 先` | rs1 ≠ rs2 なら飛ぶ | ±16 KB | 同上 | `c.bnez`（同上） |
| `blt rs1, rs2, 先` | rs1 < rs2（符号付き） | ±16 KB | 同上 | |
| `bge rs1, rs2, 先` | rs1 ≥ rs2（符号付き） | ±16 KB | 同上 | |
| `bltu rs1, rs2, 先` | rs1 < rs2（符号なし） | ±16 KB | 同上 | |
| `bgeu rs1, rs2, 先` | rs1 ≥ rs2（符号なし） | ±16 KB | 同上 | |
| `jal rd, 先` | rd = 次の命令の番地、先へ飛ぶ | 64 KB のどこへでも | 2 | `c.j`（rd = zero）、`c.jal`（rd = ra）、±2 KB |
| `jalr rd, imm(rs1)` | 先 = (rs1 + imm) のビット 0 を落とした番地。rd = 次の命令の番地 | どこへでも | 2 | `c.jr`（rd = zero、imm = 0）、`c.jalr`（rd = ra、imm = 0） |

- 「先」はラベルか番地の式で書きます。命令の中には、その命令の番地からの距離が入ります
- JALR は rd を書く前に rs1 を読むので、`jalr ra, 0(ra)` も正しく動きます
- 「次の命令の番地」は、その命令が 2 バイトなら +2、4 バイトなら +4 です

### 2.6 乗除算（M）9 命令

| 命令 | 動作 | サイクル |
|---|---|---|
| `mul rd, rs1, rs2` | 積の下位 16 ビット | 4 |
| `mulh rd, rs1, rs2` | 積の上位 16 ビット（符号付き × 符号付き） | 4 |
| `mulhu rd, rs1, rs2` | 積の上位 16 ビット（符号なし × 符号なし） | 4 |
| `mulhsu rd, rs1, rs2` | 積の上位 16 ビット（rs1 符号付き × rs2 符号なし） | 4 |
| `mulq rd, rs1, rs2, k` | 符号付き × 符号付きの 32 ビットの積を k ビット算術右シフトした下位 16 ビット（k は 1〜15） | 4 |
| `div rd, rs1, rs2` | 商（符号付き、0 の方へ切り捨て） | 18 |
| `divu rd, rs1, rs2` | 商（符号なし） | 18 |
| `rem rd, rs1, rs2` | 余り（符号付き。符号は被除数と同じ） | 18 |
| `remu rd, rs1, rs2` | 余り（符号なし） | 18 |

**割り算は例外を起こしません**（RISC-V と同じ）。0 で割ると商は 0xFFFF（全ビット 1）、余りは被除数です。`-32768 / -1` は商 -32768、余り 0 です。

**MULQ は固定小数点の積**です。下位 k ビットを小数とする数（Q14 なら 16384 が 1）どうしの積を、途中で上位のビットを失わずに 1 命令で求めます。`mul` だけでは積の下位 16 ビットしか残らず、`(a × b) >> k` の上位が欠けます。同じことを `mul`、`mulh`、`srli`、`slli`、`or` の 5 命令（4 + 4 + 3 = 11 サイクル）でしていたのが、4 サイクルになります。シフトは算術なので、端数は小さい方（負の側）へ切り捨てます（-3 × 1 を 1 ビット右へは -2）。答えは下位 16 ビットで、入りきらなければ折り返します。

```text
  li a0, 0x6000            ; 1.5（Q14）
  li a1, 0xE000            ; -0.5（Q14）
  mulq a2, a0, a1, 14      ; a2 = 0xD000（-0.75）
  li a0, 200               ; 整数の 200
  li a1, 0xFF80            ; -0.5（Q8: 256 が 1）
  mulq a3, a0, a1, 8       ; a3 = 0xFF9C（-100）
```

- k が 0 なら `mul`、16 なら `mulh` と同じ答えなので、それぞれの命令を使います（1 つの符号は 1 つの意味。量 0 の MULQ は不正な命令で、アセンブラは 0 と 16 以上を誤りにします）
- 16 ビットの圧縮形はありません

### 2.7 ビット操作（B）24 命令

| 命令 | 動作 |
|---|---|
| `andn rd, rs1, rs2` | rd = rs1 & ~rs2 |
| `orn rd, rs1, rs2` | rd = rs1 \| ~rs2 |
| `xnor rd, rs1, rs2` | rd = ~(rs1 ^ rs2) |
| `clz rd, rs1` | 上から続く 0 のビットの数（rs1 = 0 なら 16） |
| `ctz rd, rs1` | 下から続く 0 のビットの数（rs1 = 0 なら 16） |
| `cpop rd, rs1` | 1 のビットの数 |
| `min rd, rs1, rs2` / `max` | 小さい方 / 大きい方（符号付き） |
| `minu rd, rs1, rs2` / `maxu` | 小さい方 / 大きい方（符号なし） |
| `rol rd, rs1, rs2` | 左へ (rs2 & 15) ビット回す |
| `ror rd, rs1, rs2` | 右へ (rs2 & 15) ビット回す |
| `rori rd, rs1, n` | 右へ n ビット回す（0〜15）。左へ回す即値形はないので `rori rd, rs1, 16 - n` |
| `rev8 rd, rs1` | 上下のバイトを入れ替える |
| `sext.b rd, rs1` | 下位バイトを符号拡張 |
| `zext.b rd, rs1` | 下位バイトをゼロ拡張（`andi rd, rs1, 0xff` と同じ） |

| `bext rd, rs1, rs2` | rd = rs1 のビット (rs2 & 15)（0 か 1） |
| `bseti rd, rs1, n` / `bclri` / `binvi` / `bexti` | 同じことをビット番号 n（0〜15）で |

すべて 1 サイクルです。圧縮形はありません。

### 2.8 ブロック転送 2 命令（MCPY、MSET）

| 命令 | 動作 | サイクル（1 回につき） |
|---|---|---|
| `mcpy rd, rs1, rs2` | 番地 rs1 から番地 rd へ rs2 バイトを写す（memmove と同じ） | 1 ＋ 2 × 動かしたバイト数 |
| `mset rd, rs1, rs2` | 番地 rd から rs2 バイトを rs1 の下位バイトで埋める（memset と同じ） | 1 ＋ 1 × 動かしたバイト数 |

長いブロックを 1 命令で動かせます。ROM の CLS と画面の送り、BASIC の行の移動が使っています。

**1 回に 8 バイトまで動き、終わるまで同じ命令をくり返します。**

1. 1 回の実行で、残り（rs2）のうち 8 バイトまでを動かします
2. レジスタを進めます。前から写すとき（MSET は常に前から）は rd と rs1（MCPY のみ）に動かした数を足し、rs2 から引きます。後ろから写すとき（下の重なり）は rs2 だけを引きます
3. まだ残りがあれば、pc は同じ命令のままです。次の実行で続きを動かします
4. rs2 が 0 になったら次の命令へ進みます。最初から rs2 が 0 なら何もせず 1 サイクルで進みます

だから長い転送の途中でも、割り込みや BRK は命令の間と同じように入ります。ハンドラから MRET で戻ると、続きから動きます。

**重なり**: MCPY は、写し先 rd が写し元の範囲（rs1 から rs2 バイト）の中にあれば、後ろから写します。どう重なっても memmove と同じく全部正しく写ります。後ろから写している途中で、残りが写し先と写し元の距離以下になると、残りは前から写します（そこはもう重ならないため）。このとき最後の回だけ rd と rs1 が進むので、**重なった MCPY の後の rd と rs1 の値には頼らないでください**。確かな約束は「rs2 は 0 になる」ことだけです。重ならない転送では、終わったとき rd と rs1 は範囲の終わりの次を指します。

**レジスタの制約**: rd、rs1、rs2 は 3 つとも別のレジスタで、zero は使えません。ただし MSET の値（rs1）だけは zero でかまいません（0 で埋める）。それ以外の組み合わせは不正な命令で、アセンブラも誤りにします。

```asm
        li   a0, 0xe000      ; 写し先
        li   a1, 0xe0f0      ; 写し元
        li   a2, 1200        ; バイト数
        mcpy a0, a1, a2      ; a2 は 0 になる
        li   a0, 0xe000 + 1200
        li   a2, 240
        mset a0, zero, a2    ; 240 バイトを 0 で埋める
```

**書けない番地**: ROM に当たると、そこまでの進み具合をレジスタに残して例外（原因 7、mtval に書けなかった番地、mepc にこの命令の番地）になります。I/O や予約域への書き込みは、それぞれの番地の規則どおりに扱われ（I/O の奇数番地は無視など）、例外にはなりません。

### 2.9 システム 10 命令

| 命令 | 動作 | サイクル |
|---|---|---|
| `ecall` | 例外（原因 11）を起こす。ROM はこれを ROM サービスの呼び出しにしている（§5.2） | 1 |
| `ebreak` | 例外（原因 3、mtval にこの命令の番地）。ROM ではモニタに落ちて `BREAK AT 番地` | 1 |
| `wfi` | 許可された割り込みが保留になるまで眠る（§3.5） | 1 |
| `mret` | 例外から戻る: pc = mepc、mstatus.MIE = MPIE、MPIE = 1 | 1 |
| `csrrw rd, csr, rs1` | rd = CSR、CSR = rs1 | 2 |
| `csrrs rd, csr, rs1` | rd = CSR、CSR \|= rs1（rs1 が zero なら書かない） | 2 |
| `csrrc rd, csr, rs1` | rd = CSR、CSR &= ~rs1（rs1 が zero なら書かない） | 2 |
| `csrrwi rd, csr, n` | rd = CSR、CSR = n（0〜15） | 2 |
| `csrrsi rd, csr, n` | rd = CSR、CSR \|= n（n が 0 なら書かない） | 2 |
| `csrrci rd, csr, n` | rd = CSR、CSR &= ~n（n が 0 なら書かない） | 2 |

CSR は名前（`mstatus` など）でも番号（`0x300`）でも書けます。`csrrsi` などの値には記号も使えます。

### 2.10 圧縮命令（C）25 命令

圧縮命令は、32 ビットの命令の特定の形を 16 ビットにしたものです。意味は元の命令と同じで、サイクル数も同じです。**アセンブラは、入る命令を自動で 16 ビットにします**（`.option nocompress` で止められます）。`c.` で始まる名前を書けば、その 16 ビット形を指定できます（入らなければ誤り）。

| 圧縮命令 | 意味 | 条件 | 元になる書き方 |
|---|---|---|---|
| `c.nop` | 何もしない | 0x0001 だけ | `nop`、`addi zero, zero, 0` |
| `c.li rd, imm` | `addi rd, zero, imm` | rd ≠ zero、-32〜31 | `li rd, imm`、`addi rd, zero, imm` |
| `c.addi rd, imm` | `addi rd, rd, imm` | rd ≠ zero、-32〜31 で 0 でない | `addi rd, rd, imm` |
| `c.addi2spn rd, imm` | `addi rd, sp, imm` | rd ≠ zero、2〜254 の偶数 | `addi rd, sp, imm` |
| `c.andi rd, imm` | `andi rd, rd, imm` | rd ≠ zero、-32〜31 で -1 でない | `andi rd, rd, imm` |
| `c.slli rd, n` / `c.srli` / `c.srai` | `slli rd, rd, n` など | rd ≠ zero、1〜15 | `slli rd, rd, n` など |
| `c.mv rd, rs2` | `add rd, zero, rs2` | rd ≠ zero、rd ≠ rs2 | `mv rd, rs2` |
| `c.add rd, rs2` | `add rd, rd, rs2` | rd ≠ zero、rs2 ≠ zero | `add rd, rd, rs2` |
| `c.sub rd, rs2` | `sub rd, rd, rs2` | 同上 | `sub rd, rd, rs2` |
| `c.xor rd, rs2` | `xor rd, rd, rs2` | 同上 | `xor rd, rd, rs2` |
| `c.or rd, rs2` | `or rd, rd, rs2` | 同上 | `or rd, rd, rs2` |
| `c.and rd, rs2` | `and rd, rd, rs2` | rd ≠ zero（rs2 = zero は rd を 0 にする） | `and rd, rd, rs2` |
| `c.lw rd, imm(rs1)` | `lw rd, imm(rs1)` | rd ≠ zero、0〜14 の偶数 | `lw rd, imm(rs1)` |
| `c.sw rs2, imm(rs1)` | `sw rs2, imm(rs1)` | 0〜14 の偶数 | `sw rs2, imm(rs1)` |
| `c.lwsp rd, imm` | `lw rd, imm(sp)` | rd ≠ zero、0〜254 の偶数 | `lw rd, imm(sp)` |
| `c.swsp rs2, imm` | `sw rs2, imm(sp)` | 0〜254 の偶数 | `sw rs2, imm(sp)` |
| `c.beqz rs1, 先` | `beq rs1, zero, 先` | -128〜126 | `beqz rs1, 先` |
| `c.bnez rs1, 先` | `bne rs1, zero, 先` | -128〜126 | `bnez rs1, 先` |
| `c.j 先` | `jal zero, 先` | -2048〜2046 | `j 先` |
| `c.jal 先` | `jal ra, 先` | -2048〜2046 | `call 先`、`jal 先` |
| `c.jr rs1` | `jalr zero, 0(rs1)` | rs1 ≠ zero | `jr rs1`、`ret` |
| `c.jalr rs1` | `jalr ra, 0(rs1)` | rs1 ≠ zero | `jalr rs1` |
| `c.ebreak` | `ebreak` | | `ebreak` |

- `c.lwsp` と `c.swsp` は `c.lwsp s0, 0` とも `c.lwsp s0, 0(sp)` とも書けます
- `add a0, a1, a0` のように rd が rs2 の側にある形は圧縮されません（`add a0, a0, a1` と書けば圧縮されます）
- `not`（`xori rd, rs, -1`）と `neg`（`sub rd, zero, rs`）には圧縮形がなく、4 バイトです
- ECALL、MRET、WFI、CSR の命令、乗除算、ビット操作、ブロック転送に圧縮形はありません

### 2.11 不正な命令

E16 は「1 つの符号は 1 つの意味」にしてあります。何もしない書き方は命令ではなく、不正な命令（例外の原因 2、mtval に命令の最初の 16 ビット）になります。

- 0 を足す `c.addi`、x0 に書く `c.li` `c.lw` `c.lwsp` `c.addi2spn`、0 を足す `c.addi2spn`、0 ビットのシフト、16 以上のシフト量、自分への `c.mv`、x0 との `c.add` `c.sub` `c.xor` `c.or`、全ビット 1 との `c.andi`、x0 を指す `c.jr` `c.jalr`
- **0x0000** も不正です。消えた（0 の）メモリに飛び込んだ CPU はすぐ止まります
- 32 ビットの SYSTEM のうち ECALL、EBREAK、MRET、WFI（0〜3）以外の種類、ECALL などで rd や rs1 の欄が 0 でないもの
- LI、AUIPC、JAL のビット 31〜27 が 0 でないもの（予約）
- MCPY と MSET のレジスタの組が §2.8 の制約に合わないもの
- シフト量が 0 の MULQ（MUL と同じ答え）と、OP の f10 が 0x10 以上で MULQ でないもの
- 存在しない CSR を読み書きする CSR 命令

アセンブラは何もしない形の圧縮命令を作りません（`addi a0, a0, 0` は 32 ビットのまま）。逆アセンブラ（モニタの `U`）は不正な命令を `.word ?`（16 ビット）か `.word ?, ?`（32 ビット）と出します。

### 2.12 サイクル数のまとめ

| 種類 | サイクル |
|---|---|
| 整数演算（レジスタ、即値）、LI、AUIPC、ビット操作 | 1 |
| ロード、ストア | 2 |
| 分岐 | 成立 2、不成立 1 |
| JAL、JALR | 2 |
| MUL、MULH、MULHU、MULHSU、MULQ | 4 |
| DIV、DIVU、REM、REMU | 18 |
| CSR の命令 | 2 |
| ECALL、EBREAK、WFI、MRET | 1（ECALL と EBREAK の後は、ROM のハンドラの命令がその分かかる） |
| MCPY | 1 回につき 1 ＋ 1 バイト 2 |
| MSET | 1 回につき 1 ＋ 1 バイト 1 |
| 割り込みに入る | 2 |
| 数値演算ユニットの演算 | OP に書いた命令に、演算のサイクル（§4.6）が足される |

圧縮命令のサイクルは元の命令と同じです。圧縮の利点は、コードが小さくなることです。

### 2.13 符号化（ダンプを読むために）

命令はリトルエンディアンの 16 ビット単位で並びます。**最初の 16 ビットの下位 2 ビットが `11` なら 32 ビット命令、それ以外なら 16 ビット命令**です。

```text
32 ビット        31        22 21  18 17  14 13 11 10   7 6     2 1 0
  R  レジスタ    |  f10     | rs2  | rs1  | f3  | rd   | major |11|
  R  MULQ        |000001 k  | rs2  | rs1  | 000 | rd   | major |11|  f10 = 0x10 + k（k は 1〜15）
  I  即値        |   imm[13:0]     | rs1  | f3  | rd   | major |11|  符号付き 14 ビット
  S  ストア      | imm[13:4]| rs2  | rs1  | f3  |imm[3:0]|major|11|
  B  分岐        |off[14:5] | rs2  | rs1  | f3  |off[4:1]|major|11|  ±16 KB
  U  LI/AUIPC    |00000| imm[15:0]                | rd   | major |11|  16 ビット
  J  JAL         |00000| off[16:1]                | rd   | major |11|
```

| major | 命令 | 選び方 |
|---|---|---|
| 0 LOAD | LB / LW / LBU | f3 = 0 / 1 / 4 |
| 1 STORE | SB / SW | f3 = 0 / 1 |
| 2 OP-IMM | ADDI SLTI SLTIU XORI ORI ANDI | f3 = 0 2 3 4 6 7 |
| 2 OP-IMM（f3 = 1） | imm[13:4]: 0 SLLI、1 BSETI、2 BCLRI、3 BINVI（imm[3:0] が量）、0x10 CLZ、0x11 CTZ、0x12 CPOP、0x13 SEXT.B、0x14 ZEXT.B、0x15 REV8（imm[3:0] は 0） | |
| 2 OP-IMM（f3 = 5） | imm[13:4]: 0 SRLI、1 SRAI、2 RORI、3 BEXTI | |
| 3 OP | f10 = 0: ADD SLL SLT SLTU XOR SRL OR AND（f3 = 0〜7）。f10 = 1: SUB（0）SRA（5）。f10 = 2: MUL MULH MULHSU MULHU DIV DIVU REM REMU（f3 = 0〜7）。f10 = 3: ROL（1）XNOR（4）ROR（5）ORN（6）ANDN（7）。f10 = 4: MIN（4）MINU（5）MAX（6）MAXU（7）。f10 = 5: BSET BCLR BINV BEXT（0〜3）。f10 = 6: MCPY（0）MSET（1）。f10 = 0x11〜0x1F: MULQ（f3 = 0、f10 の下位 4 ビットがシフト量 1〜15） | |
| 4 BRANCH | BEQ BNE BLT BGE BLTU BGEU | f3 = 0 1 4 5 6 7 |
| 5 JAL、6 JALR（f3 = 0）、7 LI、8 AUIPC | | |
| 9 SYSTEM | f3 = 0: imm で ECALL（0）EBREAK（1）MRET（2）WFI（3）。f3 = 1〜3: CSRRW CSRRS CSRRC、5〜7: CSRRWI CSRRSI CSRRCI（imm[11:0] が CSR 番号、I 形は rs1 の欄が値） | |

```text
16 ビット        15  13 12 11 10  9 8   7 6   3 2 1 0
  象限 0（op = 00）: メモリ
    C.LW / C.SW   |f3=0/1|off[3:2]| reg   | rs1  |off[1]|00|   オフセット 0〜14
    C.LWSP/C.SWSP |f3=2/3|  reg   |    off[7:1]         |00|   sp から 0〜254
    C.ADDI2SPN    |f3=4  |  rd    |    imm[7:1]         |00|   rd = sp + 2〜254
  象限 1（op = 01）: 即値と分岐
    CI            |f3 | rd(12..9) | imm[5:0](8..3) |sub|01|   (f3,sub) = (0,0) C.ADDI (0,1) C.LI
                  |   |           |                |   |  |   (1,0) C.SLLI (1,1) C.SRLI (2,0) C.SRAI (2,1) C.ANDI
    C.BEQZ/C.BNEZ |f3=3/4| rs1    |    off[7:1]         |01|   ±128 B
    C.J / C.JAL   |f3=5/6|          off[11:1]           |01|   ±2 KB
  象限 2（op = 10）: レジスタ
    CR            | f4 | rd(11..8) | rs2(7..4) | f2 |10|   (f4,f2) = (0,0) C.MV (0,1) C.ADD (0,2) C.SUB
                  |    |           |           |    |  |   (0,3) C.XOR (1,0) C.AND (1,1) C.OR
```

C.JR と C.JALR は飛び先のレジスタを rd の欄（11..8）に持ちます。C.NOP は 0x0001、C.EBREAK は 0x200A です。

例: `02 21` は 16 ビットの 0x2102 で、象限 2、f4 = 2、rd = 1（ra）、f2 = 0 なので `c.jr ra`（`ret`）です。

## 3. CSR、例外、割り込み

### 3.1 CSR

| CSR | 番号 | 中身 |
|---|---|---|
| `mstatus` | 0x300 | ビット 3 MIE（割り込みの許可）、ビット 7 MPIE（例外の前の MIE）。ほかのビットは 0 |
| `misa` | 0x301 | 読み出し専用。0x1006（M = ビット 12、C = ビット 2、B = ビット 1） |
| `mie` | 0x304 | 割り込みの線ごとの許可。ビット 0 TIMER、1 KEY、2 CARD、3 MATH、4 LINK（ほかは書いても 0） |
| `mtvec` | 0x305 | 例外と割り込みの入口（ビット 0 は 0 になる）。**0 のときは例外で機械が止まる** |
| `mscratch` | 0x340 | ハンドラの作業用 |
| `mepc` | 0x341 | 例外の戻り番地（ビット 0 は 0 になる） |
| `mcause` | 0x342 | 原因（下の表） |
| `mtval` | 0x343 | 原因に添える値 |
| `mip` | 0x344 | 読み出し専用。保留中の線（デバイスの状態そのもの） |
| `cycle` / `cycleh` | 0xC00 / 0xC80 | サイクル数の下位 / 上位 16 ビット（読み出し専用） |
| `instret` / `instreth` | 0xC02 / 0xC82 | 実行した命令数の下位 / 上位 16 ビット（読み出し専用） |

- 存在しない CSR を読み書きすると不正な命令です。読み出し専用の CSR への書き込みは無視します
- `cycle` は 4 MHz で約 16 ミリ秒、`cycleh` まで含めても約 18 分で一周します。時間を測るのはタイマーで

### 3.2 例外

| mcause | 原因 | mtval |
|---|---|---|
| 2 | 不正な命令 | 命令の最初の 16 ビット |
| 3 | EBREAK | EBREAK の番地 |
| 4 | ワードの読みが奇数番地 | その番地 |
| 6 | ワードの書きが奇数番地 | その番地 |
| 7 | ROM への書き込み | その番地 |
| 11 | ECALL | 0 |

例外が起きると、CPU は次のことをします。

1. mepc にその命令の番地、mcause に原因、mtval に値を入れる
2. mstatus の MPIE に MIE を写し、MIE を 0 にする
3. mtvec へ飛ぶ

ハンドラは MRET で mepc に戻ります。ECALL のように次の命令へ進みたいときは、ハンドラが mepc に 4 を足します（ECALL は常に 4 バイトです）。

- **mtvec が 0 なら、例外で機械は止まります**（CORE に原因と番地が出ます）
- **ハンドラの中（MRET の前）でもう一度例外が起きると、二重の例外で機械は止まります**。ハンドラの中では ECALL を使えません
- 止まった機械は BRK/ON で再起動します（RAM は残ります）

### 3.3 割り込み

| 線 | mie / mip のビット | 立つとき | 下りるとき |
|---|---|---|---|
| TIMER | 0 | タイマーの数が比較の値に達した（§4.4） | TCMP か TCTRL に書いたとき |
| KEY | 1 | キーの FIFO が空でない間ずっと | FIFO が空になったとき |
| CARD | 2 | 記憶カードの命令が終わった | カードの STATUS を読むか、次の命令を始めたとき |
| MATH | 3 | 数値演算ユニットの演算が終わった | ユニットの STATUS を読むか、次の演算を始めたとき |
| LINK | 4 | LINK の答えが来た、すぐの誤り、取り消し（§4.8） | LINK の STATUS を読むか、次の SEND |
| BRK | 15 | BRK/ON キー | 取ったとき |

- 割り込みは命令の前に見ます。mstatus.MIE が 1 で、mie と mip の両方に立っている線があれば、**番号の小さい線から**取ります
- 取ると mcause は 0x8000 ＋ 線の番号（TIMER は 0x8000、KEY は 0x8001）、mtval は 0、mepc は次に実行するはずだった命令の番地です。入るのに 2 サイクルかかります
- ハンドラの中（MRET の前）では、割り込みは取りません
- 許可した割り込みが入ったのに mtvec が 0 なら、機械は止まります（`interrupt with no handler`）

### 3.4 BRK

BRK/ON キーは線 15 です。キーの FIFO には入りません。

- **mstatus.MIE や mie に関わらず、命令の前に必ず取ります**（mcause 0x800F）。待つのはハンドラが動いている間だけです
- WFI で眠っていても起きます
- mtvec が 0 なら、機械は止まります（`break`）
- 電源が切れている機械、止まった機械（二重の例外など）では、BRK/ON は再起動です（RAM は残ります）

BRK を取ったあと何をするかは ROM のハンドラが決めます（§3.6）。

### 3.5 WFI

`wfi` は、**mie で許可された線が保留になるまで**眠ります。

- 許可した線がすでに立っていれば、眠らずに次の命令へ進みます
- mstatus.MIE が 0 なら、起きたあと割り込みには入らず、次の命令へ進みます（RISC-V と同じ）。ROM はこの形で、割り込みを使わずにキーを待っています
- 許可していない線では起きません。BRK では必ず起きます
- 眠っている間はサイクルが進まず、ページもループを回しません

ROM が動いているときの状態は、**mstatus.MIE = 0、mie = KEY と CARD**（0x0006）です。だから `wfi` は、キーが押されるかカードが答えると起きます。タイマーで起きたいときは mie に TIMER を足し、終わったら外します（§9.4）。キーが FIFO に残っていると KEY の線が立ったままなので、WFI はすぐ戻ります。待つときは、起きるたびに条件を確かめるループにしてください。

### 3.6 ROM のトラップハンドラがすること

ROM は起動時に mtvec を自分のハンドラ（`trap`）にします。ハンドラは原因で振り分けます。

| 原因 | ROM がすること |
|---|---|
| ECALL（11） | t0 の番号の ROM サービスを、**ハンドラの外で**動かし、ECALL の次へ戻る（§5.2）。番号が 8 以上ならモニタへ（`FAULT 000B AT 番地`） |
| BRK（0x800F）、BASIC のプログラムや電卓が動いているとき | 印（BRKFLAG）を立ててすぐ戻るだけ。BASIC が文と文の間でそれを見て `BREAK IN 行` と止まる |
| BRK、それ以外のとき | 16 本のレジスタを保存して、モニタで `BREAK AT 番地` |
| EBREAK（3） | レジスタを保存して、モニタで `BREAK AT 番地` |
| ほかの例外、割り込み | レジスタを保存して、モニタで `FAULT 原因 AT 番地` |

BASIC の `CALL` で動いている機械語は「それ以外」です。`CALL` の間、BASIC は印を受け取る側を外すので、BRK は機械語をモニタで止めます（§8.6）。

モニタに落ちるとき（BRK、EBREAK、FAULT）、ROM は LINK の答えを待っている依頼を取り消し（CANCEL）、mie を KEY と CARD に戻します。止まったプログラムの答えが後から RAM に書かれることはありません。

ROM のハンドラは TIMER などの割り込みを受け付けません（`FAULT 8000 AT …` になります）。自分で割り込みを使うときは、mtvec を自分のハンドラに替え、終わったら元に戻します（§9.6）。替えている間は ECALL も BRK も自分のハンドラに来ることに注意してください。

## 4. I/O レジスタ

### 4.1 番地の書き方と一覧

I/O レジスタは FF00–FFFF の**偶数番地の 16 ビット**です。

- バイトで読むと、その番地の側の半分が読めます
- 偶数番地へのバイトの書き込みは、上位 0 の値を書いたことになります。奇数番地へのバイトの書き込みは無視します
- キーの行列（KEYMAT）だけはバイトで読みます

ロード・ストアのオフセットは -8192〜8191 なので、`lw t0, 0xff20(zero)` は書けません（アセンブラが誤りにします）。**番地 − 0x10000 の負の数を、zero からのオフセットにする**と 1 命令で届きます。ROM 自身もこの書き方です。

```asm
LCD_WIDTH = -0xe0           ; FF20
        lw   t0, LCD_WIDTH(zero)
        li   t1, 0xff20     ; li なら番地そのままでもよい
        lw   t2, 0(t1)
```

| 番地 | オフセット | 名前 | 読み書き | 中身 |
|---|---|---|---|---|
| FF00 | -0x100 | ID | 読み | 0xE016 |
| FF02 | -0xFE | MODEL | 読み | 0 POCKET-32、1 POCKET-48、2 POCKET-64、3 HANDHELD-160 |
| FF04 | -0xFC | BANK | 読み書き | C000–DFFF に出す ROM のバンク（0〜11。12 以上は無視） |
| FF06 | -0xFA | POWER | 書き | 0 を書くと電源が切れる（RAM は残る。BRK/ON で再起動） |
| FF10 | -0xF0 | KEYDATA | 読み | FIFO の先頭のキーコードを取り出す（空なら 0xFFFF） |
| FF12 | -0xEE | KEYCOUNT | 読み | FIFO にあるキーの数（16 まで） |
| FF14–FF1D | -0xEC〜 | KEYMAT | 読み | 押されているキーの行列、10 行 × 8 ビット（バイトで読む） |
| FF20 | -0xE0 | WIDTH | 読み | 液晶の幅（ドット） |
| FF22 | -0xDE | HEIGHT | 読み | 液晶の高さ（ドット） |
| FF24 | -0xDC | DEPTH | 読み | 1 ドットのビット数（1、HANDHELD-160 は 2） |
| FF26 | -0xDA | LCDCTRL | 読み書き | ビット 0: 表示 |
| FF28 | -0xD8 | CONTRAST | 読み書き | 0〜15 |
| FF2A | -0xD6 | CURSOR | 読み書き | カーソルの位置: 下位バイトが桁、上位バイトが行 |
| FF2C | -0xD4 | CURMODE | 読み書き | 0 なし、1 下線、2 ブロック、+4 で点滅 |
| FF2E | -0xD2 | ANNUN | 読み書き | 表示記号のビット（§4.2） |
| FF30 | -0xD0 | TCOUNT | 読み | 1,024 Hz で進む 16 ビットのカウンタ |
| FF32 | -0xCE | TCMP | 読み書き | 比較の値。書くと保留が下りる |
| FF34 | -0xCC | TCTRL | 読み書き | ビット 0: 一致で TIMER を上げる、ビット 1（読み）: 保留。書くと保留が下りる |
| FF38–FF3E | -0xC8〜 | CLOCK | 読み | 時計（バイトで読む。§4.4） |

| FF42 | -0xBE | DUR | 読み書き | ブザーの長さ（ms）。書いた時から鳴る |

| FF70–FF7E | -0x90〜 | LINK | | main のサービス（AI）を呼ぶ口（§4.8） |

### 4.2 液晶と VRAM

VRAM は E000 から、モデルの画面の大きさの分だけ使います。

| モデル | 画面 | 文字 | VRAM |
|---|---|---|---|
| POCKET-32 | 240×32、1 ビット | 40 桁 4 行 | 960 B（E000–E3BF） |
| POCKET-48（既定） | 240×48、1 ビット | 40 桁 6 行 | 1,440 B（E000–E59F） |
| POCKET-64 | 240×64、1 ビット | 40 桁 8 行 | 1,920 B（E000–E77F） |
| HANDHELD-160 | 160×144、4 階調 | 26 桁 18 行 | 5,760 B（面 2 枚） |

**並び**: 1 バイトは縦に並んだ 8 ドットで、ビット 0 が上です。点 (x, y) は

```text
番地   = 0xE000 + (y >> 3) * 幅 + x
ビット = y & 7
```

文字の行（8 ドット）が幅バイトの帯 1 本で、文字 1 つ（6×8 ドット）は 6 バイトです。ROM のフォントは 5×7 で、6 バイト目は空けます。

**4 階調**（DEPTH = 2）では、同じ並びの面が 2 枚あります。1 枚目（E000 から）が下位ビット、2 枚目（E000 ＋ 幅 × 高さ ÷ 8 から）が上位ビットで、0〜3 の値になり、3 が一番濃い色です。ROM の文字は両方の面に書きます。

- 画面の外（窓の残り）への書き込みは無視されます
- 画面の大きさは決め打ちせず、WIDTH、HEIGHT、DEPTH を読んでください（同梱の ASM DEMO もそうしています）
- カーソルは CURSOR と CURMODE で液晶が描きます（点滅もページが描くので、CPU は起きなくてかまいません）。ROM の PUTC はカーソルの位置を CURSOR に書きます
- **ANNUN** のビット: 0 BUSY、1 SHIFT、2 CAPS、3 KANA、4 RUN、5 PRO、6 MON、7 DEG、8 RAD、9 GRAD、10 SOUND。ROM はキーを読むたびにこのレジスタを書き直します

### 4.3 キー

キーのコードは、行列の **行 × 8 ＋ 列**（0〜79）です。BRK/ON は行列に入りません（線 15）。

| 行 | 列 0〜7 |
|---|---|
| 0 | ↑ ↓ ← → SPACE ENTER SHIFT ANS |
| 1 | MODE CLS CAPS カナ INS DEL BS |
| 2 | Q W E R T Y U I |
| 3 | O P A S D F G H |
| 4 | J K L ; Z X C V |
| 5 | B N M , . / |
| 6 | 0 1 2 3 4 5 6 7 |
| 7 | 8 9 ( ) + - * /（テンキー） |
| 8 | .（テンキー） = |

- **KEYDATA**（FF10）をワードで読むと、FIFO の先頭のコードを取り出します（空なら 0xFFFF）。取り出すのは FF10 を読んだときだけで、FF11 をバイトで読んでも取り出しません。モニタの `D FF10` もキーを取り出します
- **KEYCOUNT**（FF12）は待っているキーの数です。FIFO は 16 個で、あふれた分は捨てます
- **KEYMAT**（FF14–FF1D）は、押し続けているキーです。行 r のバイトのビット c が、コード r × 8 ＋ c のキーです。ゲームで「押している間」を見るのに使います（例: `lbu t0, -0xec(zero)` で行 0 の矢印、SPACE、ENTER など）

文字が欲しいときは、ROM サービスの GETKEY（§5.3）を使うと、SHIFT、CAPS、カナを ROM が処理した文字が返ります。

### 4.4 タイマーと時計

**タイマー**は、ホストの時刻で 1 秒に 1,024 回進む 16 ビットのカウンタ TCOUNT です（約 64 秒で一周）。

- TCTRL のビット 0 を立てると、TCOUNT が TCMP の値に達したときに保留（TCTRL のビット 1）が立ち、TIMER の線が上がります
- TCMP か TCTRL に書くと、保留は下ります
- TCMP が今の TCOUNT と同じなら、達するのは一周後（65,536 カウント後）です
- 待ち方の例は §9.4

**時計**（CLOCK）はバイトで読みます。ページが渡すホストの時刻です。

| 番地 | オフセット | 中身 |
|---|---|---|
| FF38 | -0xC8 | 秒 |
| FF39 | -0xC7 | 分 |
| FF3A | -0xC6 | 時 |
| FF3B | -0xC5 | 日 |
| FF3C | -0xC4 | 月 |
| FF3D | -0xC3 | 年 − 2000 |
| FF3E | -0xC2 | 曜日（0 日曜〜6 土曜） |

### 4.5 ブザー

FREQ に周波数（Hz）を書いてから DUR に長さ（ms）を書くと、その時から鳴ります。GATE のビット 0 を立てている間は鳴り続けます。音はページの矩形波で、インターフェースの音が切れているときは鳴りません。鳴り終わるのを待つ仕組みはないので、待つならタイマーで待ちます。

### 4.6 数値演算ユニット

10 進浮動小数点（仮数 12 桁、指数 -99〜99）の演算をする装置です。RAM の上の 8 バイトの数を扱います。BASIC の数はすべてこれで計算しています。

**数の形（8 バイト）**: 符号のバイト（ビット 7 が負。ほかのビットは 0）、指数（符号付きバイト、-99〜99）、BCD の 12 桁（6 バイト、先頭の桁は 0 でない）。値は d1.d2…d12 × 10^指数 です。0 は 8 バイトとも 0 です。

| 番地 | オフセット | 名前 | 中身 |
|---|---|---|---|
| FF50 | -0xB0 | OP | 書くと演算を始め、その命令の中で終わる |
| FF52 | -0xAE | A | 数の番地。結果もここに書く |
| FF54 | -0xAC | B | 2 つ目の数、または文字列の番地 |
| FF56 | -0xAA | ARG | 整数の出し入れ、文字列の長さ |
| FF58 | -0xA8 | STATUS | 直前の演算の誤り（読むと MATH の線が下りる） |
| FF5A | -0xA6 | RESULT | CMP の答え（-1 / 0 / 1） |
| FF5C | -0xA4 | ANGLE | 0 DEG、1 RAD、2 GRAD |

| OP | 演算 | サイクル |
|---|---|---|
| 0x01〜0x05 | ADD SUB MUL DIV POW: A = A op B | 60 / 60 / 120 / 250 / 3000 |
| 0x06 | CMP: RESULT = A と B の比較 | 30 |
| 0x07 | MOVE: A = B | 16 |
| 0x08 | IDIV: A = A ÷ B を 0 の方へ切り捨てた整数（割り算をせずに正確に。12 桁を越える商は丸める） | 250 |
| 0x09 | MOD: A = A − (A IDIV B) × B（余り。符号は A と同じ。正確） | 250 |
| 0x10〜0x15 | NEG ABS INT FRAC SGN SQR（A をその場で） | 16〜400 |
| 0x16〜0x1B | SIN COS TAN ASN ACS ATN（ANGLE の単位） | 2000〜2400 |
| 0x1C〜0x1E | LN LOG EXP | 1800 |
| 0x1F | RND: A = 0 以上 1 未満の乱数 | 100 |
| 0x20 | PI: A = π | 16 |
| 0x30 | FROMINT: A = ARG（符号付き 16 ビットの整数として） | 30 |
| 0x31 | TOINT: ARG = A の整数部（-32768〜32767、外れるとあふれ） | 30 |
| 0x32 | TOWORD: ARG = A の整数部（-32768〜65535 を 16 ビットに。番地用） | 30 |
| 0x38 | PARSE: B の文字（ARG 文字まで）を数にして A へ。ARG に読んだ文字数（読めなければ 0） | 40 |
| 0x39 | FORMAT: A を B に文字で書く。ARG に有効桁数を入れ（0 で 10 桁）、終わると ARG に書いた長さ。0 で終わらない | 200 |

STATUS: 0 なし、1 あふれ、2 0 での割り算、3 関数の引数、4 数でないバイト、5 RAM の外、6 知らない演算。

- 演算は OP に書いた命令の中で終わり、そのサイクルが命令に足されます。終われば MATH の線が上がりますが、待つ必要はありません
- 数の番地は RAM（0000–7FFF）の中でなければなりません
- 使い方の例は §9.3

### 4.7 記憶カード

ユニットの記憶カードの、名前付きのファイルを読み書きします。カードの中身は elecdex の main が持ち、機械はその答えを待ちます。

| 番地 | オフセット | 名前 | 中身 |
|---|---|---|---|
| FF60 | -0xA0 | CMD | 書くと命令を始める: 1 DIR、2 READ、3 WRITE、4 DELETE、5 RENAME、6 FREE |
| FF62 | -0x9E | BLOCK | 命令ブロック（RAM の 32 バイト）の番地 |
| FF64 | -0x9C | STATUS | 0 済み、1 BUSY、2 ファイルがない、3 名前が正しくない、4 FULL、5 RAM の外、6 知らない命令、7 INTERRUPTED、8 同じ名前がある、9 カードがない。読むと CARD の線が下りる |
| FF66 / FF68 | -0x9A / -0x98 | RESULT | 32 ビットの数（下位 / 上位）: 読み書きしたバイト数、ファイルの数（DIR）、空き（FREE） |

命令ブロック（32 バイト）:

| 位置 | 中身 |
|---|---|
| 0–11 | 名前（0 で終わる）。8 文字＋`.`＋3 文字までの英大文字と数字 |
| 12–23 | 新しい名前（RENAME のとき） |
| 24 | ファイルの中の位置（ワード）。WRITE で 0 はファイルを書き直し、それより後は上書きして伸ばす、0xFFFF は終わりに足す |
| 26 | RAM の番地（ワード） |
| 28 | 長さ（ワード） |

- READ は位置から長さ分を RAM へ、WRITE は RAM の長さ分をファイルへ書きます。DIR は 1 ファイル 16 バイト（名前 12、大きさ 2、空き 2）を長さに入るだけ書き、RESULT はファイルの総数です。DIR の名前を `SOFT` にすると、同梱ソフトの一覧になります
- 名前やブロックの範囲がおかしければ、すぐに STATUS が誤りになります。通れば STATUS は BUSY（1）になり、答えが来ると変わります。**BUSY の間は WFI で待ちます**（ROM は mie に CARD を入れてあるので、答えで起きます）
- カードの容量は 256 KB、1 ファイル 32 KB までです
- 例は §9.5

### 4.8 LINK（AI に聞く）

LINK は、elecdex の main が持つサービスを番号で呼ぶ口です。今あるのはサービス 0、**AI**（設定の AI のプロバイダが答える）と、サービス 1、**CART**（ゲーム機 PLAY-320 のカートリッジ。[elec16-play.md](elec16-play.md) §7）です。機械は問いを RAM に置いて SEND し、答えは指定した RAM に届きます。ネットワークにつなぐのは elecdex で、機械とページは直接話しません。AI を使う前に、PANEL の LINK で LINK と AI を ON にし、プロバイダを選びます（LINK 全体は既定で ON、AI は既定で OFF、CART は既定で ON）（[BASIC 取扱説明書](elec16-basic.md) §15）。

| 番地 | オフセット | 名前 | 中身 |
|---|---|---|---|
| FF70 | -0x90 | CMD | 書くと始める: 1 SEND（聞く）、2 NEW（次の SEND から新しい会話）、3 CANCEL（待っている依頼を取り消す） |
| FF72 | -0x8E | SERVICE | サービスの番号（下位 8 ビット）。0 AI（ほかは NO SERVICE） |
| FF74 | -0x8C | TYPE | サービスの中の種類（下位 8 ビット）。AI は答え方のタイプ 0〜10（BASIC 取扱説明書 §15.4 の表） |
| FF76 | -0x8A | QUERY | 問いの番地。0 で終わる 1〜255 バイト |
| FF78 | -0x88 | REPLY | 答えを置く番地。MAX ＋ 1 バイト要る（答えの後に 0 が付く） |
| FF7A | -0x86 | MAX | 答えの最大バイト数（1〜255） |
| FF7C | -0x84 | STATUS | 0 READY、1 BUSY、2 OFF、3 HELD、4 FAILED、5 BAD REQUEST、6 INTERRUPTED、7 CANCELLED、8 NO SERVICE。読むと LINK の線が下りる |
| FF7E | -0x82 | LENGTH | 答えのバイト数 |

- SEND の時に、サービス、タイプ、MAX、番地の範囲、問いの終わりの 0 を確かめます。おかしければすぐに STATUS が誤り（BAD REQUEST、NO SERVICE）になり、LINK の線が上がります。通れば BUSY になり、答えが来ると READY（または誤り）になって線が上がります。BUSY の間の SEND は無視します。答えは SEND の時の REPLY と MAX のとおりに書きます（待つ間に REPLY や MAX を書き換えても、確かめた範囲の外には書きません）
- **HELD**: SEND は、前の SEND の後に人の操作（機械のキー、BRK/ON、RESET、PANEL の RUN ▸ と LOAD ▸）があったときだけ通ります。なければすぐに HELD です。プログラムが勝手に送り続けることはできません
- 答えは液晶の文字（ASCII と半角カナ）だけで、制御文字は入りません。問いに半角カナの文字があればカナで、なければ英語で答えます（TRANS は逆）
- **会話**: AI は直近 10 往復を覚えます。NEW、TYPE や SERVICE を変えたとき、RESET、電源 OFF で新しい会話になります
- CANCEL、RESET、電源 OFF は待っている依頼を取り消します（STATUS は CANCELLED）。取り消した依頼の答えは、後から来ても RAM に書きません
- BUSY のまま機械がしまわれる（ペインを隠す、閉じる）と、戻ったときは INTERRUPTED です
- 答えを待つ時間は 180 秒（3 分）までです。過ぎると FAILED です
- 答えは数秒かかることがあります。**BUSY の間は WFI で待ちます**（mie に LINK を足し、終わったら戻す）。ふつうは ROM サービス 8（§5.3）を使えば、待つところまでしてくれます

自分で待つ例です。サービス 8 と同じことを、レジスタで書いています。

```asm
; AI に聞いて、答えを出す（LINK を直接使う）
        la   t0, question
        sw   t0, -0x8a(zero)     ; QUERY
        li   t0, 0x7200
        sw   t0, -0x88(zero)     ; REPLY
        li   t0, 100
        sw   t0, -0x86(zero)     ; MAX
        sw   zero, -0x8e(zero)   ; SERVICE 0: AI
        sw   zero, -0x8c(zero)   ; TYPE 0: NORMAL
        csrr t2, mie
        li   t0, 16              ; LINK の線（csrsi は 15 まで）
        or   t0, t0, t2
        csrw mie, t0
        li   t0, 1
        sw   t0, -0x90(zero)     ; SEND
wait:   lw   t0, -0x84(zero)     ; STATUS（読むと線が下りる）
        li   t1, 1
        bne  t0, t1, done        ; BUSY でなくなった
        wfi
        j    wait
done:   csrw mie, t2
        bnez t0, failed
        li   a0, 0x7200
        li   t0, 1               ; PUTS
        ecall
failed: ret
question: .asciz "WHAT IS A PULSAR?"
```

## 5. 呼び出しの約束と ROM サービス

### 5.1 呼び出し規約

ROM、BASIC（e16c）、CODE 画面の出力は、同じ約束で呼び合います。

- 引数は a0〜a3、戻り値は a0
- **a0–a3 と t0–t3 は、呼ばれた側が壊してよい**。呼ぶ側は、呼んだ後も要る値を s0–s3 かスタックに置く
- **s0–s3、sp、gp は呼ばれた側が守る**。使うなら入口でスタックに積み、戻る前に戻す
- ra は戻り番地。関数を呼ぶ関数は、入口で ra をスタックに積む
- スタックは下へ伸び、sp は偶数に保つ（ワードの読み書きのため）
- 呼ぶのは `call 先`（`jal ra, 先`）、戻るのは `ret`（`jalr zero, 0(ra)`）

### 5.2 ROM サービスの呼び方

ROM は 9 つのサービスを持ちます。呼び方は 2 通りです。

**ECALL**: t0 にサービスの番号を入れて `ecall`。

```asm
        li   a0, 'A'
        li   t0, 0          ; PUTC
        ecall               ; ra は変わらない
```

- ECALL で変わってよいのは **a0–a3 と t0–t3** です。**ra も s0–s3 も sp も変わりません**
- サービスはトラップのハンドラの外で動くので、キーを待っている間も BRK が効きます
- 番号が 9 以上なら、モニタに落ちます（`FAULT 000B AT ECALL の番地`）
- mtvec を自分のハンドラに替えている間は、ECALL はそちらに行きます

**表を呼ぶ**: 8010 から 4 バイトおきに、各サービスへのジャンプが並んでいます。サービス n は `call 0x8010 + 4 * n` で呼べます。

```asm
        addi sp, sp, -2
        sw   ra, 0(sp)      ; call は ra を書くので、先に積む
        la   a0, msg
        call 0x8014         ; 1 PUTS
        lw   ra, 0(sp)
        addi sp, sp, 2
        ret
msg:    .asciz "VIA TABLE"
```

- ECALL より速く（トラップを通らない）、ふつうの関数呼び出しと同じ約束です。**ra が変わる**ので、自分が戻るための ra は先に積んでおきます
- 7000 からなら 8010 まで 2 KB を越えるので、`call` は 4 バイトの JAL になります

### 5.3 サービスの一覧

| 番号 | 表の番地 | 名前 | 入力 | 出力・動作 |
|---|---|---|---|---|
| 0 | 8010 | PUTC | a0: 文字 | カーソルに 1 文字書いて進める（下の表） |
| 1 | 8014 | PUTS | a0: 0 で終わる文字列の番地 | 文字列を PUTC で書く |
| 2 | 8018 | GETKEY | | a0: 次のキーの文字。来るまで WFI で待つ |
| 3 | 801C | CLS | | 画面を消し、カーソルを左上へ |
| 4 | 8020 | LOCATE | a0: 桁、a1: 行 | カーソルを動かす（画面の中に収める） |
| 5 | 8024 | PUTHEX | a0: ワード | 16 進 4 桁で書く |
| 6 | 8028 | NEWLINE | | 次の行の頭へ。最下行なら画面を 1 行送る |
| 7 | 802C | READLINE | a0: バッファ、a1: 最大の文字数 | a0: 打った文字数。文字は 0 で終わる |
| 8 | 8030 | LINK | a0: 問い、a1: 答えの置き場、a2: 最大バイト数、a3: サービス × 256 ＋ タイプ | a0: 答えの長さ（負なら -STATUS）、a1: 答えの番地。答えまで WFI で待つ（下） |

**PUTC** の文字:

| a0 | 動作 |
|---|---|
| 0x20 以上 | その文字を書いて右へ。行の端で次の行へ、最下行の後は画面を送る |
| 0x0D（ENTER）、0x0A | 改行 |
| 0x08（BS） | 1 つ戻って消す（行の頭なら前の行の端へ） |
| 0x0C（CLS） | 画面を消す |
| ほかの 0x20 未満 | 何もしない |

文字セットは 20–7E が ASCII、A1–DF が半角カナ、80–9F と E0–FF が独自の記号です。

**GETKEY** が返す文字: 英字（CAPS と SHIFT で大小）、数字、記号、カナ（KANA モード）、SPACE（0x20）と次の制御文字です。SHIFT、CAPS、カナのキーは ROM がモードとして処理し、文字としては返しません。

| 文字 | キー | 文字 | キー |
|---|---|---|---|
| 0x03 | BRK（BASIC が機械を持っているとき） | 0x10 | MODE |
| 0x08 | BS | 0x14 | ANS |
| 0x0C | CLS | 0x1C / 0x1D | ← / → |
| 0x0D | ENTER | 0x1E / 0x1F | ↑ / ↓ |
| 0x0E / 0x0F | INS / DEL | | |

**READLINE** は、打った文字を画面に出しながら 1 行を読みます（点滅するブロックのカーソル）。BS で消せます。バッファには a1 ＋ 1 バイト（終わりの 0 の分）を用意してください。a0 は ENTER なら文字数、CLS なら -1（画面を消して行を捨てる）、BRK なら -2（BASIC が機械を持っているとき）、MODE なら -3 です。

**LINK** は §4.8 のデバイスで問いを送り、答えが来るまで WFI で眠ります。答えは a1 の番地に 0 で終わる文字列で入り、a0 はその長さです。答えがなければ a0 は -STATUS です（-2 OFF、-3 HELD、-4 FAILED、-5 BAD REQUEST、-6 INTERRUPTED、-7 CANCELLED、-8 NO SERVICE）。BASIC が機械を持っているとき（`ASK`）の BRK は依頼を取り消して -7 を返し、機械語から呼んだときの BRK はモニタに落ちます（依頼は取り消されます）。

```asm
; LINK: AI に辞書を引かせる（タイプ 7 DICT）
        la   a0, word
        li   a1, 0x7200          ; 答えの置き場（81 バイト）
        li   a2, 80
        li   a3, 0 * 256 + 7     ; サービス 0（AI）、タイプ 7（DICT）
        li   t0, 8               ; LINK
        ecall
        bltz a0, failed
        mv   a0, a1              ; a1 = 答えの番地
        li   t0, 1               ; PUTS
        ecall
failed: ret
word:   .asciz "PULSAR"
```

サービスはスタックを数バイト使います。

## 6. アセンブラ

`.asm` の IMPORT と、ROM のビルドと、CODE 画面は、同じアセンブラ（`src/shared/elec16/asm.ts`）を使います。

### 6.1 行の形

```text
ラベル: 命令 オペランド, オペランド ; コメント
```

- コメントは `;` か `//` から行の終わりまで（引用符の中は除く）
- ラベルは行頭に `名前:`。1 行にいくつ並べてもよく、ラベルだけの行も書けます
- 命令の名前、レジスタ名、CSR 名は大文字と小文字を区別しません。ラベルと記号は区別します
- メモリのオペランドは `オフセット(レジスタ)`、オフセット 0 なら `(レジスタ)` だけでも書けます
- 1 つの命令は必ず 1 つの機械語になります
- 命令は偶数番地に置きます（奇数番地なら誤り。データの後は `.align 2` で揃えます）

### 6.2 数と式

| 書き方 | 例 |
|---|---|
| 10 進 | `100`、`1_000` |
| 16 進 | `0x7000`、`0xFF_20` |
| 2 進 | `0b1010_0101` |
| 文字 | `'A'`、`'\n'`（エスケープは `\n` `\r` `\t` `\0` `\\` `\'` `\"`） |
| 記号 | ラベル、`.equ` や `=` で決めた名前 |
| `$` | その行の番地 |

演算子は C と同じ優先順位です（高い順）: 単項の `-` `~` `+`、`*` `/` `%`、`+` `-`、`<<` `>>`、`&`、`^`、`|`。括弧も使えます。`lo(式)` と `hi(式)` は値の下位バイトと上位バイトです。割り算は 0 の方へ切り捨て、0 で割ると誤りです。比較や論理の演算子はありません。

値の範囲は使う所で確かめます: `li` と `la` は -32768〜65535、`.byte` は -128〜255、`.word` は -32768〜65535、I 形とロード・ストアの即値は -8192〜8191 です。

### 6.3 ラベルと記号

- `.` で始まるラベルは**局所ラベル**で、直前の大域ラベルの中だけで通じます。`loop:` の下の `.next:` は `loop.next` という名前になり、別の大域ラベルの下でも `.next` をもう一度使えます
- `名前 = 式` か `.equ 名前, 式` で記号を決めます。後で決まる記号も使えます（アセンブラは何度もパスをくり返して解決します）
- 同じ名前を 2 度決めると誤りです（記号の値の付け直しはできません）

### 6.4 指令

| 指令 | 意味 |
|---|---|
| `.org 式` | 次に置く番地を決める。IMPORT では最初に `.org 0x7000` が置かれる |
| `.byte 値, …` | バイトを並べる。値には文字列 `"…"` も書ける |
| `.word 値, …` | ワードを並べる（下位バイトが先） |
| `.ascii "…", …` | 文字列のバイト（`.byte` と同じ） |
| `.asciz "…"` | 文字列と、終わりの 0 |
| `.space n[, 値]` | n バイト（既定は 0 で埋める） |
| `.align n` | 番地が n の倍数になるまで 0 を置く |
| `.equ 名前, 式` | 記号を決める（`名前 = 式` と同じ） |
| `.option compress` / `nocompress` | 圧縮を入れる / 止める（既定は入れる） |
| `.macro 名前 引数…` 〜 `.endm` | マクロ（§6.7） |
| `.include "ファイル"` | ほかのファイルを読む（ROM のビルドだけ。IMPORT では使えない） |
| `.bank n` | ROM のバンクの窓（C000–DFFF）に置くもののバンク（ROM のビルド用） |

文字列に書けるのは 0x00–0xFF の文字だけです。半角カナ（`ｱ` など）は文字列に書けないので、`.byte 0xB1` のように番号で書きます（A1–DF が半角カナ）。

### 6.5 疑似命令

どれも 1 つの命令になります。

| 疑似命令 | 実際の命令 |
|---|---|
| `nop` | `addi zero, zero, 0`（`c.nop`） |
| `mv rd, rs` | `add rd, zero, rs` |
| `not rd, rs` | `xori rd, rs, -1` |
| `neg rd, rs` | `sub rd, zero, rs` |
| `la rd, 番地` | `li rd, 番地` |
| `j 先` | `jal zero, 先` |
| `jal 先` | `jal ra, 先` |
| `call 先` | `jal ra, 先` |
| `ret` | `jalr zero, 0(ra)` |
| `jr rs` | `jalr zero, 0(rs)` |
| `jalr rs` | `jalr ra, 0(rs)`（`jalr rd, rs` と `jalr rd, rs, imm` も書ける） |
| `beqz rs, 先` / `bnez` | `beq rs, zero, 先` / `bne` |
| `bltz rs, 先` / `bgez` | `blt rs, zero, 先` / `bge` |
| `blez rs, 先` | `bge zero, rs, 先` |
| `bgtz rs, 先` | `blt zero, rs, 先` |
| `bgt a, b, 先` / `ble` | `blt b, a, 先` / `bge b, a, 先` |
| `bgtu a, b, 先` / `bleu` | `bltu b, a, 先` / `bgeu b, a, 先` |
| `seqz rd, rs` | `sltiu rd, rs, 1` |
| `snez rd, rs` | `sltu rd, zero, rs` |
| `csrr rd, csr` | `csrrs rd, csr, zero` |
| `csrw csr, rs` / `csrs` / `csrc` | `csrrw zero, csr, rs` / `csrrs` / `csrrc` |
| `csrwi csr, n` / `csrsi` / `csrci` | `csrrwi zero, csr, n` / `csrrsi` / `csrrci` |

### 6.6 圧縮の自動選択

圧縮が入っていると（既定）、アセンブラは命令ごとに 16 ビット形（§2.10）に入るかを確かめ、入れば 16 ビットにします。

- 分岐とジャンプは、行き先が近ければ短くなります。前の命令が縮んで番地が動くので、アセンブラは大きさと記号が変わらなくなるまでパスをくり返します。縮んだせいで行き先が届かなくなった命令は 32 ビットに戻ります（16 パスを過ぎると大きさは伸びるだけにするので、配置は必ず落ち着きます）
- まだ値の決まらない記号を使う命令は、そのパスでは大きさを変えません
- `.option nocompress` の間は 32 ビット形だけを使います。番地を決めておきたい表（ROM の 8010 の表など）に使います
- `c.` の名前で書いた命令は常に 16 ビットで、入らなければ誤りです

### 6.7 マクロ

```asm
        .macro push reg
        addi sp, sp, -2
        sw   \reg, 0(sp)
        .endm

        .macro pop reg
        lw   \reg, 0(sp)
        addi sp, sp, 2
        .endm

start:  push s0
        li   s0, 1
        pop  s0
        ret
```

- 引数は名前で、本体では `\名前` と書きます。`\@` はマクロを使うたびに違う番号になり、局所ラベルを作るのに使います（`.x\@:`）
- 行頭のラベルは、マクロと同じ名前でもラベルとして扱います
- 入れ子はマクロ 32 段、include 16 段まで。展開は全部で 10 万回、行は 20 万行までです

### 6.8 誤り

誤りは、ファイル名と行番号と理由で返ります。IMPORT のときは、最初の誤りが `Line 行: 理由` の形で返り、カードには何も書きません（行番号は自分のソースの行です）。主な誤り:

| 理由 | 意味 |
|---|---|
| `unknown instruction frob` | 知らない命令 |
| `"q9" is not a register` | レジスタでないもの |
| `a1 is a register where a value was wanted` | 値の欄にレジスタ |
| `addi takes an immediate from -8192 to 8191` | 即値が入らない |
| `c.addi does not fit 16 bits` | `c.` 形に入らない |
| `undefined symbol nowhere` | 決まらない記号 |
| `x is defined twice` | 同じ名前を 2 度 |
| `an instruction at an odd address` | 奇数番地の命令 |
| `overlaps what is already at 0x7000` | 同じ番地に 2 度書いた |
| `"ｱ" is not in the character set` | 文字列に書けない文字 |

誤りのある命令もその場所を取るので、後ろの番地はずれません。

## 7. モニタ

### 7.1 入り方と戻り方

- BASIC で **`MON`** と打つと、モニタに入ります。画面に `ELEC-16 MONITOR 0.1` と出て、プロンプト `*` になります。表示記号は MON です
- 機械語が EBREAK や例外で止まったときも、モニタに落ちます（BASIC の `CALL` から動かしたものも）
- **`Q`** で BASIC に戻ります。プログラムはそのままです

### 7.2 コマンドの書き方

- 1 行に 1 つ。コマンドは 1 文字で、大文字でも小文字でもかまいません
- 数は 16 進で、4 桁まで（`7000`、`e000`）。5 桁以上、16 進でない文字（`12ZZ`）、空白で区切られていない数は `?` になります
- 1 行は 62 文字まで。画面の幅より長い行は下の行へ続きます
- BS で 1 文字消し、CLS で画面を消して行を捨てます
- 知らないコマンドや誤りには `?` と答えます

| コマンド | 意味 |
|---|---|
| `D [番地]` | ダンプ |
| `E 番地 バイト …` | RAM と VRAM へ書く |
| `G 番地` | 機械語を呼ぶ（RET で戻る） |
| `U [番地]` | 逆アセンブル |
| `B [番地]` | ブレークポイントを置く / 外す / 一覧 |
| `R` | 最後に止まったときのレジスタ |
| `H` か `?` | コマンドの一覧 |
| `Q` | BASIC へ戻る |

### 7.3 D（ダンプ）

`D 番地` は、その番地から画面の行数 − 1 行を出します。1 行は番地、8 バイト、その文字（20–7E 以外は `.`）です。幅の狭い画面（HANDHELD-160）では 1 行 4 バイトです。`D` だけなら前の続きから出します。

```text
*D 7000
7000: F1 05 00 78 1F 0E 02 00 ...x....
7008: C2 04 05 10 27 00 00 00 ....'...
7010: 09 18 1F DC 02 00 93 0C ........
7018: E3 FF 00 58 11 04 02 21 ...X...!
7020: 00 00 00 00 00 00 00 00 ........
*
```

どの番地も読めます。I/O は CPU が読むのと同じに読むので、`D FF10` は FIFO のキーを 1 つ取り出します。

### 7.4 E（書き込み）

`E 番地 バイト バイト …` は、番地から順にバイトを書きます。バイトは 16 進 2 桁までです。

```text
*E 7000 F1 05 00 78 1F 0E 02 00
*
```

- 書けるのは RAM（0000–7FFF）と VRAM（E000–F7FF）です。ROM、予約域、I/O に当たると `?READ ONLY` と言って止まります
- 行全体を先に確かめてから書くので、誤りのある行（`E 7000 12345` など）は何も書きません
- 1 行 62 文字までなので、1 回に書けるのは 18 バイトまでです
- 0000–07FF は ROM と BASIC の作業域です。書くと BASIC やモニタが壊れることがあります

### 7.5 G（実行）

`G 番地` は、番地の機械語を `jalr ra` で呼びます。プログラムが `ret` で戻ると、プロンプトに戻ります。

```text
*G 7000
ABCDEFGHIJKLMNOPQRSTUVWXYZ
*
```

- 呼ぶときは a0 = 番地、sp = 8000、ra = モニタへの戻り番地です。**ほかのレジスタは決まっていません**（R の値に戻すのではありません）
- 置いてあるブレークポイントは、動いている間だけコードに書き込まれます（§7.7）

### 7.6 U（逆アセンブル）

`U 番地` は、画面の行数 − 1 個の命令を、アセンブラがそのまま読める形で出します。`U` だけなら続きから出します。

```text
*U 7000
7000 c.addi sp, -2
7002 c.swsp s0, 0
7004 li s0, 0x0041
7008 c.mv a0, s0
700A c.li t0, 0
*U
700C ecall
7010 c.addi s0, 1
7012 li t0, 0x005B
7016 bne s0, t0, 0x7008
701A c.lwsp s0, 0
*
```

- 16 ビットの形は `c.` の名前で出ます（アセンブラに書けば同じバイトになります）
- 分岐とジャンプの行き先は番地で、LI と AUIPC の値は `0x` の 4 桁で出ます
- 不正な命令は `.word ?`（16 ビット）か `.word ?, ?`（32 ビット）です

### 7.7 B（ブレークポイント）

`B 番地` は、その番地にブレークポイントを置きます。同じ番地にもう一度打つと外れます。`B` だけなら一覧（なければ `NO BREAKPOINTS`）を出します。4 つまで置けます。

```text
*B 700C
700C
*G 7000
BREAK AT 700C
*B
700C
*B 700C
NO BREAKPOINTS
*
```

- 置けるのは RAM の 0800–7FFF の偶数の番地（命令の先頭）だけです。奇数の番地、ほかの番地、5 つ目は `?` です
- 仕組み: `G` が動かす前に、各ブレークポイントの 2 バイトを `C.EBREAK`（0x200A）に書き換え、モニタに戻るすべての道（RET、BREAK、FAULT）で元に戻します。**`G` の行き先そのものには書きません**。だから止まった番地から `G` し直すと、その命令から動き出します
- 書き換えるのは `G` で動かしたときだけです。BASIC の `CALL` で動かしたコードでは止まりません
- ペインの CORE にも別のブレークポイントがあります。こちらは機械のコードを書き換えず、どの道で動かしても止まります

### 7.8 R（レジスタ）

`R` は、最後に止まったとき（BREAK、FAULT、モニタに落ちた BRK）の 16 本のレジスタを出します。広い画面では 1 行 4 本、狭い画面では 3 本です。

```text
*R
PC=700C RA=85EC SP=7FFE GP=0000
A0=0041 A1=0004 A2=7000 A3=00F0
T0=0000 T1=0027 T2=0000 T3=0000
S0=0041 S1=7000 S2=0003 S3=0046
*
```

PC は止まった命令の番地です。RA などの値は ROM の中の番地のこともあります。

### 7.9 止まったときの表示

| 表示 | 意味 |
|---|---|
| `BREAK AT 番地` | EBREAK かブレークポイント（番地はその命令）、または BRK（番地は次に実行するはずだった命令）で止まった |
| `FAULT 原因 AT 番地` | 例外か、ROM が受け付けない割り込み。原因は mcause の 16 進 4 桁 |

| 原因 | 意味 |
|---|---|
| `0002` | 不正な命令（0 のメモリに飛び込んだときも） |
| `0004` | ワードの読みが奇数番地 |
| `0006` | ワードの書きが奇数番地 |
| `0007` | ROM への書き込み |
| `000B` | ない番号の ECALL（t0 が 8 以上） |
| `8000`〜`8003` | 自分で許可した割り込み（ROM のハンドラは扱わない） |

モニタ自身のプロンプトで BRK を押すと、打ちかけの行を捨てて新しいプロンプトを出すだけです。BRK は掛かっている SHIFT も外します。

### 7.10 続きから動かすときの注意

`G` は「呼ぶ」命令で、R の値を戻しません。ブレークポイントで止まった番地から `G` すると、その命令から動き出しますが、レジスタは止まったときの値ではなく、スタックも 8000 からになります。ループの途中などで続けると、正しく動かないことがあります（§9.7 の例をブレークポイントの 700C から `G 700C` で続けると、s0 とスタックが違うので文字が狂い、最後は FAULT になります）。止めて調べたいところは、プログラムの頭から `G` し直すか、CORE のブレークポイントと STEP を使ってください。

## 8. プログラムを置いて動かす

### 8.1 機械語の領域

自分の機械語は **7000–7BFF（3 KB）** に置きます。BASIC のプログラムと変数はこの下（7000 の手前）で止まり、スタックはこの上（8000 から下へ）です。境は動きません。RAM は電池で保たれるので、置いた機械語は電源を切っても残り、何度でも動かせます。

### 8.2 モニタで打ち込む

1. PC のアセンブラ（この手引きのアセンブラと同じもの）か手で、バイト列を作る
2. `MON` でモニタに入り、`E 7000 …` で 8〜18 バイトずつ書く
3. `U 7000` で確かめ、`G 7000` で動かす

### 8.3 .asm を記憶カードに IMPORT する

FILES の IMPORT で `.asm`（または `.s`）を選ぶと、main がアセンブラで機械語にし、`名前.BIN` としてカードに書きます。

- ソースの前に `.org 0x7000` が置かれます。自分で `.org 0x7000` を書いてもかまいません
- `.include` は使えません。1 つのファイルに書きます
- 誤りがあると `Line 行: 理由` と出て、何も書きません
- できたバイト列は 7000–7BFF（3 KB）に収まらなければなりません。越えると IMPORT が「It ends at …: the code area is 7000–7BFF.」と断ります（BASIC の `LOAD` が読むのは 7BFF までのため）
- ソースのファイル名から、8＋3 文字の英大文字と数字の名前（`ASMDEMO.BIN` など）になります

動かすのは BASIC から:

```text
>LOAD "ASMDEMO.BIN":CALL 28672
```

FILES の **LOAD ▸** で .BIN を選ぶと、この行を打ち込んでくれます。同梱の SOFT CARD にある `ASMDEMO.BIN` が、その見本です（ソースは `resources/elec16/soft/asmdemo.asm`）。

### 8.4 BASIC から

| 文 | 意味 |
|---|---|
| `CALL 番地` | 番地の機械語を呼ぶ。`RET` で BASIC に戻る。`CALL 28672` が 7000 |
| `POKE 番地, 値` / `PEEK(番地)` | 1 バイトを書く / 読む |
| `LOAD "X.BIN"[, 番地]` | カードの機械語を RAM に読む。既定は 7000。プログラムの上と 7C00 の間だけ |
| `SAVE "X.BIN", 番地, 長さ` | RAM のバイトをカードに書く |

番地は -32768〜65535 で書け、負の数は上から数えます（`CALL -4096` は F000）。

`CALL` で呼ばれた機械語は、次の約束を守ってください。

- a0 は呼ばれた番地です
- **s0–s3、sp、gp を守る**（BASIC はこれらに値を置いたまま呼びます）。ra は BASIC への戻り番地なので、関数を呼ぶなら積んでおきます
- スタックは 7C00 まで使えますが、BASIC の分もあるので、深く積みすぎないでください
- EBREAK や例外で止まると、BASIC ではなくモニタに落ちます。`Q` で BASIC に戻れます

### 8.5 CODE 画面の出力を読む

CODE 画面は、TypeScript の部分集合を e16c で E16 アセンブリにします。右の欄に出るのは、この手引きのアセンブラが読む E16 アセンブリです。

- 7000 に入口があり、ra を積んで `e16c_init`（大域変数に最初の値を入れ、配列を 0 にする）と `main` を呼び、`ret` で戻ります。だから `CALL 28672` でも `G 7000` でも動きます
- コードと文字列は 7000–77FF、大域変数と配列は 7800–7BEF です
- 関数名はそのままラベルになります。呼び出しは §5.1 の約束どおりで、引数は a0–a3（4 つまで）、戻り値は a0、局所変数は s0–s3 とスタックです。-O0 では s0 をフレームポインタ（`fp`）に使います
- ライブラリの putc puts getkey cls locate puthex newline は、`li t0, 番号` と `ecall` になります。`memcpy` と `memset` は `mcpy a0, a1, a2` と `mset a0, a1, a2` の 1 命令です
- SAVE TO CARD は選んだ段階を `.BIN` でカードに書きます。**RUN ▸** は機械語を RAM に書いて `CALL 28672` を、**LOAD ▸** は `U 7000` を打ち込みます（CORE でブレークポイントを置いてから動かせます）

### 8.6 止め方の注意（BRK）

**BRK/ON は、どこから動かした機械語でも止めます。** モニタの `G` からでも BASIC の `CALL` からでも、終わらないループの中でも、ROM のサービスでキーを待っていても、レジスタを保存して `BREAK AT 番地` とモニタに落ちます。`R` で止まったときのレジスタを見て、`Q` で BASIC に戻ります（BASIC のプログラムと変数は残っています）。

機械語が `RET` で BASIC に戻ったあとは、BRK はまた BASIC のもので、プログラムを文と文の間で `BREAK IN 行` と止めます。

## 9. 例題

どの例も `.org 0x7000`（IMPORT なら自動で付きます）に置き、BASIC の `CALL 28672` で動かして確かめてあります。

### 9.1 文字列を出す（ECALL）

```asm
; HELLO: ROM サービスで文字列を出す
        .org 0x7000
start:
        la   a0, msg
        li   t0, 1          ; PUTS
        ecall
        li   t0, 6          ; NEWLINE
        ecall
        ret                 ; ECALL は ra を変えないので、積まなくてよい
msg:    .asciz "HELLO, E16"
```

```text
>CALL 28672
HELLO, E16
>
```

アセンブルした結果（左から番地、バイト、ソース）:

```text
7000 1F 92 80 03  la   a0, msg
7004 0D 10        li   t0, 1
7006 27 00 00 00  ecall
700A 35 10        li   t0, 6
700C 27 00 00 00  ecall
7010 02 21        ret
7012 48 45 4C 4C 4F 2C 20 45 31 36 00  msg: .asciz "HELLO, E16"
```

`li t0, 1` は `c.li`、`ret` は `c.jr ra` に圧縮されています。`la a0, msg` は値が大きいので 4 バイトです。

### 9.2 画面を MSET で埋める

画面の大きさを I/O から読み、VRAM 全体を 1 命令で埋めます。キーを押すと画面を消して戻ります。

```asm
; FILL: VRAM を MSET で埋める
        .org 0x7000
WIDTH  = -0xe0              ; FF20
HEIGHT = -0xde              ; FF22
DEPTH  = -0xdc              ; FF24
start:
        lw   t1, WIDTH(zero)
        lw   t2, HEIGHT(zero)
        mul  t1, t1, t2
        srli t1, t1, 3       ; 1 面のバイト数 = 幅 × 高さ ÷ 8
        lw   t2, DEPTH(zero)
        mul  a2, t1, t2      ; 全部の面
        li   a0, 0xe000      ; VRAM
        li   a1, 0x55        ; 1 行おきに点く
        mset a0, a1, a2
        li   t0, 2           ; GETKEY: キーを待つ
        ecall
        li   t0, 3           ; CLS
        ecall
        ret
```

既定の画面（240×48）では 1,440 バイトを 180 回（1 回 8 バイト）で埋め、180 ＋ 1,440 = 1,620 サイクルほどです。プログラムは 48 バイトです。

### 9.3 ループと分岐（1〜100 の和を 10 進で出す）

ループで和を求め、数値演算ユニットで 10 進の文字にして出します。

```asm
; SUM: 1 + 2 + ... + 100 を 10 進で出す
        .org 0x7000
M_OP    = -0xb0             ; FF50
M_A     = -0xae             ; FF52
M_B     = -0xac             ; FF54
M_ARG   = -0xaa             ; FF56
FROMINT = 0x30
FORMAT  = 0x39
start:
        li   a0, 0           ; 和
        li   a1, 1           ; n
        li   a2, 100
.loop:
        add  a0, a0, a1
        addi a1, a1, 1
        bleu a1, a2, .loop   ; n <= 100 の間（bgeu a2, a1, .loop になる）
        ; a0 = 5050 を数値演算ユニットへ入れ、文字にして戻す
        sw   a0, M_ARG(zero)
        la   t1, number
        sw   t1, M_A(zero)
        li   t1, FROMINT
        sw   t1, M_OP(zero)      ; number = 5050
        la   t1, text
        sw   t1, M_B(zero)
        sw   zero, M_ARG(zero)   ; 0: 10 桁
        li   t1, FORMAT
        sw   t1, M_OP(zero)      ; text = "5050"、ARG = 4
        lw   t1, M_ARG(zero)
        la   t2, text
        add  t1, t1, t2
        sb   zero, 0(t1)         ; PUTS のために 0 で終える
        la   a0, text
        li   t0, 1               ; PUTS
        ecall
        li   t0, 6               ; NEWLINE
        ecall
        ret
        .align 2
number: .space 8
text:   .space 16
```

```text
>CALL 28672
5050
>
```

`.loop` は `start` の局所ラベルです。`bleu` は疑似命令で、`bgeu a2, a1, .loop` になります（`bgeu` に圧縮形はないので 4 バイト）。`addi a1, a1, 1` は `c.addi` に、`add a0, a0, a1` は `c.add` になります。FROMINT は ARG を符号付きとして読むので、32767 を越える数を入れるときは工夫が要ります。

### 9.4 タイマーで待って鳴らす

1 秒（1,024 カウント）待ってから、880 Hz を 0.2 秒鳴らします。BASIC の `WAIT` と `BEEP` と同じやり方です。

```asm
; BEEP: 1 秒待って鳴らす
        .org 0x7000
TCOUNT = -0xd0              ; FF30
TCMP   = -0xce              ; FF32
TCTRL  = -0xcc              ; FF34
FREQ   = -0xc0              ; FF40
DUR    = -0xbe              ; FF42
start:
        addi sp, sp, -2
        sw   ra, 0(sp)       ; wait を呼ぶので ra を積む
        li   a0, 1024        ; 1 秒
        call wait
        li   t0, 880
        sw   t0, FREQ(zero)
        li   t0, 200
        sw   t0, DUR(zero)   ; 書いた時から 200 ms 鳴る
        lw   ra, 0(sp)
        addi sp, sp, 2
        ret

; a0 カウント（1/1024 秒）待つ
wait:
        lw   t0, TCOUNT(zero)
        add  t0, t0, a0
        sw   t0, TCMP(zero)
        li   t0, 1
        sw   t0, TCTRL(zero)  ; 一致で保留を立てる
        csrsi mie, 1          ; TIMER でも WFI から起きる
.sleep:
        wfi                   ; MIE は 0 なので、起きたら次へ進むだけ
        lw   t0, TCTRL(zero)
        andi t0, t0, 2        ; 保留が立ったか
        beqz t0, .sleep       ; キーで起きただけなら、もう一度眠る
        sw   zero, TCTRL(zero)
        csrci mie, 1          ; 元に戻す（戻さないとプロンプトでも起きる）
        ret
```

待っている間、機械は WFI で眠っていて、ペインはほとんど CPU を使いません。

### 9.5 記憶カードに書く

`HELLO.DAT` というファイルに 5 バイトを書き、STATUS を 16 進で出します（`0000` なら成功）。

```asm
; CARD: HELLO.DAT に書く
        .org 0x7000
CARD_CMD    = -0xa0         ; FF60
CARD_BLOCK  = -0x9e         ; FF62
CARD_STATUS = -0x9c         ; FF64
WRITE = 3
BUSY  = 1
start:
        la   t1, block
        sw   t1, CARD_BLOCK(zero)
        li   t1, WRITE
        sw   t1, CARD_CMD(zero)
.wait:  lw   a0, CARD_STATUS(zero)
        li   t1, BUSY
        bne  a0, t1, .done
        wfi                  ; 答えが来ると CARD の線で起きる
        j    .wait
.done:  li   t0, 5           ; PUTHEX: STATUS
        ecall
        ret
        .align 2
block:  .asciz "HELLO.DAT"   ; 0: 名前
        .space block + 24 - $ ; 新しい名前の欄（RENAME 用）まで空ける
        .word 0              ; 24: ファイルの中の位置（0 は書き直し）
        .word message        ; 26: RAM の番地
        .word 5              ; 28: 長さ
        .space 2
message: .ascii "HELLO"
```

BASIC で `FILES` と打つと、`HELLO.DAT` が並びます。`.space block + 24 - $` は、`$`（その行の番地）を使ってブロックの 24 バイト目まで埋める書き方です。

### 9.6 タイマーの割り込み

ROM のハンドラは割り込みを扱わないので、mtvec を一時的に自分のハンドラに替えます。1/16 秒ごとの割り込みを 4 回数え、ROM のハンドラに戻してから数を出します。

```asm
; TICKS: タイマーの割り込みを 4 回数える
        .org 0x7000
TCOUNT = -0xd0
TCMP   = -0xce
TCTRL  = -0xcc
start:
        csrr t1, mtvec        ; ROM のハンドラ
        la   t0, handler
        csrw mtvec, t0
        li   a1, 0            ; 数えた回数
        lw   t0, TCOUNT(zero)
        addi t0, t0, 64       ; 64 カウント = 1/16 秒後
        sw   t0, TCMP(zero)
        li   t0, 1
        sw   t0, TCTRL(zero)
        csrrwi t3, mie, 1     ; TIMER だけを許可（ROM の mie は t3 に）
        csrsi mstatus, 8      ; MIE: 割り込みを入れる
.idle:
        wfi                   ; 割り込みまで眠る
        li   t0, 4
        bltu a1, t0, .idle
        csrci mstatus, 8
        csrw mie, t3          ; ROM の mie に戻す
        sw   zero, TCTRL(zero)
        csrw mtvec, t1        ; ROM のハンドラに戻す（ECALL の前に）
        mv   a0, a1
        li   t0, 5            ; PUTHEX
        ecall
        ret
handler:
        addi a1, a1, 1
        lw   t2, TCMP(zero)
        addi t2, t2, 64       ; 次の比較の値。TCMP に書くと線が下りる
        sw   t2, TCMP(zero)
        mret
```

```text
>CALL 28672
0004
>
```

- mie は TIMER だけにします。ROM は mie に KEY を入れているので、そのまま MIE を立てると、キーが押されたとき KEY の割り込みがこのハンドラに来ます（しかも FIFO が空になるまで線が下りないので、何度も来ます）
- ハンドラは a1 と t2 を使います。この例ではほかで使わないので積んでいませんが、ふつうは mscratch やスタックに退避します
- mtvec を替えている間は、ECALL も BRK（mcause 0x800F）もこのハンドラに来ます。本当のプログラムでは mcause を見て振り分けてください
- `.idle` の `wfi` で、割り込みを待つ間は眠ります。起きると割り込みに入り、MRET で `wfi` の次に戻ります

### 9.7 モニタでの一連の操作

A〜Z を出すプログラムを、モニタで打ち込んで動かします。ECALL は a0–a3 と t0–t3 を変えるので、数える値は s0 に置き、s0 は守るために積みます。

```asm
; ABC: A から Z を出す
        .org 0x7000
start:  addi sp, sp, -2
        sw   s0, 0(sp)
        li   s0, 'A'
.loop:  mv   a0, s0
        li   t0, 0          ; PUTC
        ecall
        addi s0, s0, 1
        li   t0, 'Z' + 1
        bne  s0, t0, .loop
        lw   s0, 0(sp)
        addi sp, sp, 2
        ret
```
