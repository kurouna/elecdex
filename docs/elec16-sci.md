# ELEC-16 SCI（SCI-128）— 関数電卓モデルの仕様（案）

ELEC-16 の 3 つ目のモデルとして作る関数電卓の仕様です。**設計中**で、利用者と決めながら直します。決まったことは「決まっていること」に移し、理由は [decisions.md](decisions.md) に残します。機械の土台は [elec16.md](elec16.md)、2 つ目のモデルの進め方は [elec16-play.md](elec16-play.md)、操作できるモックは [elec16-sci-mock/index.html](elec16-sci-mock/index.html)（ブラウザで開く。CALC は本当に計算する）にあります。初版へのレビューと、それをどう反映したかは §13 にあります。

## 1. 決まっていること（2026-10-24、利用者の決定）

- ELEC-16 ペインの 3 つ目の「ソリューション」として、**関数電卓**を作る（ポケコン、ゲーム機に続く）
- カシオやシャープの関数電卓を参考にするが、**仮想・オリジナルの機械**にする。実在の機種名、ロゴ、本体のデザイン、キーの並び、機能の商標名を写さない（elec16.md §1 の 2026-10-03 の決定のとおり）
- 次の 9 つは、レビューを反映した版の提案（§12）をそのまま採った（2026-10-24）:
  1. **銘板は ELEC-16 SCI、モデル名は SCI-128、液晶は 128×64 の 1 ビット**
  2. **v1 のモードは CALC・STATS・BASE・TABLE・EQUATION**。CONST と CONV は v2
  3. **数値演算ユニットに §7 の演算を足す**（どのモデルでも使える）。BASIC に関数として出すかは、BASIC を直すときに改めて決める（v1 では出さない）
  4. **本体の色は SLATE・CHALK・PLAIN の 3 つ**。光で描く 5 つのスキンの電卓版は作らない（仕組みは使う）
  5. **CODE の RUN を SCI-128 でも使えるようにする**（PLAY と同じ直接呼び出し。RAM の 7000–7BFF を空けておく）
  6. **キーの並びと言葉は §5.1 と §9 のとおり**（SHIFT 面はそのキーの逆の関数、逆のないものは FUNC）
  7. **記号のない掛け算は × ÷ より強い、小数を打った式は小数で答える、累乗は右から**（§6.3、§6.4）
  8. **式と履歴はモードごとに持ち、モードに戻れば続きから**。変数、Ans、M、SETUP、STATS の表はモードをまたいで残る
  9. **本体は縦長の 1 つだけ**（横長の本体は作らない）
- 液晶の描き方は**今のペインの液晶と同じ**（§4.1。2026-10-24 にモックで見直した）
- 実装の前に決めた 5 つ（2026-10-24、推奨案どおり）:
  10. **電卓はピッカーの別の入口「ELEC-16 SCI」から出す**。選ぶと SCI-128 の新しいユニットを作って開く。TUNE のモデルの切り替えは残し、RAM が消えることを確かめてから替える（§8.1）
  11. **作業の単位**: 設計とモックを先に main に入れ、S1〜S7 は段階ごとにブランチを切って PR でマージする（PLAY-320 の G1〜G7 と同じ）。S2 からは、作業用のブランチを main に rebase し、確認が通ったら main に直接入れる（PR は作らない。2026-10-24、利用者の提案）。段階ごとに CLAUDE.md の「コミットの前に走らせるもの」を通し、全モデルに及ぶ段階（モデルの一覧、表示記号、フォント）はテスト一式を走らせる（§10）
  12. **本番のコードに手を入れてよい**。S1 から始め、段階ごとに何を変えるかを先に短く伝えてから着手する
  13. **公開**: 3 つの README に SCI の画像と説明、紹介ツアーに短いビート 1 つ、取扱説明書は日本語で 1 本。「ELEC-16 SCI」の商標は公開の前に J-PlatPat で確かめる（S7）
  14. **細部は作る段階で決め、この文書に書く**: STATS の標準偏差は母集団（σ）と標本（s）の両方、3 次方程式の解き方と FIND X の打ち切り（回数と精度）はその段階で決める、電源を入れたときは機種名を短く出してから計算の画面へ、打てないときの音は POCKET のブザー

これより下で「案」と書いたものは、作る段階で細部を決める。

## 2. 作れるか（見立て）

**作れます。** ELEC-16 は最初から「モデルのデータで画面と入力を替える」作りで、PLAY-320 がそれを一度通しています。関数電卓に要るものの多くは既にあります。

| 要るもの | 既にあるもの | 足すもの |
|---|---|---|
| 12 桁の 10 進演算 | **数値演算ユニット**（仮数 12 桁、表示 10 桁、指数 ±99、四則と平方根は BigInt で正確、0.1 + 0.2 = 0.3）。関数電卓の内部精度そのもの | 双曲線関数など数個の演算（§7） |
| 電卓の ROM | **e16c**（TypeScript の部分集合 → E16。TypeScript のまま動かして機械と照らすテストの仕組みごと）。BASIC の ROM（式の解析、行の編集、数の書式）が前例 | 電卓の ROM（`rom: 'sci'`）。ここが一番大きい |
| ドット液晶 | 1 ビットの液晶、液晶の描き方（反射型の地、ドットの影、残像）、6×8 の自作フォント | 128×64 の大きさ、記号（§4.3）、大きな数字、縦線のカーソル |
| 鍵盤 | キーの行列（80 キーまで）、FIFO、押した姿、PC のキー | 電卓のキー表と本体の幾何（`sci-body.ts`）、キー表をモデルごとにする |
| 変数と履歴が消えない | 電池バックアップ（スナップショット） | なし（RAM に置けば残る） |
| 待機中の負荷ゼロ | WFI で眠る runner、自動電源 OFF | プロンプトの見分けをモデルの能力にする（§8.1） |
| 本体の見た目 | 光で描くスキンの仕組み（relief、素材、書体、刻印の収め方） | 電卓の本体の色 3 つ（§8.2） |

**難しいところ**:

1. **数式どおりの表示（2D 表示）と、その中を動くカーソル**: 分数・根号・累乗を入れ子に組み、128×64 に描く。e16c で書く組版と編集器が要る。木を RAM の上の印付きの列で持てば（§6.2）、編集は列の挿入と削除で済む。モックで描き方とカーソルの動きを確かめた
2. **答えを分数や √ の形で出す**: 値を `(p + r√s)/q` の 1 つの形で正確に持ち（§6.4）、三角関数の特別な値は表で引く。どちらも ROM の仕事
3. **ROM の大きさ**: 見込みは e16c の -O2 で 40〜60 KB。ROM 全体（固定 16 KB と 12 バンク 96 KB）には収まるが、**固定 ROM は BASIC で満杯に近くなった前例がある**ので、組版と編集も最初から far_call でバンクに置ける作りにする（§6.1）。S3 の終わりに大きさを測り、decisions.md に書く
4. **精度**: 三角・対数・指数は今の演算ユニットと同じく倍精度で計算して 12 桁に丸める。双曲線関数を EXP から組むと 0 の近くで桁が落ちるので、ユニットに足す（§7）

規模は PLAY-320 の G1〜G4 くらい（本体と鍵盤、ROM の骨組み）と、BASIC の前半くらい（電卓の ROM）を足したものと見ています。

## 3. 全体

| 項目 | SCI-128（ELEC-16 SCI） | 参考: POCKET-48 |
|---|---|---|
| CPU | E16（変更なし）。既定 4 MHz、TUNE で変えられる | 同じ |
| RAM | 32 KB（変数、履歴、統計のデータ、表） | 32 KB |
| 画面 | **128×64 ドット、1 ビット**、表示記号 14 個 | 240×48 |
| 数値 | 数値演算ユニット（§7 の演算を足す） | 同じ |
| 入力 | **46 キーと十字キー（4 方向）**、ON（BRK の線）。PC のキー | キーボード |
| ソフト | **電卓の ROM**（CALC、STATS、BASE、TABLE、EQUATION） | BASIC、モニタ |
| 外とのつながり | なし（LINK も記憶カードも使わない） | LINK、記憶カード |
| 起動 | 電源を入れると前の計算の続き（RAM は電池で残る） | BASIC のプロンプト |

- **モデルのデータに足す**（`MODELS` に `sci-128`、MODEL レジスタ FF02 = 5）: `rom: 'sci'`、`keys: 'sci'`（キー表）、`annunciators: 'sci'`（表示記号の組）、`cursor: 'bar'`（縦線のカーソルを持つ）、`prompt: 'key'`（§8.1）。ほかのモデルは今の動きのまま（テストで固定する。PLAY-320 のときと同じ規則）
- 名前はほかのモデルと同じく画面のドット数（幅）で付けた。銘板は「ELEC-16 SCI」（§1）

## 4. 画面

### 4.1 液晶

- **128×64 ドット、1 ビット**。VRAM は E000 からの窓に 1,024 B（今の 1 ビットの並びのまま: 幅 × 8 ページ、1 バイトは縦 8 ドット）。液晶の描き方（`lcd-painter`）と毎秒 30 枚の上限は POCKET と同じ
- 128 は 6×8 の文字で 21 桁 8 行。入力の欄（上）と答えの欄（下）に分ける:
  - **入力の欄**（0〜38 行）: 式を 2D 表示で組む。横にはみ出せば、カーソルが見えるように横に送る。**縦には送らない**: 式の高さが 38 行を越えるテンプレート（分数は 2 段まで入る）は入れられない（打っても入らず、ブザーが短く鳴る）
  - **答えの欄**（40〜63 行）: 右寄せ。小数は**大きな数字**（§4.3）、分数と √ は入力と同じ組版で

**描き方は今のペインの液晶（Lcd.svelte と lcd-painter）そのまま**で、SCI のための描き方は作らない（2026-10-24 に見直した）:

- 機械の解像度（128×64）のキャンバスを、**1 ドットが整数個のデバイスピクセル**になるよう CSS で拡大する（`image-rendering: pixelated`）。大きさは `deviceFit` が部屋から決め、本体のほかの寸法はそこから決まる
- ドットは点いていれば色そのまま（コントラスト 8 で濃さ 1）、消えていれば透明。影は**別のキャンバス**に影の色で描き、ドットの下に `max(2, round(1 ドット / 4) + 1)` デバイスピクセルずらす
- ドットのすき間は、**1 ドットが 3 デバイスピクセル以上のときだけ**、地の色の格子として一度だけ描く。2 以下ならすき間も影もない（くっきりした面）
- 消えたドットは、格子の下に敷いたドットの色の薄い地（`unlit` 0.03）として、格子があるときだけすき間越しに見える。ガラスの反射（`glare`）は左上から真ん中の手前まで。地の色は 1 色のまま
- 液晶の色はスキンのデータと同じ形（`ground`、`dot`、`shadow`、`unlit`、`glare`、PLAIN は `flat`）で、SCI の本体の色ごとに持つ:

| 本体 | ground | dot | shadow | unlit | glare |
|---|---|---|---|---|---|
| SLATE | #c4cbb9 | #161b14 | #a3ab98 | 0.03 | 0.10 |
| CHALK | #cfd3c5 | #191c17 | #aeb2a3 | 0.03 | 0.14 |
| PLAIN | テーマの面 | テーマの文字 | なし | 0 | 0（`flat`: 格子も影もない） |

- 残像（消えるのはゆっくり）とコントラストは TUNE のとおり、POCKET と同じに効く
- 本体が縦長なので、ペインの高さが 1 ドットの大きさを決めることが多い。高さが足りないと 1 ドット 2 デバイスピクセルになり、すき間のない面で描く（読みやすさは変わらない）。大きく見たいときは本体の描き方を COMPACT か LCD にする（§8.2）

**初版のモックがかすんで見えた理由**（2026-10-24、利用者の指摘）: モックは液晶を 1 ドット 3 ピクセルの大きな絵に自分で描き、それを CSS で 0.8 倍に縮めていた（1 ドット 2.4 CSS ピクセル）。縮めるとドットとすき間が混ざってぼやける。さらに、消えたドットを全面に 6% の濃さで描いて格子の網が見え、影を半透明のドットの色で描き、点いたドットも 92% の濃さで、ガラスの反射と周辺の陰を液晶の全面に重ねていた。どれも本番の液晶とは違う描き方で、モックだけの問題。モックを本番と同じ描き方（上の箇条）に直し、1 ドットを整数個のデバイスピクセルにした。実装は今の Lcd.svelte を使うので、この問題は起きない。

### 4.2 表示記号（ANNUN のビット）

液晶の上の 1 列に印刷し、消えているときも薄く見える（POCKET と同じく、消えているときの濃さ 0.16）。SCI の組（印刷は 14 個、ビットは BUSY と合わせて 15）:

ビット 0 は **BUSY**（印刷しない。ポケコンと同じ）、1 から `S`（SHIFT）、`A`（ALPHA）、`M`（独立メモリが 0 でない）、`STO`、`HYP`、`STAT`、`D` `R` `G`（角度）、`FIX`、`EXP`（指数表示）、`2D`（2D 表示）、`▲` `▼`（上下に続きがある）

- 表示記号の組は**モデルのデータ**（`Model.annunciators: 'pocket' | 'sci'`）。今の `ANNUNCIATORS`（state.ts）は 1 つの表で、rom.ts が `ANN_*` として io.inc に出し、Lcd.svelte が描き、pc-keys.ts が KANA と CAPS のランプから PASTE を組む。SCI の表を state.ts に並べ、io.inc には別の接頭辞（`SCI_ANN_*`）で出す。**SCI ではビット 2・3 の意味が違う**ので、PASTE と「カナが点いているか」を SCI では使わない（§5.3）
- **ビット 0 はどの組でも BUSY**: CODE の受け渡し（`widgets/elec16/code/give.ts`）が `ANNUNCIATORS` の BUSY を読み、立っていれば BRK を打ってから書き込む。SCI の表でビット 0 を S にすると、SHIFT が点いているだけの機械に BRK が飛ぶ（2 回目のレビューで分かった）
- 指数表示の記号を `SCI` にしなかったのは、銘板の SCI と紛れるから

### 4.3 文字と数字

- 文字は ELEC-16 の 5×7 のフォントそのまま（`font.ts`）
- **記号を 80–96 に足す**（S1 で済み。`font.ts` の `SYMBOLS`。BASIC からも `CHR$` で出せる）: π × ÷ √ ² ³ ⁻¹ ᴇ ° ′ ″ ▶ ◀ ▲ ▼ ⇄ Σ σ ₁ ₂ → x̄ ȳ。LINE 表示の分数の区切りは ASCII の `/`（割り算は ÷ なので紛れない。初版の ⁄ は `/` と同じ形だったのでやめた）。度分秒の ′ ″ を足した。x̄ と ȳ は**1 字で 1 マス**（文字と結合記号の 2 字にしない）。形はモックに描いた（ᴇ は枡の真ん中の 3 列、⇄ は右向きの上に左向き）
  - Unicode には x̄ と ȳ の合成済みの字がない（x + U+0304 の 2 つ）。EXPORT は 2 コードポイントで書き、IMPORT は x・y に U+0304 が続けば 1 字に読む（charset.ts）
  - これは**全モデルに及ぶ**: BASIC の `CHR$(128)` は今の空の箱から記号になる。S1 で、`screenText` の読み戻し（font.ts）、charset.ts の IMPORT / EXPORT の Unicode 対応、既存の ROM のテストが箱を前提にしていないかを直す
- **大きな数字**: 答えの小数は、ドットで描いた **7×14、8 ドット送り**の「区切りのある数字」（7 つの線を 2 ドットの太さで、角を埋めて 1 本の線に見せる。点は 2×2 で 3 ドット送り）。液晶の上の 7 セグメント表示ではなく、ドットの液晶で描くこの機種の顔
  - 幅の計算: 符号 8 + 10 桁 80 + 点 3 = 91。指数が付くと `×10`（小さな字 18）と肩の数字（`-99` で 18）を、**すき間を足さずに**並べて **127 ドット**（字の最後の列がすき間なので、隣と詰めても字はつながらない）。初版の 8×14・10 ドット送りは 149 ドット、1 回目の直しでも部品の間に余白を足して 131 ドットになり、収まっていなかった
  - 負号は 5 ドット幅（数字の中の横線より左右に 1 ドットずつ長い。数字では角の埋めがそれを覆う）
  - 答えの欄の下端は、大きな数字も分数・√ の形も **62 行目**にそろえる
- フォントと大きな数字の表は、ROM のフォントと同じく `rom.ts` が TypeScript の 1 つの源から作る（アセンブリに写さない）

### 4.4 2D 表示の組み方（モックで確かめた）

- 1 つの要素は箱: 幅、基準線から上の高さ、下の深さ。文字は幅 6、上 7、下 0
- **分数**: 分子と分母の広い方 + 6 の幅（線は x+1 から x+w−3。左右の余白は、隣の字のすき間の列と合わせて 2 ドットで、隣の `+` の横棒と線がつながらない）。線は基準線の 4 つ上（`+` や `-` の横棒の高さ）、分子はその 2 つ上、分母は 2 つ下
- **根号**: 中身 + 6 の幅。左にはね、斜めの線、中身の上 2 ドットに横線
- **累乗**: 前の値の肩に、基準線を 4 上げて中身を描く（同じ大きさの字）。**累乗が続くときは、前の指数の肩にさらに 4 上げる**（階段になり、右から読むことが見て分かる。§6.3）
- **空の枠**: 点線の 5×7 の箱。カーソルはその中に入る
- カーソルは 1 ドットの縦線で、今いる欄の高さ（§6.5）
- **LINE 表示**（SETUP）: 同じ式を 1 行の文字で（分数は `/`、根号は `√(…)`、累乗は `^(…)`）。横に長い式を打つときに
- **関数の名前は小文字**で、開き括弧まで 1 つのトークン（`sin(` `log(` `abs(` `gcd(` `round(`、引数のない `rand`）。例外は `Ans` だけ。FUNC のメニューも入る形のまま小文字で見せる

### 4.5 画面の割り付け（2 回目のレビューで決めた）

メニュー・設定・表・結果の画面は、どれも同じ縦の割り付けにする（モックの `header`、`LINE`、`ROW`、`mark`）:

- **見出しの帯**: 0〜8 行目の 9 行を反転。字は 1〜7 行目で、帯の上下に 1 ドットずつ、左右は 1 ドット内側（左の字は x = 1 から、右の字は右端の 1 ドット手前まで）。初版は字が帯の上端に付いていて、帯が字より上に見えた（利用者の指摘）
- **行**: 11 行目から 9 行おき（11、20、29、38、47、56）。行の間は 2 行空き、最後の行の下に 1 行
- **選んでいるもの**: その項目の字だけを、上下 1 行ずつ広げて反転（y−1〜y+7）。続く 2 行の反転は接しない。メニューは今のモードも反転で示す
- **脚注**（AC:BACK など）は 6 行目（56）。脚注の書き方は `キー:動き`
- **表**（STATS、TABLE）: 列の見出しは 11 行目に、列の真ん中にそろえる。罫は 19 行目、データは 21 行目から 9 行おきに 5 行。数は列の右に寄せる（右の罫から 2 ドット）
- **値は右端にそろえる**: BASE の HEX・DEC・OCT・BIN の値は、名前を左、値を右端に
- 答えのない説明の文（誤りの画面など）も大文字で、ほかの画面と同じ書き方にする

## 5. 鍵盤

### 5.1 並び（モックのとおり）

**決め方**: SHIFT 面は**そのキーの逆の関数**（ただし 2 乗と √ は例外。下）（x² と √、LOG と 10ˣ、SIN と SIN⁻¹、STO と RCL）とし、逆のないもの（GCD、LCM、%、POL、REC、RAND、ROUND、定数、換算）はキーに載せず **FUNC のメニュー**に入れる。これはこの機種の決まりで、既存の機種の「どのキーの SHIFT 面に何があるか」の対応を写さない（§9）。

上の 2 段（小さな長円のキー）と十字キー（角の丸い長方形）。`主 / SHIFT 面`:

| | | | | | |
|---|---|---|---|---|---|
| SHIFT | ALPHA | （十字キー） | （十字キー） | MENU | ON / OFF |

- 数のキーの 4×3 と四則・ANS・= の並びは、電卓の機能として決まった形（使う人の手が覚えている）なのでそのまま使う。**関数のキーの並び、十字キーの形と位置、SHIFT 面の決め方、色分け、上の 2 段は独自**
- **√ は主の面**（2026-10-24、利用者の決定。初版は x² の SHIFT 面）: 中学・高校の数学では √ を 2 乗と同じくらい使うので、x² と √ をどちらも 1 回で打てるようにした。代わりに、使うことの少ない x³ を x² の SHIFT 面に、∛ を √ の SHIFT 面に置く。この 2 つのキーだけは SHIFT 面が「逆の関数」ではなく「同じ仲間の 3 乗・3 乗根」になる。2 乗の隣に 3 乗、√ の隣に ∛ は電卓に広く共通の形で、特定の機種の対応表を写すものではない（§9）
- 分数のキーの刻印は図（箱 2 つ）にせず、文字の `a/b`
- **a/b（分数）は直前の値を分子に取る**: 数字の並び、π、e、Ans、変数、√ や分数のテンプレート、閉じ括弧までの組（`(1+2)`、`sin(30)`）と、その後ろの累乗や x²・x!。前に値がなければ空の分子で待つ（`1 a/b 3` が 1/3。打つ順が書く順と同じになる）
- 16 進の A〜F は ALPHA 面（BASE では SHIFT なしで打てる）
- **ON は BRK の線**（POCKET の BRK/ON と同じく行列に入らない）。どんな状態からでも機械を取り戻し、電源が切れていれば入れる。誤りの画面では AC と同じ。**SHIFT ON（OFF）**で電源断
- DEL はカーソルの前を消す。挿入が既定で、SHIFT DEL（INS）で上書きに切り替わる（`OVR`。初めは上書きのモードを持たない設計だったが、EL-509E との比較の後、利用者の依頼で足した。§S7 の後の直し）

### 5.2 キー表

- 行列は今の 10 行 × 8 列（80 まで）のまま。KEYDATA、KEYCOUNT、KEYMAT もそのまま。SHIFT と ALPHA は ROM が持つ状態（キーとしては普通に FIFO に入る）
- 今は `MACHINE_KEYS`、`KEY_BY_ID`、`keyForChar`、`keyTable`（keys.ts）が 1 つの行列で、Keyboard.svelte、pc-keys.ts、paste.ts、rom.ts の keys.inc がそれを読む。**SCI のキー表は `shared/elec16/sci-keys.ts` に別に置いた**（S2）。キーごとに行列の番号、刻印、SHIFT 面と ALPHA 面、起動画面が出す 6 字の名前を持つ。ROM には名前の表を `scikeys.inc` として作る（rom.ts。pocket の keys.inc はそのまま）。ページはモデルの `input`（`keyboard` / `pad` / `calc`）で鍵盤と PC のキーの経路を選ぶ
- SHIFT はポケコンの SHIFT と同じ番号（6）に置き、ポケコンの CAPS の番号（10）は空ける。ページの runner は「SHIFT は次のキーまで待ち、CAPS はそれを使い切らない」を番号で覚えているので、どちらのモデルでも同じに働く

### 5.3 PC のキー

- 数字、`+ - * /`、`^`（xʸ）、`(` `)`、`.`、`Enter`（=）、`Backspace`（DEL）、**`Delete`（AC）**、矢印。文字のキーは関数に（`s` SIN、`c` COS、`t` TAN、`l` LN、`g` LOG、`r` √、`f` a/b、`e` EXP、`!` x!）
- **Esc は取らない**。Ctrl・Alt・Meta 付き、Tab、ファンクションキーも取らない（pc-keys.ts の今の規則。アプリのショートカットとペインから出る道）。判断は PLAY の `play-input.ts` と同じ形の `sciKeyFate`
- PASTE は SCI では出さない（数字と演算子だけを通す案もあるが、v1 では要らない）
- PC のキーで押したキーも本体のキーが沈む

## 6. 電卓の ROM（`resources/elec16/sci`）

### 6.1 作り

- PLAY の ROM と同じく、手書きの `main.s`（リセット、トラップ、ROM サービスの表）と e16c の TypeScript（`sci/*.e16.ts`）。`npm run gen:elec16` が -O2 で `sci.s` と `sci-rom.json` を書く（手で書き換えない）
- ROM サービスはポケコンと同じ番地・番号（PUTC、PUTS、CLS、LOCATE …）。キーボードのない READLINE などは PLAY と同じく -1
- **置き場所**: 固定 ROM には鍵盤・液晶のドライバ、far_call、式の評価の中心だけ。組版と編集器は最初から**バンクに置ける形**（far_call で呼ぶ）で書き、モード（STATS、BASE、TABLE、EQUATION）、SETUP、MENU、FUNC、誤りの文、特別な値の表もバンクへ。S3 の終わりに固定 ROM の残りを測って決める
- 眠り方: キーを待つ間は WFI（POCKET のプロンプトと同じく、ページはループを回さない）。runner の自動電源 OFF をそのまま使う（既定 10 分）

### 6.2 式の持ち方

式は RAM の上の**印付きのバイト列**で持つ。数字や演算子は 1 バイトのトークン、テンプレートは開き・区切り・閉じの印:

```
1 a/b 3 + √■ 2   →   [FRAC] 1 [SEP] 3 [END] + [ROOT] 2 [END]
```

- カーソルは列の中の位置 1 つ。←→ は 1 トークンずつ、印は飛ばすか中へ入る（モックの `moveLeft` / `moveRight` と同じ規則。分子の終わりから → で分母へ）。↑↓ は分子と分母を行き来する
- 挿入と削除は列の MCPY で済む（BASIC の行エディタと同じ）。空のテンプレートで DEL を押すと印ごと消える
- 長さは 1 式 199 トークンまで（2D 表示でも LINE 表示でも同じ）。越えると打てない
- **履歴**（▲ で前の式、▼ で戻る）: = を押した式を RAM の環状の領域（2 KB）に**写して**残す（呼び出した式を直しても履歴は変わらない）。▲ が履歴を呼ぶのは、式が空か、答えを出した後か、履歴をたどっている途中だけ（打っている式を捨てない）。電池で残る

### 6.3 評価

再帰下降。優先順位（強い順）:

1. 括弧、関数（`sin(` など。閉じ括弧は省ける: 行の終わりで閉じる）、テンプレート（分数、√）
2. 後置: 累乗（xʸ、x²、x³）、x⁻¹、x!、%。**累乗は右から**: `2^3^2` は 2⁹ = 512（2D 表示でも LINE 表示でも同じ。2D では階段に描く）
3. 符号（−）: `-2²` は −4
4. LINE 表示の分数 `⁄`
5. nCr、nPr
6. **記号のない掛け算**（`2π`、`3(4+1)`、`2√3`、`2A`）: × ÷ **より強い**。`1÷2π` は 1/(2π)、`6÷2(1+2)` は 1。教科書の読み方に合わせた（初版は × と同じ順位だった）。説明書に例を書く
7. × ÷
8. + −

- 値の後ろの符号は値ではない: `2(−)3` は SYNTAX（引き算は − のキー）
- EXP（×10ˣ）だけで始まる数は 1×10ˣ（`EXP 5` は 100000）。`.` だけの数は SYNTAX
- 数はすべて演算ユニットの 8 バイトの 10 進数（12 桁）。`asin(-1/2)` は 12 桁に丸めた −30 で、−30.000000000000004 にはならない
- **誤り**は、この機種の BASIC と同じ書き方: `ERR:MATH`（範囲、0 での割り算、あふれ）、`ERR:SYNTAX`、`ERR:STACK`（入れ子が深すぎる）。画面に短い説明と「◀▶ BACK TO THE LINE / AC CLEAR」。◀▶ は**誤りを見つけた位置**にカーソルを置いて式に戻る（テンプレートの中なら、その中の位置）。AC と ON は式を捨てる

### 6.4 答えの形（F⇄D）

**値の形は 1 つ: `(p + r√s) / q`**（p、r、q は整数、q > 0、s は平方因子のない 2〜99、p・r・q は互いに素）。分数は r = 0、√ は p = 0、二次方程式の解や tan 15° のような「整数と根号の和」も同じ形で持つ。

- **有理数のまま計算する**: 整数と分数どうしの + − × ÷ と整数乗は、この形（r = 0）のまま約分して進める。だから `1/3 + 1/6` は計算の結果として 1/2 で、近似から当て推量しない
- **あふれの検出**: p、r、q はそれぞれ 10 桁まで。掛ける前に交差約分し、それでも 2 つの数の桁数の和が 12 を越えるなら（演算ユニットの数は指数の欄で桁数がすぐ分かる）、その演算からは 10 進数だけにする。演算ユニットが 12 桁で黙って丸めた値を形に入れない
- **根号**: 有理数の平方根で、平方因子を外して s が 99 以下になるものは形のまま（`√8` は 2√2、`1/√2` は分母を有理化して √2/2）。同じ s どうしの + − と、有理数との × ÷ は形のまま（`√8 + √2` は 3√2）。違う s どうしは 10 進数
- **三角関数の特別な値**: 度で 30° と 45° の倍数（ラジアン、グラードも同じ角）の sin・cos・tan は表で引く。15° の倍数のうち形に入るもの（tan 15° = 2 − √3、tan 75° = 2 + √3）も表に入れる。sin 15° = (√6 − √2)/4 は s が 2 つあり形に入らないので 10 進数
- **小数を打った式は小数で答える**: 式の中に小数点がある（`0.1 + 0.2`）と、中では 3/10 と正確に持っていても、最初は 0.3 と出す。F⇄D で 3/10。分数で打った式は分数で答える
- 2D 表示では形で出せればそれを、出せなければ 10 桁の小数。F⇄D で行き来、SHIFT =（≈）は初めから小数。LINE 表示は小数
- **ENG**（SHIFT F⇄D）: 答えを指数が 3 の倍数の小数で出す（分数の答えでも小数にして）
- 帯分数（a b/c）は SHIFT a/b で打ち、F⇄D の行き来に含める（SETUP で「帯分数で出す」を選べる）
- FIX・EXP・AUTO（表示の桁）と FUNC の ROUND は**小数の表示にだけ**効く。分数と √ の形には効かない
- モックは倍精度の値から形を探す（連分数と、s・r・q の総当たり）。機械ではそれをせず、上の正確な持ち方にする

### 6.5 画面の組み立てとカーソル

- 組版（§4.4）は ROM が VRAM に直接描く。式が変わったときだけ描き直す（キーごと）。入力の欄と答えの欄は別々に消す
- **縦線のカーソル**: 1 ビットの液晶の VRAM に描いて点滅させると CPU を毎秒起こすので、液晶のカーソルに「縦線」の形を足し、点滅は今どおりページが描く:
  - CURMODE の下位 2 ビット = **3 が縦線**（今の `& 7` の中に収まる。+4 で点滅も今どおり）
  - 縦線のとき CURSOR は**ドットの位置**: 下位バイトが x（0〜127）、上位バイトが上端の y（0〜63）。高さは CURMODE のビット 4〜7（× 2 ドットで 30 まで）
  - CURMODE を書くときの切り捨て（bus.ts の `& 7`）と、スナップショットの検査（snapshot.ts の `cursorMode <= 7`）は、**モデルが縦線を持つとき（`cursor: 'bar'`）だけ 0xF7 まで**通す。ほかのモデルで 3 や上位ビットを書いても今どおり切り捨てる（テストで固定）。状態の欄は今の 16 ビットのままなので、スナップショットの版は上げない
  - lcd-painter の `Cursor`（今は桁・行と形 1・2 で 6×8 のセル前提）に、ドットの座標で描く形 3 を足す
- 大きな数字と記号はフォントと同じく ROM の表から描く

### 6.8 STATS の表の入力

- 表は列 X（2 変数なら Y、度数を使うなら FREQ）。十字キーで升を動き、数を打って = で入れて下へ。DEL は升の中の字を消し、SHIFT DEL ではなく FUNC の「行を消す」「行を足す」で行を出し入れする（SHIFT 面を増やさない）
- 40 行まで。結果は = で一覧（2 変数の結果はモックの STAT RESULT の画面）

## 7. 数値演算ユニットに足すもの（案）

ROM で組めるものは ROM で組む。ユニットに足すのは、ROM で組むと**桁が落ちる**か**遅すぎる**ものだけ:

| 演算 | 理由 | 約束 |
|---|---|---|
| SINH COSH TANH | EXP から組むと 0 の近くで桁が落ちる | 単項（A をその場で） |
| ASNH ACSH ATNH | 同じく、LN から組むと 0 と 1 の近くで落ちる | 単項 |
| ATN2 | 象限の場合分けと、B = 0 の扱い（POL、複素数の偏角） | A = atan2(A, B)、角度は ANGLE に従う |
| RNDTO | FIX・EXP・ROUND の丸めを 12 桁のまま正確に | ARG を**符号付き**で読む: 正は有効桁（EXP、ROUND）、負は小数点以下の桁（FIX）。四捨五入 |
| FROMI32 / TOI32 | BASE の 32 ビット | **B の番地の 4 バイト**（リトルエンディアン、符号付き）と A の数の出し入れ。新しいレジスタは足さない（ARG は 16 ビットなので使わない）。範囲の外は STATUS 1 |

- 足した演算は**どのモデルでも使える**（ユニットはモデルに依らない。今は知らない演算として STATUS 6 を返す番号が使えるようになるだけ）。状態は増えないのでスナップショットの版は上げない
- BASIC には出さない（S5 で決めた。BASIC の固定 ROM は残りが少なく、電卓のための演算を足すと予約語も増える）。機械語と e16c からは番号で使える

## 8. ペインとの関係

### 8.1 モデルの選び方とパネル

- **入口はピッカーの「ELEC-16 SCI」**（§1 の 10）。ピッカーの別の行で、選ぶと main が SCI-128 の新しいユニットを作り（名前は `SCI 1`、`SCI 2` …）、そのユニットで ELEC-16 ペインを開く。ウィジェットは今の `elec16` のまま（ペインの種類は増やさない）で、入口は「どのモデルの新しいユニットで開くか」だけを持つ。今のユニットの BASIC のプログラムには触れない
- **TUNE のモデルの一覧にも SCI-128** を足す。POCKET・PLAY との行き来は、PLAY と同じく再起動して RAM を消す（意味の違う RAM）。消える前に、二度押しで確かめる（S2 で済み: 1 度目でチップが「clear RAM?」になり、3 秒以内のもう 1 度で替わる。DELETE と同じ形）
- パネル: **CORE**、**MEM**（電卓の状態の領域に名前）、**TUNE**（クロック、自動電源 OFF、本体、色）。FILES・GAMES・LINK は出さない（使わない）
- **ROM の名前で分けている所をモデルの能力にする**: runner の `#forKey` と `#atPrompt`、TuneView の分け方は今 `rom === 'play'` で書かれている。SCI はキーを待つのがプロンプトで（自動電源 OFF は POCKET と同じに効く）、CODE の RUN は `CALL 28672` を打てないので PLAY と同じく直接呼ぶ。モデルのデータに `prompt: 'basic' | 'start' | 'key'` と `input: 'keyboard' | 'pad' | 'calc'` を置き、ROM 名での分岐を置き換えた（S2）。`prompt` は自動電源 OFF と CODE の RUN（`basic` は CALL を打つ、ほかは `code_return` に戻る直接呼び出し）、`input` は本体・PC のキー・PASTE・パネルのタブ
- **CODE**: 上の直接呼び出しにすれば、e16c で書いたプログラムが電卓の液晶と鍵盤で動く。仕組みは既にあるので費用は小さい。入れる（§1）。RAM の 7000–7BFF は空けてある

### 8.2 本体

- **縦長**。上に銘板（左「ELEC-16 SCI」と小さく「16-BIT SCIENTIFIC · SCI-128」、右に**ソーラーパネルの飾り**）、ベゼルに入った液晶と表示記号、上の 2 段と十字キー、関数のキー、区切りの線、数のキー
- 寸法は 1 か所の幾何（`sci-body.ts`。PLAY の `play-body.ts` と同じ考え）で決め、液晶は 1 ドットが整数個のデバイスピクセル（§4.1。モックも同じく、1 ドットの大きさから本体の寸法を決める）。本体は伸ばさず、部屋の中に置く（今の規則）。キーが本体に収まり重ならないことを単体テストで確かめる
- **色**（ペインの状態、TUNE）: **SLATE**（濃い灰、数のキーは明るい灰、SHIFT は琥珀、ALPHA は青緑）、**CHALK**（白っぽい本体、濃い関数キー、白い数のキー）、**PLAIN**（elecdex の見た目。本体を描かず、色はすべてテーマの変数）。光で描く 5 つ（ALLOY …）の仕組み（relief、素材の SVG、書体）を使い、キーの影と沈み方もそれに従う
- 数のキーは大きく（関数キーの 1.4 倍の高さ）、SHIFT と ALPHA はキーの色、SHIFT 面と ALPHA 面の刻印はキーの上の左右に色分け
- **字の大きさの下限**: 刻印、表示記号、銘板の小さな字は、本体がどれだけ小さくても `--step--2` を下回らない（CLAUDE.md の「Type sizes by role」）。本体の寸法から決まる大きさがそれより小さければ `--step--2` にする（モックは `max(var(--step--2), …)`）
- **刻印のコントラスト**: 本体の上の小さな字は 4.5:1 以上。CHALK は SHIFT 面 #8f4408（5.3）、ALPHA 面 #126377、銘板の小さな字 #565a61（5.3）、SHIFT キーの地 #a9520c に白。SLATE は 6.4〜7.2 で足りている
- 液晶は硝子の中で左右の真ん中に置く
- 本体の描き方（FULL / COMPACT / LCD）: COMPACT は液晶と十字キーと AC・= の 1 列、LCD は液晶だけ（PC のキーで打つ）
- モックの書体は Google Fonts から読む（docs のモックなので可。オフラインでは字体が変わる）。本番は今のスキンと同じく同梱の書体

## 9. 権利と名前

初版はレビューで「商標名は避けていても、機能の名前と SHIFT 面の組み合わせが特定の機種の系列に近い」と指摘された（§13）。次のように改めた:

- **モードと画面の言葉はこの機種のもの**: CALC、STATS、BASE、TABLE、EQUATION、FIND X、MENU、FUNC、F⇄D（答えの形の切り替え）、EXP（×10ˣ のキーと指数表示）、AUTO、RAND、DIFF（FIND X の誤差）、`ERR:MATH` などの誤りの書き方（この機種の BASIC と同じ）、「◀▶ BACK TO THE LINE / AC CLEAR」
- **SHIFT 面は「逆の関数」の決まりで割り当て、逆のないものは FUNC へ**（§5.1）。既存の機種の「このキーの SHIFT 面にこれ」の対応表を写さない。SETUP は独立のキー、OFF は ON の SHIFT 面
- 分数のキーは `a/b` の文字。表示の方式は「2D 表示 / LINE 表示」と呼ぶ
- 使わない語: 各社の機能の名前と商標（Natural Textbook Display、Natural-V.P.A.M.、V.P.A.M.、ClassWiz、WriteView、D.A.L.、Direct Algebraic Logic、MathPrint）、実在の型番（fx-…、EL-…、TI-…）、各社独特の綴り（Ran#、Rnd、DRG、S⇔D、COMP、BASE-N、Math ERROR、L−R、MthIO / LineIO）
- SHIFT、ALPHA、STO、RCL、Ans、ENG、nCr、nPr、HYP、SIN⁻¹、M+ などは数学と電卓に共通の語として使う（POCKET の BASIC と同じ考え）
- 数のキーの 4×3 と四則・= の並びは機能として共通の形なので使う
- 「ELEC-16 SCI」の商標: J-PlatPat の商標（検索用）で「ELEC16SCI」「SCI128」「ELEC16」を検索し、出願・登録とも **0 件**（2026-10-24、S7）。記号は検索で無視される。「ELEC」を含む登録は elec16.md §2 のとおり。法的な調査ではない
- README と画面の文に実在の機種名を書かない。「関数電卓のような」と言う

## 11. テスト

- **コア**（vitest）: SCI-128 のモデルのデータ、VRAM の大きさ、キー表、表示記号、縦線のカーソル（SCI では通り、ほかのモデルでは今どおり切り捨てる）。ほかのモデル（POCKET、HANDHELD、PLAY）が今のまま（PLAY-320 のときの固定のテストに足す）
- **ROM**（`elec16-sci.test.ts`）: 今の ROM のテストと同じく、キーを 1 つずつ押して画面をフォントで読み戻して比べる。2D 表示はドットの絵（`#` と `.` の文字。モックで使った読み出しと同じ）で比べる
- **計算の正しさ**: 既知の値の表（約分、√ の形、`(p + r√s)/q`、あふれで小数に落ちる所、特別な値、優先順位の例、誤りの位置）を、e16c のソースを TypeScript として動かした答えと、機械で動かした答えの両方で（e16c の「二つの実行」）
- **演算ユニット**: 足した演算を既知の値と照らす（`decimal.ts` のテストと同じ）。RNDTO の正と負の ARG、FROMI32 / TOI32 の範囲の端
- **e2e**: ライフサイクルの契約（`contracts/panes.ts`）はペインとして変わらない。モデルを SCI-128 にして押す、隠す、戻すを 1 本。PC のキーの Esc がペインから出られること

### S3 で決めた細部（2026-10-24）

- **ROM の形**: 手書きの main.s（リセット、トラップ、サービス、far_call、`calc_abort`・`calc_on`・`calc_fault` の戻り口）と e16c の 6 ファイル。固定 ROM に lcd（画面の部品、どのドットにも字を置く `glyphAt`、§4.5 の割り付けの `band`・`lineY`・`mark`、大きな数字）、tokens（トークンとその見え方）、numbers（演算ユニット、数のスタック、誤り、電源で消えない RAM）、calc（キー、行の編集、答え、変数、履歴）。バンク 0 に eval（§6.3 の再帰下降）、バンク 1 に screens（MENU、SETUP、誤り、FAULT）
- **誤り**: e16c に例外はないので、BASIC と同じく `fail(code, at)` が誤りと位置を覚えて手書きの `calc_abort` に飛び、スタックをキーのループのところへ戻して誤りの画面を出す。窓のバンクも固定 ROM の 0 に戻す
- **電源で消えない RAM**: e16c の大域変数は電源を入れるたびに初めの値に戻るので、Ans、変数 9 つ、角度、履歴 10 本（1 本 200 バイト）は 0400 からの決まった番地に置き、印（5C16）で中身が電卓のものかを確かめる
- **トークン**: 1 バイト。0x20 以上は機械の文字そのもの（数字、記号、変数の字、π、×、÷、²、³、⁻¹、ᴇ）、0x20 未満は関数（`sin(` など）、Ans、符号、`^(`、nCr・nPr、10ˣ の 10。10ˣ と eˣ は値と `^(` の 2 つを入れ、指数はその後に打つ
- **答え**: 演算ユニットの FORMAT（10 桁）の文字を、大きな数字で液晶の 6〜7 段目にそのまま描く（ずらしの計算なし）。指数は `×10` と肩の数字を、右の端から字を置く
- **S4 以降に回したこと**: 2D 表示（SETUP の 1:2D はまだ出さない）、FIX・EXP（S5 の RNDTO とともに）、F⇄D、ENG、FUNC、HYP、度分秒、f(x)、FIND X。押すと短いブザー
