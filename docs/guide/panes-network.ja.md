# ネットワークのペイン — elecdex

elecdex は Windows・macOS・Linux 向けの SF 風ターミナルエミュレーター兼システムモニターで、eDEX-UI を Electron で作り直したものです。このページでは、このマシンのネットワークを扱うペインを説明します：ネットワークの状態、通信量、接続先を示すワールドビュー、すべての TCP ソケットの表（Connections）、そして 2 つのリンク診断 Wi-Fi と Ethernet。ペインごとに、何をどのプラットフォームでどれだけの頻度で読むか、何を決して読まないかを書きます。アドレスをオンラインで調べることはなく（接続先は同梱の GeoIP データベースで位置を求めます）、OS の位置情報の許可が必要なものは読みません（Wi-Fi の BSSID もスキャンもありません）。elecdex は Windows で開発・使用しています。macOS と Linux は GitHub Actions の自動テストでビルドして動かしているだけで、人の手での確認は十分ではありません。

## ネットワークの読み取りのしくみ

- ページ（レンダラー）はネットワークにアクセスできません。このページの読み取りはすべて、別の utility process で動くメトリクスのコレクタが、ペインが購読している間だけ行います（[システムのペイン: 読み取りのしくみ](panes-system.ja.md#読み取りのしくみ)）。
- Windows では、頻繁な読み取りは常駐する PowerShell 1 本（`WindowsSampler`）が .NET と Win32 の API（IP Helper、ICMP、WLAN API、パフォーマンスカウンタ）をループで読んで得ます。読み取りのたびにプロセスを起こすことはありません。
- **1 つの ping を 3 つのペインが読みます。** インターネットへの ping の相手は `1.1.1.1` です。ネットワークの状態・Wi-Fi・Ethernet の 3 つのペインが同じ往復を読むので、同じ相手に 2 度問い合わせることはありません。ネットワークの状態だけなら 5 秒ごと、Wi-Fi か Ethernet のペインが画面に出ている間は毎秒です。ping はコレクタから送り、main プロセスからは送りません。
- **私的な読み取り。** ソケット表（`net.sockets`）、Wi-Fi の読み取り（`net.wifi`、`net.wifi.events`）、Ethernet の読み取り（`net.ethernet`）は、プラグインには決して許可できません。このマシンがどこにいたか、何と通信しているかを語るものだからです。ネットワークの状態・通信量・国ごとの接続数は許可できます。

| ソース | 周期 | 使うペイン |
| --- | --- | --- |
| `net.interface` | Windows 5 秒、ほか 30 秒 | ネットワークの状態、Cluster |
| `net.ping` | 5 秒（Wi-Fi か Ethernet が画面にある間は毎秒、共有） | ネットワークの状態、通信量、ワールドビュー、Cluster |
| `net.throughput` | 1 秒、後ろのタブでも取り続けます | 通信量、Cluster |
| `net.connections` | 5 秒 | ワールドビュー、Cluster |
| `net.sockets` | Windows 5 秒、ほか 3 秒。見えている間だけ | Connections |
| `net.wifi` / `net.wifi.events` | 1 秒 / 5 秒。見えている間だけ | Wi-Fi |
| `net.ethernet` | 1 秒。見えている間だけ | Ethernet |

## Network status

| | |
| --- | --- |
| 場所 | システムの列（cockpit と blank 以外のすべてのプリセット）。ピッカー名 *network status* |
| 読むもの | `net.interface`（既定の経路を持つアダプタ）と `net.ping` |
| プラットフォーム | Windows: サンプラー（インターフェースは IP Helper、ping は ICMP）。macOS・Linux: systeminformation、または動いていれば Wi-Fi や Ethernet のペインの ping |

- 3 つの値を示します：**STATE**、インターフェースの **IPV4** アドレス、`1.1.1.1` への **PING**（ミリ秒）。副題はインターフェースの名前です。
- **ONLINE** は、インターフェースが上がっていて*かつ* ping の相手が応答したことを意味します。インターフェースは上がっていても外へ出る経路がないことがあり、それは **OFFLINE** と表示します。まだ読み取りがなければ **UNKNOWN** です。
- 既定の経路がないとき、Windows はアドレスを持つ実在のアダプタ（ループバックは除く）に戻り、down と表示します。
- ⤢ ボタンはありません。数個の値のペインは、ウィンドウいっぱいに広げても得るものがないためです。
- elecdex は Windows で systeminformation の Wi-Fi 関数やインターフェース一覧を決して呼びません。これらは `netsh wlan` を実行し、Windows 11 はそれを位置情報へのアクセスとみなして許可のダイアログを出すためです。

## Network traffic

| | |
| --- | --- |
| 場所 | システムの列（cockpit と blank 以外のすべてのプリセット）。ピッカー名 *network traffic* |
| 読むもの | `net.throughput`（1 秒、後ろのタブでも取り続けます）と `net.ping` |
| プラットフォーム | Windows: サンプラーが読むアダプタのバイト数（既定の経路を持つアダプタ）。macOS・Linux: systeminformation の既定のインターフェースの統計 |

- 累計（`OUT` と `IN`）と、MB/s の目盛りのグラフ 1 枚。送信を軸の上に、受信を軸の下に鏡のように描き、目盛りは大きい方の向きで決まる 1 つの目盛りです。
- 通信量は後ろのタブやしまったウィンドウでも読み続けるので、また見えたときにグラフが途切れません。ペインに書く累計は、見えている間だけ更新します。

## World view

| | |
| --- | --- |
| 場所 | standard・network・earth プリセット。ピッカー名 *world view* |
| 読むもの | `net.connections`（5 秒）: 確立した TCP 接続のうち公開アドレスの相手を、同梱の GeoIP データベースで国ごとに置いたもの |
| プラットフォーム | Windows: サンプラーの TCP 表。Linux: `/proc/net/tcp` と `/proc/net/tcp6`。macOS: `netstat -anp tcp` |
| プライバシー | アドレスをどこにも送りません。OS の位置情報サービスには一切問い合わせません |

  <br><sub>World view</sub>

- 回転する地球儀の上に、国ごとの接続を表示します。接続数、国の数、接続の多い上位 6 か国も並びます。
- **「現在地」**はシステムのタイムゾーンの国（ゾーンが国を示さないときはロケールの国で、*approx.* と付きます）です。OS の位置情報サービスには許可のダイアログが出るので問い合わせません。eDEX-UI は代わりにオンラインの IP 検索サービスに問い合わせていました。どちらからも国が分からなければ、ペインは *location unavailable* と一度だけ表示し、接続は表示し続けます。
- 地震の一覧がほかの理由で最新に保たれている間（地震の通知がオン、または地震のペインが見えている）は、地震を地球儀に印します。地球儀がアプリに取得させることはありません。[外の世界のペイン](panes-world.ja.md)を参照してください。
- 地球儀は WebGL のコンテキストを 1 つ取り、ペインを閉じると返します。自分のタイマーではなく共有の 10 fps のフレームループで描き、ペインやウィンドウが隠れている間は描かず、動きを減らす設定では止まります。
- ペインに表示するクレジット: **GeoIP: NRO, CC BY 4.0 · map: Natural Earth**。データベースは [`@ip-location-db/geo-whois-asn-country-mmdb`](https://github.com/sapics/ip-location-db)、データは [NRO](https://www.nro.net/) によるもので、[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) です。

## Connections

| | |
| --- | --- |
| 場所 | network プリセット（ワールドビューの下）。ピッカー名 *connections*。複数開けます |
| 読むもの | `net.sockets`: カーネルの TCP 表と、各ソケットを持つプロセス。国は同じ同梱の GeoIP データベースから |
| 更新 | Windows は 5 秒ごと（サンプラー自身の周期）、ほかは 3 秒ごと。ペインが画面に出ている間だけ（後ろのタブでは何も読みません） |
| プラットフォーム | Windows: サンプラーの中で `GetExtendedTcpTable`。Linux: `/proc/net/tcp*`、所有者は `/proc/<pid>/fd` から。macOS: `netstat`（所有者は分かりません） |
| プライバシー | オンラインで調べることはなく、待ち受けているプログラムのポートに何かを問い合わせることもありません。この読み取りはプラグインには決して許可できません |

<p align="center">
  <img src="../screenshots/pane-connections.jpg" alt="Connections ペイン単体：上端に国の帯、その下に TCP ソケットを持っているプログラムごとにまとめ、ローカルポート・接続先・サービス・国を並べた表">
  <br><sub>Connections</sub>
</p>

- このマシンが持っているすべての TCP ソケットを、それを持っているプログラムごとにまとめて表示します。ローカルポート、接続先、そのポートの一般的な用途、接続先の国が並びます。上端の帯は接続先の国を合計したものです。
- **ACTIVE** と **LISTENING** で、接続と、待ち受け中のソケット（このマシンが開けている扉）を切り替えます。絞り込みの欄で行を絞れます。
- 2 回の読み取りの間に開いて閉じた接続も取り消し線付きで一度は表示するので、短命な接続も見逃しません。
- **MASK** はすべてのアドレスの後半を隠すので、スクリーンショットや画面共有に使えます。
- 待ち受けているプログラムは、コマンドラインから何を提供しているかを示します（`node` は `vite · my-app` になります）。待ち受けているプロセスのコマンドラインは一度だけ読み、そこから作った道具とプロジェクトだけを残して、行そのものは残しません。引数にトークンが含まれることがあるためです。ポートに接続することはありません。
- ページに送る行は最大 240 行です。

| プラットフォーム | 表 | 所有者 |
| --- | --- | --- |
| Windows | 常駐のサンプラーの中の C# から呼ぶ `GetExtendedTcpTable`（iphlpapi） | プロセス ID。サンプラーが同じ周期で読むプロセス表から名前を付けます |
| Linux | `/proc/net/tcp` と `/proc/net/tcp6`。プロセスは起こしません | ソケットの inode を `/proc/<pid>/fd` のリンクと照らし合わせます。表にある inode だけを、読み取りの間はキャッシュして |
| macOS | `netstat -an -p tcp` | 分かりません（ペインがそう表示します）。`lsof` を使うと読み取りのたびにプロセスと数百ミリ秒がかかります |

## Wi-Fi

| | |
| --- | --- |
| 場所 | network プリセット（Ethernet の上）、cockpit プリセット（右の列）。ピッカー名 *Wi-Fi status*。見出し WI-FI |
| 読むもの | OS から無線アダプタのリンクとカウンタ、ゲートウェイと `1.1.1.1` への毎秒の ping、OS の接続のログ（Windows） |
| 更新 | 毎秒。ペインが画面に出ている間だけで、隠れている間は何も読みません（タイムラインに空白が残ります） |
| プラットフォーム | Windows: サンプラーで WLAN API と WinRT。Linux・macOS: パーサを単体テストしただけで、実機では使っていません |
| プライバシー | 位置情報の許可が要るものは読みません。BSSID も周囲のネットワークのスキャンもありません。プラグインには出しません。**MASK** はネットワーク名とアドレスを隠します |

<p align="center">
  <img src="../screenshots/pane-wifi.jpg" alt="Wi-Fi ペイン単体：PC から無線・ゲートウェイを経てインターネットまでの経路と判定、信号のゲージと帯域図、信号・再送・往復時間・損失のタイムライン、ログ">
  <br><sub>Wi-Fi</sub>
</p>

無線接続のどこで問題が起きているかを示します。途切れる通話や、何度も切れる新幹線の Wi-Fi の原因を探すためのものです。

- **経路。** このマシンからインターネットまでの経路を区間ごとに測ります（電波の信号と再送、ゲートウェイとインターネットへの毎秒の ping、このマシン自身の送信量）。原因の区間を、根拠の数値とともに示します。

  | 判定 | 意味 |
  | --- | --- |
  | RADIO | マシンとアクセスポイントの間で信号が弱い、または再送が多い |
  | LOCAL LINK | ゲートウェイの応答が遅い、ばらつく、または ping を失う |
  | UPSTREAM | ゲートウェイの先が遅い、ばらつく、または損失がある |
  | UPSTREAM LOST | アクセスポイントは応答するのに、その先が応答しない（ゲートウェイが応答する中でインターネットへの ping を 4 回続けて失った）。トンネルの中の列車など |
  | OWN UPLOAD | このマシン自身の送信（500 kB/s 以上）が自分の通話を押しのけていて、往復時間もそれにつれて上がっている |
  | SIGN-IN NEEDED | キャプティブポータルがサインインを待っている |

  通話品質の推定値（**MOS**）も出します。ITU-T G.107 の E-model を簡略化した推定で、音声の目安であって測定値ではありません。
- **電波。** 信号のゲージ、2.4・5・6 GHz の帯にチャネルと DFS 帯、規格と PHY レート。
- **タイムライン。** 1〜60 分、クロスヘア付きで、信号・再送・往復時間・損失・通信量・イベントのレーン。ペインが見ていなかった時間は斜線を引いて *NOT WATCHED* と書きます。
- **ログ。** システムが記録した過去 1 日の切断とその理由（Windows）、アクセスポイントの切り替わり、フレームカウンタ。BSSID を読まないので、アクセスポイントの切り替わりは接続したままのチャネルの変化から推定します。切断の間隔がほぼ一定なら「〜分ごと」と表示します（サービスの接続時間の上限が疑われます）。
- **MASK** はネットワーク名とアドレスを隠し、**COPY** は直近数分のレポートをクリップボードに入れます。
- **説明カード。** どの項目もポインタを置くと、それが何か、判定に使うしきい値、今の値を説明します。判定の下の凡例で残りの読み方も分かります。
- **広い画面。** 広い画面で前面に出す（**Ctrl+Shift+Z**）と 2 列になり、局の間の線にその区間の直近 1 分を描き、ログの上に過去 1 日の接続を帯で出します。
- **複数のアダプタ。** 無線アダプタが複数あるときは、ヘッダーの下のチップで表示するアダプタを選べます。ゲートウェイへの ping と履歴はアダプタごとです（ping するゲートウェイは最大 4 つ）。
- 履歴はページが最大 60 分持つので、ペインを動かしても残ります。

判定のしきい値（`WIFI_LIMITS`。直近 1 分で判定し、機械に近い区間から先に疑います。近い区間の問題はその先のすべてに現れるためです）:

| 値 | 注意 | 悪い |
| --- | --- | --- |
| 信号（RSSI） | -67 dBm | -75 dBm |
| 再送（送信が毎秒 100 フレーム以上のときだけ） | 15% | 30% |
| ゲートウェイの往復時間 | 20 ms | 60 ms |
| ゲートウェイのジッタ | 10 ms | 30 ms |
| ゲートウェイの損失 | 1% | 5% |
| インターネットの往復時間 | 120 ms | 250 ms |
| インターネットのジッタ | 30 ms | 60 ms |
| インターネットの損失 | 1% | 5% |

ping に一切応答しないゲートウェイは損失とみなしません。

プラットフォームごとの読み方:

| プラットフォーム | 読むもの |
| --- | --- |
| Windows | 常駐のサンプラーで: SSID は WinRT の `WlanConnectionProfileDetails.GetConnectedSsid`（Microsoft が位置情報なしの代替として案内する API）、認証・暗号・疎通（キャプティブポータルは `ConstrainedInternetAccess`）・従量制は WinRT の接続プロファイル、RSSI・チャネル・無線のオンオフ・バックグラウンドスキャン・メディアストリーミングモードは `wlanapi` の各 opcode、規格・リンク品質・レート・周波数・MLO はリアルタイムの接続品質の opcode（Windows 11 24H2 以降）、再送などのフレームカウンタは `WLAN_STATISTICS`、アドレス・ゲートウェイ・DNS・MTU・DHCP のリースは .NET。リンクと ping は毎秒、プロファイルとアドレスは接続が変わったときと 10 秒ごとだけ。`Microsoft-Windows-WLAN-AutoConfig/Operational` のログ（8001・8002・8003：接続・失敗・切断）は、最初に過去 24 時間分、以後は 5 秒ごとに新しいレコードだけを読みます。管理者権限は要らず、名前を指定したフィールドだけがスクリプトの外に出ます |
| Linux | `iw`、`/proc/net/wireless`、`/sys/class/net`。相手ごとに常駐の `ping -i 1` を 1 本。OS のログは読まず、ログはペインが見たものです |
| macOS | `system_profiler` を 10 秒ごと。相手ごとに常駐の `ping` を 1 本。macOS 14.4 以降、ネットワーク名は位置情報サービスなしでは隠されます（`<redacted>`）。elecdex は位置情報サービスを求めません。OS のログは読みません |

- **Windows で決して呼ばないもの:** `WlanGetNetworkBssList`、`WlanGetAvailableNetworkList`、`WlanScan`、`WlanQueryInterface` の opcode 7（今の接続）。Windows 11 24H2 から、これらは位置情報の許可が必要になり、許可のダイアログを出します。単体テストがサンプラーのスクリプトにこれらがないことを確かめます。macOS では CoreWLAN を使いません。
- ゲートウェイへの ping はアダプタ自身のアドレスから送ります（Windows は `IcmpSendEcho2Ex`、Linux は `ping -I`、macOS は `ping -S`）。同じルーターに有線と Wi-Fi で繋いでいても区別できます。
- 測った負荷（i5-1335U、1920×1080）: Wi-Fi を読む間、サンプラーは 1 コアの 1.25% から 2.11% に、ページは同じ場所に時計を置いたときより約 1.3% 増えました。
- 設計: [architecture.md §5.12](../architecture.md#512-wi-fi-ペイン)。

## Ethernet

| | |
| --- | --- |
| 場所 | network プリセット（Wi-Fi の下）、cockpit プリセット（右の列の Wi-Fi の下）。ピッカー名 *Ethernet status*。見出し ETHERNET |
| 読むもの | OS から有線アダプタの状態・速度・二重・カウンタ・ドライバの設定。ゲートウェイ（アダプタ自身のアドレスから）と `1.1.1.1` への毎秒の ping |
| 更新 | 毎秒。ペインが画面に出ている間だけ（タイムラインに空白が残ります） |
| プラットフォーム | Windows: サンプラーで IP Helper。Linux: sysfs のファイル。macOS: `ifconfig` と `netstat` を 10 秒ごと。Linux と macOS はテスト用のデータでしか動かしていません |
| プライバシー | ドライバの設定は読むだけで変えません。アダプタの GUID とデバイス ID、接続プロファイルの名前、DNS サフィックス、DHCP サーバーは読み取りのスクリプトから出しません。プラグインには出しません |

<p align="center">
  <img src="../screenshots/pane-ethernet.jpg" alt="Ethernet ペイン単体：PC からリンク・ゲートウェイを経てインターネットまでの経路と判定、速度の段とドライバの設定を示す LINK パネル、タイムライン">
  <br><sub>Ethernet</sub>
</p>

有線版の Wi-Fi ペインです。有線接続のどこで問題が起きているかを、**PC・LINK・GATEWAY・INTERNET** の区間ごとに示します。

- **判定するもの。** 有線の故障は通信を止めるより遅くするので、遅くするものでリンクを判定します。
  - 前に出ていた速度からの低下（1 Gb/s → 100 Mb/s、ケーブルの 1 対の断）
  - 半二重
  - CRC エラー（10 分間の件数*と*割合）
  - 1 分以内に戻る断（Windows と Linux では、システム自身の数から 1 秒未満の断も）
  - ブロードキャストの嵐
  - 他の機械によるアダプタのアドレスの使用（Windows の Tcpip のログ、過去 1 日）
- **BELOW MAX。** ずっとアダプタの最大より遅いリンクは相手側のことなので、注記するだけです。
- **LINK パネル**は速度を段（10M〜10G）で示し（アダプタの最大に印）、リンクの使用率と、ドライバの設定（EEE、Green Ethernet、Gigabit Lite、ジャンボフレーム、フロー制御）を表示します。設定は読むだけで変えません。段と速度は速度の判定の色だけで塗ります。省電力は、それが on の状態で断か速度の低下を見たときだけ黄色になります。
- **ゲートウェイ**への ping は有線アダプタ自身のアドレスから送るので、同じルーターに有線と Wi-Fi で繋いでいても区別できます。インターネットが Wi-Fi や VPN を通るときは、INTERNET の局が *via Wi-Fi* や *via VPN* と表示し、判定はしません。
- **ログ。** 有線の断を、どのドライバでも記録する OS のログはないので、ログはペインが画面に出ている間に見たもの（LINK LOST、CONNECTED、SPEED、DUPLEX、UPSTREAM LOST と BACK、SIGN-IN、CRC ERRORS、BROADCAST）と、Windows のログからの ADDRESS CONFLICT です。Linux では、見ていなかった間の断を `carrier_down_count` から 1 行出します。
- **MASK**、**COPY**、説明カード、タイムライン、前面での 2 列は Wi-Fi ペインと同じです。COPY のレポートは MAC と IPv6 アドレスを常に隠し、MASK がオンならほかのアドレスも隠します。
- **問題は伝えます。** 読めなかったもの（応じないドライバ、開けないログなど）は一度だけトーストで知らせ、報告用の文をコピーできます。ペインは読めたもので続けます。

しきい値（`ETHER_LIMITS`。往復は直近 1 分、リンクのカウンタは直近 10 分）:

| 値 | 注意 | 悪い |
| --- | --- | --- |
| 速度 | このアダプタで前に見た速度より低い | 10 Mb/s、または半二重 |
| CRC エラー（10 分） | 5 件かつ 0.01% | 20 件かつ 0.1% |
| 1 分以内に戻る断（10 分） | 2 | 4 |
| 毎秒のブロードキャスト（30 秒の中央値） | 300 | 3000 |
| ゲートウェイの往復時間 | 5 ms | 20 ms |
| ゲートウェイのジッタ | 5 ms | 15 ms |
| ゲートウェイの損失 | 3% | 10% |
| インターネット | Wi-Fi と同じ: 120 / 250 ms、ジッタ 30 / 60 ms、損失 1 / 5% | |

- マルチキャストは表示するだけで判定しません（IPTV は毎秒 1,000 フレームを超えます）。破棄と未知のプロトコルはこのマシンの側として `host` と書き、判定しません。
- リンクが上がってもアドレスがないときは、45 秒（スイッチのポートのスパニングツリー）待ってから故障とします。
- Linux では、480 Mb/s のポートにつながった USB アダプタの通信が 20 秒間 250〜350 Mb/s に張り付いていたら、USB 2.0 のポートの疑いとして示します。

プラットフォームごとの読み方:

| プラットフォーム | 読むもの |
| --- | --- |
| Windows | 常駐のサンプラーで、見えている間は毎秒: `GetIfTable2` の行のうち、タイプ 6・物理メディア 14・ハードウェアのインターフェースでフィルタではないもの（仮想やフィルタの行ではなく物理のアダプタ 1 枚）の状態・速度・カウンタを、一度だけコンパイルする C# で読みます。アドレス・疎通・既定の経路のインターフェース（`GetBestInterface`）は、アダプタが変わったときと 10 秒ごと。二重・バス・ドライバの設定（`*SpeedDuplex`、`*EEE`、`*FlowControl`、`*JumboPacket`、Realtek と Intel の省電力のキーワード）は、アダプタが現れたときとリンクが上がるたびに、サンプラーの別のランスペースで**キーワード**で読みます（表示名はドライバの言語に訳されるため）。サンプラーのループでは読みません。システムのソースは 2 つだけで、ペインが見えている間だけ: NDIS の切断イベント（`MSNdis_StatusMediaDisconnect`、管理者権限なし）はアダプタごとに数を数えるだけで中身は読まず、1 秒未満の断に使います。System ログの Tcpip 4199（アドレスの衝突）は時刻とどの有線のアドレスかだけを残し、相手の MAC は残しません |
| Linux | sysfs だけ: `carrier`、`operstate`（dormant は 802.1X）、`speed`、`duplex`、`carrier_down_count`、`statistics/` のカウンタ（CRC・フレーム・長さのエラー、破棄、マルチキャスト、衝突）、親の USB 機器の速度。アダプタの最大速度・EEE・ブロードキャストの数は読めません |
| macOS | `ifconfig` の media 行（速度・二重・フロー制御・energy-efficient Ethernet）、`netstat -I -b`、`route -n get default`。どれもプロセスを起こすので 10 秒ごとに読み、その間は最後の答えを使います |

**制限事項（未確認）**（architecture.md §5.23.1）:

- ケーブルを挿した状態ではまだ使っていないので、速度、カウンタ、しきい値は実際の故障で試していません。ペインが見えている間のサンプラーの負荷も測っていません。
- オートネゴシエーションと実際に効いているフロー制御は読みません（ドライバの設定だけです）。1 秒未満の断の数え方も、実際の抜き差しでは試していません。
- 2.5 / 5 Gb/s をメーカー独自の `*SpeedDuplex` の値で示すドライバではその値を無視するので、アダプタの最大が低く出ることがあります。2.5G・5G のアダプタではまだ試していません。
- Windows では USB 2.0 のポートを判別できません。この判定は Linux だけです。
- ペインを閉じていた間の断は、Windows と macOS では分かりません（アドレスの衝突は、Windows では過去 1 日分を読みます）。
- Linux と macOS ではテスト用のデータでしか動かしていません。パーサを単体テストし、GitHub Actions の e2e テストがスタブで通るだけです。
