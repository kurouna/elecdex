# AI 窗格 — elecdex

elecdex 是面向 Windows、macOS 和 Linux 的科幻风格终端模拟器兼系统监视器。本页介绍它的语言模型窗格：**AI chat**，与你自己运行的模型（Ollama、LM Studio、llama.cpp 或任何兼容 OpenAI 的服务器）或你持有 API 密钥的托管服务（Anthropic、OpenAI、Gemini、OpenRouter）对话；以及 **ELEC system**，把一个是非题形式的议案交给由三个模型组成的评议会，并根据它们的投票作出决议；以及 **TRANSLATE**，用在本机运行的 PLaMo 3 Translate 在 53 种语言与简易日语之间翻译。本页说明提供方及其两种协议、API 密钥保存在哪里、长对话如何适应模型的上下文窗口、附件及其限制，以及这些窗格有意不做的事情。elecdex 在 Windows 上开发和使用；macOS 和 Linux 只经过自动化测试的构建和运行，尚未经过充分的人工验证。

**ai** 预设（Ctrl+Shift+F7）包含一个 AI 聊天窗格及其下方的 [TRANSLATE](#translate) 窗格，右侧是 ELEC system，其下是 [GPU](panes-system.zh-CN.md#gpu) 窗格。GPU 窗格显示 GPU 的负载和它自身显存的占用：在本机运行的模型所依赖的东西。两种 AI 窗格都只在你发送内容时才询问提供方，TRANSLATE 在本机运行 PLaMo 3 Translate，引擎只在第一次翻译时才启动，所以在那之前这个预设没有任何开销。

- **AI 聊天** — 与你自己运行的语言模型对话（Ollama、LM Studio、llama.cpp——任何支持 OpenAI chat API 的服务），或与你持有 API 密钥的服务对话（Anthropic、OpenAI、Gemini、OpenRouter）。回答以流式到达，推理过程默认折叠；密钥由操作系统加密，永远不会传到页面；对话保存在你的电脑上。提问时可以附上文本文件、图片和 PDF：用 **+** 选择、拖放到窗格上，或粘贴图片。图片在发送前会被缩小并重新绘制，所以相机写入文件的信息（例如拍摄地点）不会被发送出去。
- **ELEC system** — 把一个是非题形式的议案交给由三个模型组成的评议会：LOGOS（逻辑）、ETHOS（伦理）和 PATHOS（情感）各自从自己的立场评判，投票 APPROVE、REJECT 或 ABSTAIN，窗格按多数决或全体一致作出决议。席位使用 AI 聊天的提供方——三个席位都用同一个模型也可以。

### 添加提供方

1. 打开 *Settings → AI*，添加一个提供方：选一个预设，调整地址；如果是托管服务，再粘贴它的 API 密钥。
2. 和其他设置一样，密钥在离开输入框时（或按 Enter 时）保存。在此之前可以用 **show** 查看你输入的内容；已保存的密钥显示为圆点，不会再被显示出来。
3. 按 **test**。它会向提供方请求模型列表，随后可用于补全模型字段。
4. 在窗格中选择提供方和模型。

提供方就是“地址 + 协议”。协议有两种：兼容 OpenAI 的 `chat/completions`（直接用 fetch 和 Server-Sent Events），以及 Anthropic 的 Messages API（通过 Anthropic 的官方 SDK）。新的服务以预设添加，而不是新写代码。预设如下，添加后每一项都可以编辑：

| 预设 | 协议 | 默认地址 | 是否发送 PDF |
| --- | --- | --- | --- |
| Ollama | 兼容 OpenAI | `http://localhost:11434/v1` | 否 |
| LM Studio | 兼容 OpenAI | `http://localhost:1234/v1` | 否 |
| llama.cpp | 兼容 OpenAI | `http://localhost:8080/v1` | 否 |
| Anthropic | Anthropic | `https://api.anthropic.com` | 是 |
| OpenAI | 兼容 OpenAI | `https://api.openai.com/v1` | 是 |
| Gemini | 兼容 OpenAI | `https://generativelanguage.googleapis.com/v1beta/openai` | 否 |
| OpenRouter | 兼容 OpenAI | `https://openrouter.ai/api/v1` | 是 |
| Custom | 兼容 OpenAI | `http://localhost:8000/v1` | 仅当地址与读取 PDF 的预设相同时 |

- 地址必须是 http 或 https，且不含用户名、密码、查询或片段；其他任何地址都不会被请求。手工写错的地址只会让该提供方不可用，不会让整个 `settings.json` 回到默认值。
- **Anthropic 的密钥。** 请用在工作区中创建的密钥（Console → API keys，选择 Default 等工作区）。未选择工作区而创建、关联到用户的密钥（`sk-ant-usr-`）会被拒绝，提示 "the request was not accepted (400): This API key is not scoped to a workspace..."，因为 elecdex 不发送这种密钥所需的 `anthropic-workspace-id` 请求头。没有自己密钥的 Anthropic 提供方会使用 SDK 的常规来源（`ANTHROPIC_API_KEY`、`ant auth login` 的配置）。
- **重试。** 在兼容 OpenAI 的协议下，托管服务返回 408、429、500、502、503 或 504，或在应答前断开连接时，最多重试两次（0.5 秒和 1.5 秒后）；一旦回答已有内容到达就不再重试。`Retry-After` 不超过 5 秒时会遵守，更长时则不等待、直接报告该失败。本机或局域网中的服务器不重试：那里的失败（未启动、内存不足、没有该模型）会如实报告。Anthropic 的 SDK 会自行重试。
- **Anthropic 的回退。** 在 Anthropic 自己的端点上询问 `claude-opus-5` 和 `claude-fable-5-1` 时会附带服务器端回退：被其安全分类器拒绝的请求会在同一次调用中由另一个 Claude 模型回答，消息中会记下实际回答的模型名称。

### 提问

- 输入后按 Enter；Shift+Enter 换行。Esc 或 **stop** 结束回答并保留已写出的部分。
- 回答以 markdown 呈现，每个代码块都有复制按钮。模型的文字被视为不可信内容：先解析成只含已知元素的树再绘制，从不作为 HTML 绘制，因此不会带有脚本、样式或图片请求；链接只允许 http 和 https。
- 模型的推理过程（在提供方提供的情况下：Claude 的摘要式思考、`reasoning_content`、`reasoning` 或内联的 `<think>`）折叠在 **reasoning** 下。作为历史回传的只有回答正文，从不回传推理。
- 回答生成过程中，其标题会计数秒数和字符数；完成后显示读入和写出的 token 数以及每秒 token 数（在提供方报告这些数据的情况下）。
- 悬停在消息上可以 **copy** 复制、**edit** 编辑之前的提问（会替换它及其后的内容），或 **again** 重新提问。
- 没有正常结束的回答会注明结束方式，并在旁边附上提供方自己的原话：

| 代码 | 含义 |
| --- | --- |
| `STOPPED` | 你停止了它。 |
| `TRUNCATED` | 回答达到了长度上限。 |
| `DECLINED` | 模型拒绝了。 |
| `LINK ERROR` | 提供方返回了错误。 |
| `NO CARRIER` | 该地址无人应答。 |

- **+ new** 开始新对话，**log** 列出已有对话，最新的在前；指向某个对话可以将它导出为 markdown 或删除。
- 重新打开的对话会继续使用当初回答它的提供方和模型（如果提供方被删除后又重新添加，则按名称匹配）；无法发送时窗格会说明原因（例如 `NO MODEL`）。
- 空窗格会显示它指向哪里（`LINK STANDBY`、提供方和模型、地址）；没有提供方时显示 `NO LINK`。读取提供方的模型列表时模型字段显示 `QUERYING`，读不到时显示 `NO LIST` 及原因。
- 对话属于应用而不属于窗格：移动窗格、把它放到标签页后面或重新加载页面都不会中断回答。无人关注的回答会在 3 秒后停止，所以关闭窗格会停止请求。
- 设置中可选的系统提示词会放在每段对话的最前面。
- 使用 Anthropic 方言的提供方在问题需要时可能会搜索网络（Anthropic 的 `web_search` 工具，一次回答最多 5 次，每次搜索由 Anthropic 计费）。搜索之后的回答从新的段落开始，引用的网页以 **Sources** 列在下方。如果 Anthropic 的搜索循环让回答中途暂停，应用会以该回答剩余的搜索次数请它继续（最多 3 次），仍然暂停或在没有剩余次数时暂停的回答以 `TRUNCATED` 结束并附上原因。搜索前后的推理显示为不同的段落。不会请 OpenAI 兼容方言的提供方进行搜索。

### 附件

提问可以附带文件：按输入行开头的 **+**、把文件拖放到窗格上，或粘贴图片（带文本的粘贴仍作为文本）。文件以芯片的形式排在输入行上方（**PAYLOAD**，显示数量、大小和估算的 token 数），鼠标停在芯片上时，卡片会说明其余信息：完整的文件名、精确的大小、图片的像素以及缩小前的尺寸。提问可以只有文件。

| 限制 | 值 |
| --- | --- |
| 每个提问的文件数 | 5 个 |
| 一个提问的全部文件 | 15 MB |
| 文本文件 | 256 KB，完整地放在提问中发送；更长的会被拒绝，而不是截断 |
| 选择时的图片 | 40 MB |
| 发送的图片 | 重新绘制为长边不超过 1568 像素、面积不超过 115 万像素，以 PNG 或 JPEG 编码，不超过 3.75 MB |
| PDF | 10 MB、100 页；只发送给 Anthropic 的 API、OpenAI 和 OpenRouter |
| 一次请求中的图片和 PDF（含历史） | 20 MB |

- **不会从路径读取任何东西。** 页面读取你选择、拖放或粘贴的内容，并以字节交给 main；main 根据文件开头的字节判断类型，而不看文件名或系统的文件类型。
- **图片** 在页面中解码并重新绘制，然后重新编码（原图是 PNG 时用 PNG，以免截图中的文字模糊；否则用 JPEG）。因此相机的 EXIF 不会保留；仍带有 EXIF 或 PNG 文本块的图片会被 main 拒绝。
- **文本文件**：能作为 UTF-8 读取、不含 NUL、控制字符不超过 1% 的文件视为文本。它们以 `<file name="…">…</file>` 的形式放在提问中，位于图片和 PDF 之后、问题之前。
- **PDF**：对 Anthropic 协议以文档块发送；对兼容 OpenAI 的协议，只在地址与读取 PDF 的预设（OpenAI、OpenRouter）相同时发送（按地址判断）。对其他提供方，会在发送提问前显示 `NO DOCUMENT`；历史中的 PDF 会换成一行写明其名称的文字（例如 `[paper.pdf (PDF, 3 pages, 90 KB) - not sent: …]`），从不悄悄丢弃。
- 不接受图片的模型会用它自己的话说明；elecdex 不根据模型名称猜测。
- 尚未发送的文件只保存在 main 的内存中。发送后，文件保存在对话旁边（`chats/<id>.files/`，以 SHA-256 命名），随对话一起删除。编辑提问时，留下的文件会被沿用。
- 其他拒绝情况会连同文件名以代码说明：`TOO LARGE`、`UNREADABLE`、`PAYLOAD FULL`。

### 上下文窗口与 NOT SENT

本地服务器只能处理启动时设定的几千个 token，超出部分会从开头被悄悄丢掉，首先丢的就是系统提示词。因此 *Settings → AI* 中每个提供方都有一个 *context window*：

| 提供方 | 在你输入其他值之前的 context window |
| --- | --- |
| 本机或局域网中的地址（明文 http） | 8192 token |
| 托管服务 | 不限（整段对话发送） |

对于 Ollama，请填写它所设置的上下文长度（Ollama 自身的默认值是 4096）。`0` 表示“全部发送”。

- token 数不用分词器，而是估算：ASCII 字符 4 个算 1 个 token，其他字符每个算 1 个 token（日文和中文大致如此）。提供方报告的 token 数会修正这一估算，但只向上修正。
- 最多发送窗口的四分之三，其余留给回答及其推理。超出后，最早的消息一次性留到后面不发，直到只剩窗口的一半，并记住这个位置，直到窗口再次被填满。很少裁剪、一次裁很多，而不是每轮少一条，这样服务器的提示词缓存（以及 Anthropic 的）得以保留。
- 日志中的 `NOT SENT · n ABOVE` 行标出模型视野的起点。
- 对话本身及其导出始终完整。被裁剪的只是发送的内容。
- 最后一个问题即使单独也放不下，也总会发送；发生了什么由提供方的回答体现。
- 附件也计入：图片按两种协议计算方式中较大的一种，PDF 每页 2500 token，文本文件按其文字计算。一次请求中的图片和 PDF（含历史）即使对窗口不限的托管服务也限制在 20 MB 以内，用同样的方式裁剪。

### 总结

开启 *summarise what no longer fits*（*Settings → AI*；默认关闭）后，会先请模型总结留在后面的内容。

- 每次对话被裁剪时向同一提供方和模型多发一次请求，显示为 `TX · COMPACTING`。从不在回答之后或按定时器做总结。
- 此后该总结会紧跟在系统提示词之后发送，而不是作为一条消息。那一行随之变为 `SUMMARISED · n ABOVE`，展开可看到告诉了模型什么。
- 总结最多占窗口的十分之一，上限 600 token。
- 总结失败只会损失总结本身：问题照样会被提出。失败的总结会在下一个问题时再请求一次，之后直到下一次裁剪都不再请求。
- 附件只以名称传给总结。关闭该设置后，已有的总结仍会继续发送。

*未发布：***Form** 仅在目标语言为日语时提供。**Live** 开启时，更改语言、文体或术语集都会重新翻译，无论上一次翻译是如何发起的；窗格不可见时不会开始任何翻译，因窗格隐藏而停止的 LIVE 翻译会在窗格再次可见时重新发起。翻译写出期间不能交换语言。在已停止的翻译的某个块上按 **Retry** 会写出该块，但在所有块写完之前翻译仍保持停止，并在历史中记为部分完成。引擎处于故障时，译文下方的一行提供 **Restart engine**，而不是 Ctrl+Enter。在翻译写出期间打开历史条目会停止该翻译并保留已写出的部分。**HISTORY** 中有 **Keeping history** 开关。外部服务器以错误应答时，显示为拒绝了请求而不是无法连接；以非 PLaMo 3 Translate 模型重启的服务器不会被使用。

### 不做的事

- **没有工具。** 没有 MCP，也没有工具调用：模型无法读取你的文件或运行命令，也从不主动读取文件。唯一的例外是 Claude 的网络搜索，它在 Anthropic 的服务器上进行，而不是在这台电脑上。能启动进程或读取文件的模型，首先需要一套和插件同等水平的授权设计。
- 没有对话分支，也没有可命名切换的提示词配置：一个可选的系统提示词适用于所有对话。
- 放着不动不会发出请求：只是放在布局中的聊天窗格不会询问任何人。

| 限制 | 值 |
| --- | --- |
| 提供方 | 12 |
| 保存的对话 | 200（超出后拒绝新对话，而不是删除旧对话） |
| 一段对话中的消息 | 400 |
| 一条消息的字符数 | 400,000 |
| 系统提示词 | 8000 字符 |

| 位置 | **ai** 预设（Ctrl+Shift+F7），或选择器（Ctrl+Shift+A，"elec system"）。可以放大（Ctrl+Shift+Z）。不在默认布局中。 |
| 读取的内容 / 数据来源 | *Settings → AI* 中的提供方，按各席位的指定使用。评议以文件形式保存在应用数据文件夹的 `elec/` 中。 |
| 更新 | 只在你提交议案（或打开模型列表）时。每个单元收到它的立场、投票说明和议案；第二轮还会收到其他单元第一轮的陈述。每轮 3 个请求，一轮或两轮。 |
| 平台 | 与 AI chat 相同。macOS 和 Linux 尚未经过充分的人工验证。 |
| 隐私 | 页面只发送议案；席位和规则由 main 从设置中读取。密钥遵循 AI chat 的规则。 |
| 设置 | 窗格的栏中：**seats**、规则和轮数（保存在设置中，所有 ELEC system 窗格共用）。立场：*Settings → AI → elec system · standpoints*。 |

### 席位与立场

**seats** 为每个单元选择提供方和模型，**all** 把一个席位的选择应用到全部三个。因为每个单元都会被告知它自己的立场，三个席位用同一个模型也没问题。默认的立场：

| 单元 | 在舞台上的位置 | 默认立场 |
| --- | --- | --- |
| UNIT-1 LOGOS | 左下 | 科学家：证据、可行性、成本和风险。 |
| UNIT-2 ETHOS | 上方 | 守护者：责任、公平，以及决定所影响的人。 |
| UNIT-3 PATHOS | 右下 | 心：感受、欲望、直觉，以及决定对与之共处的人意味着什么。 |

在 *Settings → AI → elec system · standpoints* 中编辑（每个最多 2000 字符；留空即为默认立场）。每次评议会保留它当时所用的席位：之后更改设置不会改写它。

### 投票

1. 输入一个可以用是或否回答的议案（最多 4000 字符），按 Enter。
2. 每个单元用议案的语言写一段简短的陈述（不超过 120 个词），以一行 `VERDICT`（APPROVE、REJECT 或 ABSTAIN）和一行 `CONFIDENCE`（0 到 100）结尾，这两行都用英文。
3. 票从回答中最后一行 `VERDICT` 宽松地读取（例如 `**Verdict:** reject`），不使用结构化输出，因为本地模型对它的支持不一致。

面板随着投票亮起（`TX`、`RX`，然后是表决结果）。各单元在议案到来前处于断电状态，之后逐个通电（ETHOS、LOGOS、PATHOS 的顺序）。评议期间，光沿着正在被询问的面板和移动的网格地面流动，回答的每一段到达时都会沿着它的辐条流下，所以快速的模型会源源不断地流动，而正在思考的模型会让辐条保持黑暗（减少动效时这些都没有）。角落里的控制台记录每一步。最后一票投出后灯光熄灭，片刻之后**决议**（resolution）通电亮起，未能左右结果的单元退后。

### 决议

规则在栏中选择。决议每次显示时都根据投票计算，从不保存。

| 规则 | 通过 | 否决 | 其他情况 |
| --- | --- | --- | --- |
| **majority** | 两个席位赞成 | 两个席位反对 | `DEADLOCK`（例如 1-1-1，或一票赞成两票弃权） |
| **unanimous** | 三个都赞成 | 任何一票反对 | `NO CONSENSUS` |

- 不计入的票**算作无效票而非弃权**：连接失败（`LINK ERROR`、`NO CARRIER`）、被你停止的回答，或回答中没有表决结果（`NO VERDICT`）。因长度上限而被截断的回答，只要能读出表决结果就计入。
- 有效票少于两张则为 `QUORUM NOT MET`。
- 置信度只显示，从不计入。
- 因应用关闭而中断的评议显示为 `INTERRUPTED`。

### 轮次

选择 **2 rounds** 时，每个单元随后会阅读其他单元的第一轮陈述并再次投票——请求数翻倍（6 个）——改变的票会显示为 `REJECT › APPROVE`。传递的每段陈述都会截短以适应小的上下文窗口：提供方窗口的十分之一，上限 800 token。连接失败的单元会作为没有陈述传递。默认为一轮。

### 运行

- 位于你电脑或局域网中同一台服务器上的单元会依次询问（三个请求共用一块 GPU 会让所有请求都变慢；排队的席位显示 `QUEUED`），托管服务则同时询问。
- Esc 或 **stop** 结束评议并保留已写出的内容；尚未询问的席位记为无效票，决议以实际进行的那一轮为准。
- **again** 把同一议案交给当前就座的评议会；**log** 列出过去的评议及其决议，可重新打开、导出为 markdown 或删除。最多保存 200 次评议，超出后拒绝新的评议。
- 评议期间，光效以显示器的刷新率运行，约占一个 CPU 核心的 70%（在开发者机器上实测）；等待议案时没有任何动画，约 0.5%。不在默认布局中。

## TRANSLATE

<p align="center">
  <img src="../screenshots/pane-translate.jpg" alt="单独的 TRANSLATE 窗格：左侧是虚构的英文发布说明，四个块通过脊线上带编号的连线与右侧的日文译文相连，每个译好的块下方是译回英文的结果和 chrF 分数条；工具栏显示 EN 到 JA、礼貌体，ROUND TRIP 已开启">
  <br><sub>TRANSLATE · 替身引擎与虚构文本</sub>
</p>

TRANSLATE 通过 llama.cpp 的 `llama-server` 在本机运行 Preferred Networks 的 PLaMo 3 Translate，在 53 种语言与简易日语（やさしい日本語）之间翻译。原文按空行切成块，按顺序逐块翻译；每个块都带上前两个块作为历史，使术语和文体保持一致。两侧之间的脊线把每个块与其译文连起来。引擎在第一次翻译时由 main 启动，一段时间不用就停止；页面从不直接与引擎通信。

| | |
| --- | --- |
| 位置 | **ai** 预设（Ctrl+Shift+F7）中 AI chat 的下方；或从选择器添加（Ctrl+Shift+A，"translate"）。**Ctrl+Shift+Y** 带着剪贴板中的文本调出它并立即翻译（布局中没有 TRANSLATE 窗格时以弹出窗口出现）。可置前铺满窗口（Ctrl+Shift+Z）。不在默认布局中。 |
| 读取 / 数据来源 | 引擎：elecdex 获取的 llama-server（llama.cpp b12110）、你自己的 llama-server（b7563 或更高，在引擎设置中选择），或其他地址上的 llama-server。模型：一个 PLaMo 3 Translate GGUF 文件（0.8B、2B、8B 或 31B，Q4_K_M、Q4_0、Q3_K_M 或 Q2_K），在设置中获取一次。文件位于应用数据文件夹（userData）的 `translate/` 中：`engine.json`、`engine/`、`models/`、`glossaries.json`、`history.json`、`llama-server.pid`、`licence-consents.txt`。 |
| 更新 | 在翻译之前什么都不运行。引擎随第一次翻译启动（加载时显示其日志），10 分钟未使用即停止（5、10、30 分钟或从不）。译文边写边到，main 每 100 ms 传给窗格一次。开启 **LIVE** 时，停止输入 0.6 秒后请求翻译，只重新翻译有变化的块。打开引擎设置时，会向 Hugging Face 询问已获取模型的新版本（24 小时最多一次）。 |
| 平台 | 获取的引擎：Windows 为 Vulkan 版和 CPU 版（x64；Arm64 只有 CPU 版），macOS 为 Metal 版（Apple 芯片；Intel 为 CPU 版），Linux 为 Vulkan 版和 CPU 版（x64）。设备为 AUTO 时先尝试 GPU 版，无法启动则改用 CPU 版。不再应答（1 分钟没有任何输出，模型越大等待越久）时会停止服务器，并改用 CPU 版重新启动，直到 RESTART 或更改设置。反复发生则停在 FAULT。macOS 和 Linux 尚未经过充分的人工验证。 |
| 隐私 | 所翻译的内容留在本机：引擎只在 127.0.0.1 上监听，并有页面不知道的专用密钥。只有当你选择其他地址的 llama-server 时，文本才会发到那里，窗格底部会写明（"sent to …"）。原文和上下文从不写入布局；历史是本机上的文件，可以关闭。只有按下 Ctrl+Shift+Y 时才读取剪贴板，标记为私密的复制内容（密码管理器的）从不读取。 |
| 设置 | `settings.json` → `translate`：`modelId`（默认 `plamo3-2b-q4km`）、`ctx`（4096、8192、16384 或 32768；默认 16384）、`device`（`auto` 或 `cpu`）、`idleMinutes`（5、10、30，0 为从不；默认 10）、`live`（默认 true）、`saveHistory`（默认 true）。引擎的来源另存于 `translate/engine.json`，只在窗格中更改。窗格中：语言、文体、术语表、ROUND TRIP。 |

### 设置

第一次使用时，**> set up translation** 引导五个步骤：**ENGINE**（获取的版本、自己的 llama-server，或一个地址）、**MODEL**（四种大小，以及与本机内存的匹配程度）、**LICENCE**（见下文）、**FETCH**（引擎和模型，可 PAUSE、RESUME、CANCEL；暂停或中断的下载从中断处继续），以及 **READY**，通过引擎试译一句。引擎是 elecdex 固定的构建，并与固定的 sha256 核对。模型是其仓库的最新版本：同意许可证时向 Hugging Face 询问，使用前核对 Hugging Face 为该版本给出的大小和 sha256。

**其他地址上的 llama-server** 运行它自己的模型，因此不需要为它选择、同意或获取任何东西。*未发布：*引擎设置不再显示模型列表，而是显示服务器正在运行的模型——文件名，以及服务器给出时的大小。在 **Test** 通过时、打开设置时以及服务器再次应答时从服务器读取。**Test** 通过之前此处为空。窗格标题也显示该模型的名称，设置向导从 **ENGINE** 直接进入 **READY**。运行设置（上下文长度、设备、空闲时停止）和引擎的许可证一行也不显示：服务器如何运行由它自己的启动选项决定，请求的长度按服务器启动时的上下文长度来衡量。

**更新。** 打开引擎设置时，最多每 24 小时一次、只针对已获取的模型，向 Hugging Face 询问是否有新版本。文件有变化的模型会显示 **Update** 及该版本的日期（只改了 README 等其他文件的版本，不会重新获取同样的数 GB）；不会自行获取。**Update** 与设置一样把该模型设为窗格的模型，并再次经过 **LICENCE**（许可证可能已变更，且每次下载都需同意），然后 **FETCH** 替换现有文件，**READY** 进行测试。删除模型用 **Delete**；删除的是模型文件，同意及其记录会保留。

**引擎设置** *（未发布）*：正在运行的模型标有 **in use**；在列表中选中的模型要等按下 **Done**（未获取时为 **Set up this model ›**）才生效，列表下方会说明以其他方式离开会保留正在使用的模型。**Delete** 需要按两次，第一次会说明大小（若是正在使用的模型，则说明会停止引擎）。引擎启动期间也可以按 **Stop**（大模型要加载数分钟），待机时旁边的按钮为 **Start**。之前选过的自己的 llama-server 可通过其行直接切换，**Choose…** 选择另一个文件。地址用 **Test** 或 Enter 测试，正在使用的地址显示在输入框旁。下方说明 **Context** 和 **Device** 会重启引擎并停止进行中的翻译。日志随启动过程更新，并可复制；许可证一栏列出每个已放置模型的同意日期。**Set up a model…** 从 **MODEL** 打开，不会进入 **READY**。**Restart** 会重新询问引擎构建的 GPU。暂停的下载，或 elecdex 退出时留下的下载，在下次启动时（包括 NO MODEL 画面）显示为暂停，按 **Resume** 无需重新同意即可继续。获取另一个模型期间，正在使用的模型会继续翻译：面板底部显示下载进度（点击会在设置中打开），新模型在 **READY** 时接替。关闭设置后完成的下载会保留新模型，在列表中选中并按 **Done** 切换；一次只进行一个下载。

**LICENCE** 需要两项同意。第一项是 PLaMo 社区许可证：窗格显示摘要，但具有效力的是 Preferred Networks 网站上的许可证，且可能变更，因此必须先从窗格打开该页面，才能勾选。在工作中、在组织内部或为开发产品或服务而使用属于商业用途；年收入 10 亿日元以下时，登记用途后免费（窗格提供登记表的链接）。第二项是下载：窗格列出 **Agree and fetch** 获取的内容及其大小——来自 huggingface.co 的模型文件，以及由 elecdex 获取引擎时来自 github.com 的 llama.cpp 构建（MIT）。每次同意都会连同时间、许可证地址、打开该页面的时间、文件和 elecdex 版本追加到 `translate/licence-consents.txt`（只追加，不改写）。llama.cpp 的许可证以及 llama-server 中内置代码的许可证随 elecdex 附带，并以 `LICENSE-llama.cpp` 写在引擎旁边；引擎设置中有两份许可证的链接，窗格底部显示 Built with PLaMo。

### 翻译

- **语言** — 源语言为 53 种之一或 **AUTO**（让模型判断）；目标语言为 53 种之一或简易日语。在 AUTO 下，当文字能确定语言时（假名、韩文等文字，或某种语言的常用词明显更多），窗格显示 `AUTO ≈ EN`，此时可以交换语言。两个列表都把最近用过的语言放在前面。
- **文体** — PLAIN（だ・である）或 POLITE（です・ます），仅在译成日语时。
- **TRANSLATE**（Ctrl+Enter）重新翻译所有块；**STOP**（Ctrl+.）停止：正在写的块会保留并加上标记，其后的块不翻译。长到放不进上下文的块会说明并跳过；因长度上限被截断的块会加标记。**CLEAR** 会清空原文，译文也一并清空。
- **术语表** — 有名称的术语列表，针对某一目标语言或任意语言（日语术语表也用于简易日语）。每个块只附带它包含的术语，按长度从长到短，最多 50 个；以用空格分词的文字结尾的术语按完整单词匹配。可以以 TSV 或 CSV 粘贴。针对其他语言的术语表不会使用，窗格会说明。
- **上下文** — 最多 2,000 字，说明文本是什么、谁来读，随每个块发送，不翻译。
- **ROUND TRIP** — 把每个译好的块译回源语言，先统一数字的写法（汉字数字改为阿拉伯数字、全角改为半角），再用 chrF 与原文比较；译回日语时保留原文的文体（だ・である 或 です・ます）。低于 50 以警告色显示；词与词之间不用空格的语言（日语、中文、泰语、高棉语、缅甸语）中，正确的改写得分也偏低，因此为低于 30。数字发生变化的译回（如 5000万 与 500万，只差一个字符，得分仍高）无论得分如何都以警告色标出 **numbers differ**。这些界线是用 2B 模型实测后定的：正确的译回在英语中大多为 50～100，在日语中为 30～100，意思换成别的句子则低于 25。
- **块的按钮** — RETRY 在原位重新翻译；EDIT 手动修改，之后翻译的块会把修改后的文本作为历史；COPY 复制。指针停在脊线的编号上时，显示该块的 token 数、用时和历史。
- **HISTORY** — 原文的每个草稿一条（继续输入则替换，换成别的文本则新增一条），最多 200 条、4 MB，最旧的先删除。中途停止的翻译会保留，并标明翻译到哪里。点击一行可在 TEXT 中重新打开；CLEAR 需按两次。

### 不做的事

- 不翻译文件；文本靠输入或粘贴（最多 20,000 字）。
- 不使用托管服务：模型在本机或你指定的 llama-server 上运行。
- 不保存外部 llama-server 的密钥；要求密钥的服务器会被拒绝。
