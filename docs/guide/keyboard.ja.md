# キーボードとレイアウト — elecdex

elecdex は Windows・macOS・Linux 向けの SF 風ターミナルエミュレーター兼システムモニターで、eDEX-UI を作り直したものです。このページは、すべてのキーボードショートカットを目的別に、既定のキーと `settings.json` での id つきで挙げ、ショートカットの割り当て変更、衝突、システム全体の表示 / 非表示ショートカットの仕組みと、マウスでのワークスペースの組み立て（ペインの移動、手前に出す、保存したレイアウト、プリセット、タブグループ、ポップアップ）を説明します。macOS と Linux は自動テストでビルドと実行をしているだけで、手作業での確認は十分ではありません。

## 目的別のショートカット

以下はすべて既定のキーです。区切り線のキーと Escape 以外は、*Settings → Keyboard* で割り当て直せます（[ショートカットの割り当て変更](#ショートカットの割り当て変更)）。*Action* 列は設定の一覧とアクションパレットに出る名前、*id* は `settings.json` の `keybindings` で使うキーです。macOS では、組み合わせの Ctrl は Cmd にも一致します。

今の状態では何もしないショートカット（下の *効く条件*）はキーを取りません。キーはフォーカス中のペインにそのまま届きます。たとえば左右に隣のペインがないとき、Ctrl+Shift+← / → はそのままシェルに届き、PSReadLine では単語単位の選択になります。

### ペイン

| キー | Action | id | 動作 |
| --- | --- | --- | --- |
| Ctrl+Shift+A | Add a pane | `pane.add` | ペインの追加ピッカーを開く: 任意のウィジェットを、フォーカス中のペインの右・下、またはその隣のタブとして（またはポップアップで） |
| Ctrl+Shift+E | Split right | `pane.splitRight` | フォーカス中のペイン（タブならそのグループ全体）を右に分割 |
| Ctrl+Shift+O | Split down | `pane.splitDown` | フォーカス中のペイン（タブならそのグループ全体）を下に分割 |
| Ctrl+Shift+T | New tab | `pane.newTab` | フォーカス中のペインの隣に新しいタブ |
| Ctrl+Shift+W | Close pane | `pane.close` | フォーカス中のペインを閉じる（ホバーで表示される × ボタンでも可）。手前に出しているペインがあれば、そのペインを閉じる |
| Ctrl+Shift+Z | Bring the pane forward | `pane.zoom` | フォーカス中のペインをワークスペースの手前に出し、また元に戻す（Escape でも可）。手前に出せるペインでだけ効く |

### フォーカスとタブ

| キー | Action | id | 効く条件 |
| --- | --- | --- | --- |
| Ctrl+Shift+] | Focus next pane | `focus.next` | 常に |
| Ctrl+Shift+[ | Focus previous pane | `focus.previous` | 常に |
| Ctrl+Shift+← | Focus the pane to the left | `focus.left` | *unreleased*。その方向にペインがあり（隣り合い、その辺を一部でも共有するもの。最も近いもの、いくつも接するときは共有の長いもの）、キーボードがテキスト欄にないとき |
| Ctrl+Shift+→ | Focus the pane to the right | `focus.right` | 同上 |
| Ctrl+Shift+↑ | Focus the pane above | `focus.up` | 同上 |
| Ctrl+Shift+↓ | Focus the pane below | `focus.down` | 同上 |
| Ctrl+Tab | Next tab | `tab.next` | フォーカス中のペインがタブグループ（シェルのタブなど）にあるとき。*unreleased*：以前は Ctrl+Shift+→。テキスト欄からも効くようになった |
| Ctrl+Shift+Tab | Previous tab | `tab.previous` | 同上。*unreleased*：以前は Ctrl+Shift+← |
| Ctrl+Alt+Shift+→ | Next shell pane | `shell.next` | シェルから、移れる別のシェルペイン（またはシェルのタブグループ）があるとき |
| Ctrl+Alt+Shift+← | Previous shell pane | `shell.previous` | 同上 |

### レイアウトとプリセット

| キー | Action | id | 動作 |
| --- | --- | --- | --- |
| Ctrl+Shift+G | Saved layouts | `layout.saved` | レイアウトのダイアログを開く: 今の配置に名前を付けて残す、または保存した配置に戻る |
| Ctrl+Shift+1 … 9、0 | Apply the 1st … 10th saved layout | `layout.saved1` … `layout.saved10` | 保存したレイアウトのうち、ダイアログに並ぶ順で最初の十を適用（0 が十番目）。空いている番号のキーはフォーカス中のペインに渡る |
| Ctrl+Shift+F1 … F10 | Go to the standard … blank preset | `layout.preset.standard` … `layout.preset.blank` | プリセットへ切り替え: F1 standard、F2 network、F3 earth、F4 dev、F5 media、F6 desk、F7 ai、F8 cockpit、F9 retro、F10 blank |
| Ctrl+Shift+Backspace | Reset layout | `layout.reset` | 既定のレイアウトに戻す。シェルが開いていれば、切り替えと同じく先に確認する |

プリセットのキーはプリセットの位置ではなく id に結びついているので、割り当てを動かしたキーは同じプリセットに残ります。

### シェル

| キー | Action | id | 動作 |
| --- | --- | --- | --- |
| Ctrl+Shift+S | Focus the shell | `shell.focus` | 選択中のタブのシェルにフォーカス（シェルペインがなければ追加） |
| Ctrl+Shift+F | Search the shell | `shell.find` | シェルのスクロールバックを検索（Enter / Shift+Enter で次と前、Escape で閉じる）。検索できるシェルがあるときに効く |
| Ctrl+Shift+K | Clear the shell's scrollback | `shell.clear` | フォーカス中のシェルのスクロールバックを消す。取り消せない。シェルからだけ |
| Ctrl+Shift+= | Larger type in the shells | `shell.fontBigger` | すべてのシェルの文字を大きく。シェルが開いているときに効く |
| Ctrl+Shift+- | Smaller type in the shells | `shell.fontSmaller` | すべてのシェルの文字を小さく |

文字の大きさは `settings.json` の `terminal.fontSize` に保たれます。既定は 13 px で、8 から 32 までです。

### 探す・開く

| キー | Action | id | 動作 |
| --- | --- | --- | --- |
| Ctrl+Shift+P | Find an action | `palette.open` | アクションパレット: ショートカットのアクション・保存レイアウト・プリセット・テーマ・ペイン・設定のセクションを、文字で探して実行。それぞれのキーつき。取り消せないものは Enter 2 回 |
| Ctrl+Shift+L | Search the launcher | `launcher.focus` | ランチャーを検索（レイアウトになければワークスペースの上にポップアップ） |
| Ctrl+Shift+U | Open the utility pane | `utility.focus` | Utility ペインへ（複数あれば押すたびに次へ）。レイアウトになければポップアップし、もう一度押すと閉じる |
| Ctrl+Shift+. | Open settings | `settings.open` | 設定ダイアログ |

アクションパレットでは、↑ ↓ で選び、Tab と Shift+Tab で行の種類を切り替え、PageUp と PageDown で 8 行ずつ動き、Enter で実行、Escape で閉じます。今は実行できない行も一覧に残り、理由（たとえば *not in a tab group*）を添えて薄く表示されます。設計は [docs/palette.md](../palette.md) にあります。

Linux の IBus がこのキーを Unicode のコード入力に使う環境では、Ctrl+Shift+U が elecdex に届く前に取られることがあります。その場合は *Open the utility pane* の割り当てを変えてください。

### ウィンドウとアプリ

| キー | Action | id | プラットフォーム |
| --- | --- | --- | --- |
| F11 | Toggle fullscreen | `window.fullscreen` | すべて |
| Ctrl+Shift+M | Minimize window | `window.minimize` | Windows、Linux（macOS はフルスクリーンのウィンドウを最小化しない） |
| Ctrl+Shift+Q | Quit | `app.quit` | すべて。閉じても elecdex を通知領域に隠すだけの設定のときも終了する |
| Ctrl+Alt+Shift+E | Show or hide elecdex | `window.toggle` | どのアプリからでも効く。*Settings → Window* でオンにするまでオフ。Wayland セッションでは不可 |

### 割り当てを変えられないキー

| キー | 場所 | 動作 |
| --- | --- | --- |
| 区切り線の上で矢印キー | 2 つのペインの間 | サイズ変更（Shift で大きく動かす） |
| 区切り線をダブルクリック | 2 つのペインの間 | 両隣の 2 つのペインで広さを等分する |
| Escape | 手前に出したペイン | 元に戻す |
| Escape | ダイアログ、パレット、ポップアップしたペイン、ドラッグ中 | 閉じる、または取り消す |

## ほかのキー配列でのキー

ショートカットは物理的なキー（`KeyboardEvent.code`。`Ctrl+Shift+KeyA` など）で保存されるので、どのキー配列でも同じ位置のキーです。このページのキーは US 配列の刻印で書いています。日本語キーボードでは Ctrl+Shift+= が Ctrl+Shift+^、Ctrl+Shift+[ / ] が Ctrl+Shift+@ / [ です。アプリの中の一覧や説明では、お使いのキーボードの刻印で表示します。

## ショートカットとシェル

- elecdex の起動時には、シェルにフォーカスがあります。
- シェルでは、PuTTY や Windows Terminal と同じように、テキストを選択するとコピーされ、右クリックで貼り付けられます。Ctrl+C はシェルの割り込みのままです。
- 検索バーが移動した一致箇所はコピーされず、コピーされるのは自分で選択したものだけです。
- ショートカットは、フォーカス中のシェルがキーを受け取る前に取られます。そのため、どの組み合わせにも Ctrl か Alt（macOS では Cmd）が入るか、ファンクションキーである必要があります。それ以外のキーは、Shift つきも含めて、すべてシェルに届きます。
- ダイアログが開いている間は、*Quit* と *Toggle fullscreen* 以外のショートカットは何もしません。ダイアログの後ろで、見えないうちに何かが変わらないようにするためです。ポップアップしたペインの上では、ペインを呼び出すショートカットとアクションパレットのショートカットも効きます。
- Web ペインがキーボードを持っているときは、main がページからショートカットを受け取って実行します。その時点で何もしないショートカットはページに任されます（たとえば Web ページは Ctrl+Shift+= で拡大します）。

## ショートカットの割り当て変更

| | |
| --- | --- |
| 場所 | *Settings → Keyboard*（Ctrl+Shift+.） |
| 設定 | `settings.json` の `keybindings`: アクションの id → キー、または割り当てなしの `null` |

![Tron テーマの設定ダイアログ、キーボードの項目。ショートカットごとにアクションとキーが並ぶ](../screenshots/elecdex-settings.jpg)

1. *Settings → Keyboard* を開きます。
2. ショートカットのキーをクリックします。*press keys…* と表示されます。
3. 新しいキーを押します。Escape で記録を取り消せます。

- キーには Ctrl（macOS では Cmd）、Alt、またはファンクションキー（F1 から F24）が必要です。それ以外は *use Ctrl, Alt or a function key - the shell needs the rest* と断られます。
- *clear* でショートカットを外し（*none* と表示）、*default* で 1 つを既定に戻し、*reset all shortcuts* で一覧のすべてを既定に戻します。*reset all shortcuts* はシステム全体の表示 / 非表示ショートカットには触れません。
- アプリ内のツールチップは、既定ではなく今の割り当てでキーを示します。
- `settings.json` には変えたショートカットだけが書かれ、既定と同じキーは取り除かれます。使えないキーや、このビルドが知らないアクションの id は、ファイル全体を無効にせず無視されます。保てる上書きは 64 個までです。

```json
{
  "keybindings": {
    "app.quit": null,
    "utility.focus": "Ctrl+Alt+KeyU"
  }
}
```

## 衝突

- すでに使われている組み合わせは、*Settings → Keyboard* で *in use by* と相手のアクションつきで警告されます。
- アプリ内の 2 つのアクションが同じキーを持つときは、一覧で上にあるほうがそのキーを使います。
- 例外はシステム全体の表示 / 非表示ショートカットです。これがオンの間は OS がそのキーを先に elecdex のウィンドウ用ショートカットに渡すので、同じキーのアプリ内ショートカットのほうが警告され（*taken by the system-wide shortcut*）、効かなくなります。オフの間はキーを持たず、衝突にも加わりません。

## システム全体のショートカット

| | |
| --- | --- |
| 場所 | *Settings → Window* のスイッチの横。既定は Ctrl+Alt+Shift+E |
| プラットフォーム | Windows、macOS、X11 の Linux。Wayland セッションはシステム全体のショートカットを自分で握っているため、オプションにその旨が表示されます |
| 設定 | `window.globalShortcut`（既定 `false`）。キーは `keybindings` の `window.toggle` |

- どのアプリからでも効くので、オンにしたときだけ、main プロセスが OS に登録します。
- 使えるのは英字、数字、ファンクションキーだけです（OS は記号のキーを文字で呼ぶため、キー配列によって位置が変わります）。それ以外は *use a letter, a digit or a function key* と断られます。
- ほかのアプリがすでにそのキーを使っている場合は、その旨を添えてオフに戻ります。
- *reset all shortcuts* では変更されず、ショートカットの記録中はキーを手放すので、このショートカット自体も記録できます。
- elecdex が前面にあるときは elecdex をしまい、それ以外のときは elecdex を前面に出します。

## バックグラウンド実行

| | |
| --- | --- |
| 場所 | *Settings → Window* |
| 設定 | `window.trayIcon`、`window.minimizeToTray`、`window.closeToTray`、`window.globalShortcut`、`window.startInBackground`。どれも既定は `false` |
| プラットフォーム | 異なります（下の表）。elecdex は実際にできることだけを提示します |

*Settings → Window* には、ウィンドウの外に置くアイコン（通知領域、メニューバー、トレイ）の設定があります。アイコンをクリックすると elecdex が開き、右クリックメニューからは設定を開くか終了できます。また *launch elecdex when you sign in* もあり、システム側でオフにされた場合は、設定でもオフに戻って表示されます。ほかに何があるかはマシンによって異なります。

| | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 最小化 / 閉じるでアイコンにしまう | 可 | 不可 — ウィンドウを閉じても elecdex は動き続け、Dock から戻せます | デスクトップにアイコンを置く場所がある場合 |
| システム全体の表示 / 非表示ショートカット | 可 | 可 | X11 では可。Wayland セッションはそのキーを自分で握っているため、オプションにその旨が表示されます |
| サインイン時に起動 | Run キーのエントリ（アンインストーラーが削除） | アプリのログイン項目（macOS が許可を求めることがあります） | `~/.config/autostart/elecdex.desktop` |
| *start in the background* | 可 | 不可 — ログイン項目は引数を取れません | 可 |

- どのオプションも、オンにするまではオフです。サインイン時に起動するかどうかは `settings.json` には保たれず、プラットフォームが持っています。プラットフォーム側でオフにすることもできます。
- どの場合でも、elecdex をもう一度起動すれば動いているほうが戻ってくるので、ウィンドウに手が届かなくなることはありません。
- macOS と Linux の列は CI でビルドとテストをしているだけで、手作業での確認は十分ではありません。

## ステータスバーとウィンドウの隅

- ステータスバーは、ポインターを画面の下端に移動すると出ます。左端に保存したレイアウトごとの番号付きボタン（番号はそのレイアウトを適用するキーです）があり、ほかにペインの追加、保存したレイアウト、レイアウトのリセット、設定、テーマ、サウンド、終了のボタンがあります。
- Windows と Linux のフルスクリーンでは、ポインターを右上の隅に移動すると、最小化、フルスクリーン解除、閉じるのボタンが降りてきます。閉じるボタンは、通知領域で動き続ける設定なら elecdex を通知領域にしまい、そうでなければ確認のうえ終了します。

## ペインの移動

- ペインのタイトル（時計のようにタイトルのないペインは上端の線）をドラッグして、別のペインの上で離します。ポインターに最も近い側に、そのペインと並べて置かれます。
- 離すときに Ctrl（macOS では Cmd）を押していると、代わりにそのペインのタブとして、タブの並びのうちポインターが指す位置に加わります。すでにタブが入っているグループの上では、同じ Ctrl でタブの並べ替えになります。
- シェルのタブは単独でドラッグして取り出せ、タブグループのヘッダーをドラッグするとグループ全体が動きます。
- Escape でドラッグを取り消せます。
- 動かしたシェルはセッションを保ちます。

## ペインを手前に出す

| | |
| --- | --- |
| 場所 | Ctrl+Shift+Z、またはペインの右上の × の隣にある ⤢ ボタン |
| 設定 | なし。何も保存されません |

- 手前に出したペインは、ほかのペインの上にウィンドウの大部分を覆って表示され、ほかのペインは暗幕の後ろで元の位置に留まります。
- タブグループにも同じ隅があり、その × はグループ内のすべてのタブを閉じます。タブ自身の × はそのタブだけを閉じます。タブはグループごと手前に出るので、ほかのタブにもそのまま切り替えられます。
- 広くしても得るもののないペインは対象外です。システムの帯とネットワーク状態には ⤢ がなく、電卓、タイマー、ミキサー、Now playing、ディスク、プロセス一覧は、ウィンドウ全体ではなく中央にパネルとして出てきます。
- 手前に出ている間は、シェルの切り欠きのある枠を一回り大きくした枠（隅にブラケット付き）がペインのすぐ外側を囲みます。外側に描くので、ペインは与えられた広さをすべて使えます。隅には ⤡ だけがあり、Ctrl+Shift+W でそのペインを閉じられます。
- Escape、もう一度のショートカット、ボタン、または暗幕のクリックで元に戻ります。
- 配置は何も変わらず、何も保存されません。シェルはセッションを、Web ペインはページを保ち、アプリは次回もすべてのペインが元の位置にある状態で起動します。

## 保存したレイアウト

![Tron テーマの standard レイアウトの上に開いたレイアウトダイアログ。保存レイアウトとしてのプリセット（1〜9 が見え、それぞれに配置の縮図）と、その下にプリセットの棚とキー Ctrl+Shift+F1〜F10](../screenshots/elecdex-layouts.jpg)

| | |
| --- | --- |
| 場所 | Ctrl+Shift+G、またはステータスバーの *layouts*。最初の十は Ctrl+Shift+1 から 9 と 0、ステータスバーの番号付きボタン |
| ファイル | アプリのデータフォルダーの `layouts.json`（保存したレイアウト）と `layout.json`（今の配置）。[テーマと設定](themes-settings.ja.md#レイアウトのファイル) を参照 |
| 設定 | `layout.confirmSwitch`（既定 `true`）: *Settings → General → Layouts* |

- レイアウトは作業に追従します。今使っているレイアウトには印が付き、ワークスペースに加えた変更はすべてそのレイアウトに保たれるので、戻ってきたときには離れたときのままです。
- レイアウトをリセットしても、保存したレイアウトはどれもそのままです。そのあとに作った配置は、保存するかいずれかを適用するまでどのレイアウトにも属しません。
- ダイアログではレイアウトの名前を変えたり、上下に移動したりできます。リスト内の位置が *そのまま* 番号キーになります。保存できるのは十二個までです。
- レイアウトを適用するとワークスペースが置き換わり、置き換えられるペインのシェルは、それらのペインを閉じたときとまったく同じように終了します。シェルが開いている間は先に確認があり、その確認には、以後確認しないようにする方法（*Settings → General → Layouts*）も示されます。
- 古い配置はブラウン管のように電源が落ち、新しい配置は起動時と同じようにペインごとに立ち上がります。動きを減らす設定では、この演出はありません。
- **`layouts.json` を別のコンピューターにコピーすれば、配置も一緒に持っていけます。** このマシン固有のものは何も含みません。ダイアログの *layouts.json* ボタンで、ファイルマネージャーに表示できます。

## プリセット

レイアウトのダイアログの一覧の下に、10 個のプリセットが、それぞれペインの並びを小さな図にして並んでいます。

| プリセット | キー | ペイン |
| --- | --- | --- |
| **standard** | Ctrl+Shift+F1 | 既定のレイアウト |
| **network** | Ctrl+Shift+F2 | 地球儀の下に connections、その横に Wi-Fi の下に Ethernet |
| **earth** | Ctrl+Shift+F3 | ORBIT、地球儀、地震、天気 |
| **dev** | Ctrl+Shift+F4 | AI AGENT、Docker とシェル、clipboard と timer とシェル、GIT と AI チャットと Log Watch（組ごとにタブ） |
| **media** | Ctrl+Shift+F5 | YouTube (TV) とその下の now playing・spectrum・mixer、タブに重ねた X と RSS |
| **desk** | Ctrl+Shift+F6 | notes、timer、calculator、tasks、calendar、clipboard、utility |
| **ai** | Ctrl+Shift+F7 | 上下に 2 つの AI チャットと、GPU ペインの上に ELEC system |
| **cockpit** | Ctrl+Shift+F8 | システムの列の代わりに CLUSTER ペイン、その下にシェル 1 つ、右に Wi-Fi と、その下に Ethernet |
| **retro** | Ctrl+Shift+F9 | ELEC-16 と CHIP-8 をタブにした 1 つのペインと、その下に 16 バンドの spectrum |
| **blank** | Ctrl+Shift+F10 | ペインなし。自分で足していく |

- cockpit と blank 以外は左端にシステムの列を持つので、切り替えても計器はそのままで、舞台だけが替わります。
- プリセットを選ぶと、そこから作ったレイアウトが追加されてそこへ切り替わり、以後は作業に追従する自分のレイアウトになります。もう一度選ぶと、別のものを追加せずにそのレイアウトへ戻ります。↺ でプリセットの状態に戻せます。
- プリセットのキーを使えば、どこからでも同じことができます。
- 新しくインストールしたときは 10 個が Ctrl+Shift+1 から 0 に並んだ状態で始まり、すでにある一覧に足されることはありません。

## タブグループ

- タブグループにはシェルだけでなく、どのペインでも入れられます。ときどき使うペインは、専用の場所を取らせずにシェルと同じ場所に置けます。たとえば RSS や天気をシェルのタブの後ろに置く、といった使い方です。
- ペインをグループに入れるには、グループの上へ Ctrl を押しながらドラッグするか（[ペインの移動](#ペインの移動)）、グループ内のペインにフォーカスしてピッカー（Ctrl+Shift+A、またはステータスバーの追加ボタン）を開き、ウィジェットより先に **⧉ new tab** を選びます。
- タブをクリックして切り替えられます。背後のタブにあるシェルは動き続け、切り替えて戻ればセッションも画面もそのままです。
- グループは入れ子にできません。一つのタブには一つのペインが入ります。

## ポップアップ

- ペインの追加ピッカーで **▣ pop up** を選ぶと、ウィジェットをレイアウトに入れず、× だけの枠でワークスペースの上に表示します。レイアウトは変わらず保存もされません。Escape、×、枠の外のクリックで閉じます。
- シェル、タイマー（閉じるとカウントダウンが鳴らせないため）、ファイル以外の組み込みペインはすべてポップアップできます。Web ページとプラグインはできません。
- ポップアップで選んだ表示などは、アプリを終了するまで次に開いたときも残ります。
- Ctrl+Shift+L もレイアウトにランチャーがなければ同じように開き、ランチャーは何かを起動すると閉じます。Ctrl+Shift+U は Utility ペインを同じように開きます。
