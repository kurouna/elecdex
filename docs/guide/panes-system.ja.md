# システムのペイン — elecdex

elecdex は Windows・macOS・Linux 向けの SF 風ターミナルエミュレーター兼システムモニターで、eDEX-UI を Electron で作り直したものです。このページでは、マシンそのものを扱うペインを説明します：シェル（Terminal）、時計、システム、CPU、メモリ、GPU、ディスク、上位プロセス、Cluster ダッシュボード、ランチャー、ファイルブラウザー。ペインごとに、何をどのプラットフォームでどれだけの頻度で読むか、何を決して読まないかを書きます。elecdex は Windows で開発・使用しています。macOS と Linux は GitHub Actions の自動テストでビルドして動かしているだけで、人の手での確認は十分ではありません。両者についての記述は、長く使った結果ではなくコードの説明です。

## 読み取りのしくみ

Terminal・Clock・Launcher・Filesystem を除き、このページのペインはすべて、別の Electron utility process で動く 1 つのコレクタ（`src/services/metrics`）から**メトリクスのソース**を読みます。

- **購読は数えられます。** ソースは、少なくとも 1 つのペインが購読している間だけ読まれます。2 つのペインが同じソースを読んでも読み取りは 1 回です。最後の購読者が去ると読み取りは止まります。
- **見えている間だけ。** 後ろのタブにあるペインや、最小化したウィンドウのペインは、グラフに描くソースだけを持ち続けます（戻ったときにグラフが途切れないように）。それ以外は、ペインがまた見えるまで手放します。
- **Windows では読み取りのたびにプロセスを起こしません。** systeminformation は Windows のほとんどの呼び出しで新しい PowerShell・`wmic`・`ping.exe` を起動します。システム全体で測ると、そのやり方では既定のレイアウトの監視だけで 1 コアの約 144% かかりました。elecdex は代わりに**常駐する PowerShell を 1 本**（`WindowsSampler`）動かし、.NET と Win32 の API（IP Helper、プロセス表、ICMP、`SystemInformation.PowerStatus`、パフォーマンスカウンタ）をループで読んで、読み取りごとに JSON を 1 行書かせます。これで同じレイアウトは 13.6% になりました。サンプラーは最近コレクタに求められた種類だけを読むので、ウィンドウをしまってグラフだけが読んでいるときは、プロセス表・ソケット表・ping を取りません。親プロセスを毎秒確かめ、アプリが強制終了されても残りません。
- **変わらないものは一度だけ。** CPU の型番、OS のバージョン、マシンのメーカーと型番はアプリの実行中に変わらないので、コレクタごとに一度だけ集め、ポーリングしません。

ソースの周期（`src/services/metrics/sources.ts` より）:

| ソース | 周期 | 使うペイン |
| --- | --- | --- |
| `cpu.load` | 1 秒 | CPU、Cluster |
| `cpu.speed` | 2 秒 | CPU |
| `cpu.temperature` | 5 秒（Windows では読まない） | CPU |
| `cpu.info`、`os.info`、`hardware.system`、`gpu.info` | 1 回 | システム、CPU、Cluster |
| `mem.usage` | 1 秒 | メモリ、Cluster |
| `mem.swap` | 10 秒 | メモリ、Cluster |
| `gpu.usage` | 1 秒 | GPU、Cluster |
| `disk.io` | 2 秒 | ディスク、Cluster |
| `disk.volumes` | 30 秒 | ディスク、Cluster |
| `proc.list` | Windows 5 秒、ほか 3 秒 | 上位プロセス、CPU（タスク数）、Cluster |
| `os.uptime` | 5 秒 | システム、Cluster |
| `power.battery` | 30 秒 | システム、Cluster |

### タブと見出し

- ペインの見出しは **TERMINAL** で、選んでいるシェルのフルパスが並びます。
- 各タブにはそのフォルダーの名前が付きます（ホームもそのフォルダー名で表示されます）。2 つのタブが同じ名前になるときだけ親フォルダーが添えられます。タブにポインターを重ねると、シェルとフルパスが表示されます。
- 終了したシェルは、終了コードとともにタブにそう表示されます。キーを押すと、そのフォルダーで新しく始まります。
- 後ろのタブのシェルが出力すると、そのタブに点が付き、表に出すと消えます。
- ペインをレイアウトの別の場所へ動かしても、ページを再読み込みしても、セッションはスクロールバックを保ちます。ペインは動いているシェルにつなぎ直します。

### 動くシェル

| プラットフォーム | シェル | 選び方 |
| --- | --- | --- |
| Windows | PowerShell 7（`pwsh`） | `%ProgramFiles%\PowerShell\7\pwsh.exe`（インストーラー）か `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`（Microsoft Store のエイリアス）があれば使います。起動できなければ Windows PowerShell に切り替えます |
| Windows | Windows PowerShell | PowerShell 7 がないとき |
| macOS・Linux | `$SHELL` | bash・zsh・fish にはシェル統合が入ります。ほかのシェルは統合なしで動きます |

- シェルを選ぶ設定はなく、ページはシェルもその引数も指定できません。main プロセスが環境から決めます。PATH の検索や、ログインシェルの環境の取り込みはしません。
- シェルには `TERM=xterm-256color`、`COLORTERM=truecolor`、`TERM_PROGRAM=elecdex` を渡します。

### シェルのフォルダーの追い方（シェル統合）

eDEX-UI は `/proc/<pid>/cwd`・`lsof`・`ps` を毎秒ポーリングし、Windows ではフォルダーを追えませんでした。elecdex では、各シェルがプロンプトのたびに**端末のエスケープシーケンスでフォルダーを知らせ**、何もポーリングしません。

| シーケンス | 送るシェル | 意味 |
| --- | --- | --- |
| `OSC 7 ; file://<host><path> ST` | bash・zsh・fish | 今のフォルダー。パスは UTF-8 のバイトごとに % で書くので、ASCII 以外のフォルダー名も崩れません |
| `OSC 9 ; 9 ; "<path>" ST` | PowerShell | 今のフォルダー。引用符付きで、Windows Terminal が読むのと同じ形です。PowerShell は `ProviderPath` を送るので、`New-PSDrive` で作ったドライブも実際のパスになります。ファイルシステム以外のプロバイダー（`HKLM:\` など）では何も送りません |
| `OSC 133 ; A/B/C/D ST` | 4 つとも | プロンプトの開始、入力の開始、コマンドの開始、終了コード付きの終了 |

- **スクリプトの読み込ませ方。** bash には `--init-file`（スクリプトが自分の `.bashrc` を読み直します）、zsh には一時的な `ZDOTDIR`（自分の `.zshrc` を読み直します。フォルダーは elecdex の終了時に消えます）、fish には `XDG_DATA_DIRS` の追加（自分の設定の後に `vendor_conf.d` が読まれます）、PowerShell には `-NoExit -Command` を使い、スクリプトは環境変数で渡します。PowerShell の実行ポリシーは変えず、スクリプトファイルも実行しません。
- **受け取るもの。** これらのシーケンスは main プロセスが取り出し、xterm.js には渡しません。OSC 7 はホストが空、`localhost`、このマシンの名前のときだけ受け取るので、`ssh` 先のフォルダーは無視されます。OSC 9;9 は絶対パスのときだけ受け取ります。ほかの OSC 9（進捗、通知）はそのまま通します。
- **断るもの。** 制御文字を含むパスと、区切りが 2 つで始まるパス（`\\server\share` のようなネットワークの共有、`\\?\`、`//host`）は捨てます。どのプログラムの出力でもこのシーケンスを運べるうえ、共有を追うと Windows が NTLM の資格情報をそのサーバーに差し出してしまうためです。共有にいるシェルのフォルダーは追わず、タブには *network share* と出て、[Filesystem](#filesystem) ペインはホームに戻ります。
- 起動から 10 秒以内にシーケンスが来なければ、そのシェルには統合がないものとして扱います。フォルダーは追わず、代わりにポーリングすることもありません。
- 知らされたフォルダーはペインの状態に `cwd` として置かれ、`layout.json` と保存したレイアウトに残ります。そのため、**次の起動やレイアウトの適用で戻ったペインは、最後のフォルダーで始まります**。

### 開始フォルダー

新しいシェルのペイン（ピッカー、新しいタブ、分割、プリセット）は、*Settings → General → Terminal* で設定したフォルダー（`terminal.startDirectory`）で始まります。

- 空（既定）はホームフォルダーです。パスの先頭の `~` はホームを表します。
- もう存在しないフォルダーや、ネットワークの共有にあるフォルダーはホームに戻ります。
- フォルダーの確認は main プロセスを止めずに行います。1.5 秒以内に答えがなければ（応答しないドライブなど）、戻り先のフォルダーで始めます。`cwd` を保存しているペインも、開始フォルダーを使う前に同じ確認を通ります。

### 検索、リンク、貼り付け、ベル

- **Ctrl+Shift+F** でペインの上に検索バーが開きます。一致箇所はテーマの色で示されて件数が数えられ、Enter と Shift+Enter で順にたどり、Escape で閉じます。**Aa**、**ab**、**.*** で大文字と小文字の区別、単語単位、正規表現を切り替えます。検索で移った一致箇所はコピーされません。
- シェルが出力した URL はリンクになります（OSC 8 のハイパーリンクも）。Ctrl+クリック（macOS では ⌘+クリック）でブラウザーで開きます。
- PuTTY や Windows Terminal と同じく、選択するとコピーされ、右クリックで貼り付けます。Ctrl+C はシェルの割り込みのままです。
- 複数行のテキストを貼り付けるときは先に確認します（改行ごとにコマンドが実行されるため）。確認をやめることもできます（`terminal.confirmPaste`）。タブと改行以外の制御文字を含むテキストでも確認します。
- プログラムは OSC 52 でクリップボードに書き込めますが、読み取りの問い合わせには何も返しません。
- ベル（BEL）が鳴るとペインの縁が光って音が出ます。0.5 秒に 1 度までです。*Settings → General → Terminal* で両方・どちらか一方・どちらも出さないを選べます（`terminal.bell`: `both`・`flash`・`sound`・`off`）。
- **Ctrl+Shift+K** でスクロールバックを消し、**Ctrl+Shift+=** と **Ctrl+Shift+-** ですべてのシェルの文字を大きく・小さくします（`terminal.fontSize`、8〜32 px、既定は 13）。大きさは設定にもあります。

ショートカットは既定の割り当てで書いています。*Settings → Keyboard* で割り当て直せます（[キーボードショートカット](keyboard.ja.md)）。

### 詳細

- 端末は xterm.js 6 と WebGL レンダラーです。隠れたタブのシェルは、見えるまで WebGL のコンテキストを取りません。Chromium が同時に持てるのは 16 個ほどです。
- 隠れたペインの大きさは合わせず、途中の大きさもシェルに送りません。ConPTY は大きさが変わるたびにスクロールバックを折り返し直すためです。
- Terminal ペインはワークスペースの上にポップアップ（*▣ pop up*）できません。シェルはレイアウトの中に場所が要ります。
- 設計: [architecture.md §6](../architecture.md#6-ターミナル設計)。

## Clock

| | |
| --- | --- |
| 場所 | システムの列（最上段）。ピッカー名 *clock* |
| 読むもの | ページの中のシステム時計とタイムゾーン |
| 更新 | 毎秒、秒の境目で。ペインが見えている間だけ |

- 24 時間制の `HH:MM:SS` を大きな数字で表示します。数字は固定幅のマスに入るので、時刻が揺れません。変わる数字は転がり、変わった桁だけが動きます。
- 横にタイムゾーンの略称（`JST` など）が出ます。ポインターを重ねると IANA のゾーン名が表示されます。
- 自分のタイマーではなく共有の秒の境目で進むので、システム時計から遅れていきません。後ろのタブや最小化したウィンドウでは進まず、見えた時点ですぐ正しい時刻になります。
- このペインにはタイトルバーがありません。動かすときは上端の線をドラッグします。
- 前面に出す（**Ctrl+Shift+Z**）とウィンドウいっぱいに広がり、ピッカーからポップアップもできます。

<p align="center">
  <img src="../screenshots/pane-cpu.jpg" alt="CPU ペイン単体：コアの平均負荷を示す 2 つのグラフと、コア数・最小と最大の周波数・タスク数の行">
  <br><sub>CPU</sub>

- コアの平均負荷を示す 2 つのグラフ（コアを半分ずつに分けます）、またはタスクマネージャーのような論理コアごとのバー。ペイン内で切り替え、選択はペインの状態に残ります。
- グラフの下には、温度（読めないときはコア数）、最小と最大の周波数、タスク数が並びます。
- Windows では温度を読みません。権限のないプロセスには WMI から何も返らず、問い合わせるたびに約 400 ms かかるためです。
- ペインの副題は CPU の型番です。

<p align="center">
  <img src="../screenshots/pane-gpu.jpg" alt="GPU ペイン単体：直近 1 分の GPU 負荷と VRAM 使用率、3D・COMPUTE・COPY・VIDEO の各エンジンの負荷、VRAM と共有メモリのバー">
  <br><sub>GPU</sub>
</p>

- 直近 1 分間の GPU の負荷と、GPU 自身のメモリ（VRAM）の使用率の推移（VRAM は薄い線）、エンジンの種類ごと（3D・COMPUTE・COPY・VIDEO）の負荷、今の VRAM と共有メモリの使用量のバーを示します。
- 表示するのは専用メモリがいちばん大きいアダプタ（CPU 内蔵のグラフィックスと別にカードがあればカード）です。
- 負荷はタスクマネージャーと同じく、プロセスをエンジンごとに合計し、いちばん忙しいエンジンの値で数えます。
- 読めない機械では、ペインは **NO GPU READING ON THIS MACHINE** と表示し、Cluster ペインは GPU のレーン・VRAM の警告灯・スロットを暗く描くのではなく出しません。

| プラットフォーム | 読み方 |
| --- | --- |
| Windows | 常駐のサンプラーがパフォーマンスカウンタ `GPU Engine` と `GPU Adapter Memory` を読みます。エンジンの表はプロセス × エンジンで 1 行（数百行）なので、一度だけコンパイルする C# で合計します。アダプタの名前とメモリ量は DXGI で一度だけ読みます（WMI の `AdapterRAM` は 4 GB で止まります）。カウンタは初回に開くのに 0.5〜5 秒かかるので、スレッドプールで開き、サンプラーのループを止めません。測った負荷は 1 コアの約 0.3% です |
| Linux | amdgpu の sysfs のファイルだけ: `gpu_busy_percent`、`mem_info_vram_*`、`mem_info_gtt_*`。NVIDIA（nvidia-smi や NVML）と Intel は読み取りごとにプロセスが要るので読みません |
| macOS | 読みません。プロセスを起こさずに読む手段（`ioreg` 以外）がありません |

- どのペインも購読しなくなると、サンプラーの GPU の読み取りは 15 秒以内に失効して止まります。
- 設計: [architecture.md §5.22](../architecture.md#522-gpu-ペインgpu-の負荷と-vram)。

## Disk

| | |
| --- | --- |
| 場所 | システムの列。ピッカー名 *disk* |
| 読むもの | `disk.volumes`（30 秒）、`disk.io`（2 秒）。見えている間だけ |
| プラットフォーム | Windows: サンプラー（`DriveInfo` と `PhysicalDisk(_Total)` のパフォーマンスカウンタ）。Linux: `df` と `/proc/diskstats`。macOS: `df` だけで、読み書きの速度はありません |

<p align="center">
  <img src="../screenshots/pane-disk.jpg" alt="Disk ペイン単体：読み書きの速度と稼働率の下に、ボリュームごとの容量に対する使用量のバー">
  <br><sub>Disk</sub>
</p>

- 各ボリュームを、容量に対する使用量のバーで表示します（90% から琥珀色、97% から赤）。空き容量、ファイルシステム、リムーバブルかネットワーク上かも示します。
- その上には読み書きの速度とディスクの稼働率が並びます。macOS では表示しません。読む手段が `ioreg`、つまり毎回のプロセスしかないためです。
- Windows では固定ドライブとリムーバブルドライブだけを並べ、ネットワークドライブは除きます。応答しない共有は数秒止まることがあるためです。
- Linux と macOS では `tmpfs`・`squashfs`・`/snap`・`/run`・`/boot/efi` と macOS のシステムボリュームを除き、同じ APFS コンテナのボリュームは 1 つにまとめます。
- 前面に出す（**Ctrl+Shift+Z**）と、ウィンドウ全体ではなく中央のパネルとして出ます。

## Top processes

| | |
| --- | --- |
| 場所 | システムの列。ピッカー名 *top processes* |
| 読むもの | `proc.list`: Windows は 5 秒ごと（サンプラーのプロセス表）、ほかは 3 秒ごと（systeminformation）。見えている間だけ |

- `PID | NAME | CPU | MEM` の見出しで、いちばん忙しいプログラムを入るだけ（最大 12 行）並べます。
- プログラムのプロセスは名前でまとめて 1 行にするので、ブラウザーは 40 行ではなく 1 行です。並びは CPU、次にメモリの順です。
- CPU はマシン全体（全コア）に対する割合、メモリは物理メモリに対する割合です。
- 前面に出すと中央のパネルとして出ます。

## Cluster

| | |
| --- | --- |
| 場所 | cockpit プリセット（左上、システムの列の代わり）。ピッカー名 *cluster dashboard* |
| 読むもの | ほかのペインがすでに読んでいるソースだけ（CPU、メモリ、GPU、通信量、ディスク、ping、インターフェース、スワップ、ボリューム、接続先、プロセス、電池、稼働時間、変わらない情報）と、AWAKE の状態、地震の通知がオンのときの地震の一覧 |
| 更新 | 値は届いたその場で描きます。後ろのタブでは、グラフにする 1 秒のソース 4 つと一度だけのソースを持ち続け、残りは手放します |
| プライバシー | ソケット表、Wi-Fi ペインと Ethernet ペインのソースは読みません |
| 設定 | ありません |

<p align="center">
  <img src="../screenshots/pane-cluster.jpg" alt="Cluster ペイン単体：警告灯の行とメッセージ行、時計と日付、5 つずつ 2 行の値、マシンの仕様の行、CPU・コアごと・メモリ・GPU・ディスク I/O・ネットワークの受信と送信・ping のレーン">
  <br><sub>Cluster</sub>
</p>

車の計器盤のように、マシン全体を 1 枚のペインにまとめます。

- **警告灯。** LINK・PING・CPU・MEM・VRAM（GPU が読める機械だけ）・DISK・BATT（電池のある機械だけ）・AWAKE・QUAKE（地震の通知がオンのときだけ）。当てはまらない灯は暗く出すのではなく出しません。灯は同じ段階が 10 秒続くまで点きません。PING は同じ段階の応答が 2 回続くと点き、数えるのは直近 15 秒の応答だけです。LINK はリンクが切れるとすぐ点きます。値が戻れば灯はすぐ消えます。横の**メッセージ行**が、点いている灯のうちいちばん重いものを言葉で、ほかにいくつあるか（`+N MORE`）とともに伝えます。そのカードには点いている灯がすべて並びます。
- **GPU が忙しくても灯は点きません。** GPU 100% は仕事をしているだけで、モデルを遅くするのは VRAM があふれることだからです。
- 警告灯の下に**時計と日付**。
- **レーン。** CPU・メモリ・ディスク I/O・ネットワークの受信と送信・PING の 6 本（GPU が読める機械ではメモリの下に GPU を足して 7 本）が、直近 1 分を折れ線で、ピークと平均とともに示します。CPU・メモリ・GPU・ディスクは 0〜100%、ネットワーク（受信と送信で共通）と PING は直近 1 分に合わせた目盛りで、目盛りの上端をレーンに書きます。レーンは CPU の値が届くたびにアニメーションなしで描き直し、ひとりでに流れることはありません。余裕があれば、CPU の下にコアごとの今の負荷が並びます。
- **値。** 5 つずつ 2 行で、メモリと VRAM の量、スワップ、いちばん埋まっているディスク、接続先の数、いちばん重いプログラム、電源、稼働時間、リンクの通信量、IPv4 アドレス（とインターフェース）です。
- **仕様の行。** 余裕があれば、システムの列と同じ言い方で OS・メーカー・モデル・筐体・CPU・GPU と AWAKE の設定を 1 行に並べます。ホスト名は出しません。
- **リンク**は既定の経路を持つアダプタ 1 枚（ケーブルか Wi-Fi の、インターネットへ出ている方）で、両方を足した値ではありません。その通信量は、そのアダプタが繋がってからの累計です。
- 値ごとに、行に入りきらないことを詳細カードで示します。
- 大きさに合わせて 5 通り（wide・medium・short・compact・narrow）に組み替わり、全画面から細い列まで使えます。
- 全画面に広げてもアイドル時の負荷は 1 コアの 10〜15% で、CPU・メモリ・通信量・ディスクのペインを並べるより軽く済みます（その 4 つと時計で 24.1%。Windows 11、1920×1080 で測定）。

段階（`src/shared/cluster.ts` より。数字・バー・コア・警告灯・メッセージ行はすべて 1 つの判定に従います）:

| 値 | 注意 | 危険 |
| --- | --- | --- |
| CPU、メモリ | 85% | 95% |
| VRAM | 90% | 97% |
| いちばん埋まっているボリューム | 90% | 95% |
| ディスク I/O の稼働率 | 90% | - |
| Ping | 150 ms | 応答なし |
| 電池（放電中） | 20% | 10% |

- ディスクの稼働率が読めない機械（macOS）では、ディスク I/O のレーンがそう表示し、それによる DISK の灯は判定しません。
- 注意の黄が地色に近い Amber テーマでは、注意と危険の数字に ▲ と ◆ も付きます。
- 設計: [cluster.md](../cluster.md)、[architecture.md §5.20](../architecture.md#520-cluster-ペイン1-枚のダッシュボード)。

## Launcher

| | |
| --- | --- |
| 場所 | standard プリセット（シェルの下）。ピッカー名 *launcher*。**Ctrl+Shift+L** でランチャーを検索（レイアウトになければワークスペースの上にポップアップします） |
| 読むもの | Windows: スタートメニューのフォルダー（全ユーザーとこのユーザー）と、シェルが並べるパッケージアプリ。macOS: `/Applications`・`/System/Applications`・`~/Applications` の `.app`。Linux: XDG のアプリケーションフォルダーの `.desktop` ファイル。それに自分の項目 |
| 設定 | `settings.json` の `launcher.items` と `launcher.showSystem`（ペインの **EDIT LIST** ボタンで開けます） |

<p align="center">
  <img src="../screenshots/pane-launcher.jpg" alt="Launcher ペイン単体：絞り込み欄と、テーマのアクセント色で描かれたアプリのアイコンのグリッド">
  <br><sub>Launcher</sub>
</p>

- プラットフォームのアプリケーションと自分で追加した項目を、よく使うものから順に並べます。elecdex は起動に成功した回数を数え、その順に並べます。まだ何も起動していないうちは、自分の項目が先に来ます。
- 入力して絞り込み、Enter で最初に一致したものを起動します。
- アイコンはテーマのアクセント色で描かれ、ポインターを重ねると本来の色になります（Business テーマでは常に本来の色です）。アイコンは、スクロールして見えたタイルの分だけ取得します。
- Windows ではアイコンを Windows シェルが描き、アプリ名はスタートメニューの表示どおりで、ショートカットを持たないパッケージアプリ（Teams、Outlook、Terminal）も含まれます。
- ページは main プロセス自身の一覧にある不透明な id で起動を頼み、パスやコマンドでは頼みません。ページが乗っ取られても、一覧にないものは実行できません。
- ポップアップしたランチャーは、何かを起動すると消えます。

項目は `launcher.items` に追加します。

```json
"launcher": {
  "showSystem": true,
  "items": [
    { "name": "Project notes", "target": "C:\\Users\\me\\notes.md" },
    { "name": "Docs", "target": "https://github.com/kurouna/elecdex" },
    { "name": "Node REPL", "target": "C:\\Program Files\\nodejs\\node.exe", "args": ["-i"] }
  ]
}
```

| キー | 意味 |
| --- | --- |
| `showSystem` | プラットフォームのアプリケーションを並べるか（既定は `true`） |
| `items[].name` | 表示名。80 文字まで |
| `items[].target` | http(s) の URL、またはプログラム・文書・フォルダー・ショートカットのパス |
| `items[].args` | 省略可。あれば、target をこの引数でプログラムとして実行します |

項目は 200 個まで保たれます。

## Filesystem

| | |
| --- | --- |
| 場所 | standard プリセット（ランチャーの横）。ピッカー名 *filesystem* |
| 読むもの | 最後にフォーカスしたシェルのフォルダー（[シェル統合](#シェルのフォルダーの追い方シェル統合)で知らされたもの）。変更の監視はペインが見えている間だけ |

<p align="center">
  <img src="../screenshots/pane-filesystem.jpg" alt="Filesystem ペイン単体：追従しているシェルのフォルダーを、フォルダーとファイルのアイコンのグリッドで表示">
  <br><sub>Filesystem</sub>
</p>

- 追従しているシェルのディレクトリをグリッドで表示します。フォルダーをクリックするとそこへ `cd` し（コマンドをそのシェルに入力して実行します）、ファイルをクリックすると引用符付きのパスがプロンプトに入力され、次のコマンドに使えます。
- eDEX-UI にはできなかった、Windows での `cd` の追従もします。
- 追うシェルがないとき、またはシェルがフォルダーを知らせないときは、自分で閲覧し、**detached** と表示します。
- **drives** のタイルで、ドライブと空き容量を一覧できます。
- ネットワークの共有にいるシェルは追わず、ペインはホームに戻ります。[Terminal](#シェルのフォルダーの追い方シェル統合) で書いた理由で、main は共有のパスの一覧と監視を断ります。
- Filesystem ペインはポップアップできません。レイアウトの中のシェルを追うペインだからです。
