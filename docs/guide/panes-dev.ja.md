# 開発のペイン: AI Agent・Git・Docker・Log Watch — elecdex

elecdex は SF 風のターミナルエミュレーター兼システムモニターで、eDEX-UI を Electron・Svelte・TypeScript で作り直したものです。このページでは、ソフトウェア開発のための 4 つのペインを説明します。**AI Agent**（このコンピューターで動いている Claude Code のセッションを、そのローカルの記録から表示）、**Git**（1 つのリポジトリの変更ファイル、差分、コミットグラフと、FETCH・PULL・PUSH）、**Docker**（ローカルのエンジンのコンテナと、起動・停止・再起動・一時停止）、**Log Watch**（増えていくログファイルを追い、選んだ行を AI に説明させる）です。それぞれについて、何を読むか、どのくらいの頻度か、何を決して読まず何をしないか、設定を示します。elecdex は Windows・macOS・Linux で動きます。開発と利用は Windows で行っており、macOS と Linux は自動テストでビルドと実行をしただけなので、十分には確認されていません。

dev プリセット（Ctrl+Shift+F4）は、作業中のエージェント、それが動かすコンテナ、それが変えるリポジトリを並べたレイアウトです。

| 場所 | ペイン |
| --- | --- |
| 左の列 | cockpit と blank 以外のプリセットに共通のシステムの列 |
| 中央の上 | AI Agent |
| 中央の中ほど | Docker が前面、その後ろのタブにシェル |
| 中央の下 | クリップボード履歴が前面、その後ろのタブにタイマーともう 1 つのシェル |
| 右（全高） | Git が前面（差分に高さが要るため）、その後ろのタブに AI チャットと Log Watch |

- 前面に置いたのは、画面に出ている間だけ読むペイン（Docker エンジン、クリップボード）です。dev レイアウトを開くと、すぐにそれらが動いているのが見えます。
- 要約: **AI Agent** は、このコンピューターで作業中の Claude Code セッションを表示します。それぞれが今何をしているか、どれだけ抱えているか、サブエージェントとバックグラウンドのタスク、変更した各ファイルの差分です。**Git** は選んだリポジトリを、変化に合わせて最新に保って表示します。FETCH、fast-forward のみの PULL、強制しない PUSH があり、1 ペインに 1 リポジトリです。**Docker** はエンジンのコンテナを Compose のプロジェクトごとに表示し、行から起動・停止・再起動・一時停止ができます。**Log Watch** は増えていくログファイルを追い、**EXPLAIN** で選んだ行について AI の設定のモデルに尋ねられます。
- プリセットはひな形です。選ぶと保存レイアウトが 1 つ加わり、以後はその変更に付いていきます。新しくインストールしたときは 10 個のプリセットがすべて入っています。既存のレイアウトの一覧に後から足されることはありません。

## AI Agent

<p align="center">
  <img src="../screenshots/pane-agents.jpg" alt="AI Agent ペインを単独で表示したところ：フォルダー、状態、最後のツール、モデル、トークン数を示すセッションのカード、その 1 つの下にサブエージェントとバックグラウンドのコマンドのツリー、変更ファイルの一覧">
  <br><sub>AI Agent・架空のセッション</sub>
</p>

| | |
| --- | --- |
| 場所 | dev プリセット（Ctrl+Shift+F4）、ピッカー（Ctrl+Shift+A）の "ai agent"。レイアウトに 1 つだけで、ピッカーは画面にあるペインにフォーカスを移します。ポップアップ（▣ pop up）と前面表示（Ctrl+Shift+Z）ができます。 |
| 読むもの | Claude Code 自身のローカルの記録（`~/.claude`、または `CLAUDE_CONFIG_DIR` が指すフォルダー） |
| 更新 | AI Agent ペインが開いている間だけ。フォルダーを監視し、記録が増えたら 400 ms 後に、前回読んだ後に書かれた部分だけを読みます。セッションのプロセスが生きているかは 1 分ごとに確かめます。 |
| プラットフォーム | Claude Code がこの記録を置く環境。macOS と Linux では手で確かめていません。 |
| プライバシー | 読むだけです。どこにも何も送らず、何も起動・停止しません。記録の中のツールの出力は解析せずに読み飛ばします。 |
| 設定 | `settings.json` の `agents.sources`: どの記録を読むか（今のところ `claude-code`。ここにあるエージェントの記録しか読みません） |
| 状態 | *実験的*: 記録は Claude Code のもので文書化されていないため、Claude Code の新しいバージョンで表示できる内容が変わるかもしれません。 |

セッションのカードに表示するもの:

- 実行中の Claude Code セッションごとに 1 枚のカード。名前とフォルダー、処理中かどうか、最後に行ったこと（ツールと、その対象）、モデル、コンテキスト内のトークン数と出力したトークン数、そして回答です。
- カードの下には、セッションが起動したサブエージェントとバックグラウンドで実行中のコマンドが、**RUN**・**DONE**・**FAIL**・**STOP**（不明なら —）の状態とともに並び、実行中のサブエージェントはその最後のステップも示します。これらはセッションから枝分かれするツリーで並び、サブエージェントが起動したものはその下にぶら下がります（4 段まで）。
- 終わったものは、どう終わったかを示す 1 行（例: *4 FINISHED 3 DONE 1 FAIL*）に畳まれ、クリックで開きます。10 分間残ります。実行中のものはすべて、終わったものは 12 件まで表示します。報告を済ませたサブエージェントでも、自分のサブエージェントが動いている間は実行中として扱います。
- セッションのプロセスが消えたときに動いていたものは、完了ではなく不明と表示します。
- カードを開くと、使ったツールと変更したファイル（60 件まで。サブエージェントの分に 20 件の枠）が表示されます。ファイルを開くと、セッションが最初にそのファイルに触れる前に Claude Code が保存していたコピーとの差分が、Git ペインと同じ差分表示で出ます。サブエージェントが変更したものには **SUB** の印が付き、そのようなコピーはないので、差分はそう示します。
- 幅の広いペインでは一覧と差分を横に並べ、狭いペインでは縦に積みます。間の区切りはドラッグで動かせ、その位置はペインごとに保存されます。

読み方:

- ペインが開いている間だけ、前回の続きから 1 MB ずつ読みます。32 MB を超える記録は末尾の 512 kB から読み、その件数には *recent* と表示されます。
- 開発者の PC での実測: 124 MB の記録を全部解析すると 944 ms、末尾 64 kB を読むと 0.27 ms でした。変化のたびに記録全体を解析しないのはこのためです。
- JSON として解析するのはモデル自身の行と、バックグラウンドのタスクの終わりの通知、待っている呼び出しの結果だけです。ほかのツールの結果は文字のまま読み飛ばします。

制限:

- 今読めるのは Claude Code だけです。OpenAI の Codex のソースは設計とモックがありますが、まだ作っていません（[agents-codex.md](../agents-codex.md)）。
- 形式が文書化されていないため、Claude Code の更新で、elecdex が更新されるまで表示が変わったり出なくなったりすることがあります。

## Git

<p align="center">
  <img src="../screenshots/pane-git.jpg" alt="Git ペインを単独で表示したところ：追加・削除の行数付きの変更ファイル、変更された単語を強調した 1 ファイルの差分、ブランチの線と名前の付いたコミットグラフ">
  <br><sub>Git</sub>
</p>

| | |
| --- | --- |
| 場所 | dev プリセット（Ctrl+Shift+F4）、ピッカー（Ctrl+Shift+A）の "git status"。1 つのリポジトリにつき 1 ペインで、複数追加できます。ポップアップと前面表示（Ctrl+Shift+Z）ができます。 |
| 読むもの | **SELECT REPOSITORY** で選んだリポジトリ。`git` プログラムを通して読みます（git 2.31 以降が `PATH` にある必要があります） |
| 更新 | ペインが表示されている間だけ。変更のたびに読み直し、多くても 1 秒に 1 回で、何も変わらない間は読みません（ポーリングしません）。 |
| 書き込み | **FETCH**、**PULL**（fast-forward のみ）、**PUSH**（強制しない）だけで、どれも 2 回押しです。ステージ、コミット、チェックアウト、マージ、リベースは決してしません。 |
| プラットフォーム | Windows: `.cmd` の開くコマンドは `cmd.exe` を通して起動します。Windows 以外では、実行ビットの立つファイルは開かずにフォルダーで示します。macOS と Linux では手で確かめていません。 |
| プライバシー | レイアウトに入るのはリポジトリの id だけで（パスはアプリのデータフォルダーの `git-repos.json` にあります）、保存レイアウトにパスは入りません。ほかのペインとは連動しません。 |
| 設定 | `settings.json` の `git.openCommand`（そこでだけ設定でき、ページからは変えられません） |

表示するもの:

- ステージ済み、未ステージ、未追跡、競合中のファイルを、それぞれ追加・削除された行数とともに。
- 選んだファイルの差分。統合形式または左右並べて表示し、変更された単語を強調し、構文を色分けします。差分の中の文字は文字として描き、HTML としては挿しません。未追跡のファイルは 512 KB まで、差分は 3,000 行で切ります。
- 画像（PNG、JPEG、GIF、WebP、BMP、ICO、AVIF、5 MB まで）の変更は、差分の代わりに前後の画像を、左右か上下のうち大きく描ける方に並べます。クリックするとその側だけを表示し、ホイールで拡大縮小、ドラッグで移動、**BEFORE** / **AFTER** で同じ位置のまま見比べられます。SVG はテキストとして差分で示します。
- コミットグラフ: ブランチの線と、各コミットに付いた名前（チェックアウト中のブランチ、他のブランチ、リモート、タグ）。このブランチとその上流、または **ALL** で全ブランチを、**MORE** で 100 コミットずつ（2,000 件まで）表示します。コミットをクリックするとそのファイルと差分が開き、ポインターを置くとメッセージ、作成者、日付、変更内容のカードが出ます。
- ファイル一覧と差分の間、変更ファイルとグラフの間の区切りはドラッグで動かせ、ダブルクリックで既定に戻ります。位置はペインごとに保存されます。

FETCH・PULL・PUSH:

| ボタン | すること | 断るとき |
| --- | --- | --- |
| **FETCH** | リモートから取得し、ブランチがどれだけ遅れているかを示します | 下に挙げる、3 つに共通の場合だけ |
| **PULL** | `--ff-only`: fast-forward だけで、マージコミットも競合もエディタも起きません | 分岐しているとき: **DIVERGED** と示し、merge や rebase はターミナルに任せます |
| **PUSH** | ブランチを、その設定（`branch.<名前>.remote` と `.merge`）が示す上流へ送ります。refspec を 1 つ書き、タグは送らず、`+` も `--force` も使いません | リモートが先へ進んでいるとき: **REJECTED**（FETCH してから PULL を）。上流が無いとき: ターミナルの `git push -u` に任せます。送るものがない、遅れている、分岐しているときはボタンが押せません |

- リポジトリが読めていないとき、merge や rebase の途中、detached HEAD、ブランチに上流が無いときは、3 つとも押せません。elecdex は自分の最後の読み取りでこれを確かめます。
- どのボタンも 2 回押しです。PUSH を 1 回押すと、何件をどこへ送るかとフックが走らないことを、たとえば `push ↑2 to origin/main · no hooks` のように示します。
- **フックは一切走りません**（3 つとも）。`core.hooksPath` を elecdex 自身の空のフォルダーに向けるためです。そのため push は pre-push のチェック（テストや lint）を飛ばし、2 回目を押す前にそう表示します。
- **リポジトリ自身の設定が転送のプログラムを名指すときは押せません**（そのリポジトリの `core.sshCommand`、`core.gitProxy`、git が同梱しない資格情報ヘルパー、`remote.<名前>.uploadpack` など）。そのようなリポジトリはターミナルで同期してください。
- **話すのは https・http・ssh・git だけです**。この機械の上のフォルダー、`ext::`、リモートヘルパーは使いません。そうしたリモート（共有フォルダーが多い）で押すと、git の `transport 'file' not allowed` で失敗し、同じコマンドをターミナルで実行するよう表示します *(unreleased)*。
- 認証、ssh、プロキシには、利用者自身の global・system の git 設定をそのまま使います。git には問い合わせる端末がないと伝え、それでも 120 秒待つ転送は止めて **TIMED OUT** と示します。
- 結果はトーストで、短いコード（`PULLED 3 COMMITS`・`FETCHED · 2 COMMITS BEHIND`・`PUSHED 2 COMMITS`・`DIVERGED`・`REJECTED`・`PULL FAILED`）の横に git 自身の言葉を添えます。1 つのリポジトリにつき同時に 1 つだけ実行し、終わったらリポジトリを読み直します。

読むだけのときも git を安全に呼ぶために:

- どの呼び出しでも `core.fsmonitor`、ログの署名の確認、外部の diff プログラム、textconv を無効にします。リポジトリ自身の設定にある clean フィルターは空にし、利用者の global のフィルター（Git LFS など）には触れません。
- サブモジュールの作業ツリーは読みません。`--no-optional-locks` で status に index を書かせないので、利用者自身の git と `index.lock` を取り合いません。
- git がない、フォルダーが消えたなどで読めないときは、30 秒ごとにやり直します。

ファイルを開く:

- ダブルクリックでファイルを開きます（差分の行ならその行で）。`git.openCommand` があれば、そのコマンドを `{file}`・`{line}`・`{dir}` を埋めて、シェルを通さずプログラムと引数として起動します。例: `code -g "{file}:{line}"`。
- 空なら、システムの既定のアプリケーションで、実行されないテキスト・画像・PDF だけを開きます（ファイルの先頭のバイトと種類で判断）。それ以外（クローンしたての `setup.bat` など）はフォルダーで示します。
- 開いたりフォルダーで示したりするのは、作業ツリーの内側で `.git` の外にあるファイルだけです。

## Docker

<p align="center">
  <img src="../screenshots/pane-docker.jpg" alt="Docker ペインを単独で表示したところ：架空のコンテナを Compose のプロジェクトごとに、状態、ヘルス、公開ポート、CPU、メモリとともに並べている">
  <br><sub>Docker</sub>
</p>

| | |
| --- | --- |
| 場所 | dev プリセット（Ctrl+Shift+F4）、ピッカー（Ctrl+Shift+A）の "docker containers"。レイアウトに 1 つだけ。ポップアップと前面表示（Ctrl+Shift+Z）ができます。 |
| 読むもの | ローカルの Docker エンジンの API を、そのソケット、名前付きパイプ、またはこの機械の TCP ポートで。`docker` コマンドは実行しません。 |
| 更新 | ペインが画面に出ている間だけ。イベントのストリームを 1 本つなぎ、イベントの次の 0.25 秒の区切りと 10 秒ごとに一覧を、5 秒ごとに動いているコンテナの CPU とメモリを読みます。裏のタブ、最小化、格納中はエンジンに問い合わせません。 |
| 操作 | ▶ 起動、■ 停止、↻ 再起動、❚❚ 一時停止、▶ 再開。削除、kill、prune は決してしません。 |
| プラットフォーム | Windows: Docker Desktop の `docker_engine` パイプ。macOS: `~/.docker/run/docker.sock`、`/var/run/docker.sock`。Linux: `/var/run/docker.sock`、rootless の `$XDG_RUNTIME_DIR/docker.sock`、Docker Desktop の `~/.docker/desktop/docker.sock`。macOS と Linux では手で確かめていません。 |
| プライバシー | ディスクにもログにも書きません。コマンド、マウント、環境変数は読まず、ラベルは Compose のプロジェクト、サービス、フォルダーの 3 つだけを読みます。プラグインからは届きません。 |

エンジンの探し方: `docker` コマンドと同じ順（`DOCKER_HOST`、現在のコンテキスト（`DOCKER_CONTEXT`、または `~/.docker/config.json` の `currentContext`）、いつものソケット）で、コマンド自体は実行せずに探します。これで Docker Desktop、Linux のデーモン、rootless Docker、colima、OrbStack に届きます。別のマシン、TLS、ssh 越しのエンジンは使わず、ページからエンジンを指定することもできません。接続のたびに探し直すので、コンテキストを切り替えれば次の接続から従います。

表示するもの:

- コンテナを Compose のプロジェクトごとにまとめ（プロジェクトをクリックすると畳めます）、プロジェクト、サービス、名前の順に並べます。**コンテナの状態が変わっても行の位置は変わらない**ので、ボタンがポインターの下から逃げません。
- 各コンテナの状態とその長さ（UP、HEALTHY、UNHEALTHY、STARTING、PAUSED、RESTARTING、0 以外ならコード付きの EXITED、CREATED、DEAD）、イメージにヘルスチェックがあればその結果、公開ポート、動いているものの CPU とメモリ。
- **ALL** か **RUN**（動いているものだけ）。ペインが狭くなると、IMAGE、次に CPU と MEM、次に PORTS の順に列を畳みます。
- 名前をクリックすると名前をコピーし、公開 TCP ポートはブラウザーで開き、`›_` はシェルに入る `docker exec -it <name> sh` をコピーします。名前にポインターを置くと、行に入らないもの（イメージ全体、Compose のプロジェクトとサービス、フォルダー、アドレス付きの全ポート、メモリの上限、作成時刻、ID）のカードが開きます。
- ポインター（またはキーボード）のある行に、その状態で受け付ける操作が出ます。停止・再起動・一時停止はもう一度押して確定します（2 回目は 3 秒間有効）。停止と再起動では、コンテナに通常の 10 秒の猶予を与えます。送っている間は行に STOPPING… などと出て、結果は次の一覧で追いつきます。
- 一覧は 100 件まで（動いているもの、次に新しいものを優先）。使用量は動いているコンテナ 24 件まで読みます。

見出しのリンクの状態:

| 状態 | 意味 |
| --- | --- |
| STANDBY | ペインが画面に出ていないので、エンジンに問い合わせていません |
| LINKING / LINKED | 接続中 / 接続済み |
| NO DAEMON | 応答がありません。Docker Desktop かサービスを起動してください |
| DENIED | このユーザーがソケットを開けません（Linux では docker グループ） |
| UNSUPPORTED | エンジンの API が 1.24 より古い |
| LINK ERROR | エンジンの応答が遅い。直前の一覧を画面に残します |

含まないもの: コンテナのログ、イメージ・ボリューム・ネットワークの一覧、Kubernetes、ペイン内のシェル、別のマシンのエンジン。

## Log Watch

<p align="center">

| --- | --- |
| 場所 | dev プリセット（Ctrl+Shift+F4）の、Git と AI チャットの後ろの 3 つめのタブ。ピッカー（Ctrl+Shift+A）の "log watch"。1 ファイルにつき 1 ペインで、複数追加できます。ポップアップと前面表示（Ctrl+Shift+Z）ができます。 |
| 読むもの | **SELECT LOG FILE** で選んだ、1 ペインに 1 つのログファイル（ファイルだけ。Windows のイベントログ、journald、macOS の `log stream` は読みません） |
| 更新 | ペインが見えている間だけ。フォルダーを監視し、1 秒ごとにもファイルを確かめ、追記された分だけを読んで、0.25 秒ごとにペインへ届けます。隠れている間は何もせず、通知もしません。 |
| プラットフォーム | Windows: 別のプロセスが開いたまま追記するファイルは通知が遅れることがあり、ネットワークドライブや `\\wsl$` では通知が来ないことがあります。1 秒ごとの確認がどちらも補います。Mac では Ctrl の代わりに ⌘ です。macOS と Linux では手で確かめていません。 |
| プライバシー | ファイルには何も書かず、中身をどこにも書き出しません。**EXPLAIN** が送るのは選んだ行だけで、**SEND** を押したときだけです。 |
| 設定 | ペインごと: 文字コード、時刻の見せ方、WRAP、繰り返しを畳むか、CHART、ERROR BAR、MASK、EXPLAIN のプロバイダとモデル、ミュートしたパターン。全ペイン共通: 保持する行数と開いたときに読む行数（`settings.json` の `logWatch`）。 |

ファイルを選ぶ:

- **SELECT LOG FILE** でシステムのファイル選択が開きます。これまでに選んだファイルは RECENT に並びます（40 件まで）。レイアウトに入るのは id だけで、パスはアプリのデータフォルダーの `log-files.json` にあります。
- **FOLLOW THE NEWEST LIKE IT** は、同じフォルダーで名前が数字だけ違うファイルのうち一番新しいものを追います。日ごと、実行ごとに新しいファイルを作るログ向けです（`2026-10-12T09_08_16_117Z-debug-0.log` は `*-debug-*.log` になります）。より新しいファイルが現れると乗り換え、その区切りを示します。
- 先頭 8 KB に NUL を含むファイルはバイナリとして断ります。読む権限がなければ CANNOT READ とその理由を、まだ無いファイルは WAITING FOR FILE と示し、現れたら開きます。
- 状態の行のファイル名はボタンです。ポインターを置くとフルパスが、クリックすると別のファイルの選択が開きます。

読み方:

- 開いたときに末尾の行（既定で 500 行。末尾から多くても 4 MB）を読み、あとは追記された分だけを読みます。
- タブの後ろにあるときやウィンドウをしまっている間は何も読みません。戻ったときに、その間に書かれた分をほかの行と同じく最新まで出します（4 MB を超えるときは末尾の 4 MB）。
- ローテーションや切り詰めのあとは先頭から読み直し、*rotated · reading from its start* と示します。ファイルを開いたままにはしません。
- 文字コードは自動で判別し（UTF-8、UTF-16LE/BE、Shift_JIS、EUC-JP、Windows-1252）、手で選ぶこともできます。文字化けしていそうなときは、状態の行に **TEXT LOOKS GARBLED · CHOOSE THE ENCODING ▸** と出ます。

見分ける形式: JSON Lines（pino、bunyan、winston、Serilog など）、logfmt、syslog（RFC 3164 と 5424）、Apache と nginx のアクセスログ、IIS の W3C 形式、よくある「時刻 [レベル] 本文」。ほかはそのままの行として読み、レベルはキーワードから推します。形式はファイルごとに手で指定することもできます。

表示するもの:

- レベルの色分け。スタックトレースはその行の下に折りたたみ（▸ +n で開きます）、同じパターンの連続は ×n にまとめ、初めて見るパターンには **NEW** を付け、エラーが急に増えると **ERROR BURST** を灯します（直近 15 秒のエラーが 5 件以上で、それ以前の 15 秒あたりの平均の 4 倍＋1 以上が 2 秒続いたとき）。
- 上にレベル別の 5 分間の行数（CHART）、右端にエラーと警告の位置（ERROR BAR、クリックでそこへ移ります）。
- 絞り込み（文字列か `/正規表現/`、Escape で消えます）とレベルのトグル、**PAUSE**（読み取りは続け、画面だけを止めて *n HELD* と示します）、**MASK**（IP アドレス、メールアドレス、鍵、`Bearer` のトークン、password・secret・token・key・auth・session・cookie と名の付く値を伏せる）、**WRAP**。
- パターンごとの件数、直近 1 分の推移、最後に見た時刻と **MUTE** の **PATTERNS** タブ。
- ポインターが一覧の上にある間は自動でスクロールせず、新しい行は *▼ n NEW* のボタンに数えます。

EXPLAIN:

- *Settings → AI* にプロバイダがあるときだけ表示します。なければボタンは **EXPLAIN · SET UP AI** になり、その設定を開きます。
- 行をクリックして選びます（Ctrl+クリックで 1 行足し、Shift+クリックで連なりを選ぶ。Mac は ⌘）。**EXPLAIN** は送るとおりの本文を見せ、**SEND** で送ります。**COPY** は同じ行をコピーします。
- **送るのは選んだ行だけです**。スタックトレースは含めますが、前後の行、ファイル名やパス、判定した形式は送りません。絞り込みやレベルで隠れている選んだ行は、送りもコピーもしません。
- MASK がオンなら伏せてから送ります。オフなら送る前の画面に *MASK is off* と出ます。
- 200 行、12,000 字まで。長すぎる選択は切らずに断ります。
- 答えはマークダウンとして描き、HTML としては挿しません。ペインのメモリにだけ持ち、AI チャットの履歴には入りません。同時に 1 件まで、180 秒で打ち切ります。AI の設定の利用者自身のシステムプロンプトを、EXPLAIN 自身のものの後ろに付けます。

保持する行数と読む行数:

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 保持する行数（`logWatch.keepLines`） | 1k、5k、20k、50k | 5k |
| 開いたときに読む行数（`logWatch.initialLines`） | 100、500、2k | 500 |

開発者の Windows の PC での実測: 1 秒に 1,000 行で、main の解析は 0.25 秒分が約 1 ms。保持行数 5k でアプリ全体は main が 1 コアの 0.2%、ページが 2.4% でした（繰り返しを畳めばページは 0.3%）。

試すには、リポジトリのチェックアウトで `node scripts/log-feed.mjs [file] --format=jsonl|logfmt|generic|syslog|clf|plain --rate=20` を実行すると、スタックトレース、エラーの急増、ローテーションを含む架空のログを書きます。

## 共通の振る舞い

- **見えている間だけ読みます。** 4 つとも、ペインが画面に出ている間だけ読みます（AI Agent は開いている間）。最後のそうしたペインがなくなると main の監視、ストリーム、タイマーは止まり、ページを再読み込みしたときも手放します。
- **ネットワークに出るのは**、Git の FETCH・PULL・PUSH と、Log Watch の EXPLAIN が設定した AI プロバイダへ送るものだけです。
- **プラグイン API** はどれにも届きません。
- **パスは main に留まります。** Git と Log Watch はリポジトリとファイルを id で知り、ページがパスを送ることはありません。
- **文字は文字として描きます。** ファイルの中身、ログの行、コミットメッセージを HTML として挿すことはありません。
- **開発者向け:** テストはこの機械に触れません。AI Agent のテストは `ELECDEX_CLAUDE_DIR` を架空のフォルダーに向け、Docker のテストは代役のエンジン（`ELECDEX_DOCKER_STUB=1`）を使い、Git と Log Watch のテストは一時フォルダーで動きます。
