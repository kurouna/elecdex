# Network access and data sources — elecdex

elecdex is a desktop terminal emulator and system monitor for Windows, macOS and Linux. This page lists every place it connects to, what it sends, how often, and under which terms. The page itself (the renderer) has no network access (`connect-src 'self'`); every request below is made by the main process, only while a pane or a setting needs the data, and there is no telemetry or analytics. IP addresses are placed with a bundled GeoIP database, never a lookup service.

| Data | Source | Notes |
| --- | --- | --- |
| Weather, Japan | [Japan Meteorological Agency](https://www.jma.go.jp/) forecast JSON: `https://www.jma.go.jp/bosai/forecast/data/forecast/<office code>.json` | Read directly as JSON, not scraped from the web page. This is the data JMA's own [forecast page](https://www.jma.go.jp/bosai/forecast/) loads, not a documented API, so it is parsed leniently and the last forecast stays on screen if it fails. Fetched only while a weather pane shows a place in Japan, around JMA's publication times (0, 5, 11 and 17 o'clock JST), with conditional requests. Used under JMA's [terms of use](https://www.jma.go.jp/jma/kishou/info/coment.html), which ask for the credit 「出典：気象庁ホームページ（https://www.jma.go.jp/bosai/forecast/）を加工して作成」; the pane shows it, naming the forecast page the JSON belongs to. |
| Weather, United States | [National Weather Service](https://www.weather.gov/) (api.weather.gov) | Open data. The point lookup is kept for a day; the forecast is asked for about hourly, only while a pane shows the place. |
| Weather, everywhere else | [MET Norway](https://api.met.no/) Locationforecast 2.0 | [CC BY 4.0](https://api.met.no/doc/License), credited in the pane. Requests follow the [terms of service](https://api.met.no/doc/TermsOfService): an identifying User-Agent, coordinates to four decimals, nothing before the `Expires` of the last response (and at least 30 minutes apart), If-Modified-Since. |
| City list for the weather picker | [GeoNames](https://www.geonames.org/) (cities of 500,000 people or more, and capitals) | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); bundled. Nothing typed in the picker is sent anywhere. |
| Market quotes | [Yahoo Finance](https://finance.yahoo.com/), through yahoo-finance2 | Unofficial API, not endorsed by Yahoo; quotes may be delayed and are not investment advice (the pane says so). Fetched only while a markets pane is open: one batched request a minute (every five minutes when every listed market is closed), and each chart every five minutes (1D) to hourly (6M and longer). |
| Earthquakes | [Japan Meteorological Agency](https://www.jma.go.jp/) earthquake list JSON: `https://www.jma.go.jp/bosai/quake/data/list.json` | The data JMA's own [earthquake page](https://www.jma.go.jp/bosai/map.html#contents=earthquake_map) loads (about a month of reports), read as JSON. Fetched only while a quakes pane is seen or earthquake alerts are on: once a minute, as its `max-age=60` asks, with If-None-Match, so an unchanged list is a 304. Used under JMA's [terms of use](https://www.jma.go.jp/jma/kishou/info/coment.html); the pane credits 「出典：気象庁ホームページ（URL）を加工して作成」 and the alerts name JMA. Not the Earthquake Early Warning. |
| Tsunamis, Japan | JMA tsunami list JSON: `https://www.jma.go.jp/bosai/tsunami/data/list.json` and each report it names | Checked with the earthquake list (usually an empty list, a 304 after the first request); a new report's details are fetched once. Warnings, major warnings and advisories count; forecasts and liftings do not. Credited like the earthquakes. |
| Earthquakes, world | [USGS](https://earthquake.usgs.gov/) real-time feed `summary/4.5_day.geojson` | Public domain. Fetched only while the world source is in use by a quakes pane or alerts: once a minute (its `max-age=60`), conditionally. |
| Tsunamis, world | [NOAA Tsunami Warning Centers](https://www.tsunami.gov/): the Pacific (`PHEBAtom.xml`) and National (`PAAQAtom.xml`) Atom feeds | Public domain. Each holds the centre's latest bulletin; warnings, watches, advisories and threat messages count, information statements do not. Checked with the USGS feed, conditionally. Alerts say to follow local authorities. |
| RSS feeds | The feed URLs you list in an RSS pane | Fetched by the app, never by the page, only while a pane lists them: every 15 minutes (or as the feed asks, at most hourly), conditionally (If-None-Match / If-Modified-Since), two at a time, up to 2 MB each, without cookies and with an `elecdex/<version>` User-Agent. Headlines are shown as plain text; the last ones per feed are kept in `feeds-cache.json` in the app's data folder. Nothing is sent to any other site. |
| AI chat | The providers you list in *Settings -> AI*: a server on your computer or network, or a hosted API (Anthropic through its [official SDK](https://github.com/anthropics/anthropic-sdk-typescript); the rest as OpenAI-compatible `chat/completions`) | Asked by the app, never by the page, and only when you send a message, press **test** or open a pane's model list - a chat pane sitting in a layout calls nobody. What is sent is the conversation so far (with the files you attached to it), your system prompt and the model's name, to the address you chose and nowhere else; each provider's own terms and data retention apply. A request on Anthropic's dialect offers Claude Anthropic's web search (`web_search`, at most 5 searches an answer); Claude decides whether to search, the search runs at Anthropic and is billed per search there, and the pages it cited are listed under the answer, as Anthropic asks. No cookies, no redirects followed. An API key is encrypted by the operating system (DPAPI, the Keychain, the desktop's keyring) into `ai-keys.json`, apart from `settings.json`, and is never shown again; where the system cannot encrypt, it is kept in memory until elecdex quits. A key goes only to the address it was entered for: change a provider's address and its key is sent nowhere until you enter it again. A key is refused for a plain-http address outside your computer and local network. With no key of its own, the Anthropic SDK looks where it always does (`ANTHROPIC_API_KEY`, an `ant auth login` profile). On Anthropic's own endpoint, `claude-opus-5` and `claude-fable-5-1` are asked with server-side fallbacks (`fallbacks: "default"`), so a request their safety classifiers decline is re-run on another Claude model in the same call; the answer names the model that wrote it. Conversations are files in `chats/` in the app's data folder. |
| ELEC system | The same providers, as each seat names them | As for the AI chat, and only when you submit a motion (or open a model list): each unit is sent its standpoint, the voting instructions and the motion - in a second round, the other units' first statements too. Three requests a round, one or two rounds. Deliberations are files in `elec/` in the app's data folder. |
| Web panes | The sites you open in a browser, YouTube or X pane | Loaded by a sandboxed browser view of the app, as a browser would, only while such a pane exists; elecdex itself sends nothing to them. Cookies and site data are kept in the app's data folder (`Partitions/web`) until *sign out of all sites*. YouTube and X are used under their own terms. |
| Orbital elements | [CelesTrak](https://celestrak.org/) GP data (from the 18th and 19th Space Defense Squadrons via [Space-Track.org](https://www.space-track.org/)): `GROUP=stations` as OMM JSON, `GROUP=starlink` as TLE | Positions are computed on your computer; only elements are downloaded. Following CelesTrak's [usage policy](https://celestrak.org/usage-policy.php): only while an ORBIT pane shows the set, the stations at most twice a day and Starlink at most once a day (CelesTrak updates every two hours), kept on disk across restarts, an identifying User-Agent, and nothing more for a day after any answer but a 200. Credited in the pane. |
| Wi-Fi pane | Your own gateway, and `1.1.1.1` (the host the network status pane already pings) | One echo to each a second, and only while a Wi-Fi pane is on screen; the internet's echo is the one the network status pane reads too, so the host is not asked twice. The rest - the signal, the channel, the connection log - is read from the operating system, never from a service. On Windows the network's name comes from the connection profile and nothing behind the location permission is read (no BSSID, no scan); on macOS the name stays hidden without Location Services, which elecdex never asks for. |
| Ethernet pane | Your own gateway, from the wired adapter's own address, and `1.1.1.1` | As the Wi-Fi pane: one echo to each a second, only while the pane is on screen, the internet's echo the one the Wi-Fi and network status panes read too. The link, its counters and the driver's settings are read from the operating system and never changed; the adapter's ids and the network's name are not read. |
| Update check | [GitHub Releases API](https://docs.github.com/rest/releases/releases#get-the-latest-release) | One request for the latest published release, 15 seconds after start and then daily, while enabled (the default). Nothing is downloaded or installed: a newer release shows a notice that opens its page. |
| Translation engine and models | [Hugging Face](https://huggingface.co/pfnet) (`pfnet/plamo-3-translate-*-GGUF`, the newest version of each, and its revision API) and [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases) on GitHub (build b12110) | Fetched only when you press **Agree and fetch** in a TRANSLATE pane's setup: the llama-server build for your platform (about 62 MB on Windows) and the model you chose (0.4 to 19.5 GB). The model's newest version is asked of Hugging Face's revision API as the licence is agreed to, and opening the engine settings asks it again for the models in place, at most once every 24 hours (an update is fetched only when you press **Update**). The engine is checked against the sha256 elecdex pins, a model against the size and sha256 Hugging Face gives for its version; a paused or broken download resumes with a ranged request. Nothing you translate is sent anywhere: the engine runs on 127.0.0.1 with a key of its own, unless you choose a llama-server at another address, which then receives the text. The model is used under the [PLaMo Community License](https://plamo.preferredai.jp/info/plamo-community-license-ja), read on Preferred Networks' site and agreed to in the setup, with the download. llama.cpp's MIT licence, and those of the code built into it, come with elecdex and are written beside the engine: nothing is fetched for them. |
| AWS STATUS pane *(unreleased)* | Your own AWS account's APIs, through your own AWS CLI v2 (`aws`), under the profile the pane names | elecdex starts the CLI directly (no shell), only while an AWS STATUS pane is seen, and never sees a credential: the CLI signs in and makes the requests. Read only, read-only operations only: free APIs, plus CloudWatch's `GetMetricStatistics`, `ListMetrics` and `DescribeAlarms`, which count against CloudWatch's free tier of 1 million requests a month shared by the whole account. Never `GetMetricData`, CloudWatch Logs, S3, Secrets Manager, Health or Support. Each reading at its own period, from 5 minutes (alarms, impaired instances) to a day (certificates, domains, S3 sizes); SLOW ×4 makes them four times as long. The one paid API, Cost Explorer ($0.01 a request, two requests a reading), is called only after you turn it on for the account, at most once a day or every 12 hours, and stops at your monthly cap (100 requests, $1.00, by default). Every read is recorded by CloudTrail as a management event of your account. Unit prices for ACTIVE's estimates are shipped with elecdex; the Price List API is not called. The permissions are [below](#aws-status-permissions). Details: [Cloud panes](panes-cloud.md#aws-status). |
| GITHUB STATUS pane *(unreleased)* | [GitHub's API](https://docs.github.com/rest) on github.com, through your own GitHub CLI (`gh`) | Started directly, only while a GITHUB STATUS pane is seen; the token stays in `gh`. Only `gh api -X GET …`, read-only GraphQL queries and `gh auth status --json hosts`. Notifications every 60 seconds as GitHub's `X-Poll-Interval` asks, with If-Modified-Since (a 304 costs no rate limit); the queue every 5 minutes, the repositories every 15, events and workflow runs every 5 (conditionally), contributions, private vulnerability reports and commits since the release hourly, traffic views every 6 hours. Nothing is written to GitHub; no notification is marked read. Daily star counts of public repositories are kept in `github-stars.json` (90 days). Used under GitHub's terms, as `gh` is. Details: [Cloud panes](panes-cloud.md#github-status). |
| Public status of AWS and GitHub *(unreleased)* | [AWS Health Dashboard](https://health.aws.amazon.com/health/status)'s RSS feed `https://status.aws.amazon.com/rss/all.rss`; [GitHub Status](https://www.githubstatus.com/)'s `api/v2/incidents/unresolved.json` and `api/v2/scheduled-maintenances/active.json` | Fetched by main without the CLI and without signing in, every 5 minutes and only while a pane of that service is seen. The AWS feed is about 60 KB a time (conditional requests do not work there); GitHub's answers are a few hundred bytes when nothing is wrong, and conditional. Shown as a band only while an incident is open, and as a toast (on by default, `aws.incidents` / `github.incidents`); the incidents told are kept in `cloud-alerts.json` for 30 days. It is the service's public status, not your account's. |

## AWS STATUS permissions

*Unreleased.* AWS's managed policy `ReadOnlyAccess` (or `ViewOnlyAccess` with `AWSBillingReadOnlyAccess`) covers every read. For a policy of your own, these are the actions the pane calls; one refused shows PARTIAL and the operation's name, and the rest go on:

| Service | Actions |
| --- | --- |
| STS, IAM | `sts:GetCallerIdentity`, `iam:ListAccountAliases`, `iam:GetAccountSummary`, `iam:GenerateCredentialReport`, `iam:GetCredentialReport` |
| CloudWatch | `cloudwatch:DescribeAlarms`, `cloudwatch:GetMetricStatistics`, `cloudwatch:ListMetrics` |
| Billing | `budgets:ViewBudget`, `freetier:GetAccountPlanState`, `freetier:GetFreeTierUsage` |
| EC2, load balancers | `ec2:DescribeInstances`, `ec2:DescribeInstanceStatus`, `ec2:DescribeVolumes`, `ec2:DescribeAddresses`, `ec2:DescribeNatGateways`, `ec2:DescribeSecurityGroups`, `ec2:DescribeReservedInstances`, `elasticloadbalancing:DescribeLoadBalancers` |

| Others | `cloudformation:ListStacks`, `cloudtrail:LookupEvents`, `acm:ListCertificates`, `route53domains:ListDomains`, `savingsplans:DescribeSavingsPlans`, `backup:ListBackupJobs`, `guardduty:ListDetectors`, `guardduty:GetFindingsStatistics` |
| Cost Explorer, only when turned on | `ce:GetCostAndUsage`, `ce:GetCostForecast` |
