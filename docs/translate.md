# TRANSLATE ペイン 設計

Preferred Networks の翻訳特化モデル PLaMo 3 Translate を、llama.cpp の `llama-server` でこの PC の上で動かし、
elecdex のペインから使う翻訳ペイン。訳す文はこの PC から出ない（利用者が外部のサーバーを選んだときは別、§4.1）。
外に出る通信はエンジンとモデルのダウンロードだけ。**段階 5 まで実装済み、未リリース**（2026-11-06。§12）。要約は
architecture.md §5.25。

見た目のたたき台はモック [translate-mock/index.html](translate-mock/index.html)（ブラウザで開くだけで動く。
訳文・数値・パスはすべて作り物）。機能の裏付けは、利用者が別に作った Electron のテストアプリ
（PLaMo3TranslateTest、React。elecdex とは別のリポジトリ）で確かめた。§13 にそこから得たことをまとめる。

## 1. 目的と非目的

**目的**

- elecdex を離れずに、手元で文を訳す。訳す文は外に出さない
- 長い文も段落ごとに対応が見え、用語と文体がそろう（用語集・文脈・常体／敬体・やさしい日本語）
- 初めての人が、エンジンとモデルを迷わず用意できる（セットアップ）

**非目的**

- 外部の翻訳サービス（DeepL、Google など）への接続。AI チャットのプロバイダで訳すこともしない
- ファイル（.docx、PDF）の翻訳。.txt / .md を落として訳すのは後の候補（§12）
- 音声、画像（OCR）、ウェブページの翻訳
- モデルの学習・微調整、PLaMo 以外のモデル

## 2. PLaMo 3 Translate（確かめた事実）

- **モデル**: `pfnet/plamo-3-translate-{0.8b,2b,8b,31b}-GGUF`。量子化は Q4_K_M（既定）・Q4_0（0.8B と 2B だけ）・Q3_K_M・Q2_K。
  Q4_K_M の大きさ: 0.8B 573 MB、2B 1.81 GB、8B 5.28 GB、31B 19.53 GB。Q2_K は精度の低下が目立つ。
- **llama.cpp**: PLaMo3 の対応は PR #17304 で入った（b7563 以降。テストアプリの調べによる記録で、ここでは
  確かめ直していない）。テストアプリは **b12110**（v0.9.0 と同じコミット cd959bae）で動くことを確かめた。
- **言語**: 53（`ja`, `en`, `zh-hans`, `zh-hant`, `ko`, …）と、訳先だけに使える **`ja(easy)`（やさしい日本語）**。
  コードは小文字で、地域を付けない（`en-US` は不可）。
- **オプション**: `source_lang`（省略でモデルが判定する。判定した言語は返ってこない）、`context`、`glossary`、
  `form`（`plain` / `polite`、訳先が `ja` のときだけ。`ja(easy)` には付けられない）、履歴（前の原文と訳文の組）。
- **コンテキスト**: 学習時の上限は入出力の合計 32,768 トークン。公式例は `-c 16384`。
- **生成**: `temperature 0`、stop は `<|plamo:tag|>` と `<|plamo:bos|>`。BOS は llama.cpp が付ける。
- **llama-server**: `LLAMA_API_KEY` は `--api-key` の環境変数。`/health` は読み込み中 503、済めば 200。
  `/completion` の最後のチャンクに `stop_type` と `timings`。`/tokenize` は `add_special` / `parse_special` を取る。
- **ライセンス**: PLaMo Community License。個人・非商用は無料、年商 10 億円以下の商用は登録で無料、超えれば別契約。

**プロンプト（PFML3）**: 公式の `chat_template.jinja` と同じ並び（テストアプリで、テンプレートを llama-server で
展開した結果とバイト単位で一致することを確かめた。レビューでも構造を突き合わせた）:

```
<|plamo:tag|>dataset<|plamo:msg|>translation
[<|plamo:tag|>context<|plamo:msg|>{文脈}]
(<|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{src}]<|plamo:msg|>{前の原文}
 <|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{tgt}<|plamo:msg|>{前の訳文})*
[<|plamo:tag|>glossary(<|plamo:index|>{原語}<|plamo:item|>{訳語})+]
<|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{src}]<|plamo:msg|>{原文}
<|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{tgt}[<|plamo:key|>form<|plamo:val|>{form}]<|plamo:msg|>
```

（改行は読みやすさのため。実際は続けて書く。）

## 3. 画面構成

モックのとおり。ペインの見出しは `TRANSLATE`、副題にモデル（`plamo-3-translate-2b · Q4_K_M`）。

- **ツールバー**: TEXT / HISTORY の切り替え（クリップボードペインと同じ ViewToggle）、翻訳元（AUTO と 53 言語）、
  入れ替え、訳先（53 言語とやさしい日本語）、FORM（PLAIN / POLITE、訳先が日本語のときだけ）、GLOSSARY、CONTEXT、
  ROUND TRIP、LIVE。右端に設定のスライダー（`SettingsButton`）で ENGINE の画面。
- **言語の選択**: 絞り込みのできる一覧、最近使った言語を上に（ペインの状態に 5 つまで）。各言語のボタンの真下に
  開き、開閉は CRT（`transition:crtPower`）。ペインの中に描くものなので `tests/e2e/contracts/dialogs.ts` の対象外で、
  translate.spec が受け持つ（dialogs.ts の頭の注のとおり）。翻訳元が AUTO のときは、判定が確かなときだけ「≈ EN」と
  添える（§6.5、段階 3）。AUTO からの入れ替えは、判定ができるまで出さない。
- **原文と訳文**: シェルと同じ切り欠きの枠を 2 枚、間に**背骨**。ブロック（§6.1）ごとに背骨の上に番号のランプと
  対応線を引き、ブロックか番号にポインタを置くと両側が光る。番号の詳細カード（トークン数・時間・使った履歴）は
  `widgets/common/HoverCard.svelte` と `lib/hover-card.ts` で、カードの一覧の単体テストに足す。
- **訳文のブロック**: main が 100 ms ごとにまとめて送る差分を書く（キャレットは共有のパルス）。書き終えたら
  fx-fresh のバー。訳している間は訳文の枠をアクセント色にする。ブロックごとに RETRY / EDIT / COPY。
- **止める**: 訳している間、TRANSLATE のボタンが **STOP** になる（Ctrl+. でも止まる）。Esc はポップアップでは
  ポップアップを閉じるのに使われる（PopupPane が先に取る）ので、止めるキーにはしない。止めたブロックは「止めた」と
  添えて薄く残し、後ろのブロックは「訳していない」と出す。完了とは見せない。
- **状態**: NO MODEL（セットアップへ）、STANDBY（エンジン停止中。最初の翻訳で起動）、BOOT（llama-server の
  ログを 1 行ずつ）、TX、READY、FAULT（終了コードと stderr の末尾、RESTART、ENGINE へ）。読み込み時の GPU の失敗は
  CPU へ切り替えて続くので（§4.2）FAULT にならない。FAULT は CPU でも起動できない、または動いている途中で落ちて
  再起動の回数を越えたとき。
- **足元**: ランプとエンジンの要約（ビルド、GPU か CPU、コンテキスト、`127.0.0.1:ポート`。メモリは測らないので出さない）。ポートは
  main が表示用に送る値で、キーは送らない（ポートだけでは使えない）。右に「Built with PLaMo · PLaMo 3 Translate · PLaMo
  Community License · llama.cpp」（ライセンス第 4 条の表示、2026-11-06）。エンジンがこの PC のものなら「local, nothing leaves this PC」、外部のサーバーなら
  「sent to <ホスト>」（ループバック以外は警告の色）。
- **SETUP**: ENGINE → MODEL → LICENCE → FETCH → READY（試し訳 1 文）。LICENCE の段の同意は、確認のダイアログでは
  なくペインの中の段なので dialogs.ts の対象外。
  - **LICENCE の段**（2026-11-06、利用者の依頼）: 同意は 2 つ。(1) PLaMo コミュニティライセンス。ペインの要約は
    目安で、効力があるのは PFN のサイトの本文（変わりうる）なので、ペインからそのページを開くまでチェックできない
    （その旨を書く）。商用の行には、仕事・組織内・製品やサービスの開発での利用は商用（第 1 条）と書き、登録フォーム
    （第 3 条が示すもの）へのリンクを置く。(2) ダウンロード。**Agree and fetch** が取るもの（モデルのファイルと大きさ・
    huggingface.co、elecdex がエンジンを取るときは llama.cpp のビルドと大きさ・github.com・MIT）を並べる。両方に
    チェックして初めて進める。前に同意したモデルなら両方チェック済みで開く。
  - **同意の記録**: main は `engine.json` の `consents`（アプリが使う最新のもの）に加えて、
    `translate/licence-consents.txt` に 1 件ずつ追記する（書き換えない。トラブルのときの証拠として人が読める形）:
    日時、モデル、ライセンスの名前とアドレス、そのページを elecdex から開いた日時、同意した 2 つの文、モデルの
    リポジトリ@リビジョン・ファイル・バイト数・sha256、取得するものの URL、elecdex の版。記録を先に書き、書けたときだけ
    `engine.json` に同意を置く（記録できなかった同意では取得しない）。
  - 開くページは名前で指す（`LICENCE_PAGES`: `plamo`・`register`・`llama`）。ページがアドレスを渡すことはない。
- **HISTORY**: 絞り込み、日ごとの区切り、行を押すと TEXT に戻して開く。CLEAR は 2 度押し。
- **ENGINE**: エンジンの入手先、状態（STOP / RESTART）、モデルの一覧（取得・削除・切り替え）、実行の設定
  （コンテキスト長、デバイス: AUTO（GPU、だめなら CPU）/ CPU だけ、止めるまでの時間）、ログ、ライセンスへの同意の記録。
  **モデルの選択は仮**（2026-11-06、利用者の依頼）: ENGINE と SETUP で選んだモデルは、取得済みのモデルで DONE を押した
  とき、または SETUP で取得を始めたとき（main は設定のモデルを取得する）にだけ設定の `modelId` に書く。ほかの抜け方
  （設定のボタン、HISTORY など）では元に戻す。未取得のモデルを選ぶと DONE は「Set up this model」になり、MODEL の段へ行く。
- **狭いペイン**: 原文の下に訳文。背骨は横の線になり、対応はポインタを置いたときの光だけで見せる。

## 4. エンジン（llama-server）

### 4.1 入手（Q1）

**A（決定）: セットアップで、elecdex が固定したビルドを取ってくる。** テストアプリの `scripts/fetch-llama.mjs` の
手順を、main を止めない形で行う。

- ビルドは 1 つに固定する（今は b12110）。プラットフォームごとに GitHub のリリースのアセット名と sha256 を
  マニフェスト（`shared/translate/engines.ts`）に持つ。Windows x64 は Vulkan と CPU、Windows arm64 は CPU、
  macOS arm64 は Metal、macOS x64 は CPU、Linux x64 は Vulkan と CPU。Windows x64 はダウンロードで約 62 MB
  （Vulkan 38 MB ＋ CPU 25 MB の zip）、展開して約 132 MB。
- 取得はモデルと同じ取得器（§5）で、`.part`・Range・再試行・sha256（worker）も同じ。確かめてから、
  **新しい一時フォルダ**（`translate/engine-tmp-<乱数>/`）に `tar` で展開し、llama-server とその DLL / so / dylib
  以外を消し、llama.cpp のライセンス一式を `LICENSE-llama.cpp` として置いてから、`translate/engine/<build>/<target>/` へ
  名前を変えて置く。途中まで展開したフォルダがエンジンと取り違えられることはない。`engine-tmp-*` は起動時に消す。
- `tar` は OS のもの（Windows は `System32\tar.exe`。bsdtar は zip も開ける）を **`execFile` で非同期に**走らせる
  （テストアプリの `execFileSync` は main を数秒止める）。
- 版を上げるのは elecdex のリリースでマニフェストを変えたときだけ。古いビルドのフォルダは、新しいビルドで
  エンジンが起動できたら消す（まだ実装していない。ビルドを上げる最初のリリースで入れる）。

ほかの入手先も選べる（ENGINE 画面）。どれを使うかと、その中身は main だけのファイル `translate/engine.json`
（§8.1）に置き、設定のパッチ（`settings.patch`）では変えられない（`git.openCommand` と同じ理由: ページが任意の
実行ファイルを起動させたり、訳文を任意のホストへ送らせたりできないように）。

- **自分の llama-server**: main のファイル選択でだけ選ぶ（ページからパスは受け取らない）。`--version` でビルド番号を
  読み、b7563 より古ければ断る。
- **外部のサーバー**: 既に動いている llama-server のアドレス。elecdex は何も起動しない。アドレスは `http:` か
  `https:` の URL で、ユーザー情報（`user:pass@`）なし、パスは捨てる。リダイレクトは辿らない（`redirect: 'error'`、
  openai.ts と同じ）。TEST で `/props` を読み、`model_path` に `plamo-3-translate` を含むかを見る。401 なら
  「キーが要るサーバー（まだ対応していない）」と言い、PLaMo ではないとは言わない。

**B（採らない、テストアプリの方式）: アプリに同梱する。** 展開して約 132 MB（Windows）。翻訳を使わない人も含めて
全員の配布物が大きくなる。

**C（採らない）: 利用者が入れたものだけを使う。** 版がまちまちで、古い版は PLaMo3 を読めない。A に加えて
「自分の llama-server」として選べる。

### 4.2 起動

```
llama-server -m <model.gguf> -c <ctx> --host 127.0.0.1 --port <空き番号> --alias plamo-3-translate
  --no-webui -np 1 --log-colors off [-ngl 0（CPU のとき）]
```

- API キーは起動ごとに乱数で作り、**環境変数 `LLAMA_API_KEY`** で渡す（コマンドラインに残さない）。キーは main の
  外へ出さない。
- `/health` を 250 ms ごとに見て、200 で READY。**諦めるのは**、プロセスが終わったとき、stdout / stderr に
  **1 バイトも**出ないまま 60 秒たったとき（行で数えない: llama.cpp はテンソルの読み込みの進みを改行なしの点で
  書くので、大きなモデルでは何十秒も新しい行が出ない）、または外枠の「2 分 ＋ モデル 1 GB あたり 1 分」を
  過ぎたとき（31B を HDD から読むと 2 分では足りない）。ただし llama-server 自身が書く `/health` の要求の記録の行
  （`log_server_r: … /health`）は数えない（250 ms ごとの確かめが毎回 1 行書くので、数えると 60 秒が来ない）。
  60 秒はテストでだけ `ELECDEX_LLAMA_STALL_MS` で短くできる。
- デバイスが AUTO なら、GPU のビルドを `--list-devices` で GPU があるかを確かめてから使い、起動に失敗したら CPU の
  ビルドで起動し直す（理由を ENGINE 画面に出す）。`--list-devices` の結果はビルドごとに `engine.json` に覚える。
- 古い起動要求は世代番号で捨てる（モデルの切り替えを続けて押したとき）。
- stdout / stderr は 400 行のリングバッファ。FAULT には最後のエラー行を添える。
- PID ファイルを置き、次の起動で、そのプロセスが llama-server であることを確かめてから終わらせる。確かめ方は
  同期の `tasklist` / `ps` を使わない（非同期に 1 度だけ）。
- **新しい `spawn` は全部測る**（main で同期）: llama-server、`--version`、`--list-devices`、`tar`、孤児の確かめ。
  decisions.md に書く。

### 4.3 寿命

- **最初の翻訳で起動する**（ペインを開いただけでは起動しない。約 1.9 GB を使うため）。
- **止め時計だけで止める**: 最後の翻訳から 10 分（設定: 5 / 10 / 30 分 / 止めない）。最後の TRANSLATE ペインを
  閉じても、それだけでは止めない（Ctrl+Shift+Y でポップアップを出しては閉じる使い方で、毎回起動を待たせないため）。
  elecdex を終えるときは必ず止める: `before-quit` で、`ptyIpc.closeSessions()` の隣に、llama-server の同期の kill、
  取得の PAUSE（fetch を abort して書き込みのストリームを閉じる）、sha256 の worker の終了を置く。`will-quit` は
  チャネルの表を片付けるだけ。
- **異常終了**: 10 分に 1 回まで自動で再起動する。それより多ければ FAULT で止まり、利用者の RESTART を待つ
  （テストアプリは READY のたびに数え直していたので、起動するたびに落ちる状態で再起動を繰り返した）。
- **見えていない間**: LIVE の依頼は始めない（ページが隠れたら、そのペインの LIVE の依頼を取り消す）。TRANSLATE で
  頼んだ依頼は、待ち行列で待っていても書いている途中でも、隠れても続ける（「書いている答えは隠れても続く」の規則）。
- モデルを削除する前にエンジンを止める（Windows はファイルが掴まれている）。

## 5. モデル

- マニフェスト（`shared/translate/models.ts`）にリポジトリ、**リビジョン（コミット SHA）**、ファイル名、バイト数、
  sha256、必要なメモリの目安を持つ。URL は `<HF の基点>/<repo>/resolve/<revision>/<file>`（基点は既定で
  `https://huggingface.co`、テストでは `ELECDEX_HF_BASE_URL`）。
- 取得器（`main/translate/fetcher.ts`、エンジンと共用）は `net.fetch`。`.part` に書き、HTTP Range で再開。
  206 なのに Content-Range の始まりが合わない、Range に 200 が返った、ときは最初からやり直す。失敗は 1 s から
  15 s まで倍にして 5 回まで。取得の前に空き容量を確かめる（残りの大きさ＋256 MB）。進捗は 200 ms ごと、速さは
  指数平滑。
- 終わったら sha256 を **worker** で確かめ、合えば `replaceFile` で置く（1.8 GB を main で回すと、4 MB ずつでも
  main が止まる時間が積み重なる。テストアプリは main で計算していた）。
- ライセンスへの同意は、モデルごとに、日時・リビジョン・ライセンスの URL を `engine.json` に記録し、
  `licence-consents.txt` に追記する（§3）。別のモデルを取るときも、その都度同意を求める。
- **llama.cpp のライセンス**（2026-11-06）: リリースの zip には LLVM の OpenMP（`LICENSE-LLVM-OpenMP`）しか入って
  いない。llama.cpp の LICENSE（MIT）と、llama-server に組み込まれたコード（nlohmann/json、cpp-httplib、xxHash、
  sha256、rotate-bits、SHA-1、miniaudio、stb_image、subprocess.h）のライセンスを、`npm run gen:llama-licenses` が
  そのビルドのコミットから `resources/translate/llama.cpp-licenses.txt` に集め、main に `?raw` で組み込む。取得の
  たびに取りに行くことはしない（以前は取りに行き、失敗すると 1 行の代わりを書いていた）。ビルドを変えたら走らせる
  （translate-licences.test.ts がビルドとコミットの一致を見る）。
- 一度に 1 つ（エンジンかモデル）。PAUSE は `.part` を残し、CANCEL は消す。ペインを閉じても続く。elecdex を
  終えるときは PAUSE と同じにし、次の起動では PAUSE のまま利用者の RESUME を待つ（勝手に再開しない）。
- `chat_template.jinja` は取らない（`/completion` に PFML3 を直接渡すので要らない）。

## 6. 翻訳

### 6.1 単位と順番（Q7）

- **ブロック**: 原文を**空行**（空白だけの行を含む、1 行以上）で区切ったもの。ブロックの中の 1 つの改行は
  そのまま残す（折り返した文や箇条書きはまとめて 1 ブロック）。空行のない文は全体で 1 ブロック。ブロックが背骨の
  1 つの番号になる。
- **ブロックごとに、順番に訳す**。前の 2 ブロックの原文と訳文を履歴として渡し、用語と文体をそろえる。
- **長いブロック**: 512 トークンを超えるブロックは文（`Intl.Segmenter`）に、それでも長い文は文字数で分け、
  分けた部分を順に訳して元の区切りでつなぐ（部分どうしも前の部分を履歴に渡す）。背骨では 1 つの番号のまま。
  テストアプリのように**まとめて詰めることはしない**（1 ブロックが 1 つの番号に対応しなくなる）。
- 区切りの空行と行頭の空白は原文のものを訳文に戻す。原文は 20,000 字まで。
- llama-server は 1 スロット（`-np 1`）。コンテキストを分け合わずに済み、履歴を渡すと順番になるので並列の意味が
  薄い。
- **LIVE**（既定でオン）: 打ち終えて 0.6 秒で頼む。覚えておく鍵は「ブロックの原文・言語・文体・文脈・用語集」の
  ハッシュで、鍵が同じブロックは訳し直さない。履歴は鍵に入れない（入れると 1 ブロックの手直しで後ろが全部
  訳し直しになる）。全部を訳し直すのは TRANSLATE（Ctrl+Enter）。
- **EDIT**: 直したブロックは、**その後に訳すブロック**の履歴に使う。訳し終えている後ろのブロックは訳し直さない。
  そのブロックの RETRY か、TRANSLATE で全部を訳し直す。

### 6.2 依頼の組み立て

- PFML3 は `shared/translate/pfml3.ts` の純粋な関数で組み立てる（テストアプリのものとテストをほぼそのまま持ち込む）。
- 原文・文脈・用語・履歴の `<|plamo:` は `<|`＋ゼロ幅スペース＋`plamo:` にしてから入れる（公式テンプレートは
  この文字列を含む入力を拒む。elecdex は拒まず無害化する）。表示の前に戻す。訳文にもともと `<|`＋ゼロ幅スペース
  ＋`plamo:` があった場合もそれは戻ってしまうが、実際にはまず起きないので受け入れる。
- `/tokenize` で数え、出力の上限は「コンテキストの残り」と「入力の 4 倍（最低 256）」の小さいほう。収まらなければ
  古い履歴から減らし、それでも入らなければ「長すぎる」と言う（切らない）。
- `/completion` に `stream: true`、`cache_prompt: true`。OpenAI 互換の `/v1` は使わない（`timings` と `stop_type` が
  欲しい）。`stop_type` が `limit` なら、そのブロックに「上限で切れた」と出す。
- ストリームが stop の印なしで終わったら、そのブロックは失敗（途中までを完了として扱わない）。
- 差分は main で集め、**100 ms ごとに**まとめてページへ送る（AI チャットの `FLUSH_MS` と同じ。ローカルのモデルは
  1 秒に数百トークン出すので、トークンごとの IPC と `$state` の書き換えはしない）。

### 6.3 用語集・文脈・文体・やさしい日本語

- **用語集**: 名前を付けて複数持てる。原文に出てくる用語だけを、長い順に最大 50 件入れる。端が英数字の用語は
  隣も英数字なら別の語の一部とみなす（"pane" は "panel" に当たらない。日本語のように空白で区切らない文字は
  隣を見ない）。**用語集に訳先の言語を決められ**、違う言語へ訳すときは使わない（日本語の用語集はやさしい日本語
  にも使う。やさしい日本語だけの用語集は作らない: やさしい日本語へ訳すペインで作ると日本語の用語集になる）。使わなかったことは足元に出す。TSV / CSV の貼り付けで取り込める（1 回 5,000 件まで）。
- **文脈**: 2,000 字まで。訳さずに毎回渡す。
- **文体**: 訳先が `ja` のときだけ。`ja(easy)` では出さない。
- **やさしい日本語**: 訳先の一覧で日本語の下に置く。翻訳元には出さない（入れ替えると日本語になる）。

### 6.4 ROUND TRIP

訳し終えたブロックを、原文の言語へ訳し戻してブロックの下に出す。訳し戻しはもう一度エンジンを回すので、ROUND TRIP を
押したときだけ。一致度（chrF、文字の n-gram）を数字と棒で添え、70 未満を警告の色にする（Q6）。原文の言語は、
翻訳元を選んでいればそれ、AUTO なら判定（§6.5）が確かなときだけその言語。確かでなければ、ROUND TRIP を押したときに
翻訳元の言語を選んでもらう。

- 依頼は `roundTrip` のチャネル（§8.3）。そのペインの依頼の一部として、同じ待ち行列で 1 ブロックずつ訳す。
- 訳し戻しには**履歴も用語集も渡さない**（用語集の訳先は訳し戻しの原文側になるので合わない）。文体は、訳し戻しの
  訳先（＝原文の言語）が `ja` のときだけ `polite` を付ける。
- 同じペインの新しい依頼（LIVE・TRANSLATE）は、まだ済んでいない訳し戻しを取り消す（訳文が変われば意味がない）。

### 6.5 翻訳元の判定（AUTO）

モデルは判定した言語を返さないので、表示・ROUND TRIP・履歴・入れ替えのために、ページで文字の種類から判定する
（`shared/translate/detect.ts`、純粋な関数）。モデルへの依頼には渡さない（`source_lang` は付けずモデルに任せる）。
同じ関数を main も依頼の原文に使い、履歴の「EN → JA」の札は main が決める（ページから判定の結果は受け取らない）。

- 確かとするもの: 仮名を含む → `ja`、ハングル → `ko`、タイ文字 → `th`、ヘブライ文字 → `he`、グルジア文字 → `ka`、
  アルメニア文字 → `hy`、ラテン文字で英語の頻出語が他の候補より明らかに多い → `en`（同じやり方で fr / de / es / it /
  nl / id / pl も候補に入れる）。
- 確かでないもの: 漢字だけ（簡体字か繁体字か）、キリル文字（ru / bg / be / kk / sr / uk 以外も）、アラビア文字（ar / fa /
  ur）、デーヴァナーガリー（hi / mr / ne）、短すぎる文（20 字未満）、どの候補も明らかでないラテン文字。
- 確かでなければ、表示は「AUTO」だけ、履歴は「AUTO → JA」、入れ替えは出さない（翻訳元を選べば入れ替えられる）。

## 7. 履歴（Q3）

- main のファイル `translate/history.json`（`replaceFile`、2 秒まとめて書く）。上限 200 件、古いものから消える。
  ファイルが 4 MB（UTF-8 のバイト数）を越えたら古いものから消す。保存しない設定も持つ。
- **入力欄の下書きごとに 1 件**。ページが下書き ID を振り、空にした・前の文の半分以上を消した／置き換えたときに
  新しい ID にする（`continuesDraft`、純粋な関数）。main は、直前の 1 件と下書き ID と言語設定（翻訳元・訳先・文体）
  が同じときだけ書き換え、それ以外は新しい 1 件にする。同じ原文・同じ設定の訳し直しも書き換え。
- **いつ記録するか**:
  - TRANSLATE（Ctrl+Enter）で頼んだ依頼が全部のブロックを訳し終えたとき。Ctrl+Shift+Y で呼び出したときの最初の
    依頼もこれと同じに扱う（読んですぐ閉じる使い方でも履歴に残るように）。
  - LIVE の依頼が訳し終え、そのあと下書きが 5 秒変わらなかったとき（打つたびには書かない）。下書きが変わった、
    ペインが閉じた（依頼が捨てられた）ときは記録しない。
  - TRANSLATE の依頼を途中で止めた・失敗したときは、訳し終えたブロックが 1 つ以上あれば「途中まで（n/N）」の印を
    付けて記録する。LIVE の依頼の途中で止めたものは記録しない。
- テストアプリの最初の版は「直前と前方一致・1 分以内なら上書き」で、訳し終えた文のあとに頭の文字が同じ別の文を
  打つと前の履歴が消え、同じ文を別の言語に訳すと前の言語の履歴が消えた（§13）。
- 試し訳は履歴に残さない（`record: false`）。

## 8. main とページの分担

- **main** (`main/translate/`): エンジン（入手・起動・監視・停止）、取得器、依頼（`TranslateRun`）と待ち行列、
  PFML3 の送信とストリームの中継、用語集と履歴と `engine.json` のファイル。チャネルは 1 つの `registerTable`
  （`main/ipc/translate.ts`）。サービスは、他のモジュールと同じく子プロセス・fetch・時計・送信を注入して単体テストで
  回せる形にする。
- **ページ** (`widgets/translate/`): 画面、下書き ID、ブロックの表示と背骨、翻訳元の判定。llama-server とは話さない
  （CSP の `connect-src 'self'` のまま）。

### 8.1 ファイル

| パス（`userData/` の下） | 中身 | 書き方 |
|---|---|---|
| `translate/engine.json` | エンジンの入手先（fetched / own / external）、自分の llama-server のパスとビルド番号、外部のアドレス、ビルドごとの `--list-devices` の結果、モデルごとのライセンスへの同意 | main だけ。`replaceFile` |
| `translate/engine/<build>/<target>/` | 取ってきた llama-server と DLL、`LICENSE-llama.cpp`（同梱のライセンス一式）、`LICENSE-LLVM-OpenMP`（zip のもの） |
| `translate/licence-consents.txt` | ライセンスとダウンロードへの同意の記録（§3）。追記だけ | main だけ。`appendFile` | 一時フォルダから名前を変えて置く |
| `translate/engine-tmp-<乱数>/`、`translate/engine-<build>-<target>.zip.part` | 展開中・取得中 | 起動時に一時フォルダを消す |
| `translate/models/<model id>/<file>`（＋ `.part`） | GGUF | `.part` から `replaceFile` |
| `translate/glossaries.json` | 用語集（名前、訳先の言語、用語） | `replaceFile` |
| `translate/history.json` | 履歴（§7） | `replaceFile`、2 秒まとめて |

ペインの状態（レイアウトに入る）には、言語・文体・開いている引き出し・ROUND TRIP の有無だけ。原文は持たない（§8.5）。

### 8.2 設定（`settings.json` の `translate`）

| キー | 値 | 既定 |
|---|---|---|
| `modelId` | マニフェストの id | `plamo3-2b-q4km` |
| `ctx` | 4096 / 8192 / 16384 / 32768 | 16384 |
| `device` | `auto`（GPU、だめなら CPU）/ `cpu` | `auto` |
| `idleMinutes` | 5 / 10 / 30 / 0（止めない） | 10 |
| `live` | 真偽 | true |
| `saveHistory` | 真偽 | true |

`applySettingsPatch` は `translate` をこの 6 つのキーだけで合わせる（zod で知らないキーは捨てる）。エンジンの入手先・
パス・アドレス・同意はここに無い（§8.1 の `engine.json`、専用のチャネルでだけ変わる）。単体テストで、
`settings.patch` にそれらのキーを入れても何も変わらないことを確かめる。

### 8.3 チャネル（`CH.translate.*`）

入力はすべて main で検査する（zod か、`unknown` のままの明示の検査）。言語コードは `^(ja\(easy\)|[a-z]{2,3}(-[a-z]{4})?)$` かつ一覧にあるもの。

| チャネル | 向き | 中身 |
|---|---|---|
| `subscribe` / `unsubscribe` | ページ → main（on） | エンジンの盤（状態・モデルの一覧・取得の進捗）を購読する。`PageSubscribers`、`whenPageGoes` で落とす |
| `board` | main → ページ | 盤の全体（状態、ビルド、デバイス、ポート、モデルごとの状態、取得の進捗、入手先の種類、外部のホスト名と origin、取得するエンジンの大きさ） |
| `run` | ページ → main（handle） | `{paneId, draftId, text, srcLang|'auto', tgtLang, form?, contextText?, glossaryId?, mode: 'translate'|'live'}`。Ctrl+Shift+Y の呼び出しは `translate` で頼む（記録も同じ、§7）。1 ブロックの訳し直しは `retryBlock`、訳し戻しは `roundTrip`。答えは run の版番号 |
| `follow` / `unfollow` | ページ → main（on） | `{paneId}` の依頼を追う。追い始めにスナップショット |
| `runEvent` | main → ページ | `{paneId, seq, kind: 'snapshot'|'patch', ...}`。`patch` はブロックごとの差分（全文の置き換え・追記・状態・注記）と依頼の状態を 100 ms ぶんまとめたもの。`seq` が飛んだか版が違えば、ページは `follow` し直す。追い始めたページには、ほかのページへ差分を送り切ってからスナップショットを送り、そのあとで数に入れる（差分がスナップショットより先に届かない） |
| `stop` | ページ → main（on） | `{paneId}` の依頼を止める（STOP、Ctrl+.） |
| `cancelLive` | ページ → main（on） | `{paneId}` の LIVE の依頼を取り消す（ペインが隠れたとき） |
| `editBlock` | ページ → main（handle） | `{paneId, index, text}` 直したブロック（その後の履歴に使う） |
| `retryBlock` | ページ → main（handle） | `{paneId, index}` 1 ブロックだけ、その場で訳し直す（設計の `run` の `only` の代わり。依頼を作り直さない） |
| `roundTrip` | ページ → main（handle） | `{paneId, lang}` 訳し終えたブロックを `lang` へ訳し戻す（同じ依頼の中で、訳のあとに 1 つずつ） |
| `clear` | ページ → main（on） | `{paneId}` CLEAR: 依頼を片付け、`cleared` のスナップショットを送る |
| `engineStart` / `engineStop` / `engineRestart` | handle | 盤の STOP / RESTART、FAULT の RESTART |
| `setSource` | handle | `'fetched'|'own'|'external'`。own は選び済みのときだけ、external はアドレスを入れて TEST が通ったときだけ |
| `pickOwn` | handle | main のファイル選択。`--version` を確かめて `engine.json` に置く |
| `testExternal` | handle | `{url}` を検査し `/props` を読む。通れば `engine.json` に置く |
| `consent` | handle | `{modelId}` ライセンスとダウンロードへの同意を記録（`engine.json` と `licence-consents.txt`） |
| `fetch` / `pause` / `cancelFetch` / `removeModel` | handle | 取得（エンジン → モデルの順に必要なものだけ。止めたものの続きも `fetch`）と削除。モデルの選択は専用のチャネルではなく、設定の `modelId` を `settings.patch` で書く（§3 の仮の選択） |
| `selfTest` | handle | READY の 1 文。履歴には残さない |
| `logs` | handle | リングバッファ（ENGINE の LOG） |
| `history` / `historyClear` / `historyRemove` / `historyOpen` | handle | 一覧（各件の頭 240 字だけ。絞り込みはページ）、2 度押しの CLEAR、1 件、1 件をペインに訳し終えた依頼として置く（`{paneId, id}`） |
| `glossaries` / `glossarySave` / `glossaryRemove` | handle | 用語集の読み書き。保存は 1 つを丸ごと（zod で検査）。TSV / CSV の貼り付けはページが解いて `glossarySave` で送る（5,000 件まで） |
| `watching` | handle | 診断（§8.6）。盤の購読、取得、ペインごとの依頼 |
| `clipboardText` | handle | Ctrl+Shift+Y のとき、main のクリップボードのモジュールから文字だけ（`ELECDEX_CLIPBOARD_STUB` が効く） |
| `openLicence` | handle | `{page}`（`plamo` / `register` / `llama`）の決まったページを既定のブラウザで。`plamo` は開いた日時を同意の記録に残す |

用語集と履歴が変わると、盤の `library`（版の数）が増える。用語集か HISTORY を出しているペインは、それを見て
聞き直す（新しい購読のチャネルは作らない）。

どのチャネルも `tests/e2e/contracts/ipc-table.ts` に行を足す（IPC のメソッドの一覧の契約）。

### 8.4 エンジンの状態機械

| 状態 | 入ってくる | 出ていく |
|---|---|---|
| `absent` | エンジンかモデルが置かれていない | 取得が済む → `stopped` |
| `stopped` | 初め、止め時計、STOP、終了 | 依頼が来る・START → `starting`（世代 +1） |
| `starting` | 起動中（BOOT のログを盤へ） | `/health` 200 → `ready`。GPU で失敗し AUTO → CPU で `starting` のまま。CPU でも失敗・諦め（§4.2） → `fault` |
| `ready` | 依頼を流す。止め時計は最後のブロックが終わったときに始め、新しい依頼で止める | 止め時計・STOP → `stopping`。モデルや ctx・デバイスの変更 → `stopping` から `starting`。思わぬ終了 → 再起動の可否（§4.3）で `starting` か `fault` |
| `stopping` | 子プロセスに終わるよう頼む（5 秒で強制） | 終わった → `stopped`（または変更の後の `starting`） |
| `fault` | 最後のエラー行を持つ | RESTART・設定の変更 → `starting`（再起動の回数は数え直さない） |

`starting` の間に来た依頼は待ち行列で待つ。`stopping` の間に来た依頼は、止まってから `starting` を始めて待つ。

**外部のサーバー**（入手先が external）にはプロセスがないので、上の表の代わりにこれを使う。止め時計・再起動の
回数・STOP / RESTART のボタンはない（ENGINE と FAULT で出さない）。

| 状態 | 入ってくる | 出ていく |
|---|---|---|
| `external-untested` | アドレスを入れた | TEST が通る → `external-ready`。通らない → `external-unreachable` |
| `external-ready` | 依頼を流す | 書いている途中で繋がらなくなった → そのブロックを失敗にし、依頼を「止めた（サーバーに届かない）」、`external-unreachable` |
| `external-unreachable` | 盤に「届かない」 | 次の依頼で `/health` を 1 度だけ確かめ、通れば `external-ready` で流す。通らなければ依頼を「止めた」。TEST でも戻る |

### 8.5 依頼（`TranslateRun`）と待ち行列

- main はペイン（`paneId`）ごとに 1 つの依頼を持つ: 下書き ID、原文、設定、ブロック（原文・状態・訳文・
  統計）、全体の状態、版番号。**原文と訳文は main のメモリにだけ**あり、ファイルには書かない（履歴は別）。
  ペインの移動・再読み込み・ポップアップからレイアウトへの移動で作り直されたウィジェットは、`follow` で
  スナップショットを受け取り、原文と訳文をそのまま出す（AI チャットの会話と同じ考え）。elecdex を終えれば消える。
- **追う人がいない依頼**: どのページも `follow` していない状態が 5 秒続いたら、訳している途中なら止めて依頼を
  捨てる（AI チャットの「追われない答えは数秒で止める」と同じ）。ポップアップを閉じたときもこれで止まる。
  ライフサイクル契約の待ち（10 秒）より短い。追っていたページが**再読み込み**で離れたときは、その時計をページの
  読み込みが済む（`did-finish-load`）まで止めておき、そこから 5 秒を数える（起動の演出があると 5 秒では
  `follow` し直せない）。止めておくのは長くて 60 秒で、それを過ぎたら読み込みが済んでいなくても 5 秒を数え始める。
  ページを閉じたときはすぐ数え始める。ページが壊れた（レンダラーの異常終了）ときは、次の読み込みが来るまで再読み込みと
  同じに待つ（`whenPageGoes` は壊れたことではなく、その後の読み込みの始まりを聞く）。
- **待ち行列**: main に 1 本。一度に訳すのは 1 ブロックだけ。依頼の順番に、各依頼のブロックを順に訳す。

| 起きたこと | 訳している途中のブロック | 待っている依頼 |
|---|---|---|
| 同じペインの新しい依頼 | その依頼のものなら止め、新しい依頼に置き換える。鍵（§6.1）が同じブロックは訳文を引き継ぐ | 古い依頼を新しい依頼に置き換える（並びの場所はそのまま） |
| 別のペインの依頼 | 続ける | 後ろに並ぶ |
| STOP（そのペイン） | 止め、依頼を「止めた」にする | そのペインの依頼を外す |
| 隠れた（LIVE の依頼） | ページが `cancelLive` を送り、STOP と同じ | 同じ |
| 隠れた（TRANSLATE の依頼） | 続ける | 待ち続ける |
| 追う人がいない（5 秒） | 止めて依頼を捨てる。記録しない | 外す |
| エンジンを STOP した・モデルや設定を変えた | 止め、すべての依頼を「止めた」（理由: エンジンを止めた / モデルを変えた） | すべて「止めた」 |
| 書いている途中でエンジンが落ちた | 再起動できれば、そのブロックを**1 回だけ**頼み直す。できなければ「止めた」（理由: エンジンが落ちた）。頼み直す前に、エンジンがプロセスの終了を聞くのを最大 1 秒待つ（`settle`。落ちたサーバーはプロセスの終了より先にソケットが閉じるので、すぐ頼み直すと死んだポートへ行き、2 度目の失敗で止まっていた） | 再起動を待つ。`fault` なら「止めた」 |
| stop の印なしでストリームが終わった | そのブロックを失敗にし（まだ一文字も来ていなければ「訳していない」）、依頼を「止めた」（理由と最後のエラー） | 次の依頼へ |
| サーバーが HTTP のエラーで答えた | 頼み直さない（同じ答えが返る）。依頼を「止めた」（理由: エンジンが断った） | 次の依頼へ |
| ストリームが 60 秒何も送らない | エンジンが止まったとみなし、上の「落ちた」と同じ（1 度だけ頼み直す） | 同じ |
| `stop_type: limit` | そのブロックに「上限で切れた」と出し、次のブロックへ続ける | — |
| 同じペインの新しい依頼（訳し戻しが残っている） | 訳し戻しのブロックなら止める | 済んでいない訳し戻しを取り消す |
| 外部のサーバーに繋がらない | §8.4 の外部の表のとおり | 「止めた（サーバーに届かない）」 |

### 8.6 ライフサイクルの契約（`watching()`）

`watching()` は並べた `string[]` で、何もしていなければ空:

- `board` … どこかのページがエンジンの盤を購読している
- `run:<paneId>` … main が持っている依頼（訳している・待っている・追う人を待っている 5 秒の間）
- `fetch` … 取得の途中

契約のアプリにはモデルがないので、ライフサイクルの契約では依頼は起きない。依頼がタブの裏・再読み込み・閉じたときに
どうなるかは translate.spec が受け持つ（再読み込みで続く、閉じたら `watching()` が空になる）。

エンジンのプロセスは `watching()` に入れない（ペインより長く、止め時計で止まるのが仕様。盤の状態で見える）。
`tests/e2e/contracts/panes.ts` の `Footprint` に `translate` を足し、行を書く: 見えている間 `board`（と依頼）、
タブの裏では TRANSLATE の依頼だけが続く、`goesOn` は「書いている依頼、取得、止め時計まで動くエンジン」、
閉じたら盤も依頼も 5 秒以内に消える。`keepWhileHidden` は持たない（グラフを持たない）。

## 9. 負荷

- ページ: DOM だけ（WebGL なし）。キャレットとランプは共有のパルス、背骨は配置が変わったときだけ描き直す。
  訳文は 100 ms ごとの差分でだけ書き換える。
- main: sha256 は worker。`tar` は `execFile`。`/tokenize` はブロックの原文に 1 回と、組み立てた依頼に 1〜3 回（履歴を
  減らしながらコンテキストの残りを確かめる。§6.2）。長いブロックの部分の数は、ブロック全体の数から文字数の比で見積もる。
  新しい `spawn` を測る（§4.2）。
- エンジン: 約 1.9 GB（2B Q4_K_M、16K）。止めれば 0。止めた後の idle の CPU が 0 であることを `@perf` で確かめる。

## 10. セキュリティ

- llama-server は 127.0.0.1 だけ、キー付き、web UI なし。ページはキーを知らない（ポートは表示用に知る）。
- エンジンの実行ファイルは、マニフェストの sha256 に合ったものか、利用者が main の選択で選んだものだけ。
  ページからパスを受け取らない。入手先・パス・アドレスは `engine.json` にだけあり、`settings.patch` では変わらない。
- 外部のサーバーへは、利用者がアドレスを入れて TEST を押し、それを選んだときだけ。`http(s)` だけ、ユーザー情報なし、
  リダイレクトは辿らない。訳文がそこへ行くことを足元に出し続ける。キーは持たない（後で AI の鍵と同じ扱いにする）。
- モデルの文は信用しない。訳文は文字として書く（HTML にしない）。
- ライセンスの全文は既定のブラウザで開く（`shell.openExternal`、許可した URL だけ）。

- **外へ出ない仕組み**: `tests/e2e/support` の `STUB_ENV` に次を足し、tests.md の一覧にも書く。
  - `ELECDEX_HF_BASE_URL`、`ELECDEX_LLAMA_RELEASES_URL`: 既定は閉じたポート（どの spec も GB を取りに行けない）。

  - `ELECDEX_LLAMA_STALL_MS`: §4.2 の 60 秒を spec のために短くする（`silent-boot` の spec は 2 秒にする）。
  - `ELECDEX_LLAMA_STUB_MODE`: `slow-boot`、`silent-boot`（`/health` の要求の記録の行だけを書き、ほかは何も書かずに

- **単体**: PFML3（公式テンプレートの展開と同じ文字列）、ブロックの分け方とつなぎ方の往復、用語の選び方（語の境目、

  コードの検査、待ち行列（同じペインの置き換え・別のペインの待ち・STOP・モデルの変更・落ちたときの頼み直し・

（127.0.0.1・空きポート・環境変数のキー・`--no-webui`・`/health`・世代番号・GPU から CPU への切り替え・リング

空き容量）、用語の選び方、ゼロ幅スペースの無害化と表示前の戻し、試し訳、llama-server の固定ビルド b12110 の取り方。

**直してから持ち込むもの**（テストアプリ側も 2026-11-05 に直した）:

| 不具合 | 直し方 |
|--------|--------|
| 履歴が「1 分以内の前方一致」で上書きされ、前の訳が消えた（別の文、別の言語） | 下書き ID と言語設定で 1 件にまとめる（§7） |
| 異常終了の再起動フラグが READY のたびに戻り、起動するたびに落ちると再起動を繰り返した | 10 分に 1 回まで（§4.3） |
| 用語集が訳先の言語と結び付かず、"pane" が "panel" に当たった | 訳先の言語を持たせ、英数字は語単位（§6.3） |
| 途中で止めた訳が完了と同じ見た目で残った | 「止めた」と添えて薄く残す（§3） |
| DESIGN.md にある試し訳がなかった | セットアップの最後に、履歴に残さず 1 文訳す |

**elecdex では変えるもの**: 同梱をやめてセットアップで取る（§4.1）、アプリの起動時ではなく最初の翻訳で起動する
（§4.3）、行を詰めて 512 トークンのかたまりにせず空行のブロックを単位にする（§6.1）、依頼は main がペインごとに持つ
（§8.5）、ペイン間の待ち行列、sha256 を worker で・`tar` を非同期で（§4.1、§5）、同期の `tasklist` をやめる（§4.2）、
履歴は node:sqlite ではなく JSON（上限 200 件なら全文検索は要らない）、ショートカットの Ctrl+Shift+S（シェルへ）と
Ctrl+Shift+C（端末のコピー）は使わない。
