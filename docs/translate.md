# TRANSLATE ペイン 設計

Preferred Networks の翻訳特化モデル PLaMo 3 Translate を、llama.cpp の `llama-server` でこの PC の上で動かし、
elecdex のペインから使う翻訳ペイン。訳す文はこの PC から出ない。外に出る通信はモデル（と、選べばエンジン）の
ダウンロードだけ。**まだ実装していない**（2026-11-05、設計とモックの段階）。要約は architecture.md §5.25。

見た目のたたき台はモック [translate-mock/index.html](translate-mock/index.html)（ブラウザで開くだけで動く。
訳文・数値・パスはすべて作り物）。機能の裏付けは、利用者が別に作った Electron のテストアプリ
（PLaMo3TranslateTest、React。elecdex とは別のリポジトリ）で確かめた。§13 にそこから得たことをまとめる。

## 0. 決定の記録

| 日付 | 決定 | 経緯 |
|------|------|------|
| 2026-11-05 | PLaMo 3 Translate を llama-server で動かし、elecdex から接続する翻訳ペインを作る。名前は TRANSLATE | 利用者の依頼 |
| 2026-11-05 | UI はモック（原文と訳文を中央の背骨でつなぐ 2 枚の枠、5 段階のセットアップ、ENGINE と HISTORY の画面）の方向でよい | 利用者の判断（「UI はよさそうです」） |
| 2026-11-05 | 機能はテストアプリ PLaMo3TranslateTest を参考にする。その不具合（履歴の上書き、再起動の繰り返し、用語集の言語、止めた訳の見せ方）は直した上で持ち込む | 利用者の指示。テストアプリ側も直した（§13） |

ここから下の「案」は、利用者の決定を待っているもの（§14）。

## 1. 目的と非目的

**目的**

- elecdex を離れずに、手元で文を訳す。訳す文は外に出さない
- 長い文も段落ごとに対応が見え、用語と文体がそろう（用語集・文脈・常体／敬体・やさしい日本語）
- 初めての人が、エンジンとモデルを迷わず用意できる（セットアップ）

**非目的**

- 外部の翻訳サービス（DeepL、Google など）への接続。AI チャットのプロバイダで訳すこともしない
- ファイル（.docx、PDF）の翻訳。.txt / .md を落として訳すのは後の候補（§12）
- 音声、画像（OCR）、ウェブページの翻訳
- モデルの学習・微調整、PLaMo 以外のモデル

## 2. PLaMo 3 Translate（確かめた事実）

- **モデル**: `pfnet/plamo-3-translate-{0.8b,2b,8b,31b}-GGUF`。量子化は Q4_K_M（既定）・Q4_0（0.8B と 2B だけ）・Q3_K_M・Q2_K。
  Q4_K_M の大きさ: 0.8B 573 MB、2B 1.81 GB、8B 5.28 GB、31B 19.53 GB。Q2_K は精度の低下が目立つ。
- **llama.cpp**: PLaMo3 の対応は PR #17304（b7563 以降）、その後にトークナイザの修正がある。テストアプリは
  **b12110**（v0.9.0 と同じコミット cd959bae）で動くことを確かめた。
- **言語**: 53（`ja`, `en`, `zh-hans`, `zh-hant`, `ko`, …）と、訳先だけに使える **`ja(easy)`（やさしい日本語）**。
  コードは小文字で、地域を付けない（`en-US` は不可）。
- **オプション**: `source_lang`（省略で自動判定）、`context`、`glossary`、`form`（`plain` / `polite`、訳先が `ja` のとき
  だけ。`ja(easy)` には付けられない）、履歴（前の原文と訳文の組）。
- **コンテキスト**: 学習時の上限は入出力の合計 32,768 トークン。公式例は `-c 16384`。
- **生成**: `temperature 0`、stop は `<|plamo:tag|>` と `<|plamo:bos|>`。BOS は llama.cpp が付ける。
- **ライセンス**: PLaMo Community License。個人・非商用は無料、年商 10 億円以下の商用は登録で無料、超えれば別契約。

**プロンプト（PFML3）**: 公式の `chat_template.jinja` と同じ並び（テストアプリで、テンプレートを llama-server で
展開した結果とバイト単位で一致することを確かめた）:

```
<|plamo:tag|>dataset<|plamo:msg|>translation
[<|plamo:tag|>context<|plamo:msg|>{文脈}]
(<|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{src}]<|plamo:msg|>{前の原文}
 <|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{tgt}<|plamo:msg|>{前の訳文})*
[<|plamo:tag|>glossary(<|plamo:index|>{原語}<|plamo:item|>{訳語})+]
<|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{src}]<|plamo:msg|>{原文}
<|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{tgt}[<|plamo:key|>form<|plamo:val|>{form}]<|plamo:msg|>
```

（改行は読みやすさのため。実際は続けて書く。）

## 3. 画面構成

モックのとおり。ペインの見出しは `TRANSLATE`、副題にモデル（`plamo-3-translate-2b · Q4_K_M`）。

- **ツールバー**: TEXT / HISTORY の切り替え（クリップボードペインと同じ ViewToggle）、翻訳元（AUTO と 53 言語）、
  入れ替え、訳先（53 言語とやさしい日本語）、FORM（PLAIN / POLITE、訳先が日本語のときだけ）、GLOSSARY、CONTEXT、
  ROUND TRIP、LIVE。右端に設定のスライダー（`SettingsButton`）で ENGINE の画面。
- **言語の選択**: 絞り込みのできる一覧、最近使った言語を上に。
- **原文と訳文**: シェルと同じ切り欠きの枠を 2 枚、間に**背骨**。段落ごとに背骨の上に番号のランプと対応線を引き、
  段落か番号にポインタを置くと両側が光る。番号の詳細カードにトークン数・時間・使った履歴。
- **訳文の段落**: 届いたそばから書く（キャレットは共有のパルス）。書き終えたら fx-fresh のバー。訳している間は
  訳文の枠をアクセント色にする。段落ごとに RETRY / EDIT / COPY。EDIT で直した段落は、後の段落の履歴に使う。
- **止めた訳**: Esc や新しい入力で止めた段落は「止めた」と添えて薄く残す。完了とは見せない。
- **状態**: NO MODEL（セットアップへ）、STANDBY（エンジン停止中。最初の翻訳で起動）、BOOT（llama-server の
  ログを 1 行ずつ）、TX、READY、FAULT（終了コードと stderr の末尾、RESTART、ENGINE へ）。
- **足元**: ランプとエンジンの要約（ビルド、GPU、コンテキスト、メモリ）。右に「PLaMo 3 Translate · PLaMo Community
  License」と「local, nothing leaves this PC」を常に出す。
- **SETUP**: ENGINE → MODEL → LICENCE → FETCH → READY（試し訳 1 文）。
- **HISTORY**: 絞り込み、日ごとの区切り、行を押すと TEXT に戻して開く。CLEAR は 2 度押し。
- **ENGINE**: エンジンの入手先、状態（STOP / RESTART）、モデルの一覧（取得・削除・切り替え）、実行の設定、ログ、
  ライセンスへの同意の記録。
- **狭いペイン**: 原文の下に訳文。背骨は横の線になり、対応はポインタを置いたときの光だけで見せる。

## 4. エンジン（llama-server）

### 4.1 入手（案。§14 の Q1）

**推奨 A: セットアップで、elecdex が固定したビルドを取ってくる。** テストアプリの `scripts/fetch-llama.mjs` と同じ
手順を main で行う。

- ビルドは 1 つに固定する（今は b12110）。プラットフォームごとに GitHub のリリースのアセット名と sha256 を
  マニフェスト（`shared/translate/engines.ts`）に持つ。Windows x64 は Vulkan と CPU、Windows arm64 は CPU、
  macOS arm64 は Metal、macOS x64 は CPU、Linux x64 は Vulkan と CPU。
- 取ってきたアーカイブを sha256 で確かめてから展開し、llama-server とその DLL / so / dylib 以外を消す。
  llama.cpp の LICENSE（MIT）を同じコミットから取って置く。置き場は `userData/translate/engine/<build>/<target>/`。
- 展開は OS の `tar`（Windows は `System32\tar.exe`、bsdtar は zip も開ける）。
- 版を上げるのは elecdex のリリースでマニフェストを変えたときだけ。古いビルドのフォルダは、新しいビルドで
  エンジンが起動できたら消す。

ほかの入手先も選べるようにする（ENGINE 画面）:

- **自分の llama-server**: main のファイル選択で選ぶ（ページからパスは渡さない）。`--version` でビルド番号を読み、
  b7563 より古ければ断る。
- **外部のサーバー**: 既に動いている llama-server のアドレス。elecdex は何も起動しない。PLaMo 3 Translate が載って
  いるかを `/props`（`model_path` と、テンプレートの有無）で確かめる。訳す文がそのアドレスに送られることを画面に
  書く（この PC の外なら特に）。

**B（テストアプリの方式）: アプリに同梱する。** Vulkan 版と CPU 版で約 132 MB（Windows）。翻訳を使わない人も含めて
全員の配布物が大きくなるので勧めない。

**C: 利用者が入れたものだけを使う。** `winget install llama.cpp` / `brew install llama.cpp`。版がまちまちで、古い版は
PLaMo3 を読めない。A の代わりではなく、A に加えて選べる形にする。

### 4.2 起動

```
llama-server -m <model.gguf> -c <ctx> --host 127.0.0.1 --port <空き番号> --alias plamo-3-translate
  --no-webui -np 1 --log-colors off [-ngl 0（CPU のとき）]
```

- API キーは起動ごとに乱数で作り、**環境変数 `LLAMA_API_KEY`** で渡す（コマンドラインに残さない。elecdex の
  「PowerShell には環境変数で渡す」と同じ考え）。キーもポートも main の外へ出さない。
- `/health` を 250 ms ごとに見て、200 で READY。2 分で諦める。
- GPU のビルドは `--list-devices` で GPU があるかを確かめてから使い、起動に失敗したら CPU のビルドで起動し直す
  （理由を ENGINE 画面に出す）。`--list-devices` の結果はビルドごとに覚え、毎回は聞かない。
- 古い起動要求は世代番号で捨てる（モデルの切り替えを続けて押したとき）。
- stdout / stderr は 400 行のリングバッファ。FAULT には最後のエラー行を添える。
- PID ファイルを置き、次の起動で、そのプロセスが llama-server であることを確かめてから終わらせる。
  確かめ方は同期の `tasklist` / `ps` を使わない（main を止める）。非同期に 1 度だけ。
- **`spawn` は main で同期**なので、llama-server の `spawn` にかかる時間を測って decisions.md に書く。

### 4.3 寿命

- **最初の翻訳で起動する**（ペインを開いただけでは起動しない。約 1.9 GB を使うため）。
- 翻訳が 10 分なければ止める（設定: 5 / 10 / 30 分 / 止めない）。最後の TRANSLATE ペインを閉じたら、訳しかけが
  終わってから止める。elecdex を終えるときは必ず止める。
- **異常終了**: 10 分に 1 回まで自動で再起動する。それより多ければ FAULT で止まり、利用者の RESTART を待つ
  （テストアプリは READY のたびに数え直していたので、起動するたびに落ちる状態で再起動を繰り返した）。
- **見えていない間**: 新しく何も始めない。訳しかけの段落は書き終える（「書いている答えは隠れても続く」の規則）。
  LIVE は打っている間だけ動くので、見えている間しか起きない。
- モデルを削除する前にエンジンを止める（Windows はファイルが掴まれている）。

## 5. モデル

- マニフェスト（`shared/translate/models.ts`）にリポジトリ、**リビジョン（コミット SHA）**、ファイル名、バイト数、
  sha256、必要なメモリの目安を持つ。URL は `https://huggingface.co/<repo>/resolve/<revision>/<file>`。
- 取得は main（`net.fetch`）。`.part` に書き、HTTP Range で再開。失敗は 1 s から 15 s まで倍にして 5 回まで。
  206 なのに Content-Range の始まりが合わなければ最初からやり直す。
- 取得の前に空き容量を確かめる（残りの大きさ＋256 MB）。進捗は 200 ms ごと、速さは指数平滑。
- 終わったら sha256 を確かめ、合えば `replaceFile` で置く。**sha256 は worker で計算する**（1.8 GB を main で回すと、
  4 MB ずつでも main が止まる時間が積み重なる。テストアプリは main で計算していた）。
- ライセンスへの同意は、モデルごとに、日時・リビジョン・ライセンスの URL を main の設定に記録する。別のモデルを
  取るときも、その都度同意を求める。
- 一度に 1 モデル。PAUSE は `.part` を残し、CANCEL は消す。ペインを閉じても続く。elecdex を再起動したら PAUSE の
  ままにして、利用者の RESUME を待つ（勝手に再開しない）。
- `chat_template.jinja` は取らない（`/completion` に PFML3 を直接渡すので要らない）。

## 6. 翻訳

### 6.1 単位と順番（案。§14 の Q7）

- **段落ごとに、順番に訳す**。前の 2 段落の原文と訳文を履歴として渡し、用語と文体をそろえる。テストアプリの
  分割と同じ（512 トークンを超える段落は文に、さらに長ければ文字数で分ける。分けた部分は背骨では 1 段落）。
- llama-server は 1 スロット（`-np 1`）。コンテキストを分け合わずに済み、履歴を渡すと順番になるので並列の意味が
  薄い。モックの 4 スロット並列はやめる。
- 改行の形（空行、行頭の空白）は原文のものを訳文に戻す。
- **複数のペイン**: main に 1 本の待ち行列。同じペインの新しい依頼は、そのペインの古い依頼を取り消して置き換える。
  別のペインの依頼は待つ（テストアプリは「新しい依頼が来たら前を中断」で、ペインが 2 つあると互いに止め合う）。
- **LIVE**: 打ち終えて 0.6 秒で、変わった段落だけを訳し直す。覚えておく鍵は段落の原文と設定（履歴は鍵に入れない。
  入れると 1 段落の手直しで後ろが全部訳し直しになる）。全部を訳し直すのは TRANSLATE（Ctrl+Enter）。

### 6.2 依頼の組み立て

- PFML3 は `shared/translate/pfml3.ts` の純粋な関数で組み立てる（テストアプリのものとテストをほぼそのまま持ち込む）。
- 原文・文脈・用語・履歴の `<|plamo:` は `<|`＋ゼロ幅スペース＋`plamo:` にしてから入れる（公式テンプレートは
  この文字列を含む入力を拒む。elecdex は拒まず無害化する）。モデルが写してきたら表示の前に戻す。
- `/tokenize` で数え、出力の上限は「コンテキストの残り」と「入力の 4 倍（最低 256）」の小さいほう。収まらなければ
  古い履歴から減らし、それでも入らなければ「長すぎる」と言う（切らない）。
- `/completion` に `stream: true`、`cache_prompt: true`。OpenAI 互換の `/v1` は使わない（`timings` と `stop_type` が
  欲しい）。`stop_type` が `limit` なら、その段落に「上限で切れた」と出す。
- ストリームが stop の印なしで終わったら失敗とする（途中までを完了として履歴に残さない）。

### 6.3 用語集・文脈・文体・やさしい日本語

- **用語集**: 名前を付けて複数持てる。原文に出てくる用語だけを、長い順に最大 50 件入れる。端が英数字の用語は
  隣も英数字なら別の語の一部とみなす（"pane" は "panel" に当たらない。日本語のように空白で区切らない文字は
  隣を見ない）。**用語集に訳先の言語を決められ**、違う言語へ訳すときは使わない（日本語の用語集はやさしい日本語
  にも使う）。使わなかったことは足元に出す。TSV / CSV の貼り付けで取り込める。
- **文脈**: 2,000 字まで。訳さずに毎回渡す。
- **文体**: 訳先が `ja` のときだけ。`ja(easy)` では出さない。
- **やさしい日本語**: 訳先の一覧で日本語の下に置く。翻訳元には出さない（入れ替えると日本語になる）。

### 6.4 ROUND TRIP

訳し終えた段落を、原文の言語へ訳し戻して段落の下に出す。訳し戻しはもう一度エンジンを回すので、ROUND TRIP を
押したときだけ。一致度（chrF、文字の n-gram）を数字と棒で添え、70 未満を警告の色にする（案。§14 の Q6）。

## 7. 履歴（案。§14 の Q3）

- main のファイル `translate-history.json`（`replaceFile`）。上限 200 件、古いものから消える。保存しない設定も持つ。
- **入力欄の下書きごとに 1 件**。ページが下書き ID を振り、空にした・前の文の半分以上を消した／置き換えたときに
  新しい ID にする（`continuesDraft`、純粋な関数）。main は、直前の 1 件と下書き ID と言語設定（翻訳元・訳先・文体）
  が同じときだけ書き換え、それ以外は新しい 1 件にする。同じ原文・同じ設定の訳し直しも書き換え。
- テストアプリの最初の版は「直前と前方一致・1 分以内なら上書き」で、訳し終えた文のあとに頭の文字が同じ別の文を
  打つと前の履歴が消え、同じ文を別の言語に訳すと前の言語の履歴が消えた（§13）。
- 試し訳は履歴に残さない（`record: false`）。

## 8. main とページの分担

- **main** (`main/translate/`): エンジン（入手・起動・監視・停止）、モデルの取得、待ち行列、PFML3 の送信と
  ストリームの中継、用語集と履歴と設定のファイル。チャネルは 1 つの `registerTable`。
- **ページ** (`widgets/translate/`): 画面、下書き ID、段落の表示と背骨。llama-server とは話さない（CSP の
  `connect-src 'self'` のまま）。
- **入力の検査**: すべて zod。言語コードは `^(ja\(easy\)|[a-z]{2,3}(-[a-z]{4})?)$` かつ一覧にあるもの。文は
  20,000 字、文脈は 2,000 字、用語は 1 回 5,000 件まで。
- **購読**: エンジンの状態とモデルの一覧はペインの購読（参照カウント、`whenPageGoes` で落とす）。翻訳の
  ストリームは依頼ごとの ID でページに返す（`PageSubscribers`）。
- **設定** (`settings.json` の `translate.*`): 選んだモデル、エンジンの入手先、コンテキスト長（4096 / 8192 / 16384 /
  32768）、GPU を使うか、止めるまでの時間、LIVE、履歴を保存するか。ペインの状態には言語と文体と開いている
  引き出しだけ（原文は持たない）。

## 9. 負荷

- ページ: DOM だけ（WebGL なし）。キャレットとランプは共有のパルス、背骨は配置が変わったときだけ描き直す。
  段落の表示はトークンが届いたときだけ書き換える。
- main: sha256 は worker。`/tokenize` は段落ごとに 1 回（テストアプリは長文で行ごと・文ごとに数えていたので、
  まとめて数えてから分ける）。`spawn` を測る。
- エンジン: 約 1.9 GB（2B Q4_K_M、16K）。止めれば 0。idle の CPU は 0 であることを `@perf` で確かめる（止めた後）。

## 10. セキュリティ

- llama-server は 127.0.0.1 だけ、キー付き、web UI なし。ページはポートもキーも知らない。
- エンジンの実行ファイルは、マニフェストの sha256 に合ったものか、利用者が main の選択で選んだものだけ。
  ページからパスを受け取らない。
- 外部のサーバーへは、利用者がアドレスを入れて TEST を押したときだけ。キーは持たない（必要なら後で AI の鍵と
  同じ扱いにする）。
- モデルの文は信用しない。訳文は文字として書く（HTML にしない）。
- ライセンスの全文は既定のブラウザで開く（`shell.openExternal`、許可した URL だけ）。

## 11. テスト

- **単体**: PFML3（公式テンプレートの展開と同じ文字列）、分割と結合、用語の選び方（語の境目、言語）、
  `continuesDraft`、履歴のまとめ方、再起動の可否、マニフェストの形、言語コードの検査。
- **e2e**: 外へは出ない。`ELECDEX_TRANSLATE_STUB` で、`/health`・`/tokenize`・`/completion`（SSE）・`/props` に答える
  小さな Node のサーバーを llama-server の代わりに起動する（ダウンロードも同じスタブ）。止まらない・遅い・途中で
  落ちる・stop の印なしで終わる、をスタブで起こせるようにする。
- **ライフサイクルの契約**: `contracts/panes.ts` に行を足す（見えている間: 翻訳、隠れている間: 訳しかけだけ続く、
  閉じたら: エンジンの止め時計が動く）。

## 12. 段階（案）

1. エンジンとモデル: 入手（A）、起動と停止、取得と検証、SETUP の 5 段階、ENGINE 画面
2. TEXT: 段落ごとの順番の翻訳、背骨、言語、文体、やさしい日本語、止めた訳、FAULT
3. 用語集・文脈・HISTORY
4. ROUND TRIP・LIVE・EDIT した段落を履歴に
5. 呼び出しキー（Ctrl+Shift+Y、クリップボードの文を持ってポップアップ）、プリセットへの配置、ガイドとショット
6. 後の候補: .txt / .md を落として訳す、外部サーバーの鍵、CUDA のビルド

## 13. テストアプリ（PLaMo3TranslateTest）から得たこと

**そのまま持ち込むもの**: PFML3 の組み立てとテスト、分割と結合、llama-server の起動の仕方（127.0.0.1・空き
ポート・環境変数のキー・`--no-webui`・`/health`・世代番号・GPU から CPU への切り替え・リングバッファ・PID
ファイル）、`/completion` と `/tokenize` の使い方、モデルの取得（リビジョン固定・sha256・Range・再試行・空き容量）、
用語の選び方、ゼロ幅スペースの無害化と表示前の戻し、試し訳、llama-server の固定ビルド b12110 の取り方。

**直してから持ち込むもの**（テストアプリ側も 2026-11-05 に直した）:

| 不具合 | 直し方 |
|--------|--------|
| 履歴が「1 分以内の前方一致」で上書きされ、前の訳が消えた（別の文、別の言語） | 下書き ID と言語設定で 1 件にまとめる（§7） |
| 異常終了の再起動フラグが READY のたびに戻り、起動するたびに落ちると再起動を繰り返した | 10 分に 1 回まで（§4.3） |
| 用語集が訳先の言語と結び付かず、"pane" が "panel" に当たった | 訳先の言語を持たせ、英数字は語単位（§6.3） |
| 途中で止めた訳が完了と同じ見た目で残った | 「止めた」と添えて薄く残す（§3） |
| DESIGN.md にある試し訳がなかった | セットアップの最後に、履歴に残さず 1 文訳す |

**elecdex では変えるもの**: 同梱をやめてセットアップで取る（§4.1）、アプリの起動時ではなく最初の翻訳で起動する
（§4.3）、ペイン間の待ち行列（§6.1）、sha256 を worker で（§5）、同期の `tasklist` をやめる（§4.2）、履歴は
node:sqlite ではなく JSON（上限 200 件なら全文検索は要らない）、ショートカットの Ctrl+Shift+S（シェルへ）と
Ctrl+Shift+C（端末のコピー）は使わない。
