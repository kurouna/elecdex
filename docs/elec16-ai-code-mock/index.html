      使い方の流れ
      
    
        
      
      • 言葉を入れて SEND。1 回の SEND の中で、COMPILE が通るまで最大 3 回（最初の 1 回と自動修正 2 回）AI に頼む。誤りは e16c の言葉のまま返す
        • 
      
      • 直してほしいことも同じ入力欄に打つ（「スコアを右上に」「もっと速く」）。そのときのエディタのコードを添えて送り、また最大 3 回まで。会話は SEND ごとに新しい
        • 
      
      • エディタが最初の見本か、WRITE が最後に書いたまま（人が手を入れていない）なら、確かめずに書く。手を入れていれば説明の行が REPLACE? になる
        • 
      
      • RUN ▸ は人が押す。UNDO は書く前と入れ替える（もう一度押すと戻る）。MACHINE との行き来と RUN ▸ を越えて残る
        • 
    
      
  
      
  
      
    
      版 2 で変えたこと（レビュー）
      
    
        
      
      • 状態を足した: THINKING、STOPPED、プロバイダの失敗（言葉つき）、モデルなし
        • 
      
      • 段階の行は高さを取っておく。FIX は誤りが出てから。書いている間はトークン数でなく時間と大きさ。数字とプロバイダの select は --step--1
        • 
      
      • 確認と結果は入力欄の下の 1 行に。UNDO はボタン
        • 
      
      • 直している間は、前の答えを誤りの印つきのまま出し、直した答えが全部届いてから入れ替える。変えた行は光らせず「4 lines changed」と数だけ
        • 
      
      • COMPILE の場所に FIXING。書いている間の入力欄は読み出し専用（Esc で STOP）
        • 
      
      • 見本のゲームは、プロンプトの規則のとおりに書いたもの（試験で Sonnet が書いた答え）
        • 
      
      • 狭いペインでは、プロバイダ・モデル・SEND が入力欄の下の行に折り返す
