# ELEC-16 PLAY（PLAY-320）— ゲーム機モデルの仕様（案）

ELEC-16 の別モデルとして作るゲーム機の仕様です。**設計中**で、利用者と決めながら直します。決まったことは「決まっていること」に移し、理由は [decisions.md](decisions.md) に残します。機械の土台は [elec16.md](elec16.md)、モックは https://claude.ai/artifact/Ro5nRdZwipjDzHAhCroXBp にあります。

## 1. 決まっていること（2026-10-04、利用者の決定）

- **銘板は ELEC-16 PLAY、モデル名は PLAY-320**（2026-10-04）。ほかのモデル（POCKET-32/48/64、HANDHELD-160）と同じく画面のドット数で名付ける（HANDHELD-160 と同じく幅。320×288 は HANDHELD-160 のちょうど 2 倍）。本体の上部に書くのは銘板の「ELEC-16 PLAY」、TUNE の一覧と MODEL レジスタ（FF02 = 4、id `play-320`）はモデル名
- **独自の機械、独自の規格**。携帯ゲーム機クラスを**少しだけ上回る**性能をねらう。既存のゲーム機のソフトは動かさず、互換もねらわない。実在の機種名、ロゴ、デザインを公開物に使わない（elec16.md §1 の 2026-10-03 の決定のとおり）
- **描画回路を足す**（タイルとスプライト）。**画面は 320×288**。タイルは **1 点 4 ビット（16 色）**
- **色を足す**
- **拡張 RAM は最大 512 KB**。ユニットごとに **TUNE で選べ**、上限は後で簡単に増やせる作りにする
- **ボタンは 十字、A、B、X、Y、L、R、START、SELECT**。全部本体に付ける。ボタンと十字キーは立体的に
- **本体の上部は、左に機種名、右に電源の表示灯**（ポケコンと同じ並び）。「POWER」の文字は付けない
- **本体は縦長**。スキンの問題として、**横長の本体**（昔の液晶ゲームのような形）も用意する
- **BASIC は載せない**。**START ボタンが RUN**: ゲームを差して START を押すと始まる。ゲーム（カートリッジ）を差し替える方法を別に用意する
- **クロックは既定 4 MHz**、今までどおり TUNE で変えられる
- **音は 16 チャンネル**
- **カートリッジは LINK のサービスで読み込む**（機械の外への口は LINK だけ、という今の規則のまま）
- **電源を入れたときに何が起きるかはユニットのモデルで決める**（2026-10-04）。モデルの一覧（`MODELS`）に PLAY-320 を足し（MODEL レジスタ FF02 は 4）、モデルごとの ROM の組でリセットする。POCKET と HANDHELD は今の ROM（BASIC）、PLAY-320 は PLAY の ROM（起動画面）。電源のたびに中身を見て判定はしない
- **モデルは TUNE で選ぶ**（今の液晶の一覧に足す）。PLAY-320 との行き来は再起動して RAM を消す（BASIC のプログラムとゲームの RAM は意味が違う）。POCKET と HANDHELD の間は今どおり RAM を残す
- **ゲームのファイルは main の「ゲームの棚」に置く**（2026-10-04）。CHIP-8 のライブラリのやり方を踏襲し、CHIP-8 とは完全に独立させて混ぜない（§7）
- ゲームは **e16c** で書く
- **ゲームパッド**に対応する
- 作業は、拡張 RAM、画面、本体（スキン）のような**小さいものから先に**進める

## 2. 全体

| 項目 | PLAY-320（ELEC-16 PLAY） | 参考: 今の HANDHELD-160 |
|---|---|---|
| CPU | E16（変更なし）。既定 4 MHz、TUNE で 1〜32 MHz | 同じ |
| RAM | 32 KB ＋ **拡張 RAM 最大 512 KB**（8 KB × 64 バンク、TUNE で選ぶ） | 32 KB |
| 画面 | **320×288**、毎秒 60 枚 | 160×144、毎秒最大 30 枚 |
| 色 | **32,768 色（RGB555）**から選ぶパレット | 4 階調 |
| 描画 | ビットマップ（4 色）と**描画回路**（タイル 16 色、スプライト） | ビットマップ（CPU が描く） |
| 映像メモリ | **64 KB**（機械の外。窓と DMA で読み書き） | 5,760 B（E000 からの窓） |
| 音 | **16 チャンネル** | ブザー 1 音 |
| 入力 | 十字、A、B、X、Y、L、R、START、SELECT。PC のキー、ゲームパッド | キーボード |
| ソフト | **カートリッジ**（ROM 最大 1 MB、セーブ RAM 最大 32 KB） | BASIC、機械語 3 KB、記憶カード |
| 起動 | **起動画面**（差したゲームの名前、PRESS START） | BASIC のプロンプト |
| 開発 | e16c（カートリッジ向けの出力） | e16c（7000 から 2 KB） |

CPU は今でも携帯ゲーム機の数倍の命令を実行できる（4 MHz で毎秒約 300 万命令）ので速くしない。重い仕事（画面の組み立て、音の合成）は描画回路と音の装置が受け持ち、CPU はゲームの中身に使う。

## 3. メモリの地図

| 番地 | 中身 |
|---|---|
| 0000–7FFF | RAM 32 KB |
| 8000–BFFF | ROM 固定 16 KB（PLAY 用: リセット、起動画面、ROM サービス、モニタ） |
| C000–DFFF | **バンクの窓** 8 KB。BANK（FF04）で選ぶ: 0〜11 ROM のバンク、**0x20〜0x5F 拡張 RAM**（TUNE で選んだ大きさまで）、**0x80〜0x83 セーブ RAM**、**0x100〜0x17F カートリッジ ROM** |
| E000–EFFF | **映像メモリの窓** 4 KB。VPAGE で 64 KB を 16 ページに分けて見せる |
| F000–F7FF | 予約 |
| F800–FEFF | **ゲーム用 I/O**（描画回路、音、入力、DMA、カートリッジ）。今は予約域 |
| FF00–FFFF | I/O（今のまま。LINK は FF70） |

- BANK は今も 16 ビットで、0〜11 以外は無視している。値を足すだけなので、ほかのモデルの ROM と BASIC はそのまま動く
- 拡張 RAM の上限（今は 512 KB）は 1 か所の定数にし、BANK の範囲もそこから決める。増やすときはそこを変える
- 拡張 RAM とセーブ RAM の窓は書ける。ROM とカートリッジ ROM の窓は今と同じく、書くと例外
- 窓のコードから別のバンクを呼ぶときは、固定 ROM の `far_call`（今の BASIC と同じ仕組み）を使う
- PLAY の ROM は BASIC を持たないので、固定 ROM には起動画面とサービスとモニタだけを置く（今の ROM と別のファイルの組。同じアセンブラと e16c で作る）

## 4. 画面と描画回路

**モード 0（ビットマップ）**: 320×288、1 点 2 ビット（23,040 B）。4 色はパレットで選ぶ。起動画面、ROM のサービス（PUTS など。文字は 6×8 で 53 桁 36 行）、モニタはこのモードを使う。

**モード 1（描画回路）**:

- **タイル**: 8×8 ドット、**1 点 4 ビット（16 色）**、1 枚 32 B。最大 1,024 枚（32 KB）
- **背景 2 枚**: それぞれ 64×64 マス（512×512 ドット）。マスは 16 ビットで、タイルの番号（10 ビット）、パレット（3 ビット）、左右反転、上下反転、優先順位を持つ。背景ごとにずらし（SX、SY）を持つ。背景 1 は画面の一部に固定した窓にもできる
- **スプライト**: 128 個、1 行に 32 個まで。大きさは 8、16、32 ドット。パレット、反転、背景との前後を選べる
- **パレット**: 16 色 × 16 本（背景 8 本、スプライト 8 本）。1 色は RGB555 の 2 バイト。スプライトの 0 番の色は透明
- **映像メモリ 64 KB の割り当て**: 0000–7FFF タイル（モード 0 のビットマップもここ）、8000–9FFF 背景 0 のマス、A000–BFFF 背景 1 のマス、C000–C3FF スプライトの表、C400–C5FF パレット、残りは予約
- **割り込み**: VBLANK（毎秒 60 回、描き終わり）と、LINE（指定した行に来たとき。画面を途中で分ける表現に使う）
- **DMA**: RAM、拡張 RAM、カートリッジから映像メモリへまとめて写す。転送中も割り込みと BRK は効く（MCPY と同じ考え方）

ページはモードと映像メモリから画面を組み立て、2D canvas に描く。320×288 = 92,160 点を毎フレーム組み立てても数ミリ秒の見込みで、変わったときだけ描く。G2 と G5 で負荷を測る。今のモデルの「液晶の描画は毎秒最大 30 枚」は、PLAY だけ 60 枚にする（測ってから決める）。

## 5. 音（16 チャンネル）

- チャンネルごとに: 波形（矩形 12.5 / 25 / 50 / 75%、三角、のこぎり、ノイズ、波形表 8 本のどれか）、周波数、音量 0〜15、エンベロープ（アタック、ディケイ、サステイン、リリース）、左右、音程の変化（スイープ、ビブラート）、鳴らす・止める
- 波形表は 32 点 × 4 ビット × 8 本
- I/O の番地が足りないので、チャンネルを選ぶレジスタと 8 本のレジスタの窓で書く（F800 番台）
- **コアは設定値と「いつ鳴らしたか」だけを持ち**、音そのものはページの合成器（AudioWorklet。プラグインの楽器と同じ仕組み）が作る。コアは時計にも DOM にも触れない。今の BEEP（ブザー）は残す

## 6. 入力

- **パッドのレジスタ**: 十字、A、B、X、Y、L、R、START、SELECT の 12 ビット。押下が変わると PAD 割り込み
- **本体のボタン**: 12 個全部。十字キーと A、B、X、Y は菱形の並び、L と R は上の角、START と SELECT は真ん中の下。押すと沈んで見える立体的な形
- **PC のキー**（案）: 矢印＝十字、Z＝A、X＝B、A＝Y、S＝X、Q＝L、W＝R、Enter＝START、右 Shift＝SELECT。キーはペインに焦点があるときだけ機械に届く（今の規則）
- **ゲームパッド**: ブラウザの Gamepad API の標準の配置。ペインに焦点があるときだけ読む。フレームごとに状態を見る
- **START が RUN**: 起動画面で START を押すと、差してあるゲームを読み込んで始める

## 7. カートリッジ

- **カートリッジの中身**: ヘッダ（名前、ROM のバンク数、セーブ RAM の大きさ、入口）と ROM のバンク
- **ゲームの棚**: main が持つ、ELEC-16 PLAY 専用のゲームの一覧（記憶カードとは別）。CHIP-8 のライブラリと同じやり方にする:
  - 同梱のゲームは `resources/elec16/games/games.json`。書くのは生成スクリプト（`npm run gen:elec16` の一部か専用のもの）だけ
  - 取り込みは main のピッカーから。大きさを先に確かめ、ヘッダをコアの読み手で確かめてから棚に入れる
  - 利用者のものは main のファイル（`elec16/games/library.json`、取り込んだ像、セーブ RAM）。ペインの状態には置かない
  - ページは id で一覧と中身をもらう（`elec16.games.list` など）。棚が変わると知らせ、ページの一覧は丸ごと差し替える
  - **CHIP-8 とは完全に別**: ファイル、フォルダ、チャンネル、id、ピッカーの種類、一覧のどれも共有しない。CHIP-8 の棚に ELEC-16 のゲームは出ず、その逆もない。共通にしたくなった部品も、まず別々に書く
- **差し替え**: ペインのパネルの **GAMES** で 1 本を選んで「差す」。ほかのモデルの FILES のような一覧で、見本のゲーム（同梱）と、取り込んだゲームが並ぶ。抜くのもここ。差してあるゲームは main がユニットごとに覚える
- **読み込みの流れ**:
  1. 電源を入れると起動画面。差してあるゲームの名前と PRESS START が出る（差していなければ「パネルの GAMES で差してください」）
  2. START を押すと、起動 ROM が LINK のサービス 1（CART）に読み込みを頼む（START は人の操作なので、LINK の HELD の規則も満たす）
  3. main が中身をページへ渡し、ページがコアのカートリッジの差し口に入れる（ROM の像と同じく、コアは外を読まない）。LINK の答えはヘッダ
  4. 起動 ROM が BANK を 0x100 にして入口へ飛ぶ
- **セーブ RAM**（BANK 0x80〜）は main がユニットごと、カートリッジごとに残す。書くのは電池バックアップと同じ時（隠す、閉じる、電源を切る、ページが去る）
- 機械がしまわれる（スナップショット）ときは、カートリッジの名前だけを残し、戻るときに main からもう一度差す
- ゲームを抜くと、遊んでいたゲームは止まり、起動画面に戻る

## 8. 本体（スキン）

- **共通**: 上部の左に「ELEC-16 PLAY」、右に電源の表示灯（「POWER」の文字なし）。ボタンと十字キーは立体的（影と光で沈み込みを表す）
- **縦長の本体**: 画面が上。十字キーが左、A・B・X・Y が右、START と SELECT が真ん中、L と R は上の角、スピーカーの穴
- **横長の本体**: 画面が真ん中。十字キーと SELECT が左、A・B・X・Y と START が右、L と R は上の角
- どちらも色違いのスキンを持つ（モックは graphite、ivory、coral）。`deviceFit` で大きさを決め、伸ばさない規則は今のまま

## 9. 作業の順番（小さいものから）

| 段階 | 中身 | 規模 | 終わるとできること |
|---|---|---|---|
| G1 | **拡張 RAM**: BANK 0x20〜（最大 512 KB、TUNE で選ぶ）、スナップショットの版を上げる（古い版も読む）、モニタと e16c から使えるようにする | 小 | 大きな表や絵を RAM に置ける |
| G2 | **画面 320×288**: PLAY-320 のモデル、モード 0（4 色のビットマップ、パレット）、映像メモリ 64 KB と窓、毎秒 60 枚、VBLANK、PLAY の起動 ROM（起動画面とサービス、BASIC なし） | 小〜中 | 機械語で色つきの絵が描ける |
| G3 | **本体と入力**: 縦長と横長の本体（スキン、立体的なボタン 12 個）、パッドのレジスタ、PC のキー、ゲームパッド | 小〜中 | 本体とゲームパッドで操作できる |
| G4 | **カートリッジ**: パネルの GAMES で差し替え、START で LINK のサービス CART から読み込む、バンクの窓に ROM、セーブ RAM | 中 | 大きなゲームを差して動かせる |
| G5 | **描画回路**: タイル、背景 2 枚とずらし、スプライト、パレット、LINE 割り込み、DMA | 大 | スクロールするゲームが毎秒 60 枚で動く |
| G6 | **音 16 チャンネル** | 中〜大 | 音楽と効果音 |
| G7 | **e16c でゲームを作る**: カートリッジ向けの出力、ROM の表、バンクをまたぐ呼び出し、描画と音のライブラリ、PNG と音のデータの取り込み | 大 | TypeScript でゲームが書ける |
| G8 | **見本と説明書**: 見本のゲーム、ゲーム機の説明書、README、紹介ツアー | 中 | 公開できる |
