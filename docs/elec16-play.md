# ELEC-16 PLAY（PLAY-320）— ゲーム機モデルの仕様（案）

ELEC-16 の別モデルとして作るゲーム機の仕様です。**設計中**で、利用者と決めながら直します。決まったことは「決まっていること」に移し、理由は [decisions.md](decisions.md) に残します。機械の土台は [elec16.md](elec16.md)、モックは https://claude.ai/artifact/Ro5nRdZwipjDzHAhCroXBp にあります。

## 1. 決まっていること（2026-10-04、利用者の決定）

- **銘板は ELEC-16 PLAY、モデル名は PLAY-320**（2026-10-04）。ほかのモデル（POCKET-32/48/64、HANDHELD-160）と同じく画面のドット数で名付ける（HANDHELD-160 と同じく幅。320×288 は HANDHELD-160 のちょうど 2 倍）。本体の上部に書くのは銘板の「ELEC-16 PLAY」、TUNE の一覧と MODEL レジスタ（FF02 = 4、id `play-320`）はモデル名
- **独自の機械、独自の規格**。携帯ゲーム機クラスを**少しだけ上回る**性能をねらう。既存のゲーム機のソフトは動かさず、互換もねらわない。実在の機種名、ロゴ、デザインを公開物に使わない（elec16.md §1 の 2026-10-03 の決定のとおり）
- **描画回路を足す**（タイルとスプライト）。**画面は 320×288**。タイルは **1 点 4 ビット（16 色）**
- **色を足す**
- **拡張 RAM は最大 512 KB**。ユニットごとに **TUNE で選べ**、上限は後で簡単に増やせる作りにする
- **ボタンは 十字、A、B、X、Y、L、R、START、SELECT**。全部本体に付ける。ボタンと十字キーは立体的に
- **本体の上部は、左に機種名、右に電源の表示灯**（ポケコンと同じ並び）。「POWER」の文字は付けない
- **本体は縦長**。スキンの問題として、**横長の本体**（昔の液晶ゲームのような形）も用意する
- **BASIC は載せない**。**START ボタンが RUN**: ゲームを差して START を押すと始まる。ゲーム（カートリッジ）を差し替える方法を別に用意する
- **クロックは既定 4 MHz**、今までどおり TUNE で変えられる
- **音は 16 チャンネル**
- **カートリッジは LINK のサービスで読み込む**（機械の外への口は LINK だけ、という今の規則のまま）
- **電源を入れたときに何が起きるかはユニットのモデルで決める**（2026-10-04）。モデルの一覧（`MODELS`）に PLAY-320 を足し（MODEL レジスタ FF02 は 4）、モデルごとの ROM の組でリセットする。POCKET と HANDHELD は今の ROM（BASIC）、PLAY-320 は PLAY の ROM（起動画面）。電源のたびに中身を見て判定はしない
- **モデルは TUNE で選ぶ**（今の液晶の一覧に足す）。PLAY-320 との行き来は再起動して RAM を消す（BASIC のプログラムとゲームの RAM は意味が違う）。POCKET と HANDHELD の間は今どおり RAM を残す
- **ゲームのファイルは main の「ゲームの棚」に置く**（2026-10-04）。CHIP-8 のライブラリのやり方を踏襲し、CHIP-8 とは完全に独立させて混ぜない（§7）
- **ほかのモデルを引き上げない**（2026-10-04）。拡張 RAM、映像、パッド、音、毎秒 60 枚の描画は、どれもモデルのデータ（`MODELS`）に持たせ、PLAY-320 だけが持つ。POCKET-32/48/64 と HANDHELD-160 は今の動きのまま（BANK 0x20 以上を無視、F800–FEFF は 0、描画は毎秒 30 枚まで、スナップショットに拡張 RAM なし）。**各段階でテストで固定する**
- **LINK は TUNE とは別のパネル LINK で、サービスごとに ON/OFF する**（2026-10-04）。LINK 全体は既定 ON。サービス 0（AI）は既定 OFF、サービス 1（CART、カートリッジの読み込み）は既定 ON。ネットワークに出るのは AI だけなので、既定ではどこにもつながらない。「人の操作の後だけ送る」規則はどのサービスにも効く（CART は START で満たす）。今の設定（`elec16.link` の ON）は「AI が ON」として引き継ぐ。パネル LINK はすべてのモデルに出る（作るのは G4）
- **PLAY-320 は自動で電源が切れない**（2026-10-04。携帯ゲーム機に自動のサスペンドはないため）。TUNE の自動電源オフは PLAY-320 では出さない
- **モニタは載せない。開発と確かめはパネルで行う**（2026-10-04）。CORE と MEM で拡張 RAM のバンクと映像メモリも見られるようにする。BRK と例外は起動画面に BREAK AT / FAULT を出して止まる
- **CODE の RUN は起動画面から直接**（2026-10-04）。起動画面をプロンプトの代わりにし、RUN はプログラムを RAM（7000）に置いてページがコアに直接呼ばせる（キーは打たない）。終われば起動画面に戻る。LOAD は置くだけ
- **G2 の間は画面だけを見せる**（2026-10-04）。PLAIN と同じく枠を描かず、320×288 の画面だけ。本体は G3
- ゲームは **e16c** で書く
- **ゲームパッド**に対応する
- 作業は、拡張 RAM、画面、本体（スキン）のような**小さいものから先に**進める

## 2. 全体

| 項目 | PLAY-320（ELEC-16 PLAY） | 参考: 今の HANDHELD-160 |
|---|---|---|
| CPU | E16（変更なし）。既定 4 MHz、TUNE で 1〜32 MHz | 同じ |
| RAM | 32 KB ＋ **拡張 RAM 最大 512 KB**（8 KB × 64 バンク、TUNE で選ぶ） | 32 KB |
| 画面 | **320×288**、毎秒 60 枚 | 160×144、毎秒最大 30 枚 |
| 色 | **32,768 色（RGB555）**から選ぶパレット | 4 階調 |
| 描画 | ビットマップ（4 色）と**描画回路**（タイル 16 色、スプライト） | ビットマップ（CPU が描く） |
| 映像メモリ | **64 KB**（機械の外。窓と DMA で読み書き） | 5,760 B（E000 からの窓） |
| 音 | **16 チャンネル** | ブザー 1 音 |
| 入力 | 十字、A、B、X、Y、L、R、START、SELECT。PC のキー、ゲームパッド | キーボード |
| ソフト | **カートリッジ**（ROM 最大 1 MB、セーブ RAM 最大 32 KB） | BASIC、機械語 3 KB、記憶カード |
| 起動 | **起動画面**（差したゲームの名前、PRESS START） | BASIC のプロンプト |
| 開発 | e16c（カートリッジ向けの出力） | e16c（7000 から 2 KB） |

CPU は今でも携帯ゲーム機の数倍の命令を実行できる（4 MHz で毎秒約 300 万命令）ので速くしない。重い仕事（画面の組み立て、音の合成）は描画回路と音の装置が受け持ち、CPU はゲームの中身に使う。

## 3. メモリの地図

| 番地 | 中身 |
|---|---|
| 0000–7FFF | RAM 32 KB |
| 8000–BFFF | ROM 固定 16 KB（PLAY 用: リセット、起動画面、ROM サービス、モニタ） |
| C000–DFFF | **バンクの窓** 8 KB。BANK（FF04）で選ぶ: 0〜11 ROM のバンク、**0x20〜0x5F 拡張 RAM**（TUNE で選んだ大きさまで）、**0x80〜0x83 セーブ RAM**、**0x100〜0x17F カートリッジ ROM** |
| E000–EFFF | **映像メモリの窓** 4 KB。VPAGE で 64 KB を 16 ページに分けて見せる |
| F000–F7FF | 予約 |
| F800–FEFF | **ゲーム用 I/O**（描画回路、音、入力、DMA、カートリッジ）。今は予約域 |
| FF00–FFFF | I/O（今のまま。LINK は FF70） |

- BANK は今も 16 ビットで、持っていないバンクは選ばず、窓はそのまま（今の規則）。PLAY-320 だけが 0x20 以上を持つ。ほかのモデルは今どおり 0〜11 だけで、0x20 以上は無視する（テストで固定）
- **持っていないバンク**（TUNE で選んだ大きさを超える拡張 RAM、差していないカートリッジ、ないセーブ RAM）も同じく選ばれず、窓はそのまま
- **拡張 RAM の窓のコードも実行できる**（大きいゲームがコードを入れ替えて読み込むため）。窓に書くと、RAM と同じく覚えた命令の解読を捨てる
- **拡張 RAM は電池バックアップ（スナップショット）に入る**。電源を入れ直しても遊んでいた続きから始まる。入れるのは TUNE で選んだ大きさの分だけ。スナップショットは版 3 にし、版 1 と 2 も読む（拡張 RAM は新しい機械と同じく 0）
- **拡張 RAM の大きさ**は 0 / 128 / 256 / 512 KB から TUNE で選び、既定は 512 KB。変えると、モデルを変えたときと同じく再起動して RAM を消す
- 拡張 RAM の上限（今は 512 KB）は 1 か所の定数にし、BANK の範囲もそこから決める。増やすときはそこを変える
- 拡張 RAM とセーブ RAM の窓は書ける。ROM とカートリッジ ROM の窓は今と同じく、書くと例外
- 窓のコードから別のバンクを呼ぶときは、固定 ROM の `far_call`（今の BASIC と同じ仕組み）を使う
- **PLAY の ROM**（`resources/elec16/play`、G2 で済み）は BASIC もモニタも持たない。手書きの `main.s`（リセット、トラップ、サービスの表）と、画面と起動画面を描く e16c の `play.e16.ts`（`npm run gen:elec16` が `play.s` と `play-rom.json` を書く）。固定 ROM は 8B52 まで
  - ROM サービスはポケコンの ROM と同じ番地・同じ番号（8010 から 4 バイトずつ）。0 PUTC、1 PUTS、3 CLS、4 LOCATE、5 PUTHEX、6 NEWLINE。キーボードのない 2 GETKEY と 7 READLINE、G4 までの 8 LINK は -1 を返す。ない番号の ECALL は FAULT 000B
  - 文字はポケコンと同じ 6×8 のフォントで 53 桁 36 行、パレット 0 の色 3 を色 0 の上に。最下行を越えると 1 行送る
  - 起動画面: 機種名、モデル名、RAM と拡張 RAM の大きさ（バンクを選んで確かめる）、カートリッジ（G4 まで NO CARTRIDGE）。どの線も有効にせず WFI で眠るので、起こすのは BRK だけ
  - BRK と EBREAK は `BREAK AT 番地`、ほかの例外は `FAULT 原因 AT 番地` を起動画面の下に出す。起動画面で眠っているときの BRK は描き直すだけ（どこで眠っていたかで見分ける。ページが ROM を通らずにプログラムを呼ぶので、目印の変数は使えない）
  - CODE の RUN はページがコアに `code_return` へ戻る呼び出しをさせる。プログラムが描いたものは残り、BRK で起動画面に戻る

## 4. 画面と描画回路

**モード 0（ビットマップ）**: 320×288、1 点 2 ビット（23,040 B）。4 色はパレット 0 の 0〜3 番で選ぶ。起動画面と ROM のサービス（PUTS など。文字は 6×8 で 53 桁 36 行）はこのモードを使う。

- 並び: 映像メモリの 0000 から 1 行 80 バイト、上の行から。1 バイトに横 4 点で、**左の点が上位の 2 ビット**（ビット 7–6）
- 色: パレットの 1 色は 2 バイト（リトルエンディアン）の RGB555。ビット 0–4 が赤、5–9 が緑、10–14 が青、15 は使わない

**映像のレジスタ**（F800–F8FF。PLAY-320 だけ。ほかのモデルでは今どおり 0 を読み、書いても何も起きない）:

| 番地 | 名前 | 読み書き | 中身 |
|---|---|---|---|
| F800 | VCTRL | 読み書き | ビット 0: 表示 ON（リセットで 1）、ビット 1–2: モード（0 ビットマップ、1 描画回路は G5。ほかは何も映さない） |
| F802 | VPAGE | 読み書き | E000–EFFF に見せる映像メモリの 4 KB のページ（0〜15） |
| F804 | VSTAT | 読み書き | ビット 0: VBLANK が来た（割り込みの線 5）。1 を書くと消える |
| F806 | FRAME | 読み | VBLANK の回数（16 ビットで回る） |

- **VBLANK** は毎秒 60 回、ページが渡す時間で来る（タイマーと同じく `advance`）。割り込みの線 5（`IRQ.vblank`）。WFI で待てる
- 映像メモリ（64 KB）と映像のレジスタはスナップショットに入る（版 4）。リセットは VCTRL を 1、VPAGE を 0 にし、映像メモリは残す（今の液晶と同じ）

**モード 1（描画回路）**（G5）:

- **タイル**: 8×8 ドット、**1 点 4 ビット（16 色）**、1 枚 32 B。映像メモリの 0000 から最大 1,024 枚（32 KB）。1 行 4 バイトで、1 バイトに横 2 点、**左の点が上位の 4 ビット**
- **背景 2 枚**: それぞれ 64×64 マス（512×512 ドット）。BG0 のマスは 8000 から、BG1 は A000 から、1 マス 2 バイト（行ごと）。マス: ビット 0–9 タイルの番号、10–12 パレット（背景用の 0〜7）、13 左右反転、14 上下反転、15 前（スプライトより前に出る）。背景ごとにずらし（X、Y、0〜511 で回る）
- **スプライト**: 128 個、表は C000 から 1 個 8 バイト: X（符号付き 16 ビット）、Y（同）、タイルの語（ビット 0–9 タイル、10–12 パレット（スプライト用の 8〜15）、13 左右反転、14 上下反転、15 後ろ（背景より後ろ））、大きさ（0: 8×8、1: 16×16、2: 32×32、3 以上: 出さない）。大きなスプライトは続きの番号のタイルを左上から行ごとに並べたもの（16×16 は 2×2、32×32 は 4×4）。1 行に 32 個まで（番号の若い順）。番号の若いものが前
- **パレット**: 16 色 × 16 本（背景 0〜7、スプライト 8〜15）、C400 から。1 色は RGB555 の 2 バイト。**どの層も色 0 は透明**で、どこも描かれない点はパレット 0 の色 0（背景色）
- **重なり**（奥から）: 背景色、後ろのスプライト、BG0、BG1、スプライト、前の BG0、前の BG1
- **映像メモリ 64 KB の割り当て**: 0000–7FFF タイル（モード 0 のビットマップもここ）、8000–9FFF BG0 のマス、A000–BFFF BG1 のマス、C000–C3FF スプライトの表、C400–C5FF パレット、残りは予約
- **レジスタ**（F820–F83F）:

| 番地 | 名前 | 読み書き | 中身 |
|---|---|---|---|
| F820 | BG0X | 読み書き | BG0 のずらし X（0〜511） |
| F822 | BG0Y | 読み書き | BG0 のずらし Y |
| F824 | BG1X | 読み書き | BG1 のずらし X |
| F826 | BG1Y | 読み書き | BG1 のずらし Y |
| F828 | LAYERS | 読み書き | ビット 0 BG0、1 BG1、2 スプライトを出す（リセットで 7） |
| F82A | LINECMP | 読み書き | この行に来たら LINE 割り込み（0〜287。それ以外は来ない。リセットで FFFF） |
| F82C | LINE | 読み | 今描いている行（0〜311。288 以上は描かない間） |
| F830 | DMASRC | 読み書き | DMA の元: CPU の番地（バンクの窓も読める） |
| F832 | DMADST | 読み書き | DMA の先: 映像メモリの番地 |
| F834 | DMALEN | 読み書き | バイト数 |
| F836 | DMACTRL | 読み書き | 1 を書くと始まり、0 を書くとそこで止まる。読むとビット 0 が動いている間 1 |

- **行**: 1 フレームは 312 行（288 行を描き、24 行は VBLANK の間）。今の行は VBLANK からの CPU のサイクルで決まる（`クロック ÷ 60 ÷ 312` サイクルで 1 行）。VBLANK は今までどおりページが渡す時間で来る
- **LINE 割り込み**: 行が LINECMP に来ると VSTAT のビット 1 が立ち、割り込みの線 7（`IRQ.line`）。1 を書くと消える。VBLANK でフレームを始めるときは、VSTAT に 3 を書いて前のフレームの LINE も消しておく（残っていると、このフレームの LINE を待つ WFI がすぐ戻る）。眠っている間も行は進み、LINE はその行で機械を起こす。**ずらしと LAYERS は行ごとに効く**: 書いた行から下にだけ効くので、LINE 割り込みで画面を途中から別のずらしにできる（上はステータス、下はスクロールなど）
- **DMA**: 元から先へ 1 回に 16 バイト、8 サイクルずつ。動いている間 CPU は止まるが、割り込みと BRK は毎回確かめ、割り込みの処理の間は DMA が待って MRET の後で続く（MCPY と同じ考え方）。PLAY の ROM は BRK と例外で DMA を止める。元は CPU の番地なので、カートリッジの ROM や拡張 RAM はバンクの窓から写す
- スナップショットは版 6 でこれらのレジスタを持つ（行ごとの書き込みの記録は持たず、戻った次のフレームから描き直す）

ページはモードと映像メモリから画面を組み立て、2D canvas に描く。320×288 = 92,160 点を毎フレーム組み立てても数ミリ秒の見込みで、変わったときだけ描く。G2 と G5 で負荷を測る。今のモデルの「液晶の描画は毎秒最大 30 枚」は、PLAY だけ 60 枚にする（測ってから決める）。

## 5. 音（16 チャンネル）（G6）

- **レジスタ**（F840–F85F。PLAY-320 だけ。ほかのモデルでは今どおり 0 を読み、書いても何も起きない）: チャンネルを CHSEL で選び、その 7 本を同じ番地で読み書きする

| 番地 | 名前 | 中身 |
|---|---|---|
| F840 | CHSEL | 選んでいるチャンネル（0〜15） |
| F842 | WAVE | 0〜3 矩形（デューティ 12.5 / 25 / 50 / 75%）、4 三角、5 のこぎり、6 ノイズ、8〜15 波形表 0〜7（ほかは無音） |
| F844 | FREQ | 周波数を 1/4 Hz 単位で（1 = 0.25 Hz、最大 16383.75 Hz）。ノイズは刻む速さ |
| F846 | VOL | 音量 0〜15 |
| F848 | PAN | 0 左〜8 真ん中〜15 右 |
| F84A | ENV | ビット 0–3 アタック、4–7 ディケイ、8–11 サステインの高さ（0〜15）、12–15 リリース。時間は表で 0, 2, 5, 10, 20, 40, 80, 120, 160, 250, 400, 600, 800, 1200, 2000, 3000 ms |
| F84C | MOD | ビット 0–7 スイープ（符号付き、1/4 半音／秒）、8–11 ビブラートの深さ（1/16 半音）、12–15 ビブラートの速さ（Hz） |
| F84E | KEY | 1 を書くと鳴らし始める（エンベロープを最初から）、0 を書くと離す（リリースへ）。読むとビット 0 が押している間 1 |
| F850 | MASTER | 全体の音量 0〜15（リセットで 15） |

- **波形表**: 映像メモリの C600 から 8 本、1 本 32 点 × 4 ビット（16 バイト、左の点が上位の 4 ビット）
- **ノイズ**: 15 ビットの LFSR（決まった種から）。FREQ の速さで刻む
- **コアは設定値と「いつ鳴らしたか・離したか」（ページが渡した時刻）だけを持ち**、音そのものはページの合成器（AudioWorklet。CHIP-8 と同じ形: `shared/elec16/apu.ts` の純粋な声を、ワークレットとテストが同じように動かす）が作る。ページはフレームごとに変わったところだけを送る。コアは時計にも DOM にも触れない。今の BEEP（ブザー）は残す
- 音は設定の音（interface sounds）と ELEC-16 の音量に従い、一時停止や見えないときは止まる（ブザーと同じ）
- スナップショットは版 7 でレジスタを持つ。戻った機械はどのチャンネルも離された状態（キーやパッドと同じ）
- 起動画面に入るたびに、PLAY の ROM は 16 チャンネルをみな離し、MASTER を 15 に戻す（ゲームが何を鳴らしたまま戻っても。画面をモード 0 に戻すのと同じ）
- ページは止める・隠す・一時停止で全チャンネルをすぐ止め、続けるときは今の設定をまるごと送り直す。音を一度も鳴らさないゲームではオーディオの装置を開かない

## 6. 入力

- **パッドのレジスタ**（PLAY-320 だけ。ほかのモデルでは今どおり 0 を読み、書いても何も起きない）:

| 番地 | 名前 | 読み書き | 中身 |
|---|---|---|---|
| F810 | PAD | 読み | 今押されているボタン（12 ビット） |
| F812 | PADHIT | 読み書き | 前に消してから押されたか離されたボタン。1 を書いたビットが消える。0 でない間、割り込みの線 6（`IRQ.pad`）が上がる |

  - ビット: 0 上、1 下、2 左、3 右、4 A、5 B、6 X、7 Y、8 L、9 R、10 START、11 SELECT
  - スナップショットには入らない（キーと同じく、戻った機械はどのボタンも離されている）。リセットは PADHIT を消す
  - ボタンを押すのは人の操作なので、LINK の「人の操作」になる
- **本体のボタン**: 12 個全部。十字キーと A、B、X、Y は菱形の並び（X が上、Y が左、A が右、B が下）、L と R は上の角、START と SELECT。押している間だけ沈んで見える
- **PC のキー**: 矢印＝十字、Z＝A、X＝B、S＝X、A＝Y、Q＝L、W＝R、Enter＝START、右 Shift＝SELECT。Pause は BRK。キーはペインに焦点があるときだけ機械に届き、Ctrl、Alt、システムキー、Tab、Escape、ファンクションキーは取らない（今の規則）
- **ゲームパッド**: ブラウザの Gamepad API の標準の配置（`mapping: 'standard'`）だけ。ボタンは位置で合わせる: 右（1）＝A、下（0）＝B、上（3）＝X、左（2）＝Y、LB（4）＝L、RB（5）＝R、Start（9）＝START、Back（8）＝SELECT、十字（12〜15）と左スティック（0.5 を越えたら）＝十字。ペインに焦点があり、見えているときだけ読む。機械が動いている間は実行ループのフレームごと、眠っている間は共通の 10 fps のループで読む（自分の rAF は持たない）
- 3 つ（本体のボタン、PC のキー、ゲームパッド）の押下は OR でまとめて PAD になる
- **START が RUN**: 起動画面で START を押すと、差してあるゲームを読み込んで始める（G4）

## 7. カートリッジ

- **カートリッジの中身**（ファイルは `.E16G`）: 64 バイトのヘッダと、8 KB の ROM のバンク（1〜128、最大 1 MB）。ヘッダ:

| 位置 | 大きさ | 中身 |
|---|---|---|
| 0 | 4 | `E16G` |
| 4 | 1 | 版（1） |
| 5 | 1 | ROM のバンク数（1〜128） |
| 6 | 1 | セーブ RAM のバンク数（0〜4、8 KB ずつ） |
| 7 | 1 | 0 |
| 8 | 2 | 入口（C000–DFFF の番地。バンク 0x100 を窓に見せて飛ぶ） |
| 10 | 6 | 0 |
| 16 | 16 | id（英大文字、数字、`-`。残りは 0）。セーブ RAM はこの id ごとに残る |
| 32 | 24 | 名前（表示できる ASCII。残りは 0） |
| 56 | 8 | 0 |

- **差し口**（コア、PLAY-320 だけ）: 差したカートリッジの id、中身のハッシュ（SHA-256、main が計算する）、ROM のバンク数、セーブ RAM。ROM のバンクは BANK 0x100 から、セーブ RAM は 0x80 から窓に見える（ROM は読むだけで、書くと例外。セーブ RAM は書けて、コードも実行できる）。持っていないバンクは選ばれない
- スナップショット（版 5）には id、ハッシュ、バンク数、セーブ RAM を入れ、ROM の中身は入れない（main の棚にある）。戻るときにページが main から同じハッシュの中身をもらって差し直し、なければ起動画面に戻る
- **LINK のサービス 1（CART）**: TYPE 0 INFO は差してあるゲームのヘッダ（64 バイト）を答える。TYPE 1 LOAD は同じヘッダを答え、あわせてページが中身とセーブ RAM をコアの差し口に入れる（答えの `cart`）。差していなければ FAILED（`no cartridge`）、PLAY-320 でないユニットにも FAILED（`no cartridge slot`）
- **ゲームの棚**: main が持つ、ELEC-16 PLAY 専用のゲームの一覧（記憶カードとは別）。CHIP-8 のライブラリと同じやり方にする:
  - 同梱のゲームは `resources/elec16/games/games.json`。書くのは生成スクリプト（`npm run gen:elec16` の一部か専用のもの）だけ
  - 取り込みは main のピッカーから。大きさを先に確かめ、ヘッダをコアの読み手で確かめてから棚に入れる
  - 利用者のものは main のファイル（`elec16/games/library.json`、取り込んだ像、セーブ RAM）。ペインの状態には置かない
  - ページは id で一覧と中身をもらう（`elec16.games.list` など）。棚が変わると知らせ、ページの一覧は丸ごと差し替える
  - **CHIP-8 とは完全に別**: ファイル、フォルダ、チャンネル、id、ピッカーの種類、一覧のどれも共有しない。CHIP-8 の棚に ELEC-16 のゲームは出ず、その逆もない。共通にしたくなった部品も、まず別々に書く
- **起動画面と START**（G4 で済み）: 起動画面は CART の INFO で差してあるゲームの名前を出し、下の行に PRESS START（だれもまだ何も押していなければ HELD なので、これも PRESS START）、差していなければ NO CARTRIDGE、LINK か CART が OFF なら LINK CART IS OFF。START は LOAD で読み込んで、BANK を 0x100 にし、入口へ新しいスタックで飛ぶ。ゲームが戻れば起動画面。押されたかは「PADHIT にあり、前に見たときは離されていた」ボタンで見る（PC のキーは押して離すまでが 1 フレームに収まることが多い）
- **見本のゲーム**（`resources/elec16/games/<名前>/game.s` と `game.json`、E16 アセンブリ。同じフォルダのファイルを `.include` できる。`npm run gen:elec16` が `games.json` にする）:
  - `DEMO`: モード 0。十字キーで動き、A で色が変わる四角。A は色の音（C6・E6・G6、三角波、打って消える）をチャンネル 0 で鳴らし、四角の横の位置で左右に置く（G6）
  - `SCROLL`（G5）: モード 1。星空（半分の速さ）とレンガの壁を LINE 割り込みで行 144 から分けて横にスクロールし、上に動かない帯（BG1）、十字キーで動く 16×16 の船（スプライト）。タイルとパレットはカートリッジの ROM から DMA で写す
  - `ELECLANCE`（G7）: ゲームキットで作った縦スクロールシューティング（[elec16-eleclance.md](elec16-eleclance.md)）
  - DEMO と SCROLL は START で起動画面へ。起動画面は入るたびにモード 0 と自分のパレットに戻す（ゲームが何を残しても）
- **差し替え**: ペインのパネルの **GAMES** で 1 本を選んで「差す」。ほかのモデルの FILES のような一覧で、見本のゲーム（同梱）と、取り込んだゲームが並ぶ。抜くのもここ。差してあるゲームは main がユニットごとに覚える
- **読み込みの流れ**:
  1. 電源を入れると起動画面。差してあるゲームの名前と PRESS START が出る（差していなければ「パネルの GAMES で差してください」）
  2. START を押すと、起動 ROM が LINK のサービス 1（CART）に読み込みを頼む（START は人の操作なので、LINK の HELD の規則も満たす）
  3. main が中身をページへ渡し、ページがコアのカートリッジの差し口に入れる（ROM の像と同じく、コアは外を読まない）。LINK の答えはヘッダ
  4. 起動 ROM が BANK を 0x100 にして入口へ飛ぶ
- **セーブ RAM**（BANK 0x80〜）は main がユニットごと、カートリッジごとに残す。書くのは電池バックアップと同じ時（隠す、閉じる、電源を切る、ページが去る）
- 機械がしまわれる（スナップショット）ときは、カートリッジの **id と中身のハッシュ**を残し、戻るときに main からもう一度差す。同じ中身のゲームが棚になければ起動画面に戻る（中身の違うゲームを古い RAM のまま続きから動かさない）
- セーブ RAM は**ゲームの id ごと**に残す。同じゲームの新しい版に替えてもセーブは残る
- CART は LINK のサービス 1。LINK パネルで切れるが既定 ON。main の中だけで済み、ネットワークには出ない
- ゲームを抜くと、遊んでいたゲームは止まり、起動画面に戻る

## 8. 本体（スキン）

- **共通**: 上部の左に「ELEC-16 PLAY」、右に電源の表示灯（「POWER」の文字なし）。ボタンと十字キーは立体的（影と光で沈み込みを表す）
- **縦長の本体**: 画面が上。十字キーが左、A・B・X・Y が右、SELECT と START が真ん中の下、L と R は上の角、スピーカーの穴
- **横長の本体**: 画面が真ん中。十字キーと SELECT が左、A・B・X・Y と START が右、L と R は上の角
- **本体の選び方**（ペインの状態、TUNE）: auto（ペインの形で縦長か横長）、tall（縦長）、wide（横長）、screen（画面だけ。G2 の見た目）
- **色**（ペインの状態、TUNE）: graphite、ivory、coral（モックの 3 色、固定の色）。画面だけのときは使わない
- 大きさは本体の形の比のまま部屋に収め、伸ばさない（今の規則）。本体の寸法は画面の 1 ドットを単位にした 1 か所の幾何（`play-body.ts`）で決め、画面はデバイスピクセルの整数倍に揃える。ボタンが本体の中に収まり、重ならないことを単体テストで確かめる

## 10. ゲームキット（G7）

e16c でカートリッジのゲームを書くための道具。1 本のゲームは `resources/elec16/games/<名前>/` のフォルダで、`game.json` に `sources` があればキットで作る（ないものは今までどおりアセンブリの `game.s`）。`npm run gen:elec16` がビルドして `games.json` に入れ、ゲームのソースが読む定数を `assets.e16.ts` に、e16c が変換したアセンブリ（ライブラリの分も含む）を `compiled.s` に書く（どちらも手で直さない。テストが一致を確かめる）。作るのは `shared/elec16/kit/build.ts`（純粋。ビルドのスクリプトとテストが同じものを使う）。

- **カートリッジの並び**（8 KB のバンク）:
  1. バンク 0: 入口（`games/lib/runtime.s`）。ゲームのコードを RAM に写して、そこで始める
  2. バンク 1〜: e16c のファイルに `bank` を付けたコード（窓の中で動く。呼ぶのは RAM の `far_call`）
  3. データ: キットの表（sin、atan）、パレット、スプライトのシート、背景の地図、曲、ゲームの表
  4. 最後: RAM に写すコード
- **RAM**: 0000–01FF は PLAY の ROM、0200–027F はランタイム、0280–1FFF はゲームの大域変数と配列、2000–6FFF はコード（入りきらなければ `bank` で窓のバンクへ）、7000–7FFF はスタック
- **RAM のコードは窓を自由に切り替えてよい**。窓のバンクで動くコードは、自分のバンクを外さない（ライブラリの読み込みは窓を元に戻す）
- **割り込み**: ランタイムが自分のハンドラを持つ。VBLANK は数を数え、LINE は 8 行ごとに BG0X を表（`RASTER`、36 本）から書く（`raster(1)`）。ほかの原因（BRK、例外、ECALL）は ROM のハンドラへそのまま渡す。ゲームが戻る、または BRK や例外で止まると、ROM は起動画面で自分のハンドラと割り込みなしに戻す
- **フレームの待ち**: `frame_wait(前の数)` は割り込みを止めて確かめてから WFI するので、確かめた直後の VBLANK も取りこぼさない
- **窓で動くコードは窓を替えない**: バンクに置いたファイルの関数が `bank()` を呼ぶと、次の命令が別のバンクから読まれる。データを窓から読む関数は RAM のファイルに置く（ライブラリの読み込みは RAM にあり、窓を元に戻すので、窓のコードから呼んでよい）。バンクの使い方と制限（8 KB、番号の詰め方、文字列、呼び方の表）は [elec16-kit.md](elec16-kit.md#81-コードをバンクに置く) の 8.1
- **スプライトのパレット**: タイルの語のビット 10–12 は、スプライトでは 0〜7 が slot 8〜15。slot の番号をそのままずらすと、ビット 13（左右反転）に溢れる
- **ゲームの始まり**: 起動の START はまだ押されているので、`kitInit` はその時押されているボタンを「押した」としない
- **`game.json`**:

| 項目 | 中身 |
|---|---|
| `id`、`name`、`saveBanks`、`about` | 今までどおり |
| `sources` | e16c のファイル。`{ "file": "boss.e16.ts", "bank": 1 }` でバンクに置く |
| `palettes` | `{ "png": "art/palettes.png", "names": [...] }`。幅 16 点の絵で、1 行が 1 本のパレット（色 0 は透明）。定数 `PAL_名前` が行の番号 |
| `sheets` | `{ "name", "png", "cell": 8/16/32, "palette", "count"?, "tile"?, "stream"? }`。8 KB を越えるシートはバンクの頭から次のバンクへ続けて置く（`load` はバンクをまたげる）。`stream` は映像メモリに取るコマの数で、全部はカートリッジに残し、見せるものだけ `load` する（`_BYTES` はその場所の大きさ。ELECAIRCOMBAT の敵機）。同じ大きさのコマを左上から行ごとに。定数 `名前_TILE`（映像メモリのタイル番号）、`_BANK`、`_AT`、`_BYTES`、`_FRAMES`、`_STEP`（1 コアのタイル数） |
| `maps` | `{ "name", "png", "palettes": [{ "palette", "slot" }], "tile"?, "front"? }`。`front` で透明でないマスをスプライトより前に（計器の板）。8×8 のマスごとに、色がすべて入る最初のパレットを選び、同じ形（反転も）のタイルは共有する。全部透明のマスが最初のタイル。行は 64 マス（128 バイト）に揃え、1 バンク 64 行。定数 `名前_TILE`、`_TILES_BANK`、`_TILES_AT`、`_TILES_BYTES`、`_MAP_BANK`、`_W`、`_H`、`_ROWS_PER_BANK` |
| `music` | 曲の MML ファイル（下）。定数 `SONG_名前_BANK`、`SONG_名前_AT` |
| `tables` | `{ "name", "file" }`。数を並べたテキスト（ワード）。定数 `名前_BANK`、`_AT`、`_LEN` |

- **絵**: PNG（8 ビットの RGB、RGBA、グレー、パレット）。色はパレットの色と RGB555 で**完全に一致**しなければならず、合わない点は場所と色を示して断る（勝手に減色しない）。透明は不透明度が半分未満の点
- **ライブラリ**（`games/lib/kit.e16.ts`、`sound.e16.ts`。ゲームの名前と同じ名前空間）: `bank`、`vpoke`、`vfill`、`dma`、`load`（バンクの窓から映像メモリへ。バンクをまたげる）、`palette`、`colour`、`palKeep` と `palMix`（明滅、フェード）、`cellAt`、`mapRow`、`text`、`number`、スプライト（`sprBegin`、`spr`、`sprShow`。表は RAM に作り、フレームの始めに DMA で写す）、パッド（`padRead`、`held`、`pressed`）、`sin`、`cos`、`aim`（256 段の向き）、`rand`、点（`scoreAdd` など。下 4 桁ずつの 2 ワード）、セーブ RAM（`saveRead`、`saveWrite`）、音（`soundInit`、`play`、`soundTick`、`musicStop`、`musicMute`、`soundMaster`）
- **曲（MML）**: 1 ファイルに `song 名前` で区切って何曲でも。

```
tempo 6                                # 16 分音符のフレーム数（6 は 150 BPM）
inst lead wave=sq25 vol=12 env=2/250/9/120 vib=3,6 pan=8 drop=0
define riff = o2 l16 a a > a < a       # 何度も使う型
C0: @lead o4 l8 a4. g8 L a2 ...        # チャンネル 0。行は順につながる
C3: [$riff]4                           # 繰り返し
echo C1 = C0 delay 3 vol -4 pan 12     # C0 を 3 フレーム遅らせ、小さく、右に
```

  - 楽器: `wave`（sq12 sq25 sq50 sq75 tri saw noise tbl0〜7）、`vol`、`env`（アタック ms / ディケイ ms / サステイン 0〜15 / リリース ms。近い段に）、`slide`、`vib`（深さ, 速さ）、`pan`、`drop`（毎フレーム FREQ から FREQ >> drop を引く。キックの落ち）
  - チャンネルの中: 音名 `c d e f g a b`（`+` `#` `-`）、長さ（1〜64、付点 `.`、タイ `^`）、`r` 休み、`o` `<` `>` オクターブ、`l` 長さ、`v` 音量、`@` 楽器、`p` パン、`q` 音を保つ長さ（8 分の）、`k` 移調、`L` 繰り返しの戻り先、`[ … ]n` 繰り返し、`$名前` 定義
  - 長さはフレームの整数にならなければ断る（`tempo 5` の 32 分音符など）
  - 音符のバイトコードは 3 通り: 前と同じ長さなら音の高さだけ（AGAIN、3 バイト）、前と同じ音なら 1 バイト（REPEAT）、それ以外は 5 バイト。繰り返しを展開したアルペジオや太鼓が 1 曲 8 KB に収まる（1 曲は 1 バンクの中）
  - **チャンネル 0〜11 は曲、12〜15 は効果音**。効果音は曲を止めない。`musicMute` で曲の一部のチャンネルを黙らせ（音符は進む）、あとで重ねられる

## 11. ゲームの開発環境（G7.5）

利用者の決定（2026-10-04）: 私たち以外の人がゲームを作るために、アプリだけで完結する開発環境を用意する。CODE に貼るのはゲームには向かない（ファイルが多く、絵と曲がある）。コマンドラインは作らない（リポジトリの `npm run gen:elec16` は同梱のゲームのため）。

- **フォルダを開く**（GAMES の DEVELOP）: main のピッカーでゲームのフォルダ（`game.json` のあるところ）を選ぶ。フォルダはページごとに main が覚え、ページには名前だけを返す（レイアウトにパスは載せない。今の規則のまま）。アプリを閉じると忘れる
- **読むもの**: `game.json`（10 章の形。main が zod で確かめる）と、そこに書かれたファイルだけ（ソース、PNG、曲、表）。名前はフォルダの中の相対パスで、`..` や絶対パス、フォルダの外を指すものは断る。1 ファイル 4 MB、合わせて 16 MB まで。ライブラリ（`kit.e16.ts`、`sound.e16.ts`、`runtime.s`）はフォルダのものではなくアプリに入っているものを使う（どのゲームも同じランタイムで動く）
- **ビルドはページの Worker**: e16c は TypeScript のパーサを使うので main では動かさない（package-deps の規則）。CODE のコンパイル用の Worker（`?worker&inline`、CSP はそのまま）にキットのビルドを足す。PNG は Worker の `createImageBitmap`（色空間の変換も乗算済みアルファもなし）でほどく。依存は足さない
- **できたもの**:
  - カートリッジは main が今の取り込みと同じ検査（大きさ、`readCart`）をして棚に入れる。同じ id の取り込み済みのゲームがあれば置き換える（同梱のゲームの id は使えない）。そのままユニットに差し直す（今の GAMES の差し替えと同じく、機械はリセットして起動画面へ）
  - `assets.e16.ts` と `compiled.s` を main がフォルダに書く（この 2 つの名前だけ。中身が変わったときだけ）。エディタで定数が補完でき、変換結果を読める
  - エラーは「ファイル:行: 内容」で GAMES に出す（最大 8 件）
- **作り直し**: フォルダを開いている間、main がフォルダを見張り（`fs.watch`、0.3 秒まとめる。書き戻す 2 つのファイルの変化は無視）、変わったらページに知らせ、ページが作り直す（自動）。REBUILD でいつでも。ペインが見えない間や、ページが去ると見張りをやめる
- **新しいゲーム**（NEW GAME）: main のピッカーで空のフォルダを選ぶと、動く最小のゲームの雛形を書き出して、そのまま開く。雛形（`resources/elec16/kit-template`）: `game.json`、`main.e16.ts`、`art/palettes.png`、`art/ship.png`、`music/songs.mml`、`README.md`、`tsconfig.json`。エディタのためにライブラリの写しと e16c の型（`lib/`）も書く。`game.json` がすでにあるフォルダには書かない
- **手引き**: [elec16-kit.md](elec16-kit.md)（日本語）。フォルダの形、game.json、ライブラリの関数、MML、絵の決まり、メモリとバンクの決まり、エラーの読み方。雛形がビルドできることはテストで確かめる
- 安全: ビルドしたコードは E16 の機械語としてコアの上でしか動かない（JavaScript としては動かない）。main が書くのはユーザーが選んだフォルダの決まった 2 つのファイルと、雛形のときの雛形のファイルだけ
