# ELEC-16 PLAY-320 — ゲーム機モデルの仕様（案）

ELEC-16 の別モデルとして作るゲーム機の仕様です。**設計中**で、ここに書いたことは利用者と決めながら直します。決まったことは「決まっていること」に移し、理由は [decisions.md](decisions.md) に残します。機械の土台は [elec16.md](elec16.md)、モックは https://claude.ai/artifact/Ro5nRdZwipjDzHAhCroXBp にあります。

## 1. 決まっていること（2026-10-04、利用者の決定）

- **独自の機械、独自の規格**。携帯ゲーム機クラスを**少しだけ上回る**性能をねらう。既存のゲーム機のソフトは動かさず、互換もねらわない。実在の機種名、ロゴ、デザインを公開物に使わない（elec16.md §1 の 2026-10-03 の決定のとおり）
- **描画回路を足す**（タイルとスプライト）。**画面は 320×288**（携帯ゲーム機の画面の縦横 2 倍）
- **本体は縦長**を作る。スキンの問題なので、**横長の本体**（昔の液晶ゲームのような形）も用意する
- **音は 16 チャンネル**
- **カートリッジを入れる**。差し込みは **LINK のサービス**で行う（SOFT CARD の `GAME.BAS` などから LINK でカートリッジを差し、バンクの窓から読む）
- ゲームは **e16c** で書く
- **ゲームパッド**に対応する
- **色を足す**
- 作業は、拡張 RAM、画面、本体（スキン）のような**小さいものから先に**進める

## 2. 全体

| 項目 | PLAY-320 | 参考: 今の HANDHELD-160 |
|---|---|---|
| CPU | E16（変更なし）。既定 4 MHz、1〜32 MHz | 同じ |
| RAM | 32 KB ＋ **拡張 RAM 128 KB**（8 KB × 16 バンク） | 32 KB |
| 画面 | **320×288**、毎秒 60 枚 | 160×144、毎秒最大 30 枚 |
| 色 | **32,768 色（RGB555）**から選ぶパレット | 4 階調 |
| 描画 | ビットマップ（4 色）と**描画回路**（タイル、スプライト） | ビットマップ（CPU が描く） |
| 映像メモリ | **64 KB**（機械の外。窓と DMA で読み書き） | 5,760 B（E000 からの窓） |
| 音 | **16 チャンネル** | ブザー 1 音 |
| 入力 | 十字、A、B、X、Y、L、R、START、SELECT。ゲームパッド | キーボード |
| ソフトの置き場 | **カートリッジ**（ROM 最大 1 MB、セーブ RAM 最大 32 KB） | 機械語 3 KB、記憶カード |
| 開発 | e16c（カートリッジ向けの出力） | e16c（7000 から 2 KB） |

CPU は今でも携帯ゲーム機の数倍の命令を実行できる（4 MHz で毎秒約 300 万命令）ので速くしない。重い仕事（画面の組み立て、音の合成）は描画回路と音の装置が受け持ち、CPU はゲームの中身に使う。

## 3. メモリの地図

| 番地 | 中身 |
|---|---|
| 0000–7FFF | RAM 32 KB（今のまま。ROM の作業域、BASIC、機械語の領域、スタック） |
| 8000–BFFF | ROM 固定 16 KB（今のまま。リセット、ROM サービス、BASIC の中心） |
| C000–DFFF | **バンクの窓** 8 KB。BANK（FF04）で選ぶ: 0〜11 ROM のバンク、**0x20〜0x2F 拡張 RAM**、**0x80〜0x83 セーブ RAM**、**0x100〜0x17F カートリッジ ROM** |
| E000–EFFF | **映像メモリの窓** 4 KB。VPAGE で 64 KB を 16 ページに分けて見せる |
| F000–F7FF | 予約 |
| F800–FEFF | **ゲーム用 I/O**（描画回路、音、入力、DMA、カートリッジ）。今は予約域 |
| FF00–FFFF | I/O（今のまま。LINK は FF70） |

- BANK は今も 16 ビットで、0〜11 以外は無視している。値を足すだけなので、今の ROM と BASIC はそのまま動く
- 拡張 RAM とセーブ RAM の窓は書ける。ROM とカートリッジ ROM の窓は今と同じく、書くと例外
- 窓のコードから別のバンクを呼ぶときは、固定 ROM の `far_call`（BASIC が使っているもの）を使う
- 映像メモリの窓は、PLAY-320 のときだけ E000–EFFF の意味が変わる。ほかのモデルは今のまま

## 4. 画面と描画回路

**モード 0（ビットマップ）**: 320×288、1 点 2 ビット（23,040 B）。4 色はパレットで選ぶ。ROM と BASIC はこのモードを使い、文字は 6×8 のフォントで 53 桁 36 行。PSET、LINE、CIRCLE は色を選べるようにする（BASIC の書き方は G2 で決める）。

**モード 1（描画回路）**:

- **タイル**: 8×8 ドット、1 点 4 ビット（16 色）、1 枚 32 B。最大 1,024 枚（32 KB）
- **背景 2 枚**: それぞれ 64×64 マス（512×512 ドット）。マスは 16 ビットで、タイルの番号（10 ビット）、パレット（3 ビット）、左右反転、上下反転、優先順位を持つ。背景ごとにずらし（SX、SY）を持つ。背景 1 は画面の一部に固定した窓にもできる
- **スプライト**: 128 個、1 行に 32 個まで。大きさは 8、16、32 ドット。パレット、反転、背景との前後を選べる
- **パレット**: 16 色 × 16 本（背景 8 本、スプライト 8 本）。1 色は RGB555 の 2 バイト。スプライトの 0 番の色は透明
- **映像メモリ 64 KB の割り当て**: 0000–7FFF タイル（モード 0 のビットマップもここ）、8000–9FFF 背景 0 のマス、A000–BFFF 背景 1 のマス、C000–C3FF スプライトの表、C400–C5FF パレット、残りは予約
- **割り込み**: VBLANK（毎秒 60 回、描き終わり）と、LINE（指定した行に来たとき。画面を途中で分ける表現に使う）
- **DMA**: RAM、拡張 RAM、カートリッジから映像メモリへまとめて写す。転送中も割り込みと BRK は効く（MCPY と同じ考え方）

ページはモードと映像メモリから画面を組み立て、2D canvas に描く。320×288 = 92,160 点を毎フレーム組み立てても数ミリ秒の見込みで、変わったときだけ描く。G2 と G5 で負荷を測る。今のモデルの「液晶の描画は毎秒最大 30 枚」は、PLAY-320 だけ 60 枚にする（測ってから決める）。

## 5. 音（16 チャンネル）

- チャンネルごとに: 波形（矩形 12.5 / 25 / 50 / 75%、三角、のこぎり、ノイズ、波形表 8 本のどれか）、周波数、音量 0〜15、エンベロープ（アタック、ディケイ、サステイン、リリース）、左右、音程の変化（スイープ、ビブラート）、鳴らす・止める
- 波形表は 32 点 × 4 ビット × 8 本
- I/O の番地が足りないので、チャンネルを選ぶレジスタと 8 本のレジスタの窓で書く（F800 番台）
- **コアは設定値と「いつ鳴らしたか」だけを持ち**、音そのものはページの合成器（AudioWorklet。プラグインの楽器と同じ仕組み）が作る。コアは時計にも DOM にも触れない。今の BEEP は残す

## 6. 入力

- **パッドのレジスタ**: 十字、A、B、X、Y、L、R、START、SELECT の 12 ビット。押下が変わると PAD 割り込み
- **本体のボタン**: 十字、A、B、START、SELECT。X、Y、L、R は PC のキーとゲームパッドから
- **PC のキー**（案）: 矢印＝十字、Z＝A、X＝B、A＝Y、S＝X、Q＝L、W＝R、Enter＝START、右 Shift＝SELECT。キーはペインに焦点があるときだけ機械に届く（今の規則）
- **ゲームパッド**: ブラウザの Gamepad API の標準の配置。ペインに焦点があるときだけ読む。フレームごとに状態を見る
- BASIC を打つときは、本体にキーボードがないので PC のキーで打つ（画面に出すキーボードは要相談）

## 7. カートリッジ（LINK で差し込む）

- **カートリッジの中身**: ヘッダ（名前、ROM のバンク数、セーブ RAM の大きさ、入口）と ROM のバンク。ファイルの形は G4 で決める
- **置き場**: main のカートリッジの一覧（CHIP-8 のライブラリと同じく、取り込みは main のピッカーから）。見本のカートリッジは同梱する（このリポジトリのソースから作る）
- **差し込みの流れ**:
  1. SOFT CARD の `GAME.BAS` を動かす
  2. LINK のサービス 1（CART）で一覧を聞き、1 本を選んで差し込みを頼む
  3. main がカートリッジの中身をページへ渡し、ページがコアのカートリッジの差し口に入れる（ROM の像と同じく、コアは外を読まない）。LINK の答えはヘッダ
  4. BANK を 0x100 にして入口へ飛ぶ。セーブ RAM（BANK 0x80〜）は main が残す（ユニットごと、カートリッジごと）
- 差し込むのは人の操作の後だけ（LINK の HELD の規則のまま）
- 機械がしまわれる（スナップショット）ときは、カートリッジの名前だけを残し、戻るときに main からもう一度差す

## 8. 本体（スキン）

- **縦長の本体**: 画面が上、十字キーと A、B が下、START と SELECT、スピーカーの穴
- **横長の本体**: 画面が真ん中、十字キーが左、A と B が右
- どちらも色違いのスキンを持つ（モックは graphite、ivory、coral）。本体の形はモックで決める。`deviceFit` で大きさを決め、伸ばさない規則は今のまま

## 9. 作業の順番（小さいものから）

| 段階 | 中身 | 規模 | 終わるとできること |
|---|---|---|---|
| G1 | **拡張 RAM**: BANK 0x20〜0x2F、スナップショットの版を上げる（古い版も読む）、モニタと e16c から使えるようにする | 小 | 大きな表や絵を RAM に置ける |
| G2 | **画面 320×288**: PLAY-320 モデル、モード 0（4 色のビットマップ、パレット）、映像メモリ 64 KB と窓、毎秒 60 枚、VBLANK、BASIC 53 桁 36 行 | 小〜中 | BASIC と機械語で色つきの絵が描ける |
| G3 | **本体と入力**: 縦長と横長の本体（スキン）、パッドのレジスタ、PC のキー、ゲームパッド | 小〜中 | 本体とゲームパッドで遊べる |
| G4 | **カートリッジ**: LINK のサービス CART、バンクの窓に ROM、セーブ RAM、一覧、`GAME.BAS` | 中 | 大きなゲームを差して動かせる |
| G5 | **描画回路**: タイル、背景 2 枚とずらし、スプライト、パレット、LINE 割り込み、DMA | 大 | スクロールするゲームが毎秒 60 枚で動く |
| G6 | **音 16 チャンネル** | 中〜大 | 音楽と効果音 |
| G7 | **e16c でゲームを作る**: カートリッジ向けの出力、ROM の表、バンクをまたぐ呼び出し、描画と音のライブラリ、PNG と音のデータの取り込み | 大 | TypeScript でゲームが書ける |
| G8 | **見本と説明書**: 見本のゲーム、ゲーム機の説明書、README、紹介ツアー | 中 | 公開できる |

## 10. まだ決めていないこと

- モデルの名前（案: PLAY-320）と、本体の形の細部（モックで決める）
- タイルの色数: 1 点 4 ビット（16 色、案）か、2 ビット（4 色）で軽くするか
- 拡張 RAM の大きさ（案: 128 KB）
- ボタン: 本体に X、Y、L、R を付けるか（案: 付けない）
- 本体で BASIC を打つ方法（画面のキーボードを出すか）
- 既定のクロック（案: 4 MHz のまま）
- カートリッジのファイルの形と、記憶カードの「1 ファイル 32 KB まで」との関係
