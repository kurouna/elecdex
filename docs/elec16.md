# ELEC-16 ペイン（16 ビットポケコン）

> [architecture.md](architecture.md) §5.19 から参照する詳細設計。2026-10-03 に利用者と 4 回のやりとりで決めた仕様（v0.4、操作できる画面モックつき）をそのまま残す。
> 作るのはこれからで、段階ごとの進み具合は §13、判断と実測値は [decisions.md](decisions.md)、機種に依らない土台（`shared/emu`）は [emu.md](emu.md) にある。

elecdex の組み込みペイン `elec16`。1980 年代のポケコンのような外観（キーボードと数行の液晶）を持つ、**elecdex オリジナルの 16 ビット仮想機械**。他社の ROM・フォント・商標・外観はいっさい使わない。CPU の命令セット **E16**、ROM（モニタと BASIC）、フォントはすべて自前で作り、GPL-3.0 で同梱する。作る前に段階 0 で、CHIP-8 ペインの機種に依らない部分を `shared/emu` と `widgets/emu` に切り出した（[emu.md](emu.md)）。

## 1. 決まっていること（2026-10-03、利用者の決定）

- 外観は 80 年代のポケコンのような形: キーボードと、数行を出す昔ながらの液晶。**スキンで見た目を変えられる**
- **独自の仮想機械（案 C）**。他社の権利を侵害しない。ROM・フォント・キー配列の刻印・本体のデザインはすべて自前
- 命令は 40 個程度に絞らない。**今のトレンドを踏まえた RISC**。32 ビットの基本形と 16 ビットの圧縮形を混ぜる（§4）
- **段階 0**（`shared/emu` と共通 UI の切り出し）を先に入れ、ポケコン以外にも使える土台にする
- 名前は **ELEC-16**（商標は §2 で調べた）
- **液晶の既定は 240×48（40 桁 6 行）**。**液晶の大きさは変えられる**ようにし、将来 16 ビットのゲーム機も作れる形にする（§5「モデルと画面の大きさ」）
- **クロックは既定 4 MHz で、可変**（§3）
- 10 fps ループの例外を `EmuRunner` に広げる。ユニットは main が持ち、1 台は同時に 1 ペインだけ。貼り付けは PASTE ボタン（Ctrl+V は取らない）
- カナ入力は v1（段階 5）に入れる
- **スキンは 7 つ**: ELEC、**TRON**、**BUSINESS LIGHT**、**BUSINESS DARK**（elecdex の同じ名前のテーマから。Business は elecdex と同じく明暗を別々に）、CLASSIC、IVORY、NIGHT
- 同梱ソフトは §6 のとおり
- **ROM は E16 アセンブリで書き、同梱するのも E16 アセンブリ**。TypeScript の部分集合から E16 アセンブリを作る道具（e16c）も作る（§6）
- **e16c は最後の段階でペインに出す**: 専用の画面（CODE）で TypeScript を打ってコンパイルし、最適化の段階ごとのアセンブリを見られる。ELEC-16 の売りにする（§6）
- 液晶の大きさは TUNE でいつでも変えられ、変えると再起動。クロックの上限は 32 MHz（段階 2 でペインの中で測り、32 MHz のままと決めた。2026-10-03、利用者の決定）
- **携帯ゲーム機くらいの液晶（160×144）も用意する**。ゲーム機のそれ以外（色、スプライト、音、命令の追加）は別の仕様書で決める
- **ポケコンの中で AI とチャットする構想**を仕様に残す（§12。答えを短くするプロンプトが要る）。作るのは v1 の後、同意と課金の設計とともに。**API キーは利用者が用意し、設定の AI（AI チャットペインと同じもの）を使う**
- CODE はペイン全体を切り替える画面にする。**コンパイルした機械語を MACHINE に直接読み込める**（RUN ▸ / LOAD ▸）
- 160×144 は 4 階調。v1 は液晶だけを替え、縦長の本体（携帯ゲーム機のような形）はゲーム機の仕様書で決める
- 機械語の領域は 7000–7BFF（3 KB）。BASIC の `CLEAR` で広げられ、e16c はここに向けてリンクする
- 段階 0（`shared/emu` の切り出し）から作り始める。詳細は architecture.md に全部書かず、この文書と [emu.md](emu.md) に分ける

### メモリマップ

| 番地 | 中身 | 注記 |
|---|---|---|
| 0000–00FF | システムの作業域 | ROM が使う変数。キーの FIFO の写しなど |
| 0100–7FFF | RAM（プログラム、変数、文字列、スタック） | BASIC のプログラムは下から、スタックは 7FFF から下へ。**7000–7BFF（3 KB）は機械語の領域**として既定で取っておく（BASIC の `CLEAR` で境を動かせる）。起動時の空きは 30,208 バイト |
| 8000–BFFF | ROM 固定（16 KB） | リセット、割り込みの入口、キーと液晶のドライバ、**フォント**（約 1.5 KB。液晶のドライバがバンクを切り替えずに引けるように）、モニタ、ROM サービス、バンクをまたぐ呼び出しの踏み台 |

| F800–FEFF | 予約 | 拡張 RAM カードの窓など、後のため。割り当てのない番地は読むと 0、書いても無視（ROM への書き込みだけは例外） |
| FF00–FFFF | I/O レジスタ | §5。ここへの読み書きはデバイスに届く |

## 4. CPU と命令セット E16

RISC-V に倣った、今風の RISC です。ロード・ストア、3 オペランド、x0 は常に 0、条件フラグなし（比較と分岐が一体）、リンクレジスタでの呼び出し、固定長の符号化（32 ビットの基本形と 16 ビットの圧縮形）、乗除算とビット操作の拡張、CSR と例外を持ちます。データとアドレスは 16 ビットです。RISC-V そのものではなく、16 ビット機に合わせて作り直したオリジナルの命令セットです。

### レジスタ

| 番号 | ABI 名 | 役割 |
|---|---|---|
| x0 | zero | 常に 0。書いても捨てられる |
| x1 | ra | 戻り番地（JAL / JALR が書く。JALR は飛び先のビット 0 を落とす） |
| x2 | sp | スタックポインタ |
| x3 | gp | グローバル域（ROM は 0000 のシステム作業域を指す） |
| x4–x7 | a0–a3 | 引数と戻り値 |
| x8–x11 | t0–t3 | 一時（呼ばれた側が壊してよい） |
| x12–x15 | s0–s3 | 保存（呼ばれた側が守る） |
| pc |  | 16 ビット。命令は 2 バイト境界 |

16 本にしたのは、圧縮命令の 4 ビットの欄ですべてのレジスタを指せるようにするためです（RISC-V の圧縮命令は 8 本しか指せません）。

### 命令の一覧（101）

| 群 | 命令 | 数 |
|---|---|---|
| 整数（レジスタ） | ADD SUB AND OR XOR SLL SRL SRA SLT SLTU | 10 |
| 整数（即値） | ADDI ANDI ORI XORI SLLI SRLI SRAI SLTI SLTIU LI AUIPC | 11 |
| ロード・ストア | LB LBU LW SB SW | 5 |
| 分岐・ジャンプ | BEQ BNE BLT BGE BLTU BGEU JAL JALR | 8 |
| 乗除算（M） | MUL MULH MULHU MULHSU DIV DIVU REM REMU | 8 |
| ビット操作（B） | ANDN ORN XNOR CLZ CTZ CPOP MIN MAX MINU MAXU ROL ROR RORI REV8 SEXT.B ZEXT.B BSET BCLR BINV BEXT BSETI BCLRI BINVI BEXTI | 24 |
| システム | ECALL EBREAK WFI MRET CSRRW CSRRS CSRRC CSRRWI CSRRSI CSRRCI | 10 |
| 圧縮（C、16 ビット） | C.LI C.ADDI C.ADDI2SPN C.MV C.ADD C.SUB C.AND C.OR C.XOR C.SLLI C.SRLI C.SRAI C.ANDI C.LW C.SW C.LWSP C.SWSP C.J C.JAL C.JR C.JALR C.BEQZ C.BNEZ C.NOP C.EBREAK | 25 |

- **16 ビットの即値が 1 命令に入る**: `LI rd, imm16` と `AUIPC rd, imm16`。32 ビット機の LUI と ADDI の 2 命令の組が要らない
- 割り算は例外を起こさない（RISC-V と同じ）: 0 で割ると商は全ビット 1、余りは被除数。`-32768 / -1` は -32768 と余り 0
- ワードのロード・ストアは 2 バイト境界。外れると例外（misaligned）。ROM への書き込みは例外（store fault）。BASIC が壊れた番地を POKE しても、機械は止まらずモニタに落ちる
- `WFI` は、`mie` で許可された割り込みが保留になるまで眠る。`mstatus.MIE` が 0 なら、起きたあと例外の入口へは飛ばずに次の命令へ進む（RISC-V と同じ）。**プロンプトで待つ ROM は WFI で眠るので、ページはその間ループを回さない**（§9）。コアは眠るときに「何で起きるか」（キー、タイマーの一致時刻、カードの完了）を返し、runner はそれだけを待つ。許可されていない割り込みでは起きない
- 例外の処理中にもう一度例外が起きたら（二重の例外）、機械は止まる（`halted`）。CORE に原因と番地を出し、BRK/ON で再起動する。RAM は残る
- `ECALL` は ROM サービスの呼び出し（a0 に番号）。機械語のプログラムから文字の表示、キー、液晶、数値演算、カードを使う入口

### 符号化（段階 1 で確定、`src/shared/elec16/isa.ts`）

命令の最初の 16 ビットの下位 2 ビットが `11` なら 32 ビット命令、それ以外なら 16 ビット命令（RISC-V と同じ）。命令はリトルエンディアンの 16 ビット単位で、2 バイト境界に置く。**符号化の表は `isa.ts` の 1 か所だけ**で、アセンブラ、逆アセンブラ、CPU がそれを読む。単体テストが、全命令の「符号化 → 解読 → 文字 → アセンブル」の往復と、16 ビットの 49,152 通りすべての解読を確かめる。

```
32 ビット       31        22 21  18 17  14 13 11 10  7 6    2 1 0
  R  レジスタ   |  f10     | rs2  | rs1  | f3  | rd  | major|11|
  I  即値       |   imm[13:0]     | rs1  | f3  | rd  | major|11|   符号付き 14 ビット
  S  ストア     | imm[13:4]| rs2  | rs1  | f3  |imm[3:0]|major|11|
  B  分岐       |off[14:5] | rs2  | rs1  | f3  |off[4:1]|major|11|  ±16 KB
  U  LI/AUIPC   |00000| imm[15:0]                | rd  | major|11|   16 ビット
  J  JAL        |00000| off[16:1]                | rd  | major|11|   64 KB のどこへでも
```

| major | 中身 | f3 と選び方 |
|---|---|---|
| 0 LOAD | LB / LW / LBU | f3 = 0 / 1 / 4 |
| 1 STORE | SB / SW | f3 = 0 / 1 |
| 2 OP-IMM | ADDI SLTI SLTIU XORI ORI ANDI | f3 = 0 2 3 4 6 7 |
| 2 OP-IMM（f3 = 1） | imm[13:4] で選ぶ: 0 SLLI、1 BSETI、2 BCLRI、3 BINVI（imm[3:0] が量）。0x10 CLZ、0x11 CTZ、0x12 CPOP、0x13 SEXT.B、0x14 ZEXT.B、0x15 REV8（imm[3:0] は 0） | |
| 2 OP-IMM（f3 = 5） | imm[13:4]: 0 SRLI、1 SRAI、2 RORI、3 BEXTI | |
| 3 OP | f10 = 0: ADD SLL SLT SLTU XOR SRL OR AND（f3 = 0〜7）。f10 = 1: SUB（0）、SRA（5）。f10 = 2: MUL MULH MULHSU MULHU DIV DIVU REM REMU。f10 = 3: ROL（1）XNOR（4）ROR（5）ORN（6）ANDN（7）。f10 = 4: MIN（4）MINU（5）MAX（6）MAXU（7）。f10 = 5: BSET BCLR BINV BEXT（0〜3） | |
| 4 BRANCH | BEQ BNE BLT BGE BLTU BGEU | f3 = 0 1 4 5 6 7 |
| 5 JAL / 6 JALR / 7 LI / 8 AUIPC | | JALR は f3 = 0 |
| 9 SYSTEM | f3 = 0: imm で ECALL（0）EBREAK（1）MRET（2）WFI（3）、rd と rs1 は 0。f3 = 1〜3: CSRRW CSRRS CSRRC、5〜7: CSRRWI CSRRSI CSRRCI（imm が CSR 番号、I 形は rs1 の欄が 4 ビットの値） | |

```

  象限 0（op=00）: メモリ
    C.LW / C.SW   |f3=0/1|off[3:2]| reg   | rs1  |off[1]|00|   オフセット 0〜14
    C.LWSP/C.SWSP |f3=2/3|  reg   |    off[7:1]         |00|   sp から 0〜254
    C.ADDI2SPN    |f3=4  |  rd    |    imm[7:1]         |00|   rd = sp + 2〜254
  象限 1（op=01）: 即値と分岐
    CI            |f3 | rd(12..9) | imm[5:0](8..3) |sub|01|   (f3,sub) = (0,0) C.ADDI (0,1) C.LI
                  |   |           |                |   |  |   (1,0) C.SLLI (1,1) C.SRLI (2,0) C.SRAI (2,1) C.ANDI
    C.BEQZ/C.BNEZ |f3=3/4| rs1    |    off[7:1]         |01|   ±128 B
    C.J / C.JAL   |f3=5/6|          off[11:1]           |01|   ±2 KB
  象限 2（op=10）: レジスタ
    CR            | f4 | rd(11..8) | rs2(7..4) | f2 |10|   (f4,f2) = (0,0) C.MV (0,1) C.ADD (0,2) C.SUB
                  |    |           |           |    |  |   (0,3) C.XOR (1,0) C.AND (1,1) C.OR
                  |    |           |           |    |  |   (2,0) C.JR (2,1) C.JALR (2,2) C.EBREAK
```

- **1 つの符号は 1 つの意味**: 何もしない書き方（0 を足す C.ADDI、x0 に書く C.LI や C.LW、x0 を指す C.ADDI2SPN、0 ビットのシフト、自分への C.MV、x0 との C.ADD・C.SUB・C.XOR・C.OR、全ビット 1 との C.ANDI）は不正な命令にした。C.NOP は 0x0001 だけ。32 ビットの SYSTEM の種類の欄も、ECALL・EBREAK・MRET・WFI の 0〜3 のほかは不正。**0x0000 も不正**なので、消えたメモリに飛び込んだ CPU はすぐ止まる
- JAL の欄は 17 ビットの距離を持てるが、番地は 64 KB で一周するので、アセンブラは常に ±32 KB の側を書く
- アセンブラは、圧縮できる命令を自動で 16 ビットにする（`.option nocompress` で止める）。`c.` で始まる名前はその 16 ビット形を指定し、入らなければ誤り

### CSR、割り込み、例外

| CSR | 番号 | 中身 |
|---|---|---|
| mstatus | 300 | MIE（ビット 3、割り込み許可）、MPIE（ビット 7） |
| misa | 301 | 読み出し専用: M（ビット 12）、B（ビット 1）、C（ビット 2） |
| mie / mip | 304 / 344 | 割り込みの許可と保留。ビット 0 TIMER、1 KEY、2 CARD、3 MATH。mip は読み出し専用（デバイスの状態） |
| mtvec | 305 | 例外と割り込みの入口。**0 のままなら例外で機械は止まる**（ROM が入口を置くまで、とテストのため）。許可した割り込みが入っても止まる（`interrupt with no handler`） |
| mscratch / mepc / mcause / mtval | 340 / 341 / 342 / 343 | 作業用、戻り番地、原因、原因の値 |
| cycle / instret | C00 / C02 | サイクル数と命令数の下位 16 ビット（上位は C80 / C82）。4 MHz で約 18 分で一周するので、時間を測るのはタイマーで |

- 特権モードは 1 つ（M 相当）。存在しない CSR を読み書きすると不正な命令。読み出し専用の CSR への書き込みは無視する
- mcause: 2 不正な命令（mtval に命令の最初の 16 ビット）、3 EBREAK、4 / 6 境界外れの読み / 書き、7 ROM への書き込み、11 ECALL。割り込みは最上位ビット（0x8000）に線の番号
- 例外: mepc にその命令の番地、MPIE に MIE を写して MIE を 0 にし、mtvec へ。**処理中にもう一度例外が起きたら二重の例外で止まる**（`halted`）。MRET は mepc に戻り、MIE を MPIE に戻す
- 割り込みは命令の前に見る: MIE が 1 で、mie と mip の両方に立った線があれば、番号の小さい線から取る。KEY は FIFO が空でない間ずっと立っている（ハンドラは空になるまで読む）。TIMER は比較の値を書き直すか、制御を書くと下りる
- **BRK は線 15（段階 2）**: キーの FIFO には入らず、ページが `brk()` で上げる。MIE や mie に関わらず、命令の前に必ず取る（mcause 0x800F）。待つのはハンドラが動いている間だけ。WFI で眠っていても起きる。mtvec が 0 なら `break` で止まる。電源が切れている機械と、止まった機械（二重の例外など）では、BRK は再起動（RAM は残る）。実機のポケコンの BRK キーと同じく、どんな状態からでも機械を取り戻せる
- WFI は、mie で許可された線が立つまで眠る。MIE が 0 なら、起きた後は割り込みに入らず次の命令へ進む

### サイクル

ALU は 1、ロード・ストアは 2、分岐が成立したときとジャンプは 2、MUL は 4、DIV と REM は 18、CSR は 2、圧縮命令も同じ数です。BASIC は 4 MHz で毎秒 1,500 文ほどの見込みで、80 年代の実機より速く、それでも計算している様子が見えます（段階 3 で測って決めます）。クロックを上げるとその分速くなります。ゲーム機のモデルは 16〜32 MHz を見込みます。

**エミュレーションの費用（段階 1 で測り、早いうちに最適化した）**: 解読した命令を番地ごとに持ち（RAM に書かれた番地と、バンクの窓は捨てる）、命令ごとの関数の表で実行する。測り方: ALU だけ、メモリの読み書き、再帰の呼び出し（fib）の 3 つのプログラムを、素の Node で（Electron と同じ V8。vitest の中は変換の分だけ遅く、比べられない）。

| | ALU | メモリ | 呼び出し |
|---|---|---|---|
| 最初の実装 | 73 | 69 | 68 |
| 最適化の後 | **102** | **96** | **91** |

（毎秒百万命令、i5-1335U の 1 コア）。効いたこと: 命令ごとの処理を 1 回の関数呼び出しにした（共通の包みが別の関数を呼んでいた）、RAM への読み書きを最初に直接見る、RAM に書いたときの解読の捨て方を直接に（呼び出しを挟まない）、解読の表を穴のない配列に（穴を読むとプロトタイプまでたどる）、割り込みは許可されている線があるときだけ見る、サイクル数を表から引く。**効かなかったので戻したこと**: 実行のループを run に展開する（V8 が既に展開していて差が出なかった）。命令あたり平均約 1.3 サイクルなので、毎秒約 1 億命令は約 130 MHz 分。動いている間の費用は 4 MHz で 1 コアの約 3%、16 MHz で約 12%、**32 MHz で約 25%** の見込み。プロンプトで眠っている間はクロックによらずほぼ 0。上限は 32 MHz とし、段階 2 でペインの中で測って判断し直す（利用者の決定）。段階 2 の測定（§9）のあと、32 MHz のままと決めた（2026-10-03、利用者の決定）。MAX と同じく 1 フレーム 8 ms の予算は超えない。

## 5. デバイス（I/O は FF00–FFFF）

レジスタは偶数番地の 16 ビット。バイトで読むとその半分、偶数番地にバイトで書くと上位 0 の値を書いたことになり、奇数番地へのバイトの書き込みは無視する（キーの行列だけはバイトで読む）。`src/shared/elec16/bus.ts` の `REG` が番地の表。

| FF50–FF5F | MATH | | 数値演算ユニット（段階 3）。下の表 |
| FF60–FF6F | CARD | | 記憶カード（段階 4）。下の表 |
| FF70–FF7F | LINK | | 予約（AI チャットの構想、§12）。読むと 0 |

| 番地 | デバイス | 振る舞い |
|---|---|---|
| FF50–FF5F | 数値演算ユニット | 10 進浮動小数点（仮数 12 桁、表示は 10 桁、指数 ±99）の演算。RAM 上の 8 バイトの数を 2 つ取り、結果を書く。四則、べき、平方根、三角と逆三角（DEG/RAD/GRAD）、対数、指数、整数部、比較、文字列との変換。演算ごとにサイクルを使い（SIN は 2,000 など）、終われば MATH 割り込み。コアの中で決定的に動く（ページを待たない）。実装は TypeScript の純粋な関数: 四則と平方根は BigInt の 10 進で正確に、三角・対数・指数は倍精度で計算して 12 桁に丸める |
| FF60–FF6F | 記憶カード | 名前付きファイルの DIR、LOAD、SAVE、DELETE、RENAME、FREE。RAM の命令ブロックで指示し、終われば CARD 割り込み。ファイルの中身は main が持つ（§8）。名前は 8+3 文字の英大文字と数字だけで、パスにはならない。**コアはカードに触れない**: 命令を受けると「カードへの依頼」をフレームの結果としてページに返し、ページが main に頼み、答えをコアに戻す。読み込み先の番地と長さは、書く前にコアが RAM の範囲に収まるかを確かめる。依頼の途中でスナップショットを取った機械は、戻したときに依頼を「CARD BUSY」のエラーで終える（割り込みを待ち続けないように） |

**数値演算ユニットの約束（段階 3、`src/shared/elec16/math-unit.ts`、数は `decimal.ts`）**:

| 番地 | 名前 | 中身 |
|---|---|---|
| FF50 | OP | 書くと演算を始める。二項は A = A op B、単項は A をその場で |
| FF52 / FF54 | A / B | 数（8 バイト）の番地。文字は B に |
| FF56 | ARG | 整数の出し入れ（FROMINT / TOINT）、文字の長さ（PARSE は入れて読んだ長さが返る、FORMAT は桁数を入れて長さが返る） |
| FF58 | STATUS | 直前の演算の誤り（0 なし、1 あふれ、2 0 での割り算、3 関数の引数、4 数でないバイト、5 RAM の外、6 知らない演算）。読むと MATH の線が下りる |
| FF5A | RESULT | CMP の答え（-1 / 0 / 1） |
| FF5C | ANGLE | 0 DEG、1 RAD、2 GRAD |

- elecdex の電卓（`src/shared/calc`）は使わず、10 進の数を新しく書いた（`decimal.ts`）。電卓は JavaScript の倍精度で計算するので 0.1 + 0.2 が 0.30000000000000004 になり、12 桁の 10 進を正確に扱うユニットにならない。電卓の本体は elecxzy の写しで手を入れられず、`shared/elec16` は自分と `shared/emu` しか import しない（`emu-boundary.test.ts`）ことも理由（2026-10-03、利用者の提案を受けて確かめた）
- 数は 8 バイト: 符号のバイト（ビット 7。ほかのビットは 0）、指数（符号付き、-99〜99）、BCD の 12 桁（先頭は 0 でない。0 は全部 0）。値は d1.d2…d12 × 10^指数
- 演算: ADD SUB MUL DIV POW CMP MOVE、NEG ABS INT FRAC SGN SQR SIN COS TAN ASN ACS ATN LN LOG EXP RND PI、FROMINT TOINT、PARSE FORMAT。四則と平方根は BigInt の 10 進で正確に計算して 1 回だけ丸める（四捨五入）ので、0.1 + 0.2 は 0.3、1 / 3 × 3 は 1。三角・対数・指数は倍精度で計算して 12 桁に丸める。度とグラードは 1 周に正確に戻してから計算し、丸めの誤差だけの値は 0 にする（COS 90 は 0）
- サイクルは演算を始めた命令に足す（SIN は 2,000、DIV は 250、ADD は 60 など。`stall`）。演算はその場で終わり、MATH の線が上がる。機械が眠っている間にサイクルは進まないので、終わりを待つ仕組みにはしなかった
- FORMAT は 10 桁（ARG で 1〜12）で、整数や小数で書けるうちはそのまま、はみ出せば指数で（`1.23456789E10`、`1.5E-12`）。RND は状態に持つ乱数で、同じ始まりからは同じ列

数値演算をユニットにしたのは、ROM の大きさと仕事の量を抑えるためです。実在のポケコンにも演算用のチップを持つものがありました。BCD の演算を E16 のアセンブリで書く代わりに、TypeScript で一度だけ書き、単体テストで既知の値と照らします。

### モデルと画面の大きさ

画面の大きさは機械の「モデル」で決まります。モデルはデータ（`ELEC16_MODELS`）で、CPU、メモリ、タイマー、時計、カード、演算ユニットは共通です。画面、入力、音のデバイスをモデルが選びます。

| モデル | 画面 | VRAM | 用途 |
|---|---|---|---|
| POCKET-32 | 240×32、1 ビット | 960 B（窓） | 40 桁 4 行 |
| POCKET-48 | **240×48、1 ビット（既定）** | 1,440 B（窓） | 40 桁 6 行 |
| POCKET-64 | 240×64、1 ビット | 1,920 B（窓） | 40 桁 8 行 |
| HANDHELD-160 | **160×144、4 階調（2 ビット）** | 5,760 B（窓） | 26 桁 18 行。携帯ゲーム機くらいの画面。v1 は液晶だけを替え、本体は横長のまま。縦長の本体と十字キー、ボタン（携帯ゲーム機のような形）はゲーム機の仕様書で決める。公開する文では実在の製品名を使わない |
| GAME（将来） | 例: 256×192、16 色、タイルとスプライト | 映像デバイスが自分のメモリを持つ（I/O ポートか DMA で書く） | 16 ビットゲーム機。パッドの入力、数チャンネルの音 |

- ROM は液晶の `WIDTH` と `HEIGHT` を読んで行数を決めます。BASIC からは `LCDW`、`LCDH` で読めます（同梱ソフトはこれで画面の大きさに合わせる）
- ユニットの液晶は TUNE で変えられます。変えると機械は再起動し、RAM は残り、VRAM は消えます
- ページの画面は `fitScreen` の単位をモデルの解像度にし、描き方（液晶のドット、ゲーム機の色）を差し込みます。`shared/emu` の画面部品は大きさを決め打ちしません
- **命令の追加**: ゲーム機には、飽和演算、8 ビットを 2 つ詰めた演算、積和、ブロック転送のような拡張が欲しくなる見込みです。基本の E16 は固定し、拡張は名前付きの組（例: G 拡張）で足し、CSR の `misa` で持っているかを知らせます。POCKET のモデルの ROM は拡張なしで動きます
- ゲーム機は ELEC-16 の別モデルとして作るのが自然です。CPU、アセンブラ、e16c、runner、保存の仕組みをそのまま使えます。描画は 2D canvas のまま（GPU コンテキストの予算の規則）で、タイルとスプライトを ImageData に合成します

### 文字セット

20–7E は ASCII、A1–DF は JIS X 0201 の半角カナ、80–9F と E0–FF は独自の記号（罫線、矢印、π、√、²、トランプの記号、カーソル用のブロックなど）です。フォントは 5×7 の自作です（設計のときに描いた 95 字が元になる）。5×7 の格子では A や 0 のように形がほぼ決まってしまう字もあり、その字は昔からある液晶のフォントと同じ形になります。IMPORT と EXPORT のときは Unicode と対応させます（半角カナは U+FF61–FF9F）。

## 6. ROM（モニタと BASIC）

**ROM は E16 のアセンブリで書き、同梱するのも E16 のアセンブリです**（決定）。HLE（ROM の仕事を TypeScript で肩代わりすること）はしません。CORE を開くと、BASIC を実行している CPU がそのまま見えます。自前のアセンブラ（`shared/elec16/asm`、純粋。マクロ、局所ラベル、include、バンクの指定）で `npm run gen:elec16` がビルドし、`resources/elec16/rom.bin` とシンボルの表（CORE と MEM がラベルを出すため）を出します。

### アセンブラ（段階 1、`src/shared/elec16/asm.ts`）

純粋な関数 `assemble(source, { include, compress })` で、ビルドのスクリプト、ページ（.asm の IMPORT、CODE）、vitest が同じものを使う。

- 1 行は `ラベル: 命令 オペランド ; コメント`（`//` もコメント）。`.` で始まるラベルは直前の大域ラベルの中だけで通じる（`loop:` の下の `.next:` は `loop.next`）
- 数: 10 進、`0x`、`0b`、`'A'`、`_` で区切ってよい。式は C と同じ優先順位の `* / % + - << >> & ^ |`、単項の `- ~ +`、`lo(e)` `hi(e)`、`$` はその行の番地。まだ決まっていない記号は次のパスで解決する
- 指令: `.org` `.bank`（C000–DFFF に置くもののバンク、0〜11）`.byte` `.word` `.ascii` `.asciz` `.space n[, 埋める値]` `.align n` `.equ 名前, 式`（と `名前 = 式`）`.include "ファイル"` `.macro 名前 引数…` 〜 `.endm`（引数は名前。本体で `\引数`、`\@` は使うたびに違う番号。行頭のラベルはいくつでも、マクロと同じ名前でもラベルとして取る。入れ子はマクロ 32 段、include 16 段まで）`.option compress` / `nocompress`
- 疑似命令（どれも 1 命令になる）: `nop` `mv` `not` `neg` `j` `call` `ret` `jr` `la` `beqz` `bnez` `bltz` `bgez` `blez` `bgtz` `bgt` `ble` `bgtu` `bleu` `seqz` `snez` `csrr` `csrw` `csrs` `csrc` `csrwi` `csrsi` `csrci`。`jal ラベル` は `jal ra, ラベル`、`jalr r` は `jalr ra, 0(r)`。CSR は名前でも番号でも書け、`csr…i` の値にも記号を使える。`li` と `la` の値は -32768〜65535、`.byte` は -128〜255、`.word` は -32768〜65535
- 1 つの命令は必ず 1 つの機械語になる（16 ビットの即値が 1 命令に入るので、分ける必要がない）。圧縮は、パスごとに各命令の大きさを決め直し、大きさも記号も変わらないパスが来るまで繰り返す。前の命令が縮んで行き先が届かなくなった命令は、また 32 ビットに戻る。16 パスを過ぎたら大きさは伸びるだけにするので、配置は必ず落ち着く。まだ決まらない記号があるパスでは、その命令の大きさを変えない
- 誤りはファイル名と行で返す（知らない命令、レジスタでないもの、値の欄のレジスタ、入らない即値、16 ビットに入らない `c.` 形、決まらない記号、2 度定義した名前、奇数番地の命令、同じ番地への 2 度の書き込み）。誤りのある命令もその場所を取るので、後ろの番地はずれない
- `romImage` が ROM の像（固定の 16 KB と使ったバンク、書いていないバイトは 0xFF）を、`ramImage` が RAM に置く機械語の像を作る
- 逆アセンブラ（`disasm.ts`）は、アセンブラが読める形で書く（分岐と JAL の行き先は番地）

### モニタ ROM（段階 2、`resources/elec16/rom`）

- 源は `main.s`（リセット、トラップのハンドラ、ROM サービスの表）、`lcd.s`、`keys.s`、`monitor.s`、`ram.inc`（作業域）。フォント（`font.inc`）、キーの表（`keys.inc`）、I/O の番地と制御文字（`io.inc`）は、`src/shared/elec16/rom.ts` が TypeScript の 1 つの源（`font.ts`、`keys.ts`、`bus.ts`）から作って include に渡す。表をアセンブリに写さない
- `npm run gen:elec16` が `src/renderer/widgets/elec16/rom.json`（像の base64 と大域ラベル）を書き、ペインはそれを読み込む（ORBIT の `tz-lines.json` と同じく、生成したデータをページに同梱する。ROM は機種の一部で、ユニットのものではないので main を通さない）。`elec16-tables.test.ts` が、ファイルが今の源から作ったものと同じかを確かめる
- ラベルは小文字（CORE と MEM がコードを名前で示す）、定数は大文字。I/O の番地は `IO_KEY_COUNT = -0xee` のように 0x10000 未満の負の数にしてあるので、`lw t0, IO_KEY_COUNT(zero)` の 1 命令で届く。作業域の変数も `CURX(zero)` で届く
- **作業域（0000–00FF）**: カーソル、桁と行、画面の幅と面の大きさ、SHIFT と CAPS、D の続き、ECALL の戻り先、最後の中断の原因と 16 本のレジスタ（0020–003F）、入力の行（0040–007F）。スタックは 8000 から下へ
- **ROM サービス**: 8010 から 4 バイトおきの飛び先の表（0 PUTC、1 PUTS、2 GETKEY、3 CLS、4 LOCATE、5 PUTHEX、6 NEWLINE、7 READLINE）。`call` で呼ぶか、`t0` に番号を入れて ECALL。ECALL はハンドラの外でサービスを動かすので、キーを待っている間も BRK が効く。ECALL で変わってよいのは a0–a3 と t0–t3（結果は a0）
- **モニタ（段階 2 の分）**: プロンプトは `*`。`D [番地]`（画面いっぱいのダンプ。8 バイトと文字、狭い画面は 4 バイト。番地なしは続き）、`E 番地 バイト…`（RAM と VRAM へ。ROM と I/O は `?READ ONLY`）、`G 番地`（機械語を呼ぶ。RET で戻る）、`R`（最後の中断のレジスタ。広い画面は 1 行 4 本）、`H` か `?`。EBREAK と例外は `BREAK AT 7004`、`FAULT 0004 AT 7002` のように場所を言ってプロンプトへ。BRK は、プログラムの中なら（ROM のサービスでキーを待っていても）場所を言い、モニタ自身のプロンプトでは行を捨てるだけ（作業域の MONWAIT で見分ける）。BRK は掛かっている SHIFT も外す。数でないもの（`12ZZ`）や 2 桁を越えるバイトは `?` で、`E` は行全体を確かめてから書くので、誤りのある行は何も書かない。`D FF10` は KEYDATA をバイトで読むので FIFO のキーを取り出す（§5 のとおり）。行は画面の幅より長くてよく、下の行へ続く。`U`（逆アセンブル）と `B`（ブレークポイント）は段階 5
- 起動は `ELEC-16 MONITOR 0.1` とプロンプト。キーは WFI で待ち（割り込みは使わない。mie の KEY で起きるだけ）、表示記号は MON と、SHIFT・CAPS の状態
- テスト: `elec16-rom.test.ts` が vitest の中で ROM を動かし、キーを 1 つずつ押して、画面をフォントで文字に読み戻して比べる（4 つのモデルすべて）

### TypeScript から E16 アセンブリへ（e16c）

**難しいか**: TypeScript 全体を扱うのは無理です。しかし、ROM を書くための**部分集合なら現実的**です。構文の解析と型は TypeScript 自身のコンパイラ API（リポジトリに既にある）に任せるので、書くのは検査、中間表現、コード生成で、3,000〜5,000 行ほどの見込みです。BASIC を全部手でアセンブリにする（1 万行を超える）より、速く確実に進められます。

```
TS の部分集合 (*.e16.ts)
  → TypeScript のコンパイラ API で型付きの構文木
  → 検査: 部分集合の外は、場所と理由を出して止める
  → スタック型のバイトコード（中間表現。ここで定数の畳み込みなど）
  → E16 アセンブリ（スタックの上の方をレジスタに載せる簡単な割り付け、圧縮命令を優先）
  → いつものアセンブラ → rom.bin
```

- **部分集合**: 型は `u16` `i16` `u8` `bool`（number の別名。演算は 16 ビットで折り返す）、RAM の番地に置く固定長の配列と構造体（interface をオフセットに）、関数（再帰可、引数 4 つまでレジスタ）、`if` `while` `for` `switch` `break` `continue` `return`、定数、文字列リテラル（ROM のバイト列）。**ないもの**: クロージャ、オブジェクトの生成、GC、例外、浮動小数点（演算ユニットを呼ぶ）、async
- **機械に触る組み込み関数**: `peek` `poke` `ecall` `csr` `wfi`、インラインのアセンブリ（`asm`...``）、バンクの指定。手書きのアセンブリの関数も名前で呼べる
- **二つの実行で確かめる**: 同じ TS のソースを vitest でそのまま動かし（組み込み関数と 16 ビットの折り返しは JS 版で）、e16c で作った E16 のコードを機械で動かした結果と比べます。BASIC の正解が ROM のソースそのものになります
- **速さが要るところは手で書く**: 文の振り分け、液晶のドライバ、キー、数の書式。e16c のコードは手書きの 1.5〜2.5 倍の大きさになる見込みで、ROM のバンク（最大 112 KB）に収まるかを段階 3 で測ります
- **同梱するもの**: ビルドに使うのは生成した E16 アセンブリ（`resources/elec16/rom/*.s`）です。読める形にします（ラベルは関数名、元の TS の行と局所変数の名前をコメントに）。TS のソースも同じリポジトリに置きます（GPL の「改変に適した形」はこちら）。単体テストが、コミットされた .s が今の e16c の出力と一致することを確かめます（CHIP-8 の programs.json の見本と同じやり方）
- **最適化の段階**: -O0（素直な変換。変数はスタック）、-O1（変数をレジスタに置き、圧縮命令を選ぶ、のぞき穴最適化）、-O2（小さな関数の展開、定数の畳み込み、使われないコードの削除、**定数の引数で呼ばれる純粋な関数をコンパイル時に実行する**）。TypeScript のコンパイラ自身は型を外すだけで最適化はしないので、最適化は e16c が自分で行います。型が分かっている（`u16` など）ことが最適化の手がかりになります

**e16c の実装（段階 3、`src/shared/e16c/`）**:

- 構文は TypeScript の構文解析器（`ts.createSourceFile`）だけを使い、型の検査器は使わない。型は e16c が自分で決める（`u16` `i16` `u8` `bool`、`u8[]` `u16[]`）。CODE 画面の Worker でも軽く動かすため
- `body.ts` が関数ごとに型付きのスタック型の中間表現（`ir.ts`）にし、`front.ts` が宣言（関数、`declare function` のアセンブリの関数、定数、RAM の大域変数、`bytes(n)` `words(n)` の配列、`str("…")` の ROM の文字列）を集める。大域変数と配列は呼び出し側が渡すデータ領域に宣言順に置き、`e16c_init` が最初の値を入れて配列を 0 にする
- 組み込み関数とワードの型は `src/shared/e16c/builtins.ts` から import する。e16c は import を読まず名前で解決し、TypeScript として動かすときはそれが本物の関数になる（64 KB のメモリの上で）。両方の実行が合うための決まり: 16 ビットを越えうる計算は `wrap16`、割り算は `div`（`/` は TypeScript では小数になるので拒む）、配列は数ではない（番地は `addr(a)`）。i16 と符号なしを混ぜた計算や比較は `as` で読み方を言わない限り拒む
- `-O0`: 式のスタックは機械のスタック、局所変数は fp（s0）の下のフレーム
- `-O1`（`back1.ts`）: スタックの絵を compile 中に持ち、定数・局所変数・番地は要るまでレジスタに載せない（`x + 1` は `addi`、`if (a < b)` は分岐 1 つ）。局所変数は使う回数の多い順に s0〜s3、残りはフレーム。ラベルをまたぐ値は深さごとに決まったレジスタに。呼び出しでは引数の下にある値を機械のスタックへ。計算した一時レジスタをすぐ変数に入れるときは、計算する命令が変数のレジスタに直接書く。終わった範囲の局所変数の場所は次の変数が使う
- 確かめ方: `tests/fixtures/e16c/sample.e16.ts` を TypeScript のまま動かした答えと、-O0 と -O1 で翻訳して機械で動かした答えを比べる（`tests/unit/e16c.test.ts`）。.e16.ts は配列の要素が常にワードなので、`noUncheckedIndexedAccess` を外した `tsconfig.e16c.json` で型を検査する
- e16c は TypeScript（devDependency）を読み込むので、main・コレクタ・preload からは import しない（`package-deps.test.ts` が確かめる）。-O2 と中間表現の解釈器は次の段

### CODE 画面（段階 6）: e16c をペインで使う

帯の **MACHINE / CODE** で切り替える、ペイン全体の画面です。左に TypeScript、右に E16 アセンブリを並べ、最適化の段階ごとに大きさとサイクル数を比べられます。「TypeScript で書いて、ポケコンの機械語で動く」ことを ELEC-16 の売りにします。

- 操作: COMPILE、-O0 / -O1 / -O2、**RUN ▸**、**LOAD ▸**、SAVE TO CARD（`.BIN` を記憶カードへ。BASIC の `CALL` かモニタの `G` で動かす）。ソースもカードに `.TS` として残る。誤りは行と桁と理由で出す
- **MACHINE に直接読み込む**: e16c は機械語の領域の先頭（7000）に向けてリンクします。RUN ▸ と LOAD ▸ は、できたバイト列をコアの読み込み口（`loadCode(address, bytes)`）で RAM に書き、MACHINE に CRT の演出で戻ってから、人が打つのと同じ形で続けます。RUN ▸ は `CALL &H7000`、LOAD ▸ はモニタで `U 7000`（CORE でそこにブレークポイントも置ける）
  - 書き込めるのは、機械がプロンプトで眠っているか、止まっているときだけです。実行中なら先に BRK と同じことをします
  - 機械語の領域（ROM がシステム変数に持つ境）に収まらない、または BASIC のプログラムに重なるときは、書かずに理由を出します
  - 読み込んだ機械語は RAM なので、電池バックアップに入ります。電源を切っても残り、`CALL` で何度でも動かせます
- e16c はページの Web Worker で動かし、CODE を初めて開いたときにだけ読み込みます（TypeScript のコンパイラ API は数 MB あるため）。**利用者のコードを JavaScript として実行することはありません**。コンパイル時の実行は e16c の中間表現を解釈する小さな実行器で、手数に上限があります。CSP（`unsafe-eval` なし）はそのまま
- できた機械語は ELEC-16 の中だけで動きます。カードの読み書きも ECALL の ROM サービス経由で、機械の外には出ません
- CODE で使える部分集合は、ROM を書くのと同じものです（組み込み関数の `ecall` と `SVC` の表で、文字の表示、液晶、キー、音を使う）

### 起動とモード

- 電源 ON: 表示の確認 → `ELEC-16 BASIC 1.0` → `30,208 BYTES FREE` → プロンプト `>`。電池で保持された RAM はそのまま（プログラムは消えない）
- **RUN**: 文を直接実行する。式だけを打つと電卓として答えを右に寄せて出し、`ANS` に残す
- **PRO**: プログラムを書く。↑↓ で行を呼び出して直す
- **MON**: 機械語のモニタ。`D`（ダンプ）、`E`（書き込み）、`U`（逆アセンブル）、`G`（実行）、`B`（ブレークポイント）、`R`（レジスタ）、`Q`（BASIC へ）。例外が起きるとここに落ちる
- 自動電源 OFF（TUNE で 10 分 / 30 分 / しない）。ROM がプロンプトで WFI に入る前にタイマーの比較を仕掛けるので、新しい仕組みは要らない（ページが待つのは、いつもの「次の一致の時刻」の `setTimeout` 1 つ）。負荷は WFI で既にほぼ 0 で、これは実機らしさのため
- `OFF` 文で電源を切る（RAM は残る）。`WAIT n` の単位は 64 分の 1 秒

### BASIC の範囲（v1）

| 種類 | 語 |
|---|---|
| 命令 | RUN LIST NEW CONT AUTO RENUM DELETE TRON TROFF FILES LOAD SAVE KILL MON |
| 文 | PRINT INPUT LET IF THEN ELSE FOR TO STEP NEXT GOTO GOSUB RETURN ON END STOP REM DIM DATA READ RESTORE CLEAR WAIT BEEP DEG RAD GRAD POKE CALL |
| 画面 | CLS LOCATE CURSOR PSET PRESET LINE (,B / ,BF) GPRINT POINT |
| 関数 | SIN COS TAN ASIN ACOS ATAN SQR ABS INT SGN LOG LN EXP RND PI ANS PEEK POINT |
| 文字列 | LEN LEFT$ MID$ RIGHT$ CHR$ ASC STR$ VAL INKEY$ TIME$ DATE$ |
| データファイル | OPEN CLOSE PRINT# INPUT# EOF（カードの .DAT） |

数は 10 進浮動小数点（演算ユニット）、配列は 2 次元まで、文字列は 255 文字までです。エラーは短い語で示します（`ERR:SYNTAX IN 30`）。方言は独自のものです。ROM、取扱説明書の文、特定の機種の方言をそのまま写すことはしません。RUN / PRO のモード、`ANS`、`GPRINT` のような 80 年代のポケコンの BASIC に共通の語は使います（プログラム言語の語彙は著作権の対象外です。著作権法 10 条 3 項）。

自作し、GPL で同梱します: SINEWAVE（グラフ）、BOUNCE、PRIMES、CLOCK、HIT&BLOW、LANDER（月着陸）、MAZE、BIORHYTHM、UNITS（単位換算）、ASM DEMO（ECALL で液晶に描く機械語の例）。8〜10 本です。

## 7. ペインの画面と操作

- **本体の描き方は 3 通り**で、ペインの大きさから自動で選び、TUNE で固定もできます。FULL（本体とキーボード）、COMPACT（液晶とキー 1 列: BRK、MODE、CLS、SHIFT、矢印、ENTER。打つのは PC のキーボード）、LCD（液晶だけ）
- **液晶はデバイスピクセルの整数倍**（`fitScreen`、単位はモデルの解像度。既定 240×48）。ドットの描き方は機種の差し込みです。反射型の地、ドットの影（地へ少しずらした薄い影）、応答の遅さ（点くのは速く、消えるのはゆっくり）、コントラスト。描き直すのは VRAM の版が動いたときと、残像が消えていく間だけです
- **スキン**は本体の色と形、キーの色、液晶の地とドットの色を持つデータです（テーマと同じく CSS 変数）。初めは 7 つ: **ELEC**（今のテーマに従う HUD 風、角の括弧、液晶はアクセントの濃淡）、**TRON**（elecdex の TRON テーマの色で固定、縁が光る）、**BUSINESS LIGHT** と **BUSINESS DARK**（elecdex の 2 つの Business テーマ。Windows 11 の色と Segoe UI、角の丸いキー）、**CLASSIC**（黒い本体と黄緑の反射型液晶）、**IVORY**（ベージュの本体と灰色の液晶）、**NIGHT**（紺の本体と青い透過型液晶）。実在の製品の配色は写しません。既定はペインごとで、新しいペインには設定 `elec16.skin` を使います
- 右の **PANEL**（CHIP-8 と同じく畳める）: CORE（16 本のレジスタと ABI 名、pc、CSR、命令数、眠りの表示、逆アセンブル、STEP / HALT / ブレークポイント）、MEM（共通の MemView: PC / SP / VRAM / FREE を追い、ROM / RAM / VRAM / I/O で色分け）、FILES（カードのファイル。LOAD は機械に `LOAD "名前"` を打ち込む）、TUNE（クロック、液晶の大きさ、本体の描き方、コントラスト、残像、音、スキン、自動電源 OFF）
- 帯: ユニット名、CPU ランプ（`running` / `asleep` / `off`）、SND、KEYS（フォーカス）、POWER、PANEL
- CHIP-8 と同じ作法: ボタンはタイルの点滅、画面の出入りは `crt-on` と `crtPower`、ランプは `lib/pulse.svelte.ts`、ファイルの行の詳細は HoverCard（`detail-cards.test.ts` の一覧に足す。開いているカードから隣の行へは待たずに）、文字は読むものが `--step--1` 以上
- **本体の文字も大きさの規則に従います**。キーの刻印と表示記号は `--step--2` を下回らない。FULL を選ぶのは刻印がその大きさで収まるときだけで、狭ければ COMPACT か LCD にする。キーの左上の小さな SHIFT 面の刻印は、収まるときだけ出す
- 液晶の中身は、画面読み上げ用に文字として出す（VRAM をフォントで読み戻したもの。見えない要素で、変わったときだけ書き換える）
- 大きさは `ResizeObserver` の entry から読む（中で測り直さない）。0 は無視する（CHIP-8 で見つけた不具合と同じ）
- 前面表示は `zoom: 'full'`。ポップアップにはしない（ダイアログで閉じると動いている機械が止まるため。CHIP-8 と同じ判断）

### キーの割り当て

| PC のキー | 機械のキー |
|---|---|
| 英字（`event.code` の KeyA〜KeyZ） | その英字。大文字か小文字かは機械の CAPS と PC の Shift で決め、OS の CapsLock の状態は見ない（見ると機械の CAPS と二重に効く） |
| 数字と記号（`event.key`） | その文字。機械の SHIFT 面にある記号は、機械の SHIFT を付けて送る。画面のキーで掛けた SHIFT は、PC から次の 1 字を打っても外れる |
| `Enter` `Backspace` `Delete` `Insert` 矢印 | ENTER、BS、DEL、INS、矢印 |
| `Home` | CLS |
| `Pause` | BRK / ON |
| `CapsLock`、`かな`（`KanaMode`） | CAPS、カナの切り替え（機械の状態として持ち、表示記号に出す） |
| カナ入力中の文字キー（`event.code`） | JIS かな配列で半角カナ |
| `Esc` `Tab` F キー、Ctrl / Alt / OS キーとの組み合わせ | 取らない（アプリのショートカットと前面表示のため。CHIP-8 と同じ） |

ペインは編集できる要素ではないので、IME は入りません。貼り付けは TUNE の **PASTE** ボタンで、テキストを機械のキーの列として打ち込みます（Ctrl+V は取りません）。キーが機械に届くのは、ペインにフォーカスがある間だけです。

**キーの並び（段階 2、`src/shared/elec16/keys.ts`）**: 行列の行 0 に矢印、SPACE、ENTER、SHIFT、ANS（ゲームが KEYMAT の 1 バイトで読める）、行 1 に MODE、CLS、CAPS、カナ、INS、DEL、BS、行 2〜5 に英字と `; , . /`、行 6〜8 にテンキー（0〜9、`( ) + - * /`、`.`、`=`）。BRK/ON は行列に入らない（線 15）。英字は小文字を打ち、CAPS と SHIFT のどちらか一方が掛かっていれば大文字（CAPS XOR SHIFT）。だから英字キーには SHIFT 面の記号を置かず、キーのない 24 の記号はテンキー、括弧、句読点の SHIFT 面に置いた（`1`→`!` `2`→`@` … `9`→`[` `0`→`]`、`(`→`{` `)`→`}`、`/`→`?` `*`→`"` `-`→`_` `+`→`~` `.`→`` ` `` `=`→`|`、`;`→`:` `,`→`<` `.`→`>` `/`→`\`）。SHIFT は次の 1 キーだけ掛かり、もう一度押すと外れる。CAPS は押すまで続き、起動時は掛かっている

## 8. 保存とデータ（main）

- **ユニット**（本体 1 台）は main が持ちます: `userData/elec16/units.json`（id、名前、速さ、時計のずれ、作った日）。ペイン状態はユニットの id と表示の選択だけです。レイアウトはパスも RAM も持ち運びません
- **1 台は同時に 1 つのペインでだけ動きます**。2 つ目のペインには「UNIT 1 は別のペインで開いています」と出し、ここに移す（MOVE HERE）か、新しいユニットを作るかを選べます。
  - ロックは main が持ち、鍵は（ページ、ペイン id）。ページが去れば `whenPageGoes` で外れ、ペインが消えるときは明示の release で外れる
  - **release は最後のスナップショットを一緒に運びます**。main はユニットごとに書き込みを 1 列に並べ、次の claim はその書き込みが終わってから RAM を渡します（古い RAM を読んでプログラムを失わないように）
  - ペインの移動（同じペイン id、`park` で預けた機械）はロックを持ったまま。MOVE HERE で別のペインが取ったら、預けられている機械は捨てます
- **電池バックアップ** = スナップショット（`units/<id>/ram.e16s`、CPU、RAM、デバイス、約 34 KB）。書くのは CHIP-8 の AUTO と同じ時です: 見えなくなった、ペインが消えた、電源 OFF、`pagehide`。タイマーでは書かず、前回から動いていなければ書きません。main は書く前と読むときに、コアの decode で中身を確かめます
- **記憶カード**: ユニットごとに 1 つのファイル `units/<id>/card.json`（名前、種類、日付、中身の base64）。**機械が付けた名前はパスにならない**ので、Windows の予約名（CON、NUL、AUX、COM1、LPT1 など）やパスの文字で困ることがありません。名前は 8+3 文字の英大文字と数字だけで、main が検査します。容量は 256 KB、1 ファイル 32 KB まで。書き込みは `replaceFile`
- **IMPORT / EXPORT**: main の picker で、.bas（テキスト。行番号付きのリストを機械の文字セットに変換し、読めない文字は理由を返して断る）、.bin（機械語）、.dat、.asm（ページの純粋なアセンブラで .bin にしてからカードへ）。大きさは読む前に確かめます
- 設定: `elec16.volume`（操作音とは別、既定 0.5）、`elec16.skin`（新しいペインのスキン）
- 変更は `elec16:changed` で全ウィンドウに知らせ、ページのファイル一覧は丸ごと置き換えます（CHIP-8 のライブラリと同じ）

## 9. 動かし方と負荷

- 実行するのは、電源が入っていて、眠っておらず、ペインが `seen` の間だけです。ループは共通の `EmuRunner` で、**いつ回すかは機種ごとの方針**として runner に渡します。CHIP-8 は今のまま（画面が動く間は rAF、30 フレーム止まればタイマー。テストが固定している）。ELEC-16 は**実行は 60 Hz のタイマー、描画は VRAM が動いたフレームだけ rAF を 1 回**にします（CHIP-8 で、空の rAF だけで 1 コアの 5.5% かかると測ったため）
- **WFI で眠ったら、ループを止めます**。起こすのはキー、または次のタイマー一致の時刻の `setTimeout` 1 つです。カーソルの点滅はページが描きます。だからプロンプトで待っている ELEC-16 の費用は、動かないペインとほぼ同じになる見込みです
- 見えなくなったら止め、電池バックアップを書きます。戻っても動き出すのは、眠っていた機械なら即座に（プロンプトのまま）、実行中だったものは一時停止の表示から
- クロックを上げるほど CPU を使います。実行中だけの費用で、プロンプトで眠っている間はクロックによらずほぼ 0 です。e2e の予算は 4 MHz で測り、32 MHz の数字も decisions.md に残します
- MAX は 1 フレームに 8 ms までの予算で、それ以上は回しません（ページを固めないため）。コアは時計を読めないので、runner がサイクル数の小分けで `run(cycles)` を呼び、間に `host.now()` を見ます
- **液晶の描画が負荷の本命**です（CPU ではなく）。段階 2 で測って決めた描き方（`widgets/elec16/lcd-painter.ts`、`Lcd.svelte`）:
  - 液晶は**機械の解像度の canvas**（240×48 なら 240×48）に 1 ドット 1 ピクセルで描き、CSS で整数倍に拡大する（`image-rendering: pixelated`）。その下に同じ大きさの影の canvas を少し右下にずらして置き、上にドットの隙間の格子（デバイスピクセルの bitmap、大きさが変わったときだけ描く。`drawDotGrid`）を重ねる。点いていないドットは透明で、地はガラスの背景色。消えかけは不透明度の段（6 段）。CSS の `filter` は使わない
  - 最初はデバイスピクセルの canvas に、ドットの絵（ドット、隙間、影）を前もって描いて貼っていたが、1 フレームの転送が 0.7 MB になる。ただし測ると、費用の大半は転送ではなく**フレームを作ること自体**だった（GPU プロセスとレンダラーの合成で、毎フレーム描くと約 2 割。CHIP-8 のアトラクトが休止より約 2 割高いのと同じ）
  - そこで**描くのは 1 秒に 30 回まで**にした（`TimedLoop` の `drawMs`）。液晶は数十 ms で応えるので、60 回描いても見え方は変わらない。最後の変化は必ず描く
  - 画面読み上げ用の文字は、変わったときだけ、多くて 1 秒に 1 回読み直す（毎フレームの aria-live の書き換えを避ける）
  - カーソルはページの印なので、そのセルは消えかけを通らずすぐ変わる（通すと点滅が薄くなるだけだった）。止まっているときは消えかけを描かず正確に。影は隙間を越えない大きさ（1 ドット 2 デバイスピクセル以下）では描かない。canvas の作り直しは大きさ・色・コントラストが変わったときだけ（BRK や STEP では作り直さない）
- **測った値**（段階 2、Windows、AC 電源、アプリ全体のプロセスの合計、1 コア比。`elec16.spec.ts` の費用のテスト）: プロンプトで眠る 6.9〜7.1%、一時停止 9.3〜9.5%（差は測りの揺れ。眠っている機械はループも rAF も止まっている）。4 MHz で計算だけ 12.5〜13.2%（眠りより +5〜6%）、4 MHz で毎フレーム画面を書く 27.5%（30 回の上限の前は 37〜40%）。32 MHz で計算だけ 25〜26%、画面を書く 38.7%。MAX は 33〜37%（8 ms の予算で頭打ち）
- 10 fps のループの例外は、CHIP-8 のゲームループから「エミュレータの `EmuRunner`（実行中で見えている間だけ、眠れば止まる）」に広げた（利用者の決定。CLAUDE.md は段階 0 で書き換えた）
- 測る（予算の案）: プロンプトで待つ = ペインなしとの差 1% 未満、BASIC を 4 MHz で実行 = 1 コアの 8% 未満、液晶が止まっている実行（計算だけ）では rAF なし。`metrics.spec` と同じやり方で e2e の予算にします

## 10. テスト

- 単体: 命令ごとの適合テスト（自作のアセンブリで、0 除算、シフト量、符号、境界外れを含む）、アセンブラと逆アセンブラの往復、符号化の表、各デバイス、10 進演算を既知の値と照らす、スナップショットの decode に壊れた入力を与える
- ROM: vitest の中で機械を動かし、キーを打ち、VRAM をフォントで文字に戻して比べます。BASIC の文ごとのゴールデンテスト、同梱ソフトが最後まで動くこと
- 境界: `shared/elec16` は自分と `shared/emu` だけを import し、DOM、Node、タイマー、時計、`Math.random` に触れない（`emu-boundary.test.ts`）
- コンポーネント: CORE、MEM、FILES、TUNE、キーの割り当て（`keyFate` と同じ考え方の純粋な関数）
- e2e: 起動して `PRINT 1+1`、同梱ソフトの RUN、BRK、隠れたペインは止まる（`hidden-panes.spec.ts` に入れる。`hidden-panes-list.test.ts` が求める）、再起動で RAM が戻る、IMPORT / EXPORT（picker はスタブ）、2 つ目のペインでの同じユニット（MOVE HERE で RAM が失われない）、ペインの出入りとシートの電源の入り切り（`motion.spec.ts`）、スキンとテーマのスクリーンショット、費用
- main: elec16 のチャネルは `registerTable` の 1 つの表にし、入力はすべて zod で検査する。カードの名前の検査（予約名、長さ、文字）、ユニットのロックと書き込みの順番、壊れた `units.json` と `card.json` は項目ごとに捨てる

## 12. v1 の後の構想

ゲーム機（GAME モデル、§5）と、下の AI チャット。`shared/emu` のほかの使い道（Linux 系ペインなど）は [emu.md](emu.md) にある。

### 構想: ポケコンの中の AI チャット

ポケコンの画面とキーボードで AI と話せたら楽しい、という構想です。v1 には入れず、決まっていることではありません。作るときに守ることを先に書いておきます。

- **通信の口**: モデムのようなデバイス `LINK`（I/O の予約域 FF70–FF7F を当てる）。機械は送る文をバッファに書いて SEND し、答えは受信の FIFO に入って割り込みで知らせる。ROM に `CHAT` 命令（専用の画面）を持たせる
- **ネットワークは main だけ**: 機械もページも直接は話さない。main が AI チャットペインのプロバイダ（`AI_PRESETS`、鍵は `ai-keys.json`）を使う。**鍵は機械にもページにも届かない**
- **API キーは利用者が用意し、設定の AI に入れたものを使う**（AI チャットペインと同じ設定、同じ鍵）。ELEC-16 には鍵を入れる場所を作らず、TUNE で「どのプロバイダで話すか」を選ぶだけにする（`elec16.chat.provider`。プロバイダの id だけを持つ）。鍵がないプロバイダは選べず、「設定の AI で鍵を入れてください」と出す
- **答えを短くするプロンプト**: ELEC-16 用の固定のシステムプロンプトで「1〜3 文、合計 200 字（40 桁 × 5 行）以内、表・Markdown・コードブロックを使わない、文字は ASCII と半角カナ」と頼む。それでも長い答えは main が文の切れ目で切って「…」を付け、画面の文字セットにない文字は置き換える。モデルの文は信用しないデータとして文字だけを渡す
- **漢字は出せない**: 液晶のフォントは英数と半角カナだけです。日本語の答えはカタカナになり、それも味ですが読みにくくなります。英語で答えさせるか、漢字のフォント ROM（モデルの拡張）を足すかは、そのときに決めます
- **勝手に送らせない**: 送るたびに、前回の送信の後に機械のキーが押されていることを条件にする（ENTER が人の手で押された印）。BASIC のプログラムが繰り返し送ってお金を使うことができないようにする。既定は OFF（`elec16.chat`）で、ペインに LINK の表示記号を出す
- 会話は main が持ち、送る文脈は短く切る（AI チャットペインの `chatWindow` と同じ考え方で、窓はずっと小さく）。会話は、ユニットの電池バックアップとは別に保存する
- e16c と組み合わせれば、TypeScript で書いたチャットのプログラムを ELEC-16 の機械語で動かす、ということもできます
